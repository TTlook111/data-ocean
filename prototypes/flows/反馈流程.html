反馈处理流程说明

长图

答

结论

知识定义在治理工作台修改，程序问题由技术人员处理，业务记录由源系统负责人修正。反馈页负责分派、跟进、验收和回告。

  1. 不需要修复时，按核查依据说明结案。
  2. 三种任务按核实原因选择，不必全部建立。
  3. 技术和源数据任务，先完成实际修正，再回来登记结果。

适用于当前方案与原型；实际修复、数据写入和外部测试未对接

来源只说明线索从哪里来。分派者选择负责人，负责人核查后再选择修复路径。角色决定功能，任务分派决定具体办理人。业务原文和 SQL 继续核对已有权限。1

图中展示常见办理主线。取消、无法补齐或未复现时，可凭依据说明结案。重复事项合并与新证据重开，继续保留历史记录。

  1. 反馈入队 ↗

    点踩、知识缺口或失败线索进入同一队列。先保留来源线索，再由负责人核查原因。

  2. 分派主负责人 ↗

    有分派功能的人选负责人。当前任务负责人提交处理结果，协调者通过转派调整责任。

  3. 信息齐备? ↗

    核对原问题、时间条件和当时依据。缺少必要信息时先补充，不为推进流程随便填值。

  4. 需要修复? ↗

    已有口径正确、未复现或权限正常阻止时，可以说明结案。确需修正时再建立必要任务。

  5. 安排并完成修复 ↗

    选择下方三条路径。一个问题确有多个原因时，才并行建立多个任务。

  6. 验收通过? ↗

    按生效对象、明确数据条件和原问题检查实际结果。尚在开发或等待外部修正时不能记为已解决。

  7. 结案并回告 ↗

    已解决与其他结案分别记录。使用受控模板，发送失败只重试回告。

三条路径各自要做什么

以下都以“跨周退货的时间归属需要核对”为例。先核实企业口径，再判断规则、程序或原始记录哪一处有问题。这里不替企业规定退货应计入哪一周。

图的结构
  • 需要改哪里? choose
  • 修改业务定义 knowledge
  • 安排技术处理 program
  • 跟进数据修正 data
  • choose → data · 业务记录
  • choose → knowledge · 定义
  • choose → program · 程序
对照项新增治理任务新增技术任务新增源数据任务
什么时候选退货时间口径缺失，或已确认定义有错口径已确认，但 SQL、检索、连接或展示出错原业务记录的日期、状态或数量有错
谁负责有相应治理功能并获派任务的人获派任务的开发或运维人员跟进人协调源系统负责人处理
去哪里做现有治理工作台、知识文档和发布页面对应程序的研发、发布或运维流程原业务系统及其既有修正流程
实际动作核实口径，修改并确认治理内容，再按需要更新和发布知识复现问题，修代码或恢复配置，完成对应测试和生效操作联系负责人员核实记录，在源系统按制度修正
回反馈页做什么关联实际发布，说明如何覆盖原问题先记录进展；实际修复后登记复查结果与生效确认先跟进外部修正；完成后登记修正人、记录范围和复查结果
怎样算完成当前有效知识覆盖问题，生效后复验通过修复已生效，原问题与相关边界验证通过数据修正已生效，在明确条件下重新核对通过

治理路径复用现有页面。反馈页本身不提供程序编辑功能，也不能写入业务数据库。技术修复与源系统修正完成前，事项继续跟进。2 1

这里按职责区分，同一人具备相应能力时可以兼任。实际修正仍须在对应位置完成。

技术和数据记录现在怎么填

先选择目前进展。尚在排查、联系或等待生效时，只填写已做工作及下一步。处理好以后，再填写实际修正和复查结果。保存进展保持处理中，提交完成记录后仍需人工复验。2 3

当前字段什么时候填写填写什么
关联问题系统只读带出对应原问题，受限原文仍不显示
目前进展每次记录仍在处理、等待生效，或已处理好提交验收
已做的工作和下一步处理或等待阶段已核对什么、联系了谁、下一步准备做什么
实际修正人或负责团队源数据完成时实际执行源系统修正的人或团队，不要求平台账号
做了什么修复或修改已处理好时修复内容；源数据写清记录范围和实际改动
怎样复查、实际结果如何已处理好时检查位置、原问题条件、已核实记录及实际结果
相关处理记录有现成记录时工单、发布记录、批次或链接，没有可留空
生效确认已处理好时由处理人核对真实生效情况后确认
相关场景测试结果及确认查询或权限相关技术变更完成时核对原问题及本次变更涉及的受限场景，确认测试通过

原问题不再预填到复现方式，回答编号不再预填成验证数据依据。技术和源数据记录不强制填写工单号、版本号或数据水位。原有记录仍可回看，改回跟进会使旧验收失效。2 3

在页面中按什么顺序操作

页面入口实际处理位置在反馈页做什么
新增治理任务治理工作台、知识文档与发布页面关联治理条目和实际发布，说明问题覆盖范围
安排技术处理对应程序的研发或运维流程保存跟进；修复生效后提交修正和复查记录
跟进数据修正源业务系统记录联系与修正进展；完成后记录执行团队和复查结果
  1. 还没处理好

    选仍在处理或等待生效，填写已做工作和下一步，保存处理记录。

  2. 已经处理好

    切换到提交验收，补充真实修正和复查结果，核对生效情况。已有外部记录可补充。

  3. 等待别人的处理

    从我负责的继续跟进；有新进展后更新，不把等待记录混作当前待办。

  4. 提交后继续复验

    必要任务全部具备依据后，登记人工验收。通过后才可以验证结案。
