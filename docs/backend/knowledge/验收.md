# D 批首个事项验收

使用隔离平台 MySQL、合成商品源、原有 Redis 和独立命名的 Milvus 代次。确认两种商品属于同一测试分类，其中一种有两条展示记录。两种商品都是事先准备的合成事实。把期望值写入审核题单，实际结果独立运行。

## 当前实测

- 隔离平台已迁移到 V31。真实文档接口覆盖同源确认、四类治理引用、必要依赖补齐、防重、过期写入、历史回读和越界拒绝。旧依据被 C 批修改时，确认需重新核对。见[文档接口](../../../output/acceptance/2026-11-20-d-knowledge/documents-api.json)和[权限与过期依据](../../../output/acceptance/2026-11-20-d-knowledge/permission-stale-api.json)。
- 商品事项的数值题与说明题已审核。发布准备按实际确认修订读取两道审核题，并披露来源未启用、目录需核对或缺少向量配置等阻断。样例自身有三条展示记录及两种不同商品，样例查核与候选运行分别取证。见[题单与发布准备接口](../../../output/acceptance/2026-11-20-d-knowledge/tests-preflight-api.json)和[隔离环境复验](../../../output/acceptance/2026-11-20-d-approval/approved-api.json)。
- ego-lite 通过文档创建、保存、确认和回读依据，以及题目编辑、重新审核和发布准备检查。见[1024px 文档依据](../../../output/playwright/2026-11-20-d-knowledge/documents-confirmed-1024.png)和[发布准备](../../../output/playwright/2026-11-20-d-knowledge/release-preflight-1024.png)。
- 文档规划和生成节点已在隔离库分配。向量配置通过真实 Embedding 探测，合成商品候选使用 1024 维向量构建独立 Milvus 代次。Strong 回读与 MySQL 的完整章节、边界和七项治理引用一致，代表性问题命中同版索引。见[向量连接](../../../output/acceptance/2026-11-20-k04/embedding-probe.json)及[存储对账](../../../output/acceptance/2026-11-20-k04/strong-readback.json)。
- 缺题时可保存准备任务，直接构建被拒绝。补齐两道审核题后回到同一任务，首次构建才关联候选并冻结输入。重复命令返回同一构建代次，原候选历史仍可回读。见[构建前接口](../../../output/acceptance/2026-11-21-release-task/before-build.json)、[首建结果](../../../output/acceptance/2026-11-21-release-task/result.json)及[桌面交互](../../../output/playwright/2026-11-21-release-task/browser.json)。
- 原任务可改用同一文档的最新确认或替换为另一份同源文档。隔离实测 r1 调整到 r2 后回到准备中，旧修订和构建可在历史候选回读，补齐审核题后新候选完成真实索引构建。构建中拒绝调整，旧任务版本和旧文档修订均被拒绝。见[调整接口](../../../output/acceptance/2026-11-21-release-scope/adjusted.json)、[实际构建](../../../output/acceptance/2026-11-21-release-scope/rebuilt.json)和[同源替换](../../../output/acceptance/2026-11-21-release-scope/replaced.json)。
- 合成商品候选构建后自动跑两道已审核题。只读 MySQL 去重查询实得 2，说明题实际命中同版片段，浏览器阅读证据后提交裁定并进入待发布。另以预期 3 验证明确失败，接口拒绝改判及裁定旧运行，重测保留历史。见[自动运行](../../../output/acceptance/2026-11-21-release-validation/automatic-run.json)、[人工裁定](../../../output/acceptance/2026-11-21-release-validation/judged.json)和[失败及重测](../../../output/acceptance/2026-11-21-release-validation/failure-and-retry.json)。
- 合成商品首版及 r2 已实际切换。首版原命令重放返回同一回执。两份 r2 候选均基于 r1，先提交的一份生效，另一个以基础版本变化拒绝。r2 提交后的首次索引确认注入一次不可达，浏览器通过核实原入口确认同一绑定，并读回正式 r2 和原 r1 正文。见[首版](../../../output/acceptance/2026-11-21-release-switch/first-publication.json)、[第二版与旧基础阻断](../../../output/acceptance/2026-11-21-release-switch/r2-and-stale-base.json)、[绑定与事件对账](../../../output/acceptance/2026-11-21-release-switch/mysql-switch.txt)。
- 发布复审验证了无源授权不能核实，有权用户可确认同一绑定。绑定模型停用期间显示不可用。索引回读期间并行停用模型时，切换被拒，恢复后重新核对可正常发布。见[核实权限和模型状态](../../../output/acceptance/2026-11-21-release-switch-review/after.json)及[模型切换竞态](../../../output/acceptance/2026-11-21-release-switch-review/model-race.json)。
- 候选审查验证了更换向量配置后拒绝旧预检、只读角色无法创建、同源确认标题查询与空列表页码校正。浏览器实测候选第二页回看及焦点恢复，并模拟已提交但回包丢失、原请求未送达两种网络故障。见[接口复验](../../../output/acceptance/2026-11-20-release-review/api.json)及[界面复验](../../../output/playwright/2026-11-20-release-review/review.json)。
- 仅对隔离 Worker 注入 Milvus 不可达，候选进入构建失败，SSE 回读到终态；恢复后原候选生成新代次，保留首次失败记录，刷新后回读待验证。另验证取消阻断旧工作消息。构建和取消均保持原正式绑定。本次首版没有旧生效版本。见[失败与取消](../../../output/acceptance/2026-11-20-k04/failure-cancel.json)与[浏览器重试](../../../output/playwright/2026-11-20-k04/browser.json)。

## 验收用例

| 场景 | 通过条件 |
| --- | --- |
| K01 同源范围和依赖 | 以 PC 实际创建商品文档草稿。精确回读表与字段、关联、指标、实际修订和自动纳入的依赖。跨源身份或未确认条目退回 |
| K02 草稿确认和失效 | 保存正文后确认。重复提交复用原回执；并发编辑保留先提交的修订。确切的 C 批依据变更能定位相应文档，旧候选不能发布 |
| K03 标准题审核 | 数值题独立给出期望 2；说明题包含判定依据。草稿、无相关题或缺少必要覆盖时阻断构建或发布，页面能定位办理 |
| K04 实际构建 | Python 用当前固定配置构建独立 Milvus 代次。Strong 读取命中同一候选，返回完整条件和同版治理证据。构建失败或迟到结果保留现行入口 |
| K05 自动验证和人工裁定 | 实际去重查询得到 2。说明题给出实际结果及依据，待裁定时阻断，裁定后方可发布。明确失败和异常只能修复后重跑 |
| K06 真实切换 | 先发布首版，再从同一基础版发起两个候选。兼容产物就绪且检查通过的候选才可切换。下一候选因基础版过期阻断；同键重试只生效一次。实际 MySQL/Milvus 读取的绑定、片段和事实一致 |
| K07 故障与回退 | 构建失败旧版不变；切换回包丢失查询原命令。实际回退到直接上一版，缺必要匹配索引或受当前禁止影响时给出阻断。正常回退不解除任何仍有效的限制 |
| K08 权限和桌面操作 | 分别核对文档、题单、构建、裁定、发布和回退权限。跑通 PC 的来源定位、提交后回读、失败处理与返回。浏览器证据记录视口和操作结果 |

当前状态以实际接口、存储记录和浏览器证据为准。
