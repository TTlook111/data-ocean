# 正式问数首条链路

## 接口与执行边界

| 接口（`/api/v1/query`） | 请求与结果 | 权限与一致性 |
| --- | --- | --- |
| `GET /sources` | 返回当前可选来源的编号和名称 | 请求人的功能与实时来源资格 |
| `GET /requests?sourceId=` | 返回同一用户、同一来源的近期轮次摘要 | 查询前核验当前权限，列表不返回结果或 SQL |
| `GET /conversations?sourceId=` | 返回本人的同源对话及各自最新轮次 | 各来源只返回当前本人可访问的对话 |
| `GET /conversations/{id}/requests` | 返回同一对话可回看的轮次摘要 | 跨用户返回 404。撤权后拒绝读取 |
| `POST /requests` | 请求包含来源、问题、可选对话和原轮次编号。重查可指定 `inheritContext=false`。使用 `Idempotency-Key`，返回轮次编号 | 一轮一个源。相同用户与命令键恢复原回执，内容不一致返回冲突 |
| `GET /requests/{id}` | 返回阶段、执行代次、终态、澄清、限量结果和独立解释修订。仅有 SQL 查看权限时包含校验后的模板 | 本人归属、问数权限及当前源权限；结果按固定知识与当前输出规则再次核验。无可信水位时数据更新时间为空 |
| `POST /requests/{id}/clarifications` | 提交缺项补充，恢复同一轮次 | 服务端幂等，等待超时后创建新轮次。已明确的问题仍保持原意 |
| `POST /requests/{id}/cancel` | 终止待执行轮次、为在途执行登记取消，或停止当前结果说明 | 已交付结果独立保留。数据库停止未核实前保持可核对状态 |
| `POST /requests/{id}/explanations` | 使用 `Idempotency-Key` 对原已交付结果提交新解释修订 | 复核原结果、当前权限与规则。保持原执行编号、结果及查询时间 |
| `GET /requests/{id}/events` | `query.updated` 推送状态、游标及核验通过的当前修订答复 `explanationText`；结构化结果与依据仍通过详情读取 | 同会话、本人及当前权限；正文复核原结果的有效期、规则和发布绑定；重连用原编号和最新快照，无派发副作用 |

Java 保存请求、阶段、实际执行身份、规则修订、知识绑定、列血缘和限量结果。执行前在安全共享锁下重新取得权威资格，并登记一次性派发许可。查询使用源只读账户、绑定参数、实际目录标识和限制行数。从已派发状态恢复时先保留执行未知，不能自动重发 SQL。模型和索引由受认证的 Python 服务调用，模型配置通过现有节点分配获取。Milvus 召回严格核对 MySQL 已发布的同版候选、文档修订、模型修订、代次和证据摘要。

可选 `rag-rerank` 在 Java 核验每条召回片段的同源授权、生效版本、摘要和当前治理依据后，使用任务固定的 Cohere Rerank 模型修订对多条候选排序。只提交本轮与向量召回相同的检索表述及已确认片段正文。排序必须返回原候选的完整排列，模型全程只改变顺序。回包后仍核对权限和候选有效性。未配置、单候选、预算不足、提供方失败或排序无效时沿用原召回顺序。采用的顺序或回退在后续规划前写入本轮，澄清后的阶段单独固定，恢复不得重复外发。重排沿用问数模型来源准入，实际调用及提供方报告的 Token 进入模型运行概览。

同一发布的候选按既定次序核对完整计划，包括投影、筛选、日期、指标和关联。排名靠前的片段缺少必要依据时，继续核对该版本中的其他已获准片段。新问题还会对本轮召回的其他有效发布独立核对同一指标、滤值和物理输入，每个候选按自己的已确认日期口径在同一请求时间锚点下解析业务日期。只有实际筛选、日期、输出列、计量单位和连接路径均等价，才允许按既定次序采用候选，冲突时停止派发。首选发布不能执行且业务输入身份和计划唯一时，可采用其他已获准发布的唯一可执行口径。物理表有歧义时暂停派发，在原轮次请用户补充 `模式名.表名`。用户明确指定表时，Java 在规划前限定证据。首轮有目标表依据时直接使用，首轮漏召回时从本轮冻结且仍获准的发布中按实际表身份补查一次。找不到目标表的可用依据时结算为知识不足。规划后的实际 SQL 血缘必须包含指定表，有指定表依据仍生成异表计划时结算为技术失败，诊断为 `QUERY_PLAN_TARGET_MISMATCH`。最终采用的片段进入语义、权限复核和审计。

当前轮次确立的知识不足和技术失败在同一次结算中记录受控诊断。后台按原问可靠派发至[自动事项](../feedback/问数自动线索.md)，自动入队与原问终态回看独立。

对话上下文在实际请求进入工作者时固定。读取同一个用户、同一个源和同一个对话中的已交付轮次，保留最近五个可用轮次的提问、补充及已确认口径，并将更早的可用计划汇总为带来源编号的条件摘要。结果明细留在原请求。请求接受时刻是相对日期的锚点，澄清和进程恢复沿用原锚点。旧轮次的授权、规则或知识失效后不向后继请求传递。

有需复用的窗口外口径时，可按 `history-summary` 的独立模型修订挑选旧轮次。Java 先按同一绑定和指标压缩到最新确认的条件，剔除近期已经替换的旧值。摘要模型只接收当前原问和批准回用的结构化计划，回包只引用本轮确认过的旧轮次。理解、规划和语义审核读取保留的原计划，不采纳模型新增的业务值。未分配模型、预算不足、无确认回执或引用无效时使用结构化摘要。已采用的回包或回退决定在下一节点开始前写入原请求，澄清及重启复用同一决定。摘要使用既有问数外发准入和节点回执，实际请求计入模型运行概览。

只改前后一天的短追问以上一轮实际执行的物理表、关联修订和单个业务日期为基准。明确仅改变日期的追问在匹配片段前固定原发布、计算公式和输出字段。Java 在当前授权下使用原执行血缘核对候选及筛选列，编译仅取用原关联修订。缺少原表或原关联依据时结算为知识不足。原范围可核验但日期条件不唯一时，在原轮次请用户指出要调整的日期列，补充后仍核对实际执行范围。历史追问以原实际筛选为底稿。明示「其他条件不变」或只改变日期时，保留所有未修改的日期、文本和编号筛选，仅合并本轮明确提出的变更。明确换题从空上下文开始，后续追问只读新主题。按跨日定义统计的指标在省略时间时保留原统计范围。

只问「那上周呢」或「上周？」且上一轮已确认日指标时，Java 以本轮接受日计算前一个北京时间自然周，保留原指标、对象和筛选，按日查询周一至周日。独立提问缺少上文时只澄清指标和对象范围。仍需正式证据、语义与输出核对。已冻结的旧版轮次沿用原派发路径。

Java 在派发前固定知识入口、模型修订、原时间锚点、上下文和规则摘要。进程退出后，MySQL 租约到期由新代次领取。Python 使用独立 Redis 的 LangGraph 检查点保存节点回执，`thread_id` 沿用原请求编号。成功提交过的节点只核对原输入和实际回执。没有可核实回执的节点不自动重发。SQL 执行回来后先捕获结果，恢复可以从已捕获结果继续做交付复检。仍处于已派发但未捕获状态的 SQL 保留未知，重复旧命令只回原请求。

新轮次入队前核对 `intent` 节点已分配、启用且符合部署准入。检索前固定该节点修订独立理解问题，在原问题、上轮同源问题和已确认指标的基础上补充模型整理的召回表述。后续规划和审核沿用原有授权与证据。实际提供方请求及用量计入模型运行概览。已登记步骤按原输入和修订回读检查点，模型停用仍可读取已有回执，首次外发仍检查启停和访问许可。首次响应超时或暂不可用时只查一次原回执。未接入问题理解时已冻结的轮次沿用原召回输入。

首条链路接收可证明的单源查询计划，由 Java 编译普通表上的参数化查询。计划提议和语义核对分别使用现有节点配置。允许固定关系上的去重计数、求和或两数相减后求和，支持等值业务条件。受限输出、来源或证据失效时拒绝；无法证明适用规则和候选安全时失败关闭。证据和模型产物不能提供数据行，最终数值来自本次 JDBC 查询。结果快照暂按 24 小时保留。

聚合查询使用指标确认修订里的 `metricRules`。规划和语义复核都读取当前片段可定位的确认规则，其中日期、固定筛选和单位列使用与计划一致的表列标识。理解节点分别读取原问与补充，使用各自回执。Java 核对完整原句并保留跨逗号、换行和列表的否定上下文。补充用原文前缀定位每次追加、替换或撤销，重复句也按各自出现的位置执行。替换和整列撤销只影响同一物理字段的用户范围，定向撤销只移除实际等价且方向一致的条件。合并后只确认仍有效的取值。

补充节点将原话编号分段交给模型，依据各项返回的动作、片段和词位在服务端还原前缀。同句内重复的词按出现位置区分。结构错误或无法定位时，在同一模型修订及节点预算内重新提取一次，仍失败时保留范围不明确。无法确认的外发超时不重发。

各候选以同一份用户条件核对物理字段、已确认的编码和商品映射，并分别补入自己的固定筛选。模型复述的任一发布固定值不进入用户范围。Java 拒绝与包含或排除条件冲突的固定值，包括已确认的固定 SKU。识别原话中的字面编码、绑定、定向撤销和候选比较共用实际列的类型及源库等值规则。排除条件按实际参数执行，空值不自动纳入排除结果。同一发布的不同片段也须核对实际筛选、时间、单位与连接口径；首选公式不可用时，使用可信同名指标和相同物理输入核对可执行的后备公式。仍有冲突或范围不能唯一确定时在原轮次澄清。语义复核读取原问及补充的编辑动作、有效条件、全部已核验落选片段的理由与依据，以及已编译计划的实际关联键、物理范围和日期。关联编译失败时同时提供所需表、判断用的业务日期和已确认的关联键、修订及适用期，供复核区分日期不适用和路径无法确认。

业务日必须有已确认且仍有效的日期依赖，跨发布比较忽略未生效的日期草案并按实际绑定类型比较。来源单位使用精确值判断是否混用，单位格式与固定单位一致。有参与行时要求其单位完整且同一，空结果的去重计数交付 0 并保留空单位。缺少完整结构化规则的指标须补确认并发布。

所需表无法通过已有直接关联接入时，Java 从同一片段的已确认关系中补全唯一的普通表连接路径。补全的中间表只参与 `JOIN`，表、连接键与关联修订均进入实际 SQL 血缘。路径缺失或有多条可用路径时，该片段不能支持本次编译。跨表求和或差额求和从每张度量表分别核对实际联接方向，包括筛选、指标依赖和补表所用的关系。只有每步的精确数值等值键覆盖对端完整主键，才能证明联接不会放大该度量的行数。依据不足时不派发该候选。

关联按确认修订的 `relationWindow` 核对主查询对象唯一可信业务日期或完整区间，起止端点包含当天。正文中的日期须由治理人员核实并写入结构化窗口。与窗口一致的独立 ISO 日期注记可保留。关联用途、规则或适用说明存在额外业务限制时，须有可执行的依据。选择不限日期仍要核对这些限制。已确定超期的关系不进入本次路径。适用性待核实的关系如果可能改变所需路径，会阻止选路和派发。适用的候选继续比较实际关联键。

支持按已治理的业务日期聚合。趋势省略日期时，由 Java 使用接收问题时的北京时间，取包含当天的最近 7 个自然日。单值需要业务日期且未给日期时取当天，实时字段继续直接查询。提问中的明确日期或区间优先。对可独立确定的单日，Java 以用户原话及补充为准生成并检查 SQL 绑定值。审核提示中的确认日期来自用户单日解析或服务端对历史范围的确定性计算。确认的同源对话可以按提问要求沿用原日期。只有发布文档示例提供日期时，执行前清除该筛选。按日查询最多 366 天，图表日期维度参与输出复核，日期区间作为结果元数据交付。缺少快照时保留空值，出现零值时照实交付。

常见日常日期用原提问的北京时间解析，按周一开始的自然周区分「这周五」和「上周五」。只给日号且无可用月份时澄清，补充月份沿用原始请求锚点。商品问数按已发布的真实名称与规格对应关系识别，中英文等义表达可以落到同一商品。目标商品有多种规格时询问必要规格，缺少可核实映射时保留知识不足；适用指标要求锁定商品，草案漏掉商品条件也不能派发。范围明确的普通库存问题可从正式映射和指标直接构造有限计划，仍经独立语义、输出及权限复核。

部署通过 `dataocean.query.model-source-ids` 显式准入可以发送问数内容的来源。首条链路复用已生效绑定的向量模型修订及 `intent`、`sql-generate`、`sql-semantic-check`、`output-meaning` 的节点分配。当前限制按已验证的采购成本及采购单价规则识别，遇到无法解释的输出规则直接拒绝。

启用采购输出限制时，Java 在保留真实投影核验的基础上，检查结果单元格中由采购标签明确关联的金额。文本识别完整的金额数值，保留年份和日期说明。JSON 按键值和数组结构核对已识别采购字段中的数值及金额字符串。已知年份或日期键需与有效标量匹配，其他值和嵌套节点继续检查。命中时整份结果不交付，保留已发生的只读执行状态。新快照入库、已捕获任务恢复、历史回看和说明外发共用这项检查。

结果说明使用独立队列和 `result-explanation`。业务结果外发需另外准入 `dataocean.query.explanation-source-ids`。首次说明、手动生成和重试在入队前按来源、结果最多 20 行、至少 2 秒剩余预算以及修订上限校验，领取时复核同一套条件。首次说明以交付时结算后的预算为准，未通过时直接记录为 `UNAVAILABLE`。详情用 `blockedReason` 返回当前不可生成的原因。同一命令回放保留原修订，`blockedReason` 仍按当前最新修订计算。重新获准的来源若历史修订在模型调用前结束，按 `NOT_GENERATED` 展示，并按当前资格允许生成。已交付且仍可查看的说明正文继续保留。每次说明从原请求的剩余预算中预留时间，单次上限 22 秒。模型收到本次已执行且可披露的范围与事实，从中选择最多三条。Java 核对引用，并按已核验投影的列义、原值和单位构成说明正文。外发及交付前均复核原结果的当前权限、规则签名和知识版本。原问题、补充和受保护的筛选值不进入说明请求。手动请求使用新修订，最多三次，并保留原查数结果。

Java 只向说明模型提供能独立放入 1,000 字正文的完整事实。交付时按模型返回的顺序装入完整事实，跳过超出剩余空间的引用。所有候选都超限时，工作台显示原因，说明任务在预留模型预算前结束。

## 验收用例

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| E01 | 库存查看人使用已发布的《连锁超市日末库存口径》r1，问“常温饮料品类中，有库存快照记录的商品有多少种？” | 真实索引命中同版证据，按唯一 SKU 去重，只读查询得 4，与独立 SQL 对账一致 |
| E02 | 询问 2026-11-20 日末 1 L 原味燕麦奶可售库存及在途口径 | 在库减锁定可售量为 85 箱，不计在途，记明日期、规格与所用依据 |
| E03 | 库存查看人询问采购成本或采购单价 | 不派发受限结果 SQL，结果、依据、历史和 SQL 接口不返回受限信息 |
| E04 | 保留问数功能，撤销唯一库存源授权，回读旧回答并发起新问 | 当前源移出可选列表，旧答案和新执行均拒绝，撤销无需重新登录生效 |
| E05 | 重复原命令、断开订阅、再次读取、在派发前取消 | 同命令返回同一编号；读取不派发；已取消请求无 SQL 执行 |
| E06 | 问数页面与既有原型、设计参考对照 | 在桌面大窗及窄窗核对来源、对话、输入、状态、结果依据和键盘；后台只做既有页面回归 |
| E07 | 沿用库存商品，只修改业务日期，再从独立会话提交缺少商品的追问 | 同一对话按新日期取数。独立会话不读取旧条件，跨用户无法回看原会话 |

## 代码审查回归

- 原命令保存规范化输入指纹。显式轮次与省略轮次按各自提交语义比较，旧格式记录沿用原校验。等价 SQL 的等值条件采用稳定顺序，已核验的 SQL 与参数使用带密钥的执行指纹。已登记但尚未核实的同源等价执行会阻断新派发。 [命令接口回归](../../../tools/acceptance/query-command-review.mjs) · [MySQL 状态用例](../../../backend/src/test/java/com/dataocean/module/query/service/QueryPersistenceIT.java)
- 补充和取消在原请求行锁内决定状态。解释工作者先锁原请求，再锁确切修订，避免与取消的锁顺序相反。已清理或过期的捕获结果不能标为已交付，前一代次不能更新后续租约和结果。
- 字段类型随已确认目录提供给规划节点。模型把商品编码写入数值外键时，Java 在执行许可前拒绝，并允许在原权限、绑定和预算内重规划一次。真实双会话同时提交相同补充，两个调用均返回 202 和同一轮次，改用另一日期重放返回 409。原轮次最终返回 85 箱。 [并发补充实测](../../../output/acceptance/2026-11-22-e-code-review/clarification.json)
- Redis 中同一线程的检查点提交使用短写锁，外部节点调用仍保持独立。实际 Redis 回归先保存第二份回执，再让第一份晚到，最终能够分别回读两份且不触发重发。 [Redis 回归](../../../python-service/tests/unit/test_query_journal.py)
- 旧对话的迟到提交回执只刷新列表。已切换的对话保持可见，解释重试保留原结果，未知执行没有重新查询入口。 [前端用例](../../../frontend/src/modules/query/QueryWorkbench.test.tsx) · [真实浏览器回归](../../../output/playwright/2026-11-22-e-code-review/late-receipt.png)
