# 反馈概览与对账

业务口径见[产品方案第 8 章](../../product/modules/08-dashboard.md)，页面行为见[运营看板页面](../../frontend/pages/dashboard.md#正式反馈概览)。

## 接口与授权

| 只读接口 | 必要权限 | 返回 |
| --- | --- | --- |
| `GET /api/v1/feedback/overview` | `feedback-dashboard.view` | 可统计的来源、读取截止时间、日／周／月粒度、趋势点与期间总计 |
| `GET /api/v1/feedback/overview/details` | `feedback-dashboard.view` 和 `feedback.view` | 指定指标的贡献记录分页，含事项编号、活动版本、来源、时间及适用的解决耗时 |

两端使用 `sourceId`、`fromDate`、`toDate`、`timeZone`。缺省汇总当前获准来源，默认近 30 个北京时间业务日（含今天）。日期两端包含，区间最长十年。60 天及以下按日，61 至 180 天按自然周，其余按自然月。首尾分组以用户实际选择的日期为界。今天的分组以当前数据库截止时间为界。

下钻使用上一步返回的 `asOf`，按 `metric` 选择 `ADDED`、`RESOLVED`、`CLOSED_OTHER`、`MERGED`、`OPEN` 或 `PENDING_VERIFICATION`。下钻重新核对页面资格和当前源授权。显式选择已失权或不存在的来源统一返回 404；没有任何可见来源时，汇总的 `total` 为空。事项证据原文复用原详情授权。

## 事实与时间口径

| 指标 | 来源 |
| --- | --- |
| 新增 | `fb_issue.created_at`，每个事项计一次 |
| 已解决、其他结案 | `fb_issue_activity` 的结案活动按当次状态分类。升级前的结案使用同轮次回告的模板确定是否已解决 |
| 已合并 | 同源原事项的合并事件。纠正合并保留原事件，期末按纠正后的状态计算 |
| 期末未结 | 创建、结案、合并、纠正及重开的活动重建截止状态。待验证和待补充均属于未结 |
| 期末待验证 | V49 起由生效状态台账重建。涉及升级前存量且当期末早于记录起点时返回空值 |
| 平均解决耗时 | 建单至实际解决结案的时长合计除以本期间解决次数，单位为小时。无已解决样本时为空 |

V49 保存升级时实际状态，并在后续反馈办理写活动时同事务记录动作后的状态。旧活动保留原始内容。历史存量取期末快照，自然周或月的快照只取该组截止状态。同一事项重开再结案时，各结案轮次分别保留。汇总与下钻查询共用权威事实及来源过滤。
