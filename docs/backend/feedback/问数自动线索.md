# 问数知识缺口与技术失败

已提交的 `KNOWLEDGE_INSUFFICIENT` 和 `TECHNICAL_FAILURE` 自动接入问题队列，来源分别为 `QUERY_KNOWLEDGE_GAP` 和 `QUERY_TECHNICAL_FAILURE`。入队时默认方向分别为业务知识和技术问题，人员分派沿用当前角色和事项版本。取消、超出范围、澄清、权限拒绝和资源超限保留在各自问数状态。

问数结算时记录固定失败分类、原阶段和当时已核验的输出范围摘要。源端是否实际执行继续沿用问数独立状态。待派发标记和原终态同时落盘，后台分批生成 `feedback.query.failure.recorded`。Outbox 编号和原问标记同事务提交，消费回执和事项证据也同事务提交。

事项首个证据指向原请求，用户点踩保留确切的已交付回答修订。自动来源追加独立的原问证据关联，同一原问只入队一次。问数可核实当前来源完全没有生效知识、确认指标缺少结构化规则或指定字段依赖、单一关联缺少适用依据时，在同一来源、原提问人和输出范围内复用开放事项。指标与关联按实际确认修订及缺失依赖区分，问法变化仍可追加到同一事项。不同缺口、未定位的知识不足和各次技术失败分别建事项。已结案的历史继续保留，旧终态不自动补建或归并。

后台队列的 `origin` 可与事项、数据源和队列分组交集筛选。详情里的问数诊断使用固定编码、原问编号、失败阶段和执行状态。原问正文仍要求证据功能与当前来源授权，且输出范围和原问一致。事件载荷只携带原问编号和来源，后台按持久原问回查诊断。
