# 反馈事项的处理结果、复验与回告

已分派且当前负责人已核查的技术事项可以提交处理结果。结果包括实际修正、复查方式与结果、影响范围及已生效确认。查询和安全变更同时记录相关场景并确认测试通过。当前一项技术结果沿用主负责人办理。

| 接口 | 服务端办理条件 |
| --- | --- |
| `POST /api/v1/feedback/issues/{id}/results` | 当前负责人持有 `feedback.process` 且已核查。提交成功进入待验证。 |
| `POST /api/v1/feedback/issues/{id}/knowledge-results` | 业务知识负责人已核查，具备当前原问证据和发布查看资格。关联同源、已核实且可用的正式发布版本，提交后进入待验证。 |
| `POST /api/v1/feedback/issues/{id}/rechecks` | 复验人有当前原问证据和问数权限。使用本人的权限从原问题派发，保留原补充及业务日锚点。原问依赖其他对话历史时阻止重放。 |
| `POST /api/v1/feedback/issues/{id}/verifications` | `feedback.verify`，使用当前登录人的有效问数与来源授权，记录场景、期望、实际结果和数据依据。复验未通过退回处理中。 |
| `GET /api/v1/feedback/issues/{id}/closure-preview` | `feedback.close`。结案类型、原因和有效复验核验后返回当前版本、原提问人和固定模板。 |
| `POST /api/v1/feedback/issues/{id}/closures` | 提交事项所见版本和所确认模板与接收人。已解决仅接受当前结果的有效通过记录。说明结案保留真实类型与内部依据。 |
| `GET /api/v1/feedback/notices` | 只分页查询本人的已投递回告。 |
| `PUT /api/v1/feedback/notices/{id}/read` | 按消息和本人身份标记首次已读，返回当前授权下的定位。 |

V40 保存不可变的处理结果和复验版本，转派清除当期引用。复验授权摘要包括当前账号认证版本、使用能力、源授权来源和输出规则。已解决操作再核对当前负责人、结果修订、复验人员资格及摘要。技术处理记录、复验和结案内文按证据权限裁剪。

结案、回告接收和 `feedback.completion.recorded` Outbox 同事务写入。回告以事项、完成轮次和接收人去重。站内可见状态同本地消费回执落盘。收到、实际投递和已读独立记录。投递与回看均复核原提问人资格、源和输出规则。停用账号只保留后台不可用状态，失权账号的站内提示为通用模板。原问链接随可见资格返回，后台自由结案文本不进入回告。

V42 为知识办理固定正式发布引用和实际复验请求。系统在复验与解决结案时核对当期结果、当前发布资格、原问题、复验执行人及结果所用的发布绑定。复验通过必须来自本期重跑且实际交付的结果。技术复验继续登记实际核对结果。多任务、源数据修正和事项重开继续采用产品方案。
