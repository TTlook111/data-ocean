# B 批业务验收

## 可复验入口

隔离平台库已应用 V5—V9，Flyway 校验 V1—V9。以 MySQL 8.4.9 和 PostgreSQL 16.16 为业务源，各通过 13 组真实接口场景，覆盖连接、采集、账号和数据源停用、独立与联合审批、授权及业务说明。见 [MySQL 接口报告](../../../output/acceptance/b-closeout-20261119/mysql/api-report.json)和 [PostgreSQL 接口报告](../../../output/acceptance/b-closeout-20261119/postgresql/api-report.json)。

隔离库拒绝单个合成审批命令的审计写入时，申请仍待审批，授权来源和成功审计均为零。移除临时约束后按原命令重试，生成一笔来源及一条成功审计。见[审批回滚结果](../../../output/acceptance/b-closeout-20261119/audit-rollback.json)。

真实浏览器验证了批准待联合生效与已生效的历史记录、只读关联申请、Esc 回到原审计详情及焦点、进入授权目录再返回原筛选与详情、精确定位已撤销的来源，以及仅审计人员看不到关联入口。见[审计操作](../../../output/playwright/2026-11-19-b-closeout/audit-journey.json)和[授权来源截图](../../../output/playwright/2026-11-19-b-closeout/revoked-origin.png)。

正式构建在 ego-lite 用鼠标两次打开并关闭同一审计记录。抽屉关闭后浮层移除，筛选保持，焦点返回原按钮。窗口获焦回读时已有审计结果仍可点击。见[审计鼠标复验](../../../output/playwright/2026-11-19-b-ui-polish/audit-mouse.json)。

按已确认原型复查了数据源、采集、目录、结构变化、资料、审批责任、规则、申请与授权等 13 个正式页面或页签。在 1440px 和 1024px 核对筛选换行、表格滚动和操作可达性；授权表另在四档桌面宽度测得表头与数据列对齐。复查包含字段错误聚焦、无匹配与重置、抽屉和编辑往返，以及新增合成规则后提示成功并回读列表。见[逐页复查](../../../output/playwright/2026-11-19-b-ui-polish/review.json)。

10 个页面在 1024、1280、1440、1536px 桌面视口保持常驻菜单可见，页面无整页横向溢出。此前浏览器整单操作覆盖草稿恢复、分派、要求补充、重提、批准、授权追溯及撤销。见[当前视口结果](../../../output/playwright/2026-11-19-b-closeout/viewport.json)和[整单操作记录](../../../output/playwright/2026-11-19-b-recheck/request.json)。

ego-lite 通过浏览器原生「网页缩放」在 125% 和 150% 对正式页面完成 9 项检查。窗口外宽保持 1920，设备像素比分别为 1.25 和 1.5，页面有效宽度分别为 1526px 和 1272px。未见整页横向溢出，授权抽屉在两档均可按鼠标打开、按 Esc 关闭。已恢复初始 100%。见[原生缩放实测](../../../output/playwright/2026-11-19-b-acceptance/native-zoom.json)。

Windows 本机 Vitest 已改用单 VM 工作器，并在测试环境为 Ant Design 预打包浏览器依赖及加载图标 ESM 入口。标准 `npm run test:run` 通过 10 个文件、28 项用例；同一构建的前端生产打包和 ESLint 通过。

## 验收结论

本机补验通过 PC 原生缩放及 MySQL 8.4.9、PostgreSQL 16.16 的采集停止回包丢失恢复。连接编号冲突采用真实库加等价身份输入，核实了同号异身份、实例不符，以及 PostgreSQL 启动时刻不符的判定。详见[采集验收](../datasource/验收.md#证据与完成判定)。

MySQL 8.4.9 和 PostgreSQL 16.16 的[对象支持范围](../datasource/验收.md#本次支持的源对象)已按真实只读连接、成功快照和字段回读确认。DS28 新增双库共 8 个进程退出断点样例，DS40 双库通过窗口外人工采集与跨午夜双工作者竞争，夏令时边界由固定时钟用例覆盖。见[进程退出与定时证据](../datasource/验收.md#进程退出与定时证据)。

DS29 双库各通过 4 项实测。平台库不可用、采集发布时审计写入失败及 Outbox 写入失败均保留原成功目录。Redis 通知回包丢失后按同一事件 ID 补投，业务事实只提交一次。见[DS29 采集发布故障证据](../datasource/验收.md#ds29-采集发布故障证据)。

**B 批在已确认范围内具备正式验收条件。** 验收范围包括 MySQL 8.4.9 和 PostgreSQL 16.16 的已验证对象、B 批数据源与访问授权流程，以及 PC 桌面浏览器操作。治理任务取用说明和目录、知识发布及问数输出约束按对应批次联调。
