# B 批数据访问授权

数据源接入与目录由 [采集设计](../datasource/设计.md) 维护。业务规则见 [人员角色与权限](../../product/modules/02-people-access.md)。

## 数据与事务

| 记录 | 权威含义 |
| --- | --- |
| access_output_rule | 共享规则名称、正文及当前修订。编辑在原编号递增修订，当前计算直接读取新版 |
| access_responsibility | 每源唯一的主审批人与替代负责人。待办理项按当前配置及人员资格计算分派，历史决定保存实际办理人 |
| access_request / access_request_item | 本人申请、组合方式及稳定子项。部分补充仅覆盖相应独立子项的资料，任何子项办理均推进整单修订 |
| access_request_revision | 追加保存生效前、中间办理与调整事实，保留动作时的内容和规则 |
| access_request_item_action | 经办关系绑定实际决定的版本。重提、更换负责人后，已办队列按原经办人的快照显示和筛选 |
| access_department_source / access_department_rule | 部门每次配置的源、规则与有效区间。实时计算结合直属成员、部门状态及待复核标记 |
| access_grant / access_item_rule | 批准生成的个人来源，绑定申请子项和目标人员。带外键的规则关系用于读取当前规则，批准时快照用于历史回看 |

写入复用 IAM 配置排他锁、原命令回执、权限复核、审计及授权版本事件。联合组合的最后一次批准同时提交所有来源，任一校验失败整体回滚。撤销结束来源并保留批准事实。部门来源只取仍开放的直属归属，叠加有效个人来源后按当前规则正文去重。

## HTTP 入口

统一前缀 `/api/v1/access`。列表复用公共分页，所有写入使用 `Idempotency-Key`。聚合变更携带当前 `expectedVersion`，ID 按公共字符串契约表示。

| 入口 | 作用与权限 |
| --- | --- |
| GET /rules；POST /rules；PUT /rules/{id} | 查询和维护共享规则，使用 `output-rules` 权限；配置或审批选项仅向实际办理者开放 |
| GET /responsibilities；PUT /responsibilities/{sourceId} | 回看与配置当前源责任，使用 `sources.view` 与 `sources.approval-config` |
| GET /my-requests；POST /my-requests；PUT /my-requests/{id} | 本人列表、创建、补充及草稿修改，使用 `my-requests` 权限 |
| POST /my-requests/submission-preview | 本人核对新建、草稿提交或重提的实际来源与预计状态，可选 id 指定原单 |
| GET /requests；GET /requests/{id} | 按本人归属、待分流权或申请所有权返回受限内容 |
| GET /requests/{id}/handled | 当前经办人只读回看本人实际处理过的子项 |
| POST /requests/{id}/action-preview；POST /requests/{id}/actions | 核对和提交核定、组合调整、批准、补充请求、驳回及本人撤回 |
| GET /departments/{id}；PUT /departments/{id} | 回看及变更初始配置，复核直属成员和配置版本 |
| GET /grant-directory；GET /grants；POST /grants/{id}/revoke | 管理列表以同一查询、总数及分页显示个人申请和部门来源。目录接受 `requestId` 或 `grantId` 精确定位个人来源，包括已结束记录。个人来源可回看和撤销，联合组合一次结束 |
| GET /my-sources；GET /users/{id}/sources | 以权威状态汇总本人或有权查看人员的当前范围 |
| GET /department-grants；GET /my-grants；GET /my-department-grants | 回看管理范围或本人申请与部门来源的历史 |
| GET /my-requests/{id}/history | 只向原申请人披露实际办理动作、处理人及提交时刻 |

共享规则修改、审批责任配置、部门初始配置使用各自资源的 POST `/impact-preview`，提交携带签名。签名绑定可信操作者、原始提案、业务版本及当前授权配置版本。撤销使用 `POST /grants/{id}/revoke-preview`，显示各受影响数据源和其余来源。用户停用或归档结束其个人来源并阻断尚待办理项，重启后回读持久化状态。部门停用及复核状态随组织配置生效。

## 业务验证

申请核对展示实际接手人、独立或联合范围、规则全文及预计状态。整单尚无办理决定时才返回完整的计划来源，已筛选队列仍只展示符合条件的子项。草稿首次提交记录为 `SUBMIT`，已有待补充项重提记录为 `RESUBMIT`。

审批审计列表和详情返回当次批准的 `approvalEffect`。取 `APPROVED` 时仍待联合生效，取 `EFFECTIVE` 时当次批准已使来源生效，后续撤销不改写该历史结果。关联申请和授权目录按各自的读取权限返回。

验证范围见[授权验收](验收.md)。问数 SQL 及结果交付按 [分批计划](../详细设计与验收.md#分批依赖与完成条件) 接入权威访问条件。
