# 首批本地运行与验收

Java 和前端在宿主机运行，MySQL 与会话 Redis 复用已核实的本机服务。启动或诊断前先完整阅读 `.dataocean/local-environment.md`（若存在），核对实例、端口、数据库及服务归属。基础依赖停止时启动准确的原有服务，不新建另一套容器替代。

## 开发配置

共享配置完整维护在 [application.yml](../../backend/src/main/resources/application.yml)，开发账号、端口与 HTTP Cookie 设置位于其中的 `dev` 段，不另设 `application-dev.yml`。开发约定随项目提供：[初始密码](../../backend/src/main/resources/development/initial-password.txt)、[前端开发变量](../../frontend/.env.development)。首管理员为 `admin / admin123`，根部门为“总公司 / ROOT”；开发人员初始密码使用 `admin123`。首次登录仍执行必要改密，已有账号不会在启动时被重置。

主配置列齐当前应用的 MySQL 连接与连接池、迁移、Redis 连接与会话前缀、HTTP 与 Cookie、持久层映射、HMAC 文件引用、会话与限流、操作核对、可靠事件及日志参数。公共默认值在主配置维护，密码和机器文件路径使用环境变量占位；example 仅展示本机差异的填写格式，不能代替主配置中的完整字段。

两台设备各自在 `backend/src/main/resources` 中将 [application-local.example.yml](../../backend/src/main/resources/application-local.example.yml) 复制为同目录的 `application-local.yml`，填写本机 MySQL、Redis 连接和凭据。`application.yml` 与 example 随 Git 同步，local 由 Git 忽略，各设备独立保存；example 不参与运行时加载。启动脚本默认加载该 resources 目录并启用 `local,dev`，local 覆盖共享配置；需要调整后端端口时可在 local 中设置 `server.port`，或显式传入 `-Port` 覆盖。HMAC 文件保存在 `.dataocean/hmac-key.txt`，只初始化一次，重启保留。

Maven 不复制或打包本机 `application-local.yml`，启动脚本直接加载 resources 源目录。IDE 启动时启用 `local,dev` 并将 `spring.config.additional-location` 指向该源目录，保持相同加载方式。

example 的连接信息是格式样例，复制后直接填写本机地址、端口、库名、账号和密码，无须额外设置密码环境变量。开发脚本通过 `DATAOCEAN_SECRET_FILE` 注入本机 HMAC 文件路径，并在退出后恢复原环境变量，模板中的密钥段默认保持注释。用 IDE 手动启动时，除启用 `local,dev` 和加载本机配置目录外，还须设置该环境变量或启用 local 中的 `dataocean.secret-key-file` 示例并填写已存在的本机密钥文件绝对路径。

Flyway 在指定的新平台库上执行建库基线；`clean` 已禁用。非空或来源不明的数据库不能当作可弃目标。空库初始化只执行一次，不提供匿名 HTTP 初始化接口；已执行的迁移不修改，通过新迁移补充。

## 启动

使用 [前端](../frontend/README.md#工程版本与验证边界)及[后端](README.md#版本基线与验证边界)规定的工具。当前 PowerShell 的 `JAVA_HOME` 指向 JDK 17，`PATH` 选择兼容的 Node/npm。命令从仓库根目录执行：

```powershell
# Java 使用仓库内 Maven Wrapper 和固定镜像配置。
./tools/dev/start-backend.ps1

# 在另一个终端启动前端。
./tools/dev/start-frontend.ps1

# Python 正式内部 API 使用同一份 uv.lock。
./tools/dev/start-python.ps1
```

后端默认 `127.0.0.1:18080`，前端默认 `http://127.0.0.1:5173` 并代理 `/api`。使用外部已有配置时执行 `./tools/dev/start-backend.ps1 -ConfigurationDirectory '<配置目录>'`。停止应用使用各自终端的 Ctrl+C，不停止共享 MySQL、Redis 等依赖。

Python 默认 `127.0.0.1:18090`，当前 `/health` 只确认进程存活。其正式包、`.env` 加载边界、构建及检查命令见[Python 运行说明](../../python-service/README.md)，工作流与执行器随实际业务接入。

`.dataocean` 只保存本机环境说明、说明模板和私有密钥。开发日志及临时验证脚本放 `output/dev`，验收探针编译产物和依赖列表放 `backend/target/acceptance`，界面和接口证据分别沿用 `output/playwright`、`output/acceptance`。

## 检查与真实验收

静态检查、单元测试、真实 API/数据库和浏览器分别记录，不能互相替代。下列真实验收会创建带独立前缀的合成人员、部门、角色和审计记录；应在明确可用于开发验收的新平台库执行，不用于正式业务库。密码变更用例会恢复合成开发账号为 `admin123`，最后恢复途径用例会使管理员已有浏览器会话失效。

```powershell
# Java 格式和单元测试。
./backend/mvnw.cmd -f backend/pom.xml -s backend/.mvn/settings.xml spotless:check test

# 前端生产构建、代码检查和组件回归。
npm.cmd --prefix frontend run build
npm.cmd --prefix frontend run lint
npm.cmd --prefix frontend test -- --run

# 已启动应用后的普通接口验收。
node tools/acceptance/iam-api.mjs
```

会话时限、物理约束和故障测试还需要读取当前机器配置的 Java 探针，准备方式见[验收工具](../../tools/acceptance/README.md)。真实接口证据放 `output/acceptance/iam-first-stage`，页面证据放 `output/playwright`。当前覆盖和剩余边界见[首批验收](iam/验收.md)，后续数据访问来源、AI 任务和 SSE 按对应批次接入，不能用固定结果冒充已完成。
