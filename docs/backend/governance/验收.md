# 表说明与字段治理验收

以下为 C 批验收用例，实际覆盖见当前验证。依据为[设计](设计.md)和[接口与权限](接口.md)。使用隔离平台 MySQL、B 批已验证的 MySQL 8.4.9 和 PostgreSQL 16.16 只读业务源。准备两源同名表、一个含状态／金额／时间字段的对象和一份带附件的企业业务说明。修改结构用隔离源的维护连接，治理运行仍使用原只读连接。外部模型联调用合成资料及已获准配置。

## 当前验证

- 隔离平台已应用并校验 V1–V11。双库真实接口完成表说明保存、同命令重发、逐项确认、字段引用资料，以及资料只改标题与后续正文实质变化的区别。确认使用已失效资料时受到阻断，更新实际引用后完成复核。两库均已有真实字段注释变化引发定向复核的证据，内容未经修改时保留原修订。MySQL 一次采集未核实结束，后续重新采集成功。见[接口报告](../../../output/acceptance/c-governance-20261119/api-report.json)和 [MySQL 复采证据](../../../output/acceptance/c-governance-20261119/mysql-structure.json)。
- MySQL 合成金额字段由 DECIMAL 改为 VARCHAR，成功快照发布后接口同时显示该字段禁止使用及待复核。旁系状态字段保持可用。见[不兼容变化接口证据](../../../output/acceptance/c-governance-20261119/incompatible-api.json)。
- ego-lite 对正式 React 构建执行真实登录、从工作台读成功目录、编辑表说明、保存、确认及返回原关键词。字段办理包含固定资料修订回看、Esc 关闭来源、保留未保存输入、保存及确认。该窗口菜单可见，工作区没有整页横向溢出。见 [PC 表说明记录](../../../output/playwright/2026-11-19-c-governance/table-journey.json)、[PC 字段记录](../../../output/playwright/2026-11-19-c-governance/field-journey.json)及[字段确认截图](../../../output/playwright/2026-11-19-c-governance/field-confirmed.png)。
- 实际将一源字段传入另一源对象，接口返回 404001。只授予元数据目录查看权的人员请求治理列表，返回 403003。见[真实权限接口证据](../../../output/acceptance/c-governance-20261119/permission-api.json)。
- PC 原生缩放 125% 和 150% 时，字段导航、编辑区、确认按钮和常驻菜单均可见，文档宽度与视口一致。验证后恢复初始 100%。见[原生缩放记录](../../../output/playwright/2026-11-19-c-governance/native-zoom.json)。
- Java 50 项测试、React 生产构建和 ESLint、Python 3 项测试及治理模块 Ruff 检查通过。前端全套首轮通过 26 项，人员页两项超过缺省 5 秒。两项使用 20 秒测试时限单独复验通过。
- Java 接收表说明任务后经 Redis Streams 和独立 Python 工作者执行。通义接口使用合成目录和资料返回 HTTP 200，实际建议已持久化。同命令重发复用任务，缺少服务令牌的内部上下文请求返回 401。选择性填入草稿后保留人工用途，只有人工提交才产生确认。真实接口和 PC 页面均有回填、保存及确认记录。见[真实模型接口证据](../../../output/acceptance/c-governance-20261119/model-api.json)、[PC 生成操作](../../../output/playwright/2026-11-19-c-governance/model-journey.json)和[建议差异截图](../../../output/playwright/2026-11-19-c-governance/model-difference.png)。
- 表说明模型配置复验使用独立平台库 V12。通过 PC 后台新增并改绑同一个「表说明生成」节点，LangChain 分别向百炼的 OpenAI Chat Completions 和 Anthropic Messages 兼容端点发起真实调用，均取得 HTTP 200 并持久化建议。两次选择性填回「一行代表什么」，核对原人工用途后保存并确认。编辑两套配置到 r2 后，调用记录页和平台数据库均显示两笔调用分别绑定各自的 r1。见[PC 回填与确认](../../../output/playwright/2026-11-19-c-models/model-journey.json)、[调用历史](../../../output/playwright/2026-11-19-c-models/model-history.json)和[平台库对账](../../../output/acceptance/c-governance-model-config-20261119/model-db.json)。

仓库用例入口为 [governance.mjs](../../../tools/acceptance/governance.mjs)。上述结果覆盖已运行的场景。附件格式全量验收、批量生成、辅助读取业务行、开放资料映射的完整页面、故障注入和其余 PC 窗口检查仍按下列用例核对。

## 目录、修订与审核

| 编号 | 触发与操作 | 预期结果和取证 |
| --- | --- | --- |
| GOV01 | 首次成功。先后有失败、取消和回包丢失。再次打开同一对象 | 真实 API 和平台库显示治理只用成功指针。第一次展示空白业务定义且无伪造确认。查看列表和详情不物化空修订。重读同一对象、分页和数量一致 |
| GOV02 | 两源均有同名 `product.status`。将另一源的表、字段、资料或历史 ID 混入本源请求 | 来源、世代和成员绑定准确。各自确认互不影响。越界 ID 返回不可披露错误且无写入。配置范围外对象不计为当前目录可治理对象 |
| GOV03 | 保存半填内容。原样再保存。并发编辑和同键重发 | 保存可部分填写。无变化不加修订。竞争中至多一笔按原版本更新，另一笔按冲突保留输入。同键重发无额外修订、成功审计或事件。不同内容同键冲突 |
| GOV04 | 分别测试无粒度、无字段含义、单位缺失、编码缺漏或重复、业务时区未知、依据冲突与普通选填空白 | 关键缺口逐项提示且定位字段。编码 `01`、`1`、空值及 0 按声明语义区分，普通空白可确认。样本出现值不冒充完整枚举。核清后内容、结论、人员和时间可回看 |
| GOV05 | 逐项确认任一独立字段。编辑已确认内容。只持审核权的人员提交带修改确认 | 部分确认更新真实计数，表与字段可独立办理，新修订待确认，原确认仍绑定原内容。仅审核者可确认已保存草稿，带修改须具备编辑权。兼任者可审核自己填写的内容 |
| GOV06 | 用角色分别测试仅目录、仅工作台、仅生成、编辑、审核、补充、禁止及只具有授予权。直接访问选项、分页、历史和写入 | 操作各自核权，列表与计数无旁路。草稿、事件和建议内容按当前权限裁剪。撤权后重放命令、回看、写入或继续收流按实际资格拒绝。人工维护不依赖模型、辅助采样或问数源授权 |

## 企业业务说明与模型建议

| 编号 | 触发与操作 | 预期结果和取证 |
| --- | --- | --- |
| GOV07 | 同源同时存在有效、撤下、示例及他源资料。提交建议任务。并发删除及替换资料 | 任务自动选择获准的当前有效修订，接收事务固定各资料输入。任务取用先提交时删除被挡。删除先提交时该资料不进任务。建议实际引用、草稿引用与任务输入可分别对账。用过的任一历史修订阻止删除 |
| GOV08 | 使用 B 批允许的六种实有格式、破损／扫描 PDF、加密文件及超限输入。以仅治理权限访问历史附件 | 正常可提取文本固定到修订与真实位置。失败原因可回看，其他获准依据继续有效。原文、片段、文件名和下载在列表、详情、任务事件和直接 URL 都检查资料权限。无法检查必要原文的审核人不能确认 |
| GOV09 | 字段含义已经由结构和资料说明。另造必须辅助读取的含义缺口，分别使用已授权、无源授权和撤权账号 | 有充足依据时没有业务源采样。需要读取时只使用当前授权与只读交集、限定字段和预算。超时／失败计次，撤权后不追加采样或回传受限结果。模型目的地和凭据不出现在任务／审计／日志内容 |
| GOV10 | 对选定表说明或部分字段运行真实任务，包含一条字段失败、模型超时、同一执行回写重复和旧执行代次迟到 | 结果只写选定条目，成功和失败独立。原始建议和调用修订保留，审核状态不变。人工输入默认保留，选定差异后才保存。重跑、迟到回包、应用重启或权限变化均不能覆盖人工内容或产生重复建议 |
| GOV11 | 发起建议后变更当次实际输入或撤回发起人资格，再返回原任务结果。仅改无关标题后重复 | 实质来源变化阻断陈旧建议回填，按当前资格限制结果与历史。标题变化不触发复核或使内容等价的输入失效。拒绝及事件重放中不披露已失权来源 |

## 结构与资料变化复核

| 编号 | 触发与操作 | 预期结果和取证 |
| --- | --- | --- |
| GOV12 | 在两个业务源各成功采集新增字段、表和字段注释变化、列重排及无变更。一个字段和另一个表有明确依赖 | 新字段只进入自身治理，注释影响定位到具体条目，沿真实同源依赖扩展。无依赖的列顺序差异、无变化采集与其他表不产生复核。两侧确切结构均可回看，旧确认仍在 |
| GOV13 | 分别改变键约束名称、主键字段集合、外键映射、字段类型精度。制造兼容扩大和确定不兼容 | 只有实质键变化触发表粒度或引用项复核。可兼容变化建立定向复核，风险明确的对应对象或字段在来源事务内禁止。未受影响字段继续，表被禁止时其字段无法绕过 |
| GOV14 | 查到对象访问丢失或身份疑点。按核实分支排除、确认删除、同身份更名、同名重建或成功重读 | 未核实表阻断治理，其他表可办。事实结论只在 B 批核实。排除、恢复和范围变动保留已有确认。确定重建产生独立空白世代，旧身份与引用不转绑。已移除只可确认处理，历史仍可追溯且禁止持续 |
| GOV15 | 调整 PostgreSQL 配置范围并重新采集，再恢复旧范围。中途断开源连接 | 新范围以自己的成功结果开放，历史结构可回看并标原范围及新鲜度。范围缩小和临时不可见不构造删除、重做审核或自动恢复既有禁止 |
| GOV16 | 输入资料 r1，改标题到 r2，修改正文或附件到 r3。分别构造两条明确引用、一个仅输入和一个纯历史条目 | 无标题待办。r3 仍能命中引用 r1 相同内容的条目。已验证不相关的片段和仅历史引用只保留记录。输入已失效的在途任务安全收束。资料历史证据仍指向实际修订、附件和出处 |
| GOV17 | 撤下已引用资料，留一个明确影响和一个缺少映射的实际影响。关联同源后恢复并再次撤下 | 实际复核和待定位并存。重复关联同一目标不增行，跨源或过期映射命令整批拒绝。恢复让新任务可用，不关闭已打开复核。再次撤下按资料聚合版本区分。资料变更本身不触发生产禁止 |
| GOV18 | 同一来源影响两个条目，同时一个条目有两条待复核来源。先保存再逐个确认，分别走内容不变和内容实改 | 真正办理才进入治理中。一次确认结转实际复核，来源必须等最后必要项。无变化复核追加确认沿用内容修订，有知识工作时保持知识处理中。原阶段、现行计数、审计和每条确认互相对账 |
| GOV19 | 来源变更与草稿保存或确认同时执行。模拟实际影响、禁止、审计和 Outbox 插入失败。重复或乱序投递 | 平台库确认无半提交，失败保留之前成功目录或资料版本，禁止与确证风险同步可查。竞争按源锁先后决定，旧版本冲突。重启、通知丢失或重放不会漏掉同事务事实、重复生成复核或重新打开已结项 |
| GOV20 | 在既有 B 批数据库接入 C 批，包含结构历史、待核实对象以及实际变化记录中缺少稳定字段 ID 的情况 | 当前目录和资料正常读取。待核实继续阻断，按两侧精确快照可定位的字段给出稳定 ID，不能定位的不猜测。缺少旧治理的数据不产生历史草稿、虚假确认或伪造成功阶段 |
