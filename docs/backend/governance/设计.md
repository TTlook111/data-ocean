# C 批表说明与字段治理设计

本设计覆盖治理工作台的表和视图说明、字段定义、关联、指标、人工确认及来源复核。业务依据为[产品方案](../../product/产品方案.docx)第 4 章，交互依据为[治理页面](../../frontend/pages/governance.md)。实际接口和验证范围见[接口与权限](接口.md)与[当前验证](验收.md#当前验证)。模型能力与节点分配遵循[配置页专题](../../frontend/pages/models.md)，治理确认结果按约定交接知识发布。

## 接入 B 批目录与资料

| B 批事实 | C 批怎么接 |
| --- | --- |
| `ds_source.current_snapshot_id`、当前连接范围及目录版本 | 通过数据源模块的 Java 读服务获取当前成功目录投影。分页、计数和状态使用同一次一致性读取。首次成功直接开放治理，失败、取消、未成功候选均不进入工作台 |
| `ds_snapshot_object`、`ds_object`、`ds_object_revision`、`ds_object_column`、`ds_column_revision` | 按 `sourceId + objectId + generation` 定位表，按其成员中的稳定 `columnId` 定位字段。保存依据时固定成功快照、对象结构修订及字段修订。结构、原注释和技术类型只读，业务定义从空白开始。打开历史依据时按固定修订回读，名称只用于展示与搜索 |
| `ds_change`、`ds_change_review`、`ds_change_impact_ref` | 复用事实核实、前后成功快照和影响引用。目录提交及核实提交调用治理模块写入实际影响。B 批现有差异写入可能只有两侧观察和值，字段编号可空。接入时须按两侧各自的成功快照成员补出稳定字段及修订，保存或投影成类型明确的目标。仍有歧义时走 B 批核实。禁止在当前目录按名称猜测或将两个世代自动转绑 |
| `ds_business_note`、`ds_business_note_revision` 及修订附件 | 只使用当前源有效资料。按 `noteId + revisionId` 固定正文和附件成员，展示修订号。预置示例不进入生产治理输入。资料新建、恢复后的下一次任务按当前有效修订重新选择 |
| `ds_business_note_reference` | 经资料服务登记 `GOV_TASK_INPUT` 及 `GOV_ITEM_REVISION`，目标分别是任务 UUID 和治理修订 ID。该表主要保证实际用过的资料不能删除。治理自己的依据引用负责按条目与具体内容反查。锁次序沿用 B 批的先数据源、再资料 |

数据源模块负责解析当前目录投影和固定历史证据，治理模块维护业务内容、当前复核和使用控制。跨模块调用使用归属模块的 Java 服务，不共用对方 Mapper。正式目录查看、变化详情及资料原件仍沿用 B 批权限。治理工作台返回办理所需的结构摘要。参见[目录与结构核实接口](../datasource/接口.md#结构变化与核实接口)、[采集表结构](../datasource/表结构.md#快照观察与结构修订)和[企业业务说明契约](../datasource/接口.md#企业业务说明)。

## 字段级数据模型

沿用[数据模型总则](../数据模型设计.md#数据归属与共用规则)。下表 ID 为 BIGINT UNSIGNED，版本为 INT UNSIGNED，时间为 UTC DATETIME(3)，任务和命令 ID 为 UUID。业务类型及状态用有约束的 CODE，长度按枚举上限定义。关系、引用和定位键使用独立列。表内 JSON 只保存有明确契约且随修订整体固定的内容、差异或结构证据。

| 实体 | 字段及约束 |
| --- | --- |
| `gov_item` | `id, source_id, object_id, generation, kind, target_id, version, head_revision_id?, last_confirmed_revision_id?, created_at, updated_at`。`kind=TABLE/COLUMN`，`target_id` 分别是 B 批的 objectId 和 columnId。唯一 `(source_id,kind,target_id)`，索引 `(source_id,object_id,kind,target_id)`。两个指针通过所属条目核验，最后确认修订供追溯 |
| `gov_item_revision` | `id, item_id, revision, previous_revision_id?, content, origin, suggestion_id?, snapshot_id, object_revision_id, column_revision_id?, changed_by, created_at`。内容按下表分型，`origin=MANUAL/AI_ASSISTED`。唯一 `(item_id,revision)`，内容、形成依据和前修订不可修改，历史差异由确切前后修订计算 |
| `gov_confirmation` | `id, item_id, item_revision_id?, action, snapshot_id, object_revision_id, column_revision_id?, command_id, confirmed_by, confirmed_at`。动作 `CONFIRM/ACK_REMOVAL`。只有从未保存定义的移除确认允许修订为空，移除时绑定最后成功的结构及确证删除记录。唯一 `(confirmed_by,command_id)`，索引 `(item_id,confirmed_at,id)`。一次提交可结转多条复核影响，内容不变时追加确认记录并沿用原内容修订 |
| `gov_evidence_ref` | `id, source_id, item_revision_id?, suggestion_id?, content_path, kind, locator_key, snapshot_id?, object_id?, object_revision_id?, column_id?, column_revision_id?, note_id?, note_revision_id?, attachment_id?, location?, manual_basis?, created_by, created_at`。仅归属一个治理修订或一条原始建议。类型 `STRUCTURE/NOTE/MANUAL` 决定必填列。结构引用按成功快照验证成员归属。资料引用指向实际使用的段落或附件位置。两个归属分别按 `(归属ID,content_path,locator_key)` 防重。按 `(source_id,note_id,note_revision_id)`、`(source_id,object_id,column_id)` 反查。仅整表上下文或候选输入不作为所有内容项的依赖 |
| `gov_gap` | `id, item_id, found_revision_id?, suggestion_id?, content_path, question, origin, state, resolved_revision_id?, resolution?, opened_by, opened_at, resolved_by?, resolved_at?`。状态 `OPEN/RESOLVED`，来源 `AI_SUGGESTION/MANUAL_SUPPLEMENT`。存在开放的实际关键缺口时阻断确认。结论绑定保存后的内容修订，问题和原结论留痕，新疑点另起记录。索引 `(item_id,state,id)` |
| `gov_note_change` | `id, source_id, note_id, kind, note_version, before_revision_id, after_revision_id?, mapping_state, version, occurred_at`。类型 `CONTENT_CHANGED/WITHDRAWN`，撤下时后修订为空，状态 `MAPPED/NEEDS_MAPPING`。唯一 `(note_id,note_version)`，索引 `(source_id,mapping_state,occurred_at,id)`。用于固定资料变化证据和待定位入口 |
| `gov_impact_task` | `id, source_id, item_id, structure_change_id?, note_change_id?, baseline_revision_id?, impact_kind, state, created_at, started_at?, confirmation_id?, resolved_at?, knowledge_required?`。必须且只能关联一个变化，分别以 `(structure_change_id,item_id)`、`(note_change_id,item_id)` 去重。类型 `NEW_ITEM/RECHECK/REMOVAL`，阶段 `PENDING/IN_PROGRESS/REVIEWED`。索引 `(item_id,state,id)`。确认后记录是否需知识处理，来源可回看本次结果 |
| `gov_usage_control`、`gov_usage_control_event` | 当前限制按 `item_id` 唯一，保存 `blocked, version, updated_at`。事件保存 `id, item_id, control_version, action, reason_code, reason, structure_change_id?, command_id?, actor_kind, actor_id?, occurred_at`，唯一 `(item_id,control_version)`。表被禁止时其字段继承阻断。字段被禁止只阻断该字段及其依赖 |
| `gov_generation_task`、`gov_generation_target` | 任务保存 `request_id, command_id, source_id, object_id, snapshot_id, requested_by, state, run_version, version, created_at, started_at?, ended_at?, failure_code?`。唯一 `(requested_by,command_id)`，按源、发起人和时间索引。目标以 `(request_id,item_id)` 唯一，保存 `base_item_version, object_revision_id, column_revision_id?, content_paths, state, failure_code?`。记录任务接收事务结束时的条目版本 |
| `gov_generation_input` | `request_id, note_id, note_revision_id, state, reason_code?, processed_at?`。主键 `(request_id,note_id)`，索引 `(note_id,note_revision_id,state,request_id)`，状态 `REGISTERED/USED/SKIPPED/STALE`。登记与 B 批任务引用同事务。`USED` 标明当次实际取用，结论依据仍按建议中的具体内容项另存 |
| `gov_suggestion` | `id, request_id, item_id, model_call_id, content, gap_proposals, created_at`，唯一 `(request_id,item_id)`。建议及其依据为不可变原始结果。模型实际配置修订继承调用快照。后续编辑、确认、重试或换模型均保留原结果 |

治理身份可由当前目录派生。列表和打开详情不预建内容修订或确认，首次产生实际治理事实时创建条目。新增字段和删除处理可由来源事务创建条目及影响。写操作在归属与版本校验后物化条目，数据库唯一键兜底，历史按原身份保留。

### 内容、审核和进度

| 内容类型 | 修订内容字段 | 确认门槛 |
| --- | --- | --- |
| 表说明 | `businessName, purpose, rowGrain, rowIdentity, dataScope, timeSemantics, updatePolicy, usageNotes, qualityNotes`，均为文本。涉及行标识、业务时间等明确技术对象时带对应结构引用 | 用途和记录粒度必填，已明确影响使用的范围、口径、更新或质量问题须核清。更新频率和业务时间由业务证据说明，采集时间独立展示 |
| 字段 | `businessName, meaning, valueDescription, valueMappings[{code,meaning}], unit, format, nullMeaning, emptyMeaning, zeroMeaning, timeSemantics, businessTimeZone, usageRule, usageNotes, sensitivityNotes`。编码按字符串保存并区分前导零，空值、空字符串和 0 各有解释 | 业务含义必填。状态／分类说明适用编码，金额或数量说明单位，时间说明业务时间及适用时区，适用筛选、计算或统计规则须明确。编码行不接受空或重复编码、空含义。不适用或无关项可空，定位实际冲突和待核清问题 |

内容字段按语义复用为明确的表说明和字段两种 DTO。业务名称、单位、格式和单个编码不超过 160 个 Unicode 字符。其余单个文本不超过 4000 字，编码含义不超过 400 字，编码表最多 200 行。限值为首段接口容量，数据层无截断，实际 PC 编辑和真实样例随验收核对。适用项结合技术类型与可核验的业务证据判断并给出字段路径。名称和样本值只提供线索，样本出现过的值不能当作完整枚举。必需依据无权查看时，条目继续待确认。

确认校验使用真实技术类型和有效业务内容。例如时间戳需给出业务时间及适用时区，业务日期或确有依据的无时区语义在时间说明中明确。金额、数量和编码的适用性结合已填写定义和可核验依据判断，技术列名、数值类型和模型只能提供待核对线索。

保存做格式及归属检查，允许部分填写。实际内容或实质依据变化才产生新修订，相同输入保留当前修订。当前内容状态可为 `UNSTARTED/DRAFT/CONFIRMED`，另算是否有未完成复核、当前结构可用性和生产禁止。复核保留原内容和旧确认，无实质修改可直接确认原内容并绑定本次核对的结构，审计记录本次覆盖的来源。重跑建议保留既有确认。

表主进度按当前成功目录的表说明和必要字段汇总。当前有效确认且无未完成复核才计入已确认数。总数内无实际办理为待治理，有办理而未齐为治理中，全部确认才为已治理。复核单列标明，已移除字段的历史和待办单列回看。仅目录范围调整的提醒不重置已确认项。表说明和字段可独立确认。同一条目存在多个来源影响时保留每笔来源及状态。

建立复核时固定受影响条目当时最后一次确认的修订。未曾确认的条目保留空基线。业务确认时按基线判断重用或交接，按当前待处理来源记录本次实际覆盖的影响。

### 企业资料取用和证据

1. 生成前列出当次受控取用范围。提交时 Java 在源锁下重新选择当前源的有效资料及其确切修订，核对当前操作者、任务范围和模型处理规则，在任务接收事务内登记 `GOV_TASK_INPUT`。预览之后资料内容或可取用资格变化时重读范围。仅标题变化可以沿用相同内容依据，实际任务仍记录采用的修订编号。
2. 附件解析固定到当次修订成员。TXT／Markdown 按行或段落，CSV 按行列，PDF 按文本页，DOCX 按段落或表格单元，XLSX 按工作表及单元格范围定位。解析在有界资源内进行，不执行公式、宏或外部链接。无可提取文本、加密、失败或超量分别记录原因，保留可用依据。任务记录区分选入、实际取用和具体引用。未实际读取的片段不记为结论证据，附件类型和容量沿用 B 批。
3. 人工可独立编辑。需要关联资料时校验确切修订、同源及实际出处。建议引用只取实际依据且定位到具体内容项。建议中的实际缺口随所选内容项保存为待核对记录。保存草稿或确认时，依当次实际引用登记 `GOV_ITEM_REVISION`。只取用但未引用的资料仍受防删除约束，不能由此推定整批条目依赖该资料。
4. 资料共享用途包含获准治理任务。原文、文件名和片段的用户可见性仍由 `business-notes.view` 约束。发给模型前检查当前资料、字段限制和传输规则。面向操作者的建议仅交付获准披露的业务结论。无法判定可披露的内容保留缺口。只读业务采样另核 B 批实时源授权、企业只读账号、字段限制和有效预算。资料接入及人工维护可独立运行。

## 来源变化与复核

### 结构变化

| 来源事实 | 定位和复核 | 即时使用控制 |
| --- | --- | --- |
| 首次成功、新范围基线 | 按当前目录展示空白条目，无人工确认继承。范围外保留历史与原核对，待该范围适用的成功采集后继续 | 当前目录资格拦截范围外、待重新采集的新范围及不可读对象 |
| 已确认新增表／字段 | 新表从表说明和当次字段开始。新增字段只创建自身的待治理项，已有定义仅在确有依赖变化时复核 | 新项无已确认修订，按后续知识纳入门槛办理 |
| 已确认注释、同身份改名、默认值、空值或可兼容类型变化 | 表注释定位表说明，字段属性定位该字段。再沿明确依赖定位受影响条目。列顺序等仅展示差异，存在实际依赖时才触发复核 | 业务语义疑点进入复核，可由有权人按影响核对后禁止 |
| 主键、外键或索引变化 | 主键字段集合变动定位表粒度、相关键字段和显式依赖。外键字段对应、目标变化定位实际使用该外键的定义。约束更名、等价排序或普通索引变化保留事实 | 已有业务关系是否成立由实际依据核对 |
| 已确认删除或结构明确不兼容 | 删除字段保留原稳定身份供确认移除并处理实际依赖。表删除或同名重建处理旧对象及受影响依赖，新世代和字段从空白独立治理。类型跨度导致原语义或查询失效、精度收窄使原值不可表示、已使用的必要键变更使原定义失效等属于明确不兼容。安全扩大且语义未变只复核对应定义 | 同事务禁止受影响的原对象或字段。历史确认、重采集、生产回退和业务审核均保留这一限制 |
| 访问丢失、身份未核实、事实排除 | 复用 B 批的当前目录投影与同表完整待核实查询。疑点期间该表只能回看来源，其他表可继续。成功重读或排除只结束对应来源阻塞。可见性变化保留历史业务确认 | 对象不可读时实时拦截，未核实的观察不能绑定旧身份。排除不清除其他事实产生的禁止 |

收到可靠差异时按稳定身份、两侧确切结构及实际引用展开影响。能确认相同身份的改名才延续条目，证据不足时由 B 批处理。跨表只沿同源明确依赖传播，按条目和单条变化去重。表说明与字段间没有默认强制审核先后。来源核实已确认或排除后，工作台直接沿用 B 批结论。未结核实、待适用采集或只读来源仍可回看，按 B 批可用性阻断业务写入和生成。确证移除用独立的确认动作。

### 资料变更

| B 批动作 | 处理结果 |
| --- | --- |
| 新提交、仅标题变化、等价正文和附件、从未使用的资料发生变化 | 后续任务读取当前有效修订，不新增复核。比较采用 B 批规范化正文和实际附件内容及其成员，标题和修订号只用于展示与追溯 |
| 已引用的正文或附件实质变化、撤下 | 固定原修订和具体依据，反查当前草稿及现行确认修订实际使用的范围。命中时逐条创建复核，保留原确认和历史。附件能定位到实际片段时按对应片段判断。不能可靠证明未受影响的已引用片段纳入该条目的复核。资料变化本身不触发生产禁止 |
| 任务输入仍在使用，尚未形成条目依据 | 标记受影响的在途输入失效，保留当次引用、执行历史与原建议。新建议在更新后重新发起。能确认只有历史使用且没有当前依赖时保留历史。若资料确有业务影响线索但技术映射未明，在表治理列表留下同源待定位项，由编辑权限者关联具体条目后办理。不能按标题、同名表或批量所选条目猜测依赖 |
| 恢复 | 恢复供后续任务取用，不自动收掉未完成事项、恢复原确认资格或解除已有禁止 |

对比时兼容「正文修订 r1 → 只改标题 r2 → 正文变化 r3」。仍使用 r1 同内容依据的条目应被定位，历史证据维持 r1。B 批现有通知识别正文变化和上传新原件等操作。C 批判定业务影响时，进一步按实际写入的正文、附件摘要和成员比较。反查覆盖当前草稿、现行确认及有现实影响的活跃任务，按精确片段或实质内容跳过未影响的条目。撤下使用资料聚合版本区分同一内容修订下再次撤下。

来源事务只使用持久化的正文、原件摘要、已验证出处及反向引用。换入原件后尚未解析时，将引用该原件的当前定义纳入复核。原件解析与模型调用由任务在源锁事务外完成。

### 提交、回写与恢复

1. 结构发布、B 批核实确认和实质资料变更在持有同一 B 批源锁的事务内写入权威事实、受影响项、必要禁止、审计与 Outbox。任何一步失败整体回滚。现有 `datasource.catalog.changed`、`datasource.business-note.changed` 用于提交后通知与回读。目录版本、资料聚合版本及准确来源记录分别判断。消费重复、乱序和重启不重复创建影响或重新打开已处理项。既有通知的资料修订号不能当作聚合版本，补充按资料变化 ID／聚合版本定位的载荷。
2. 治理写入按源锁、资料锁（需要时按 ID 顺序）、条目锁顺序办理。确认重新核对当前源、同表事实、结构修订、资料资格、条目版本和待处理影响。新影响进入时改变涉及条目的并发版本。旧页面提交返回冲突并保留输入。任务固定输入绑定原来源，迟到的结果不能覆盖新编辑或恢复过期用权。
3. 真正保存、补充或生成时推进相关来源为治理中。逐项确认或确认移除后为该来源回写具体修订／结果，最后一个必要条目处理后判断知识阶段。定义、必要依据、纳入范围发生实质变化、删除或仍受禁止时交给 D 批并保持知识处理中。内容仍适用且无下游工作时随本次确认自动完成。一个来源涉及多条定义或多个来源影响同一条目时逐项结算，不按最新一条替换全部。B 批结构来源通过 `ds_change_impact_ref` 定位条目和使用控制，通过数据源服务回写其 stage。资料详情读取 `gov_note_change` 与影响结果的汇总。
4. 禁止、复核与是否已发布分别判断。可对修复后当前结构可读的对象完成业务确认，仍保持已有禁止。删除字段走确认移除，原身份保留为历史。D 批接收来源、影响条目、固定治理修订、准确依赖及当前控制。生产解除按[知识一致性](../../architecture/知识版本与索引一致性.md#暂停禁止与显式恢复)检查全部在效禁止原因。C 批验收当前控制和交接事实。
5. 首次接入现有 B 批数据时，从当前成功目录派生条目。尚未核实的来源仍拦截，已知删除或不兼容的历史对象按当前事实校验。接入后仍影响当前定义的来源按相同规则办理，历史记录保留原事实和证据，不补造治理修订、任务或审核。真实差异的字段定位与旧目录回读列入首轮迁移联调。

| 来源阶段 | 汇总条件 |
| --- | --- |
| `PENDING_REVIEW` | 仅结构来源，由 B 批待核实事实决定 |
| `PENDING_GOVERNANCE` | 有待定位或未处理的影响，且各影响均未开始办理 |
| `GOVERNANCE_IN_PROGRESS` | 已实际办理，且仍有待定位事项或未审核影响 |
| `KNOWLEDGE_IN_PROGRESS` | 无待定位且所需业务审核均完成，至少一项需进入知识处理 |
| `COMPLETED` | 事实已排除、无治理影响，或所需业务审核已完成且无需知识处理。已进入知识阶段的由 D 批按实际完成结果回写 |
