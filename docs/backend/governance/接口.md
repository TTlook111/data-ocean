# 表说明与字段治理接口

以下为 C 批接口契约，配套[字段级模型与复核设计](设计.md)。实际覆盖见[当前验证](验收.md#当前验证)。浏览器只访问 Java。通用信封、标识、分页、版本、错误、幂等、权限复核及 SSE 继承[公共契约](../../architecture/接口与事件契约.md)。源选择复用 `SourceOptionVO`，分页复用 `PageQuery`、`PageVO`，写命令复用 `MutationService` 和 `CommandStatusVO`。危险操作复用影响预览契约，普通草稿和确认在既定编辑区提交。

## 工作台读写

`S` 为 `/api/v1/governance/sources/{sourceId}`，`O` 为 `S/objects/{objectId}`，`I` 为 `O/items/{kind}/{targetId}`。表说明使用 `TABLE/{objectId}`，字段使用 `COLUMN/{columnId}`。同表成员、世代、当前可用性均由服务端从 B 批确认。

| 方法及路径 | 请求与返回 | 权限与写入 |
| --- | --- | --- |
| GET `/api/v1/datasources/options?purpose=GOVERNANCE` | 扩展 B 批源选项用途，返回 `SourceOptionVO[]` | `governance.view`。只返回源 id、名称、生命周期及版本 |
| GET `S/objects` | `GovernanceTableQuery` → `GovernanceTablePageVO` | `governance.view`。只读，使用一致的目录版本和汇总口径 |
| GET `O` | 无请求体 → `GovernanceObjectVO` | `governance.view`。只读，返回办理所需的结构摘要、影响及可用性 |
| GET `O/columns` | `GovernanceColumnQuery` → `PageVO<GovernanceColumnRowVO>` | `governance.view`。字段导航及计数使用相同条件，已移除仅在待办及历史定位可见 |
| GET `I` | 无请求体 → `GovernanceItemVO` | `governance.view`。按读权限裁剪草稿、核对项、资料细节和可用动作。打开虚拟空条目不写数据库 |
| GET `I/history` | `PageQuery` 与可空 `revision` → `PageVO<GovernanceHistoryRowVO>` | `governance.view` 加草稿及历史读取资格，按记录和证据分别核权，指定修订时包含其内容及审核记录 |
| PUT `I/draft` | `GovernanceDraftDTO` → 200，`GovernanceMutationVO` | `governance.edit`。追加内容修订、依据及核清记录，更新实际开始的复核、审计。相同内容及依据返回当前结果 |
| POST `I/gaps` | `GovernanceGapDTO` → 200，`GovernanceMutationVO` | `governance.supplement`。登记具体关键缺口并使该条目待确认，保留已有内容。已存在同一开放缺口返回当前结果 |
| POST `I/confirmations` | `GovernanceConfirmDTO` → 200，`GovernanceMutationVO` | `governance.confirm`。含待保存修改时同时要求 `governance.edit`。合法内容、确认、实际影响进度、审计及 Outbox 同事务。确认任一门槛失败保留原草稿与进度 |
| GET `S/unmapped-note-changes` | `PageQuery` → `PageVO<GovernanceNoteChangeVO>` | `governance.view`。无原文权限仅返回脱敏的待定位提示 |
| POST `S/unmapped-note-changes/{changeId}/targets` | `GovernanceImpactTargetsDTO` → 200，`GovernanceNoteChangeVO` | `governance.edit`，查看和识别原资料另核 `business-notes.view`。在一个事务关联所选同源条目及复核，更新资料定位状态。保留已有明确关联 |
| POST `I/impact-preview`，POST `I/usage-control` | `action=FORBID`、`expectedVersion`、`proposal.reason`。正式提交追加 `reviewToken` → 预览返回 `ImpactPreviewVO`，提交返回 200、`GovernanceMutationVO` | `governance.forbid`。对稳定、可办理条目预览并核对实际受影响范围。提交检查依赖版本并登记使用限制及审计。已禁止且无变化返回当前状态。解除由知识发布侧沿用 `governance.allow` |

每个 governance 操作权均同时核 `governance.view`。真实风险限制由在平台库运行的来源事务以系统身份提交，人工禁止使用其当前用户身份。确证移除使用 `ACK_REMOVAL`，仅处理删除证据与业务交接，旧结构历史和禁止继续保留。

## 请求与响应字段

| 模型 | 字段与校验 |
| --- | --- |
| `GovernanceTableQuery` | `keyword` 匹配表名、业务名称、原注释，`pendingKind=TABLE/COLUMN`、`hasPendingImpact`、`progress=UNSTARTED/IN_PROGRESS/COMPLETE` 可空，组合取交集，再应用 `PageQuery`。默认限定路径与 objectId 升序，排序白名单 `objectName` |
| `GovernanceTablePageVO` | `page: PageVO<GovernanceTableRowVO>, currentSnapshotId?, catalogVersion, freshness, effectiveScope, snapshotScope?`。范围、新鲜度复用 B 批相同口径 |
| `GovernanceTableRowVO` | `sourceId, objectId?, observationId, generation?, qualifiedName, objectType, sourceComment?, businessName?, purpose?, availability, progress, confirmedCount, totalCount, pendingKinds[], pendingImpacts[]`。回传工作台列及精确定位，不带不获准的草稿正文。身份未核实只给观察标识和阻断信息，不返回可办地址 |
| `GovernanceObjectVO` | 表行字段加 `structureBasis?, tableEntry, pendingFactCount, nextPendingTarget?, actions`。无稳定身份的观察从 B 批事实入口回看。待核实数按该对象全部未结束事实计算 |
| `GovernanceColumnQuery`／`GovernanceColumnRowVO` | `keyword` 匹配字段名和原注释，`status=ALL/PENDING/CONFIRMED`，加 `PageQuery`，按结构 ordinal 再按 columnId。行返回 `target, name, nativeType, nullable, sourceComment?, structureBasis, state, pendingReview, blocked` |
| `TargetRef`／`StructureBasisVO` | 目标 `{objectId,kind,targetId}`。结构依据 `{snapshotId,objectRevisionId,columnRevisionId?}` 绑定成功快照。历史、变更、建议及资料 URL 仅根据服务端归属回填，客户端不能声明采用的结构来源 |
| `GovernanceItemVO` | `target, itemId?, version?, structureBasis, state=UNSTARTED/DRAFT/CONFIRMED, pendingReview, currentRevision?, latestConfirmation?, gaps[], impacts[], blocked, availability, actions`。当前修订含 `revisionId, revision, content, origin, structureBasis, evidenceRefs[], createdBy, createdAt`。确认摘要含 `action, revisionId?, confirmedBy, confirmedAt, structureBasis`。未落库时 `version=null`。草稿版本及旧确认分开呈现 |
| `GovernanceHistoryRowVO` | `kind=REVISION/CONFIRMATION, occurredAt, actor, revisionId?, revision?, previousRevisionId?, action?, structureBasis, changes[]`，默认发生时间及稳定 ID 倒序。指定 `revision` 时附相应的 `content, evidenceRefs[]`。差异按双方固定修订计算，按当前查看权限过滤 |
| `ImpactVO`／`GovernanceNoteChangeVO` | 影响返回 `impactId, kind, state, target, startedAt?, resolvedAt?, confirmationId?, knowledgeRequired?, origin?`。获准的 origin 分型结构变化 `changeId, factState` 或资料变化 `noteChangeId, noteId, beforeRevision, afterRevision?`。待定位记录返回 `id, sourceId, version, occurredAt, mappingState, stage, origin?, targets[]`。来源详情聚合实际审核、待定位和知识处理需求 |
| `EvidenceRefVO`／`GapVO` | 依据为 `{kind,contentPath,redacted,structure?,note?,manualBasis?}`。获准的结构依据附固定快照及对象或字段修订，资料依据附 `noteId,revisionId,revision,attachmentId?,location`。缺口为 `{gapId,contentPath,question,state,resolution?,resolvedBy?,resolvedAt?}`，受限线索按权限裁剪 |
| `availability`／`actions` | 可用性取 `AVAILABLE/SCOPE_PENDING/PENDING_SOURCE_REVIEW/INACCESSIBLE/READ_ONLY/REMOVED`，查询时优先识别确证移除，再按实际 B 批事实给出阻断。动作给布尔值 `canEdit,canSuggest,canConfirm,canSupplement,canForbid,canAcknowledgeRemoval`，仅供界面显示，提交重新核权 |
| `EntryPreconditionDTO` | `expectedVersion` 为正整数，虚拟空条目传 null。还传 `expectedStructureRevisionId`，表说明取对象修订 ID，字段取列修订 ID。移除确认取该删除记录的最后成功结构修订 ID。无关快照推进不必重填，但仍校验当前目录及条目关联 |
| `GovernanceDraftDTO` | `precondition: EntryPreconditionDTO, draft: DraftInputDTO`。`DraftInputDTO={content, structureRefs?, manualEvidence?, suggestionSelection?, gapResolutions?}`。content 是按路径类型完整填写的已声明表或字段模型。普通未填项用 null 或空集合 |
| `DraftInputDTO` 的依据和核清 | `structureRefs[]` 引用同源已采集对象或字段、业务字段路径。服务端固定结构版本。`manualEvidence[]` 是 `{contentPath,noteId,revisionId,attachmentId?,location}` 或 `{contentPath,manualBasis}`，其中人工说明最多 1000 字。未传引用集合沿用当前依据，显式空集合清除对应可编辑依据。`suggestionSelection={suggestionId,contentPaths[]}` 只能选当前条目的获准建议及实际替换项。人工实改保留为人工内容，证据随实际结论匹配。`gapResolutions[]` 为 `{gapId,resolution}`，结论最多 1000 字，与更新后的对应内容一并保存，归属或状态不符退回 |
| `GovernanceGapDTO` | `precondition,contentPath,question`。路径为条目已声明的具体业务字段，文本 1—1000 字。记录实际缺口，普通空字段按确认校验提示 |
| `GovernanceConfirmDTO` | `precondition,action=CONFIRM/ACK_REMOVAL,draft?`。可选 draft 与保存共用 `DraftInputDTO`。移除确认限制 `draft` 为空，绑定当前确证删除及开放的移除任务。提交时返回实际处理的影响 |
| `GovernanceImpactTargetsDTO` | `expectedVersion, targets: TargetRef[]`。至少一个目标，不允许重复。每个目标在同一数据源并可办理，由服务端核对，任一无效整批拒绝 |
| `GovernanceMutationVO` | `commandId,target,itemId?,version?,currentRevision?,confirmationId?,resolvedImpactIds[],blocked`。对虚拟空条目保存空内容时返回当前空状态。列表计数及来源阶段由前端按原筛选回读 |

内容约束见[字段级模型](设计.md#内容审核和进度)，条目阶段和现有复核事实由响应单独表达。保存、确认及补充均使用 `Idempotency-Key`。普通重发按原命令回读。不同键重复确认也核对当前版本，无内容、新影响或依据变化时返回现有结果。核清问题与实际说明一并保存，新确认需要已经解决所有关键缺口。并发或来源冲突按公共码返回，前端保留当前输入和位置。

## AI 建议任务

本次实现接收单张表的表说明任务，工作台使用持久任务快照回读。字段生成、批量结果和浏览器 SSE 按下表后续接入。外发输入使用当前获准范围内的目录摘要、正文及可提取的 TXT、Markdown、CSV、DOCX、XLSX 文本。本阶段先验证结构和资料的表说明起草。

| 方法及路径 | 请求与返回 | 权限及结果 |
| --- | --- | --- |
| POST `O/generation-preview` | `GenerateScopeDTO` → 200，`GenerationPreviewVO` | `governance.suggest`。只读核对对象、选定项和可用资料。签名凭据固定当时的实质来源、范围和条目版本 |
| POST `O/generations` | `GenerateScopeDTO` 与预览凭据 → 202，`GenerationAcceptedVO` | `governance.suggest`，使用 `Idempotency-Key`。同一事务保存任务、目标、确切资料输入引用、待派发状态及审计 |
| GET `S/generations/{requestId}` | 任务 UUID → `GenerationDetailVO` | 原发起人和当前 `governance.suggest`，或具有 `governance.edit/confirm` 且能查看该任务来源条目的人员。按条目和引用逐项裁剪 |
| GET `S/generations/{requestId}/events` | `Last-Event-ID` 可空 → SSE | 与详情同权，续订和事件回放按当前资格校验。复用通用任务信封，事件通知回读任务状态和已获准的结果 |
| GET `/api/v1/commands/{commandId}` | 公共命令查询参数 `operationCode=governance.suggest` | 原命令主体及当前操作权，查询安全的任务引用，接收回包丢失沿用原命令 |

| 模型 | 字段与校验 |
| --- | --- |
| `GenerateScopeDTO` | `targets[{kind,targetId,precondition,contentPaths[]}]`，同一对象下一个或多个不重复条目。省略 `contentPaths` 表示所选条目的所有内容项。范围预览固定实际请求参数，不接收资料清单、当前用户、模型或授权结果 |
| `GenerationPreviewVO` | `sourceId, objectId, targets[], notes?, noteVisibility, reviewToken`。获准时 notes 给资料编号、标题、实际修订，遮蔽时省略可识别详情和数量 |
| `GenerationAcceptedVO` | `requestId,commandId,state,version`。提交成功初始为 `PENDING_DISPATCH` |
| `GenerationDetailVO` | 接收字段加 `sourceId,objectId,requestedBy,startedAt?,endedAt?,targets[],failureCode?,notes?`。目标返回 `target, state, originalStructure, suggestion?, gapProposals[], failureCode?`。建议含 `suggestionId,content,evidenceRefs[],modelCallId?`，模型调用定位另按所属权限过滤。获准的 notes 附取用状态和可披露原因 |

表说明生成和字段解释各用相应模型节点。Java 管理业务任务和资料选择，Python 按[调用与任务协议](../../architecture/调用与任务协议.md)接收并执行。批量是一笔接收命令，结果逐项落库。任务状态为 `PENDING_DISPATCH/QUEUED/RUNNING/SUCCEEDED/PARTIAL_FAILED/FAILED`，目标状态为 `PENDING/RUNNING/SUCCEEDED/FAILED/STALE`。使用 requestId、执行代次和目标 ID 拒绝重复或迟到回写。只有已落库的成功结果可填入编辑区。批量单项失败保留其他结果，重试需新命令且重新核对输入。模型不可用时可继续人工编辑和确认。

建议成功后在空编辑区填入待保存草稿，用户已有输入和确认内容通过差异界面选择具体替换项，默认保留人工内容。只拥有生成权限的用户可发起和查看获准建议。持有编辑权才能写入定义。用户已修改条目、结构变化、引用失效或授权移除时，陈旧建议保留为获准历史，不能应用到现在。建议接收版本与编辑区重新生成预览、提交时的版本及实际输入同时校验。

Java 与 Python 内部接口复用已确认的服务认证和任务协议，按 `requestId + runVersion + target` 提供固定上下文、提交类型化结果。Java 在取用结构、资料、辅助数据、接收结果和交付前复核原发起人及任务资格，状态变化导致的拒绝按准确原因记录。每次模型补充前核当次模型配置和传输限制，禁止从附件、提示词、任务回调接收目的地或执行凭据。只读采样由 Java 受控执行，固定有效预算，失败也计次。目录、资料和模型配置的具体读取接口保持所属模块边界。

表说明生成在受理时固定 `table-description` 节点配置修订。工作者准备资料后使用服务 JWT 调用 `POST /internal/v1/governance/tasks/{requestId}/model?runVersion=...`，Java 重新核对实际权限、依据、准入地址、模型状态和剩余预算，并记录此次外发许可。调用配置仅在当次内部响应中供适配器消费，响应禁止缓存。重复领取返回执行结果待核查，不重复向提供方请求。诊断配置来自任务固定的修订，真实调用返回后由 Java 校验记录。

## 领域通知

| 类型 | 公共 Outbox 载荷 |
| --- | --- |
| `datasource.catalog.changed` | 沿用 B 批 `sourceId, currentSnapshotId, catalogVersion`，消费时回读已经提交的事实和影响 |
| `datasource.business-note.changed` | 沿用 `sourceId, noteId, revision, change`，附 `noteVersion` 和可空 `noteChangeId`。消费时按源、资料和聚合版本回读，去重仍以公共事件编号和业务唯一键为准 |
| `governance.generation.requested` | `sourceId, requestId`，用于派发已接收任务 |
| `governance.item.confirmed` | `sourceId, itemId, confirmationId, revisionId?, resolvedImpactIds[]`，消费者按确认和具体影响回读 |
| `governance.usage.changed` | `sourceId, itemId, controlVersion, blocked`，当前限制已在平台库生效，消费用于刷新及影响通知 |

生成 SSE 用公共任务信封，`generation.snapshot` 返回裁剪后的任务快照，`generation.updated` 返回 `requestId, state` 并提示回读。两类通知都不传资料正文、样本、凭据或模型原始响应。

## 权限及披露

| 场景 | 服务端检查 |
| --- | --- |
| 治理工作台、表和字段摘要及已确认内容 | `governance.view`。未另加数据源／字段管理白名单、角色名称判断或问数源授权前置条件。无查看权时列表、选项、计数、详情和历史均拒绝 |
| 草稿和历史审核内容 | `governance.view` 加 `governance.edit`、`governance.confirm`、`governance.supplement` 之一。只拥有查看权限可见工作台办理状态、可披露已确认内容和来源摘要 |
| 编辑、补充、审核、生成和禁止 | 分别按 IAM 既有动作目录检查。审核人可审核自己的定义，任务分派及授予权不产生实际使用权，确认不会产生发布或数据访问授权 |
| B 批正式目录、实际差异证据、资料详情与下载 | 分别核 `catalog.view`、`collections.view`、`business-notes.view` 及归属。治理工作台所需结构摘要和确认状态来自同一 B 批投影。无权时去除可复原的原文、文件名、片段、附件地址及受限来源标识。能看到摘要仍需核验用户可检查本次必要依据，才允许确认 |
| 自动取用及来源映射 | 生成检查发起人的治理权限、资料当前状态及任务的受控用途，模型传输范围另校验。手工跨入口选取和定位资料需原文查看资格。原资料历史、样本、原始模型输出或失败详情都不得成为绕过入口 |
| 辅助读取业务数据 | 在治理操作权之外调用 B 批实时授权服务 `AccessScopeService.requireSource`，结合只读账户、当前对象及字段范围、脱敏与模型发送规则、当次预算。从历史、进度或原始依据查看数据同样检查，不用任务所有权扩展权限 |

后台普通写入使用已确认身份及 CSRF。未知参数、关键字段及缺口使用 `VALIDATION_FAILED` 和定位路径。当前源不可治理、事实待核或条目已移除使用 `STATE_CONFLICT`。条目并发使用 `VERSION_CONFLICT`，失效预览使用 `REVIEW_STALE`，必要结构或证据变更使用 `DEPENDENCY_STALE`。缺少操作权限返回 `PERMISSION_DENIED`。资源跨源或不可披露统一按 `RESOURCE_NOT_FOUND`。模型业务失败在任务结果中记录，已提交的前端输入保留，平台存储或必要权威服务不可用按公共契约处理。
