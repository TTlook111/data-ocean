# 治理概览与对账

界面与统计入口见[治理概览](../../frontend/pages/dashboard.md#正式治理概览)，口径沿用[治理进度规则](设计.md#内容审核和进度)与[运营看板方案](../../product/modules/08-dashboard.md)。

| 只读接口 | 权限 | 返回 |
| --- | --- | --- |
| `GET /api/v1/governance/overview` | `governance-dashboard.view` | 来源、截止时刻、趋势分组和整个期间的计数 |
| `GET /api/v1/governance/overview/details` | `governance-dashboard.view` 与 `governance.view` | 同期间、来源和截止时刻的贡献记录分页 |

沿用后台来源范围以及看板共用的 `fromDate`、`toDate`、`timeZone`、`asOf`。默认近 30 个北京时间业务日，使用日、自然周、自然月分组。明细按 `metric` 选择 `TABLE`、`COLUMN`、`RELATION`、`METRIC`、`RECHECK`、`COMPLETE`、`IN_PROGRESS` 或 `UNSTARTED`。查看和编辑治理正文继续由原入口核权。

| 指标 | 事实与期间口径 |
| --- | --- |
| 表说明／字段确认 | `gov_confirmation` 的 `CONFIRM` 记录按实际确认时刻归组 |
| 关联／指标确认 | `gov_discovery_revision` 中已确认的追加修订按写入时刻归组 |
| 期末待核对 | `gov_impact_task` 中期末之前已创建、期末仍在办的 `RECHECK` 按业务条目去重 |
| 期末治理进度 | 成功快照、当时已生效的连接范围及已核实身份共同决定对象。使用当时最新治理修订、最后确认、当时仍未完成的影响与缺口复用工作台的三类判定；对象进度只取所选期间末 |

治理确认趋势计算发生的审核次数。实际需要再次复核而产生的新确认进入其发生区间。只有存在稳定身份的成功目录表或视图参与进度分母，关联和指标审核另列。V51 为确认时段读取增加索引；历史进度直接使用既有带时间的快照、连接修订、治理修订和核对台账。

## 验收

- 隔离库的真实既有记录与汇总对账，包含表说明确认 4 项、字段确认 12 项、关联确认 2 项、指标确认 2 项。当前期末进度与治理工作台的稳定对象一致。[原始台账核对](../../../output/acceptance/2026-11-23-governance-overview/baseline.json)
- 在已有的两次成功快照上补入可控早期确认，新增字段后原对象由已治理转为治理中。单独范围样本在同一采集快照上从两个 Schema 缩至一个，早期与晚期期末对象数分别为 2 和 1。[期末进度验证](../../../output/acceptance/2026-11-23-governance-overview/statistics.json)
- 同一条目的两个复核来源计为一个待核对条目。通过真实确认命令结转后，期末存量下降 1，确认数增加 1；重放原命令回读同一确认。隔离账号验证聚合、明细与旧会话撤权。[复核及汇总明细](../../../output/acceptance/2026-11-23-governance-overview/statistics.json) · [权限验证](../../../output/acceptance/2026-11-23-governance-overview/permissions.json)
