## 数据库与可靠提交检查

在已核实的独立空白测试库执行建表设计，核对实际 MySQL 版本和强制 CHECK；不能把文本解析或另一数据库模拟当作 MySQL 验证。保留实际建表结果和 SHOW CREATE TABLE 核对依据。

至少验证：角色名规范化唯一；登录名精确匹配与归档不复用；每用户／角色一条当前分配；每用户／部门一条当前关系；最多一条当前主部门；历史结束关系可并存；外键拒绝悬空引用；非法生命周期和零版本被 CHECK 拒绝。确认事务回滚、死锁重试保留原 commandId、连接 UTC 及毫秒精度。

MySQL 唯一约束只保证“最多一个主部门”，服务测试还须验证正常人员“至少一个”。外键不保证部门无环或最后恢复途径；这些必须使用并发真实事务验证，不能把存在外键当作完整业务约束已通过。

角色快照与当前角色版本在同一提交中一致；快照不随当前角色修改。所有角色状态与上限变更都产生相应版本快照，历史分配引用存在；恢复时角色内容变化能被检测。命令、业务、成功审计及 Outbox 不存在隐藏半提交。

## B 批接入后的回归

首批先验收实际提供的身份、组织和角色接口。A09／A10 中的真实任务 SSE、A25 中实际来源结束、A30 中实际在途任务取消，分别在 C/E、B 及工作流接入时补验；首批只验证对应认证版本、事务和通知机制，不将这些跨模块效果记为已通过。每批实施记录其当前可运行的场景及受前置模块影响的剩余项。

以下场景是整个权限链路的完成条件，首批 A 不单独声称已覆盖：部门初始数据配置只影响直属及兼任；调岗只结束对应来源；共享规则修改采用最新内容但保留旧快照；审批主／替代及本人不自批；独立项即时生效及联合整组提交；批准与来源及单条合并审计同事务；撤销后重算其余来源；账号／角色停用和撤权阻断实际失权任务；恢复不复活旧下载与旧 SQL 许可。

这些用例必须在 B 批真实权限服务、数据源及后续问数入口中分阶段补验。没有数据源／问数真实实现时，准确记录阻断点，不以首批用户表或原型的 accessFor 函数推导真实授权安全已验收。

## 完成判定

首批完成要求正式工程可重复构建、物理约束及服务用例通过、上述必要并发和故障场景有真实证据、界面任务在规定 PC 环境通过，剩余未验项清楚列明。证据按单元／集成测试、真实 API、数据库和浏览器分开；浏览器证据放 `output/playwright`，不把长期设计正文写成测试流水或只报一个测试总数。
