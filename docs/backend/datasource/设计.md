# 数据源接入与采集设计

本设计覆盖连接草稿、分项测试、启用、手动及定时采集、目录与结构变化、失败重试，以及在途采集期间的账号／密码替换。当前为评审稿。请求与返回见[接口](接口.md)，字段与约束见[表结构](表结构.md)，完成条件见[验收](验收.md)。

业务依据为[产品方案](../../product/产品方案.docx)第 3 章第 2、5—7、9—10、13—15 节；页面与字段见[数据源页面](../../frontend/pages/datasources.md)。全局实体归属见[数据模型](../数据模型设计.md)，认证、返回、幂等、秘密与审计沿用[公共契约](../../architecture/接口与事件契约.md)及[安全边界](../../architecture/安全执行与审计.md)。

## 范围与模块衔接

Java 管理业务库连接、凭据、元数据采集和平台 MySQL 事实。采集只读取元数据，目录以成功快照为依据，来源注释与已确认的业务解释分别保存和返回。Python 与 Milvus 不参与采集或结构比较。

MySQL、PostgreSQL 沿用原型接入类型；平台库使用 MySQL 不代表业务源已经适配。每个类型、版本及对象类别须形成真实能力矩阵，未经验证的组合不进入正式可选范围。MySQL 的数据库是连接边界；PostgreSQL 还绑定明确的 Schema 集合，不跨数据库发现对象。

本设计确定结构事实、技术核实及向治理、知识和问数交接的依据。业务审核、知识发布和解除禁止由各自模块办理。审批授权、企业资料和数据源退出有独立设计边界。本范围的手动、定时、比较、核实与替换按一套链路评审和验收。

## 启用与能力判断

同源只配置一套企业专用只读账号。元数据读取能力满足、业务行暂不可读或未验证时，允许启用并采集目录；后续采样和问数分别核验实际业务读取能力及其余放行条件。只读安全本身不满足或无法核实时不得启用，不通过试写验证安全性。

七项分项结果保留原型的展示结构。服务端另保存只读安全判定和业务行读取判定，不能用一个“业务只读能力通过”覆盖两种事实。

| 检查 | 启用所需条件 | 结果边界 |
| --- | --- | --- |
| 配置有效性 | 当前连接必填项、范围、适配器及运行参数合法 | 草稿可缺连接资料，已填写值仍须合法 |
| 网络与加密 | 当前目标可连接且通过平台证书策略 | 失败不关闭 TLS 或证书验证 |
| 账户认证 | 当前账号与凭据认证通过 | 凭据不进入返回、核对内容或日志 |
| 目录枚举 | 配置边界能够枚举，PostgreSQL 所选 Schema 均在已核验范围 | 只承诺当前账号可见范围，不承诺拥有数据库全部资产 |
| 结构读取 | 已测试范围内的必要结构读取通过；完整枚举零对象时标记本次对象读取不适用 | 明示测试覆盖对象；零对象仍须使用已验证必要结构能力的适配器，抽查通过不等于全量采集完成 |
| 业务只读能力 | 只读安全判定必须通过；业务行读取可失败或未验证 | 分别保存安全性与可读性；测试不抓取业务样本 |
| 限制与兼容性 | 必需能力受支持，平台与数据源限额可执行 | 可选属性不支持明确列出；必要对象身份或字段类型无法读取时不能伪装成成功 |

测试记录绑定操作者、源及基础版本（未保存源可为空）、连接参数摘要、凭据依据、适配器版本、平台连接策略版本、已核验 Schema、覆盖对象和时间。前端只持有 `checkId` 与可披露结论；保存、启用和更换凭据由服务端复核绑定。密码摘要使用既定带密钥 HMAC，不用普通密码哈希或明文作为关联键。

测试依据初始有效期为 5 分钟，作为可调整的运行参数。地址、端口、数据库、账号、密码、适配器或安全策略变化立即失效。仅改名称、联系人、用途、Schema 顺序或从已核验集合缩小范围，不要求重复网络测试；超出已核验范围须补测。修改运行限额重新校验，不冒用旧测试覆盖新适配能力。测试到期不自动停用已启用源，后续实际连接仍按当前能力执行。

原型密码输入规则继续沿用：新增或明确替换时提供非空密码；编辑已配置凭据时留空保留，不 trim 或归一化密码。未保存源的检查只由原操作者使用；已绑定同源当前连接依据的检查按现有启用资格重新核验，不因测试人不同机械要求重测。未知、过期、其他源或无法核验依据的检查不能用于启用，核对凭据仍须属于当前操作者。

## 交互与权限

新增、编辑、测试及核对保留居中宽弹窗。启用后有 `catalog.view` 者进入当前源目录，未采集且具备采集动作资格时展示首次采集入口；无目录查看权者返回原列表。从采集记录发起或重试须具备 `collections.view` 与对应动作权。

保存草稿仅要求新增／编辑权；测试另核 `sources.test`；保存并启用同时核新增／编辑权与 `sources.enable`。已有草稿只变更生命周期时核启用权，不能通过该入口夹带配置修改。其他动作与其所属页面权见接口权限表。目录、任务、连接详情和联系人选项分别核权，不以隐藏按钮代替服务判断。

源名称按 `trim → NFKC → Locale.ROOT 小写` 防重，稳定编号与名称分开。归档联系人可以保留历史展示，但不能作为新增可选人员。连接地址限数据源详情。采集核对和任务详情按采集权限展示当次范围及账号，目录只展示元数据。所有回看入口都排除密码、连接串和密钥。

发起采集只做一次只读范围及账号核对，复用公共核对凭据；不增加第二次确认。列表查询、分页、详情返回、取消及字段错误沿用正式公共组件。连接失败、无权、尚未采集、成功但零对象分别表达。

## 状态与提交边界

| 维度 | 取值与事实 |
| --- | --- |
| 源生命周期 | DRAFT／ENABLED／DISABLED／RETIRED；退役无恢复或删除入口，完整退出设计随 B 批后续细化 |
| 能力结果 | PASS／FAIL／UNVERIFIED；完整枚举零对象时结构分项可为 NOT_APPLICABLE，属性另允许 NOT_APPLICABLE／UNSUPPORTED，读取权限不足按失败记录 |
| 采集任务 | QUEUED／RUNNING／SUCCEEDED／FAILED／CANCELLED，只对应方案已有五种状态 |
| 取消进度 | `cancelRequestedAt`、`executionState`、取消原因与确认时间独立于任务五态；收到取消命令不代表数据库已经停止 |
| 执行事实 | NOT_STARTED／RUNNING／STOP_REQUESTED／STOPPED／UNKNOWN；未知时继续核实，不能释放同源执行占位 |
| 凭据替换 | PENDING_STOP／APPLIED／FAILED；是替换操作进度，不增加源生命周期状态 |
| 当前目录 | 源的 `currentSnapshotId` 只指向同源成功快照；候选和失败快照不进入目录查询 |

手动发起（含首次采集）、失败或取消后的人工重试、定时触发均调用同一接收事务。首次人工采集成功后才接收定时任务。事务检查源为 ENABLED、当前配置可用于采集、没有待替换凭据或活动任务。人工触发校验角色与本次范围核对，定时触发校验当前计划、周期与允许窗口。已启用源的旧连接测试到期本身不阻断采集，工作者仍按当前只读安全、范围和连接策略连接。事务一起保存任务、候选快照、同源占位、命令结果及待执行事件。202 表示接收，工作者取得执行租约后开始。

采集以启动时的范围、账号、配置修订和策略写候选。分批读源和比较在平台事务外；所有候选写入校验 `runVersion`。成功事务复核生命周期、固定配置是否仍适用、执行代次、取消意图、当前办理资格、源侧读取已经结束、候选完整性和比较依据。名称、联系人和用途变化不使已固定范围失效，采集中不可调整 Schema 范围。目录指针与目录版本先由比较过程读取，若核实提交改变了目录版本，重新比较后再尝试。超过执行预算时按失败收尾。

同一事务写结构事实、完整快照、当前目录指针、确知影响的使用控制、任务成功、必要计划状态、审计及 Outbox，并释放同源占位。首次只建立基线，对象可供正常治理，结构变化列表保持空。失败、取消或提交回滚保留上次成功目录，候选仅用于受控诊断。已经提交但回包或通知丢失时按原任务回读。

## 枚举、结构与计数

对象按数据库实际可见能力分类，包含表、视图、适用的物化视图、系统／临时／分区／外部对象。分区保留父子关系；临时对象保留会话或时效依据。未暴露对象不计入已发现总数，不能为了成功静默跳过已发现但不支持处理的对象。

每种适配器和对象类型明确必要属性、可选属性及不适用项。核心对象身份、字段及类型缺失不能判成功。普通视图不套用普通表的物理索引、主键和生成默认值；不支持的可选属性带原因，真实无注释或无外键则保存已读取的空结果。

| 计数 | 定义 |
| --- | --- |
| discoveredCount | 当前配置范围内已发现且去重的对象数 |
| enumerationComplete | 是否完成当前配置范围的枚举 |
| totalCount | 枚举完整后等于 discoveredCount；此前为 null，不填 0 或预计总数 |
| attemptedCount | completeCount＋partialCount＋failedCount；读取失败也算尝试过 |
| completeCount | 已读取全部应读属性，明确不适用或可选不支持不算失败 |
| partialCount | 核心结构已取得，但有应读属性因权限、读取错误或未知未取得 |
| failedCount | 核心结构未取得的对象数 |
| unprocessedCount | discoveredCount－attemptedCount，不得小于 0 |

成功要求枚举完整、所有已发现对象尝试完毕、completeCount＝totalCount，partialCount／failedCount／unprocessedCount 均为 0。完整枚举的零对象范围可以建立空基线，明确“本次可见对象为 0”；PostgreSQL 仍须选择至少一个可见 Schema，不能以未完成枚举冒充空库。

源库采集中出现 DDL 时记录读取时段，按适配能力检测并复读变化对象；超出预算仍不稳定则失败。不承诺跨全部对象的数据库全局一致时刻，不把不同修订的字段和约束拼成一份可靠结构。

## 快照对比与目录

每次任务在接收时分配候选快照。成功快照固定本次可见对象、读取时段和实际配置，历史查询按当时的成员和结构回看。上一次当前成功快照用于追溯交接，与本次实际比较的快照分别记录。

| 本次结果 | 比较依据 | 目录与分析结果 |
| --- | --- | --- |
| 第一次成功 | 无成功快照 | 切换到初始基线，分析为 INITIAL_BASELINE，不生成变化 |
| 后续成功且有可比快照 | 同源、同一规范化范围、可按同一证据语义解释的最近成功快照 | 内容相同则分析为 NO_CHANGE，复用对象与字段修订。发现可靠差异或新核实疑点则为 CHANGES_FOUND |
| 后续成功且无可比快照 | 前次成功作为历史来源，不用于断言对象增删 | 分析为 NEW_SCOPE_BASELINE，目录按本次范围更新。范围外对象保留历史，首次读到的对象进入正常治理入口；若实际观察与已有身份冲突，可单独保留核实记录 |
| 失败或取消 | 无 | 候选保留用于受控诊断，当前成功指针和已记录的结构变化不变 |

MySQL 范围为配置数据库，PostgreSQL 还包含 Schema 集合。范围键按适配器标识语义规范化，Schema 顺序、联系人、周期或密码更新不改变范围键。比较契约键单独固定可验证的来源身份及证据语义；连接指向的实际来源或适配规则变化后，须证明比较契约仍等价才复用旧快照。账号或权限变化即使落在同一范围，也须在逐对象判断时区分可见性和结构。

比较按对象身份匹配，再比较对象、字段、约束、视图依赖等类型化事实。可靠原生身份须限定源库实例与可验证的身份世代；名称近似、位置、定义摘要和可能复用的原生编号不能单独证明身份。字段改名同样需要证据，无法对应的字段不继承旧解释。摘要只用于定位变化，逻辑以规范化事实为准；可选属性从已读取变为不支持时保存能力差异，不能当作属性被删除。无变化时继续生成成功快照并刷新采集时间，沿用同一结构修订和未办变化。

对象因访问丢失而不在最近的比较快照中时，仍从未恢复的记录查找其最后一次确证观察。重新读到并证明为同一身份时复用对象 ID，与该确证结构比较，并在差异中记录实际引用的旧快照；任务仍保留整体比较快照。仅恢复可见时更新目录可用性，结构分析为 NO_CHANGE。已确认移除的旧身份不得用此规则恢复。

当前目录查询返回当前成功快照中属于已配置范围的成员，并在同一范围投影尚未恢复的访问丢失与身份冲突。范围实际变更时，配置事务同时递增目录版本并记录目录变化事件，当前成功快照指针保留至下一次完整成功。在当前范围取得新的完整成功前，显示「待重新采集」，可见旧结构注明原快照和范围，新纳入对象以实际成功读取为准。返回以前使用过的范围同样重新采集，历史快照仍可作为比较基准。移出范围、身份待核实、访问丢失或确认移除的对象不计入当前可读对象数。历史快照成员不随目录投影、事实核实或治理修改而改写。

## 结构变化与核实

| 证据 | 结构事实与记录 | 对后续使用的影响 |
| --- | --- | --- |
| 可直接证实的新增对象、字段、注释、类型、默认值、约束或视图变化 | 自动确认，按对象及属性记录前后值、任务、前后快照和结构来源 | 进入受影响条目的治理。仍兼容的已有内容按实际依赖继续使用 |
| 在同一对象的完整结构中可确认字段删除，或适配器和依赖核验能确认不兼容 | 自动确认并关联实际受影响对象、字段和依赖 | 提交时立即禁止受影响使用，保留无关条目 |
| 旧对象在完整的同范围采集中消失但缺乏删除证据 | 标为访问丢失，创建待核实项。同一疑点仍无新证据时沿用未决项 | 当前源读取资格按实际可用性判断。核实删除后留存旧身份并禁止受影响使用；核实仍存在则排除删除推断，读取异常直到确认读回同一对象才解除 |
| 新出现于可见范围或 Schema 集合变化 | 按可见事实标为新发现或范围变化，旧快照保留 | 新对象按正常治理办理；范围外依赖按当前范围拦截，既有确认与历史可回看 |
| 重命名、同名重建或字段身份不明 | 有可信连续证据则识别为原身份变更；有可信重建证据则保留旧身份并建立新世代；其余进入待核实 | 待核实观察可回看，稳定身份和旧治理引用暂不转绑。确认同名重建时只推进一次世代，旧依赖须按实际影响复核 |
| 仅有业务含义疑点 | 交由治理条目记录疑点与证据 | 由有权人核实业务影响，按当前使用控制规则办理 |

变化保存事实状态 PENDING／CONFIRMED／EXCLUDED，另保存处理阶段 PENDING_REVIEW／PENDING_GOVERNANCE／GOVERNANCE_IN_PROGRESS／KNOWLEDGE_IN_PROGRESS／COMPLETED。被接续的历史记录以 COMPLETED 加后续变化引用表达，原事实状态和证据保留。变化筛选按对象、类型、发现日期、阶段；同表的待核实项按完整对象身份计算，分页与筛选不影响进入治理的门槛。无实际影响的排除项完成本条；确认有影响的事实进入对应治理条目。

变化核实使用其版本、固定的前后快照、证据和最新可办理记录。访问丢失只允许「已删除／仍存在」，身份不明只允许「原对象／同名重建」，其余疑点允许「确认／排除」；均留依据。取消或返回不提交结论。人工确认删除或重建前复核最新目录及绑定，后续采集若已证实相反事实须提示重新读取，不能保存过期判断。

同一身份疑点没有新证据时继续使用原未决记录。新观察实际改变身份依据时，同一事务关闭旧记录的办理入口并转交新记录，始终带上最后一次已确认的基准，未决的中间观察不能当作已确认身份。原对象核实通过后，按原基准补算先前暂停判断的真实字段与注释差异；重建则分配新对象 ID 和下一世代。核实形成追加记录，记录被确认的观察、解析身份与正式修订，只更新当前投影，不覆盖成功快照里的原观察。重复提交同一结论按原命令回读，跨记录或旧版本提交拒绝。

变化来源记录受影响的治理条目和使用控制引用。明确删除或不兼容时，负责使用控制的 Java 服务须与快照或核实结果在同一事务写入权威限制；写入失败时整笔回滚。访问丢失、范围外及待确认身份由当前目录的可用性拦截实际读取。Outbox 用于通知、补偿及定位受影响任务，不能承担第一道拦截。

治理条目实际开始办理后回写 GOVERNANCE_IN_PROGRESS，审核后从实际依赖判断进入 KNOWLEDGE_IN_PROGRESS 或 COMPLETED。必要知识更新、验证、发布和显式解除完成后，按[知识与使用控制](../../architecture/知识版本与索引一致性.md#暂停禁止与显式恢复)回写结果。同一变化涉及多个条目时，按尚未完成的必要环节推进；新采集或目录恢复可见不会替代业务办理，也不会解除已有禁止。

## 定时调度与陈旧状态

首次成功事务创建每源唯一计划，起点为本次成功提交时间。周期以经过的小时数计算，按平台部署的业务时区判断允许窗口。周期初值 24 小时。以 [开始, 结束) 判断窗口，支持跨日；遇本地时间跳过则找下一个实际可执行瞬时，重复的本地时间仍以 UTC 周期编号去重。界面显示有效时区及可计算的下次计划时间。

调度扫描以经过时间除以周期并向下取整，得到最新到期序号，从 1 开始。锁源后重核计划修订、窗口、ENABLED、暂停、待替换凭据、活动任务和平台容量。通过时，使用「源、计划修订、到期序号」作为唯一触发键，按系统身份写命令、采集任务及调度游标，同一次提交接受一笔任务。任务固定计划修订、名义到期时间和当时业务时区。错过多个周期只考虑最新到期序号；同源忙、超出窗口或暂停时不预建任务。任务已接收后，即使出队时窗口已结束，也按原预算运行。

暂停或恢复沿用数据源管理动作，暂停阻止后续定时接收，当前任务及手动采集仍按各自资格执行。恢复按原起点与当前窗口接收最新到期项。周期或窗口实质修改时递增计划修订，以当前配置提交时间为新起点，旧调度工作者的触发键失效；一般配置修改不重排计划。首次成功前可以保存计划参数，页面显示等待首次成功。停用、退役或凭据替换中的源不接收定时任务，恢复后按当前计划重新计算。人工采集和人工重试不受窗口限制，所有后续任务都走同一套快照对比。

从当前范围最近一次完整采集成功起，经过两个当前配置周期仍无新成功则标为陈旧并记录告警。首次成功以前保持等待；已有成功后变更范围，陈旧计时从范围调整提交时开始，随后只用该次范围调整后的适用成功。以源行锁写一次陈旧区间起点和告警，成功或范围再次调整后结束该段。周期修改影响下一次陈旧判定，已标记的陈旧仍以该段结束条件清除。范围调整待采集、陈旧和连接健康分别表达；陈旧不能作为删除证据。

## 取消、失败与恢复

取消先在平台记录意图，阻断新的源读取并禁止成功提交。排队且尚未运行的任务可直接取消；运行任务须确认所有源读取结束后才写 CANCELLED。停止未知则保留 RUNNING 与同源占位，页面展示核实进度。取消先提交时迟到结果不能切换目录；成功先提交时回读该成功结果。

每条可能发起采集 SQL 的专用源连接在开始读取前登记执行记录，关联任务、执行代次和适配器可核实的源侧执行标识。建立连接后取得必要身份信息，登记提交后才能执行采集；未完成登记的连接只允许初始化与关闭。多连接并发逐条登记。取消时先关闭继续发起读取的资格，再请求取消或关闭连接。停止证据须同时覆盖原读取已结束以及旧连接已关闭或已不可继续发起采集，且能区分连接编号复用及目标实例变化。单条查询结束时仍可执行的旧连接继续核实。适配器的结束证明及源端硬时限适用条件在真实矩阵中逐项验证；平台租约、取消回包和客户端网络超时本身不作为源端停止证据。

接管者先以原任务回读提交事实，再按已登记的执行核实。旧代次不得登记新执行、继续使用已封闭的连接或写入候选；核实时对仍可能执行的原连接须确认已结束或被封闭。全部确认后，已有取消意图的任务写 CANCELLED，否则进程中断写 FAILED；候选保留，不接续拼装。无法确认时按有界间隔继续核实并保留占位，界面展示当前阻断原因。到达工作预算后进入停止核实，预算耗尽不会自动释放占位。源库取消与确认仅使用已验证的只读接入能力。

网络瞬时故障可在固定任务时限和次数内重试，前一次读取须先确认结束。认证、权限不足及必要能力不支持直接进入失败处理。排队有独立等待上限；任务执行预算从实际开始计时，涵盖重试和比较。页面关闭、退出和重连只影响展示；真实撤权或停用须阻断受影响任务。失败详情展示实际原因和基本信息，已取消展示原因及执行状态，候选供受控诊断。

## 账号与密码替换

凭据替换可用原账号或明确的新账号，保持数据源数据库身份和 Schema 范围。已启用源改成另一数据库按数据源页面规则新建源。

1. 在旧配置继续运行时分项测试新凭据。测试失败不提交替换。核对展示旧／新账号、受影响任务及计划进入等待的影响，密码不进核对或审计。确认时若实际待停止的任务变为该核对未涵盖的另一笔，重新核对；原任务已结束时保留其实际结果。
2. 提交事务按当前权限、版本及测试绑定复核，保存加密候选、替换操作和原命令结果，设置同源替换占位并记录旧任务取消意图。阻止新的手动及定时采集；已有成功目录继续供有权人员查看。重复命令回读同一操作。
3. 工作者按[取消与恢复](#取消失败与恢复)核实对应任务的全部旧连接，重启后按原操作、原任务及已登记执行恢复。停止未知保持 PENDING_STOP。确认停止后复核当前源、基础配置修订、办理资格及新测试有效期，才原子切换配置与凭据运行引用，提交 APPLIED、审计和 Outbox。任务终态沿用其真实结果。
4. 如果确认停止后发现测试已过期、配置冲突或实际失权，记 FAILED，保留原运行引用并按安全策略隔离候选秘密，页面提供重新测试和发起入口。已经结束的任务维持终态；失败不会把旧凭据在源库的实际可用性当作已验证。核实或提交回包不明时按原操作回读，不能用新替换绕过占位。

成功后下一次手动或定时采集使用新凭据，保持原计划周期和既有快照历史。用户可从替换结果发起新任务；有取消记录需要重试时关联原任务，按新配置全量读取。后续问数同样须消费凭据失效及受影响在途读取的边界。

## 持久化与实施输入

[表结构](表结构.md)定义字段类型、关联、唯一约束、索引和跨表事务。需要联合加锁时，按权限 guard → 源 → 计划 → 任务 → 替换 → 执行记录 → 快照 → 变化及影响记录的顺序，只锁实际涉及的行。源库网络调用在平台事务外。执行与候选进度按代次更新，取消、撤权、核实、成功切换和使用限制遵守同一顺序。

适配验证按真实源库类型、版本、对象类别和配置权限记录，覆盖标识语义、只读判定、结构事实读取、取消与停止证明。正式连接和分项测试共用部署允许的地址、端口、TLS 及解析策略。平台 DDL 与迁移在评审通过后从字段结构生成并另行核实，实际场景见[验收](验收.md)。
