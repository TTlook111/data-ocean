# 数据源接入与首次采集设计

本设计覆盖连接草稿、分项测试、启用、首次全量采集、失败重试、目录回看，以及账号／密码替换对在途采集的处理。当前仅完成设计，未新增业务代码、迁移脚本或运行服务。接口见[接口](接口.md)，完成条件见[验收](验收.md)。

业务依据为[产品方案](../../product/产品方案.docx)第 3 章第 2、5—7、9、11—15 节；页面与字段以[数据源页面](../../frontend/pages/datasources.md)为准。全局实体归属见[数据模型](../数据模型设计.md)，认证、返回、幂等、秘密与审计沿用[公共契约](../../architecture/接口与事件契约.md)及[安全边界](../../architecture/安全执行与审计.md)，不另建一套公共协议。

## 范围与模块衔接

Java 管理业务库连接、凭据、元数据采集和平台 MySQL 事实。首次采集不调用模型、不获取业务样本，不依赖 Python 或 Milvus。目录只接纳成功快照；采集所得原始注释与治理后的业务解释分开，不能复制原型中的固定解释充当采集结果。

MySQL、PostgreSQL 沿用原型接入类型；平台库使用 MySQL 不代表业务源已经适配。每个类型、版本及对象类别须形成真实能力矩阵，未经验证的组合不进入正式可选范围。MySQL 的数据库是连接边界；PostgreSQL 还绑定明确的 Schema 集合，不跨数据库发现对象。

本设计不展开数据访问申请、审批责任、企业资料附件、治理、知识发布或 SQL 问数。源级状态和稳定对象编号为后续模块保留关联。二次及定时采集必须接入可比快照与结构变化处理后才能开放；不得将首次基线逻辑直接用于覆盖有依赖的旧目录。本轮不宣称整个 B 批契约、DDL 或实现已经齐全。

## 启用与能力判断

同源只配置一套企业专用只读账号。元数据读取能力满足、业务行暂不可读或未验证时，允许启用并采集目录；后续采样和问数分别核验实际业务读取能力及其余放行条件。只读安全本身不满足或无法核实时不得启用，不通过试写验证安全性。

七项分项结果保留原型的展示结构。服务端另保存只读安全判定和业务行读取判定，不能用一个“业务只读能力通过”覆盖两种事实。

| 检查 | 启用所需条件 | 结果边界 |
| --- | --- | --- |
| 配置有效性 | 当前连接必填项、范围、适配器及运行参数合法 | 草稿可缺连接资料，已填写值仍须合法 |
| 网络与加密 | 当前目标可连接且通过平台证书策略 | 失败不关闭 TLS 或证书验证 |
| 账户认证 | 当前账号与凭据认证通过 | 凭据不进入返回、核对内容或日志 |
| 目录枚举 | 配置边界能够枚举，PostgreSQL 所选 Schema 均在已核验范围 | 只承诺当前账号可见范围，不承诺拥有数据库全部资产 |
| 结构读取 | 已测试范围内的必要结构读取通过；完整枚举零对象时标记本次对象读取不适用 | 明示测试覆盖对象；零对象仍须使用已验证必要结构能力的适配器，抽查通过不等于全量采集完成 |
| 业务只读能力 | 只读安全判定必须通过；业务行读取可失败或未验证 | 分别保存安全性与可读性；测试不抓取业务样本 |
| 限制与兼容性 | 必需能力受支持，平台与数据源限额可执行 | 可选属性不支持明确列出；必要对象身份或字段类型无法读取时不能伪装成成功 |

测试记录绑定操作者、源及基础版本（未保存源可为空）、连接参数摘要、凭据依据、适配器版本、平台连接策略版本、已核验 Schema、覆盖对象和时间。前端只持有 `checkId` 与可披露结论；保存、启用和更换凭据由服务端复核绑定。密码摘要使用既定带密钥 HMAC，不用普通密码哈希或明文作为关联键。

测试依据初始有效期为 5 分钟，作为可调整的运行参数。地址、端口、数据库、账号、密码、适配器或安全策略变化立即失效。仅改名称、联系人、用途、Schema 顺序或从已核验集合缩小范围，不要求重复网络测试；超出已核验范围须补测。修改运行限额重新校验，不冒用旧测试覆盖新适配能力。测试到期不自动停用已启用源，后续实际连接仍按当前能力执行。

原型密码输入规则继续沿用：新增或明确替换时提供非空密码；编辑已配置凭据时留空保留，不 trim 或归一化密码。未保存源的检查只由原操作者使用；已绑定同源当前连接依据的检查按现有启用资格重新核验，不因测试人不同机械要求重测。未知、过期、其他源或无法核验依据的检查不能用于启用，核对凭据仍须属于当前操作者。

## 交互与权限

新增、编辑、测试及核对保留居中宽弹窗；启用不是采集成功。启用后有 `catalog.view` 者进入当前源目录，未采集时展示首次采集入口；无目录查看权者返回原列表，不因启用获得目录权限。只有采集查看权的办理人可从采集记录发起任务，不要求额外取得目录查看权。

保存草稿仅要求新增／编辑权；测试另核 `sources.test`；保存并启用同时核新增／编辑权与 `sources.enable`。已有草稿只变更生命周期时核启用权，不能通过该入口夹带配置修改。其他动作与其所属页面权见接口权限表。目录、任务、连接详情和联系人选项分别核权，不以隐藏按钮代替服务判断。

源名称沿原型 `trim → NFKC → Locale.ROOT 小写` 防重，稳定编号与名称分开。归档联系人可以保留历史展示，但不能作为新增可选人员。连接地址与账号只向有连接查看资格者返回；目录和任务上下文不夹带密码、连接串或密钥。

发起采集只做一次只读范围及账号核对，复用公共核对凭据；不增加第二次确认。列表查询、分页、详情返回、取消及字段错误沿用正式公共组件。连接失败、无权、尚未采集、成功但零对象分别表达。

## 状态与提交边界

| 维度 | 取值与事实 |
| --- | --- |
| 源生命周期 | DRAFT／ENABLED／DISABLED／RETIRED；退役无恢复或删除入口，完整退出设计随 B 批后续细化 |
| 能力结果 | PASS／FAIL／UNVERIFIED；属性另允许 NOT_APPLICABLE／UNSUPPORTED，不能用不支持掩盖权限不足 |
| 采集任务 | QUEUED／RUNNING／SUCCEEDED／FAILED／CANCELLED，只对应方案已有五种状态 |
| 取消进度 | `cancelRequestedAt`、`executionState`、取消原因与确认时间独立于任务五态；收到取消命令不代表数据库已经停止 |
| 执行事实 | NOT_STARTED／RUNNING／STOP_REQUESTED／STOPPED／UNKNOWN；未知时继续核实，不能释放同源执行占位 |
| 凭据替换 | PENDING_STOP／APPLIED／FAILED；是替换操作进度，不增加源生命周期状态 |
| 当前目录 | 源的 `currentSnapshotId` 只指向同源成功快照；候选和失败快照不进入目录查询 |

初次任务由有权人员手动发起。接收事务核对源为 ENABLED、配置与核对依据仍有效、无凭据替换阻断且无活动任务，原子保存任务、候选快照、同源占位、命令结果和待执行事件；202 仅代表接收。工作者取得租约后运行，所有写入携带任务执行代次，迟到工作者不能继续提交。

采集将枚举及结构结果分批持久化为候选。源库读取位于平台事务外，不长时间占用平台权限锁。成功提交前重新核对当前源、固定配置的适用性、执行代次、取消意图、操作者当前资格及结果完整性；在同一短事务内确认快照、切换当前目录指针、写成功终态、审计及 Outbox，并释放同源占位。配置的名称／联系人等描述变化不使已固定范围失效。

首次成功只记录“初始基线已建立”，不创建虚假的新增对象变化；对象可供后续治理读取，但不自动确认业务解释、发布知识或授予访问。

## 枚举、结构与计数

对象按数据库实际可见能力分类，包含表、视图、适用的物化视图、系统／临时／分区／外部对象。分区保留父子关系；临时对象保留会话或时效依据。未暴露对象不计入已发现总数，不能为了成功静默跳过已发现但不支持处理的对象。

每种适配器和对象类型明确必要属性、可选属性及不适用项。核心对象身份、字段及类型缺失不能判成功。普通视图不套用普通表的物理索引、主键和生成默认值；不支持的可选属性带原因，真实无注释或无外键则保存已读取的空结果。

| 计数 | 定义 |
| --- | --- |
| discoveredCount | 当前配置范围内已发现且去重的对象数 |
| enumerationComplete | 是否完成当前配置范围的枚举 |
| totalCount | 枚举完整后等于 discoveredCount；此前为 null，不填 0 或预计总数 |
| attemptedCount | completeCount＋partialCount＋failedCount；读取失败也算尝试过 |
| completeCount | 已读取全部应读属性，明确不适用或可选不支持不算失败 |
| partialCount | 核心结构已取得，但有应读属性因权限、读取错误或未知未取得 |
| failedCount | 核心结构未取得的对象数 |
| unprocessedCount | discoveredCount－attemptedCount，不得小于 0 |

成功要求枚举完整、所有已发现对象尝试完毕、completeCount＝totalCount，partialCount／failedCount／unprocessedCount 均为 0。完整枚举的零对象范围可以建立空基线，明确“本次可见对象为 0”；PostgreSQL 仍须选择至少一个可见 Schema，不能以未完成枚举冒充空库。

源库采集中出现 DDL 时记录读取时段，按适配能力检测并复读变化对象；超出预算仍不稳定则失败。不承诺跨全部对象的数据库全局一致时刻，不把不同修订的字段和约束拼成一份可靠结构。

## 取消、失败与恢复

取消先在平台记录意图，禁止新的源读取和目录提交，再尝试停止当前调用。确认结束后写 CANCELLED；停止未知保留 RUNNING 与独立取消进度，继续核实。取消先提交则迟到成功不能切换目录；成功先提交则返回当前成功结果，不能倒写为取消。

网络瞬时故障在固定任务时限和次数内重试；认证、明确权限不足及不支持的必要能力直接失败。任务时限包含任务实际处理与重试，不因重试重置。排队有平台容量和等待上限。原型连接数 4、采集并发 2、重试上限 2、任务处理时限 600 秒作为联调初值，具体容量与方言能力由真实适配验证，不构成生产容量承诺。

页面关闭、刷新、SSE 断线和正常退出不取消已接收任务；账号停用或实际撤销采集资格主动阻断相应人工任务。系统定时任务记录系统调度身份及配置来源，不冒充配置人的活动登录会话。

工作进程退出后，接管者先核实旧执行、租约和完成事实。原任务因进程中断结束为 FAILED，保留候选记录；有权人员重新采集另建任务、重新读完整范围，不自动从候选片段拼接成功。旧执行无法确认停止时仍保留同源占位，禁止立即启动重叠任务。平台提交结果不明先按原任务和命令核实，已成功者不重采。

失败详情只展示实际原因及基本任务信息；已取消展示取消原因和执行状态。候选对象及属性级记录保存在服务端供受控诊断，不在普通失败详情增加统计、对象清单、候选快照或未执行分析区块。

## 账号与密码替换

凭据替换沿用原账号或明确的新账号，不能改变源的数据库身份。已启用源的数据库类型、地址、端口或数据库变化按原型要求新建源；本阶段不增加迁移流程。

1. 在不改变运行配置的情况下测试新账号／密码。失败只返回分项原因，原配置、当前任务和定时计划保持有效。
2. 核对页显示凭据已替换的事实、受影响活动采集及停止后果，秘密不进入提案、核对凭据或审计。
3. 提交后将候选秘密加密保存，持久记录替换操作，阻断新的手动／定时采集并对旧任务记录取消意图。原任务已成功时保留成功事实，不倒改其结果。
4. 只有确认旧任务与所属源读取已结束、源和配置版本仍匹配且新测试依据有效后，才原子切换配置／凭据引用、保存修订、审计和 Outbox，解除新任务阻断。停止未知时显示正在停止，不能先宣布密码更新成功。
5. 测试过期、版本冲突或替换失败时不覆盖原运行引用，保留已发生的取消事实；候选秘密按安全策略解除引用。成功后由用户发起新的完整采集，不恢复或改绑旧任务。

替换操作不取消已经形成的成功快照，不自动授予业务读取能力。后续问数接入时必须扩展对旧连接与在途读取的失效处理，未完成这部分真实验证不能宣称全业务凭据轮换已验收。

## 定时采集衔接

源启用后、首次成功前不创建定时任务。首次成功写入调度起点，之后按已保存周期和允许时段调度；初始周期 24 小时。手动采集和失败后的人工重新采集不受定时时段限制，仍受并发与预算约束。

时段使用平台部署的业务时区解释，界面显示有效时区，不用宿主机隐式本地时间。到期但不在时段内等待下一允许时段；同源忙碌或替换凭据期间不累计多个等待任务，错过的触发合并处理。暂停、停用及未完成的变化处理不得被调度绕过。

调度需要二次采集的成功快照比较与变化影响链路。本次首次链路可独立验收，但在后续处理接通前不把原型里的周期配置或定时样例称为真实调度完成；部署不开放未实现的定时动作。

| ds_object | id、source_id、generation INT、source_identity（可空）、first_seen_at | 稳定身份不可被名称复用；当前路径、父对象及类型由成功结构修订表达；按 source_id、source_identity 查询，不能假定每种源均提供可靠原生编号 |
| ds_object_revision | id、object_id、revision、namespace、source_name、object_type、parent_object_id（可空）、source_comment、comment_read_status、definition_digest、created_at | (object_id,revision) 唯一；内容不原地覆盖；来源注释与治理解释分离；成功但未变复用原修订 |

`verified_scope` 等有限快照的结构由接口定义。`candidate_structure` 仅保存本次对象的类型明确 JSON 候选：原始注释、字段定义数组、有序约束定义数组、视图事实和各属性读取状态；缺少的属性保留读取原因，不含业务行、业务解释或秘密。这样失败前可靠读到的字段及索引仍有落点，不能只留失败状态丢失已读结构。成功目录的成员、字段、Schema 和约束继续使用关系表，不能以候选 JSON 替代。

涉及候选名称的唯一比较键按适配器规则生成，不依赖平台库默认排序规则合并大小写不同的源对象。计数使用 BIGINT 并按公共契约防止对外精度丢失；路径和原生定义长度以真实适配输入校验，不静默截断。

锁顺序沿公共权限 guard，再锁源、当前任务／替换操作，最后快照；源库网络调用不放在这些事务内。仅采集进度更新不占用权限 guard，最终成功、取消、撤权及凭据切换须保证同一顺序和版本核对。所有跨模块引用提供反向定位，后续治理依赖固定 object_id、generation、结构修订和 snapshot_id。

## 实施前检查

实施者需完成各适配器的真实版本矩阵、目录大小写规则、只读安全验证办法、平台连接目的地和证书策略、源读取超时／取消能力，以及任务容量参数。网络策略从受控部署配置读取，连接测试和实际采集使用同一套地址解析及端口限制，不能因预先测试通过绕过后续检查。

这些是实施与验收输入，不重新选择技术栈、不要求负责人逐个确定线程数，也不授权新建基础设施。保留与清理沿产品各类数据策略；本阶段不启动自动清理。完整字段类型、约束及索引在进入真实实施前生成并审阅 DDL，不能把本设计当作已建表或已验证。
