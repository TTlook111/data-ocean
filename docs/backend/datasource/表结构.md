# 数据源接入与采集表结构

本页与[设计](设计.md)、[接口](接口.md)和[验收](验收.md)对应。平台使用 MySQL InnoDB、utf8mb4 和 UTC 毫秒时间，实际 DDL 由 [Flyway V3](../../../backend/src/main/resources/db/migration/V3__datasource_collection.sql) 执行，真实应用范围见[验收](验收.md#当前验证范围)。

## 类型与关联

表中 ID 为 BIGINT UNSIGNED，对外按十进制字符串传递；UUID 为 CHAR(36) ASCII；版本和世代为 INT UNSIGNED；时间为 DATETIME(3)；CODE 为 VARCHAR(48) ASCII；FLAG 为 BOOLEAN 且只接受 0／1；摘要为 BINARY(32)。字段组按 `字段 类型` 表示，注明可空的字段允许 NULL，其余必填。固定状态、版本正值、计数与时间关系使用 CHECK；跨表的状态、范围、对象归属和当前版本由事务重核。

模块内引用使用 RESTRICT。源、任务、快照和对象的关键引用以包含父归属的唯一索引和组合外键防止串源，例如快照的 `(source_id, task_id)`、对象修订的 `(object_id, id)`。互指记录先允许当前指针为空，按源、子记录、指针顺序提交；DDL 在引用两端存在后补外键。IAM、治理与知识等跨模块引用由归属服务核验，并建反向查询索引。结构事实、执行证据和跨模块记录均按各自保留策略维护。

## 源、配置与凭据

| 表 | 字段及含义 | 唯一约束、索引与写入要求 |
| --- | --- | --- |
| `ds_source` | id ID；name VARCHAR(80)、name_key VARBINARY(1280) 为展示名及规范化 UTF-8 键；lifecycle CODE、version 版本为生命周期及配置写入版本；catalog_version 版本为目录投影版本；current_connection_revision_id、current_snapshot_id、active_task_id（UUID）、pending_change_id（UUID）可空；schedule_paused FLAG；first_success_at、scope_changed_at、stale_since 时间，可空；stale_scope_key 摘要，可空；created_by ID、created_at、updated_at 时间 | name_key 唯一；当前指针须同源，成功快照才可挂为当前。索引 `(lifecycle,updated_at,id)`。首次成功时写 first_success_at，范围发生实质变化时写 scope_changed_at。stale_since 与 stale_scope_key 同时空或有值，只在陈旧区间开始时写入并同时发告警。目录版本因快照切换、实际范围变更或核实改变投影而递增，任务进度不改变配置写入版本 |

| `ds_connection_schema` | connection_revision_id ID；schema_name VARCHAR(160) 原始名称；schema_key VARBINARY(640) 适配器身份键；ordinal INT UNSIGNED 展示顺序 | 主键 `(connection_revision_id,schema_key)`；同修订 ordinal 唯一；MySQL 无 Schema 行，PostgreSQL 启用至少一行。顺序不参与范围比较 |
| `ds_credential_revision` | id、source_id ID；key_version VARCHAR(64)；ciphertext BLOB（受控 AES-GCM 密文封装）；created_by ID、created_at 时间 | 按 source_id 反查；秘密只存封装所需的密文与认证材料，无明文列。待替换候选经操作引用，只有切换成功才进入运行配置；失败解除候选运行资格并按秘密保留策略处理 |
| `ds_capability_check` | id、actor_id ID；source_id ID、base_version 版本可空；connection_fingerprint、credential_fingerprint BINARY(32)，fingerprint_key_version VARCHAR(64)；adapter_version、policy_version、detected_version VARCHAR(64)，detected_version 可空；verified_scope、coverage、results JSON；read_only_safety、business_read_status CODE；checked_at、expires_at 时间 | 摘要为带密钥 HMAC，公开检查仅返回声明的范围、覆盖和结果。索引 `(source_id,checked_at,id)`、`(actor_id,expires_at)`；expires_at 晚于 checked_at。未保存检查绑定原操作者，命中有效连接依据后才可归属新源 |
| `ds_connection_change` | id、command_id UUID；source_id、actor_id、base_connection_revision_id、check_id、candidate_credential_revision_id ID；expected_source_version 版本；candidate_account VARCHAR(160)；review_evidence JSON；blocking_task_id UUID、applied_connection_revision_id ID 可空；state CODE；accepted_at、stop_confirmed_at、completed_at 时间，后两项可空；failure_code CODE、failure_message VARCHAR(500) 可空 | `(actor_id,command_id)` 唯一；`(source_id,accepted_at,id)` 供回看，`(state,accepted_at,id)` 供接管；按 blocking_task_id 反查。核对快照只存非秘密计划和关联编号。APPLIED 时必须有停止确认与生效修订，FAILED 时保留失败原因。候选账号和秘密在替换记录，实际切换才创建新的连接修订；每源有效操作由 pending_change_id 串行化 |

`ds_source.created_at` 记录数据源首次创建。配置、生命周期、计划暂停设置、目录投影变化及新鲜度状态变化会刷新 `ds_source.updated_at`，供数据源列表按更新时间排序。活动任务和凭据替换的内部占位使用对应业务记录追踪。

## 调度、任务与源侧执行

| 表 | 字段及含义 | 唯一约束、索引与写入要求 |
| --- | --- | --- |
| `ds_collection_schedule` | source_id ID 主键；revision 版本；anchor_at 时间；last_admitted_cycle_no BIGINT UNSIGNED，初始为 0；next_check_at 时间，可空；updated_at 时间 | 首次成功时创建；周期与窗口在当前配置修订读取，周期／窗口变化递增 revision 并归零游标。索引 `(next_check_at,source_id)` 定位扫描。next_check_at 仅是内部唤醒时间，可从权威计划修复，展示按计划重新推算。暂停、停用、窗口或线程容量变化不单独生成排队任务 |
| `ds_collection_task` | id、start_command_id UUID；task_no VARCHAR(40)；source_id、config_revision_id、credential_revision_id ID；parent_task_id UUID 可空；trigger_kind、actor_kind CODE；actor_id ID 可空；actor_ref JSON 冻结可披露身份；schedule_revision 版本、schedule_cycle_no BIGINT UNSIGNED、scheduled_for 时间均可空；state、phase、execution_state CODE，phase 可空；version、run_version 版本；stream_epoch UUID；lease_owner VARCHAR(64)、lease_until 时间可空；created_at、queue_deadline_at 时间；started_at、execution_deadline_at、ended_at 时间可空 | task_no 唯一；人工 `(actor_id,start_command_id)` 唯一；定时 `(source_id,schedule_revision,schedule_cycle_no)` 唯一且周期大于 0，系统身份无 IAM 用户 id。仅 RETRY 带同源失败／取消父任务；索引 `(source_id,created_at,id)`、`(source_id,started_at,id)`、`(state,lease_until,id)` 与 `(state,queue_deadline_at,id)`。命令按实际 USER／SERVICE 主体复用 sys_command |
| `ds_collection_task` 统计与停止字段 | enumeration_complete FLAG；discovered_count、complete_count、partial_count、failed_count BIGINT UNSIGNED；total_count BIGINT UNSIGNED 可空；stop_requested_at、cancel_requested_at、stop_confirmed_at、stop_next_check_at 时间可空；cancel_reason VARCHAR(500)、failure_code CODE、failure_message VARCHAR(500) 可空 | attemptedCount 和 unprocessedCount 从已保存计数派生；完整枚举时 total_count 等于 discovered_count，未完成时为空，终态检查同设计。索引 `(execution_state,stop_next_check_at,id)` 支持继续核实；停止未知保留占位。队列上限与执行上限分别保存，重试不续期 |
| `ds_collection_execution` | id UUID；task_id UUID、run_version 版本；source_instance_key 摘要、adapter_version VARCHAR(64)；locator_envelope BLOB（核实原连接所需的内部执行标识封装）；state CODE；registered_at 时间；stop_requested_at、last_verified_at、stopped_at、server_deadline_at 时间可空；stop_proof_kind CODE 可空 | 索引 `(task_id,run_version,state,id)`，跨代次追查同一任务；每次连接登记后才可发出采集读取，重连另登记。STOPPED 需要 stopped_at 和来源可核实的依据，server_deadline_at 仅在适配器证实硬上限时保存。记录用于源侧核实，普通接口只返回聚合执行状态与时间，不返回封装内容 |

定时任务另存 `schedule_time_zone VARCHAR(64)`，与 schedule_revision、schedule_cycle_no、scheduled_for 同时有值。scheduled_for 为对应周期的名义到期时间，created_at 为实际接收时间；计划时区为接收当时的部署业务时区。

执行记录使用 REGISTERED／READING／STOP_REQUESTED／UNKNOWN／STOPPED。stop_proof_kind 记录来源证据类型（源会话已关闭、权威隔离及结束确认、或已验证硬时限及隔离），适配器核验实际同一执行后才能写。任务仍使用五种业务状态和独立执行状态。终态、释放活动占位及取消确认同事务写入。先取得源行再核当前执行资格；源运行占位和调度触发键由数据库事务裁定。

| `ds_column`、`ds_column_revision` | ds_column 为 id、object_id ID；ds_column_revision 为 id、column_id ID、revision 版本、source_name VARCHAR(160)、ordinal INT UNSIGNED、native_type TEXT、nullable FLAG、default_expression、generated_expression、source_comment TEXT 可空，created_at 时间 | 稳定字段归对象，`(column_id,revision)` 唯一。字段映射使用可核实身份；原始定义及表达式按适配边界完整保存。历史快照通过成员定位具体修订 |

候选 JSON 只接收类型明确的原始字段、注释、约束、视图和各属性读取结果。用于分批持久化、失败受控诊断及尚未绑定身份的观察；已绑定的成功结构使用关系成员及不可变修订。原始源结构执行容量校验，超出生成的物理字段上限时报明原因。

排队取消或失败的任务仍记录任务结束时间。候选快照在尚未进入读取阶段时保留 `read_started_at` 和 `read_ended_at` 为空。

## 变化、核实与影响引用

| 表 | 字段及含义 | 唯一约束、索引与写入要求 |
| --- | --- | --- |
| `ds_change` | id、source_id ID；discovery_task_id UUID；before_snapshot_id、after_snapshot_id、before_observation_id、after_observation_id ID，观察可空；comparison_object_id、object_id、column_id ID 可空；change_key 摘要；discovery_kind、change_type、target_kind、attribute_kind、fact_state、stage CODE；before_value、after_value、evidence JSON，前后值可空；successor_change_id、visibility_restored_snapshot_id ID 可空；version 版本；discovered_at、updated_at 时间 | `(discovery_task_id,change_key)` 唯一，键由事实目标、属性以及比较证据确定；同一疑点的新观察按接续规则办理。索引 `(source_id,stage,discovered_at,id)`、`(source_id,change_type,discovered_at,id)`、`(source_id,comparison_object_id,stage,id)`、`(source_id,object_id,stage,id)`，并按来源快照及 successor 反查。证据边绑定实际对象和字段修订；可见性恢复指针仅指向真实成功重读的快照，与事实核实分离 |
| `ds_change_review` | id、source_id、change_id ID；command_id UUID，系统核实可空；actor_kind CODE、actor_id ID（系统可空）；reviewed_version 版本；decision CODE；evidence_text VARCHAR(1000)；verified_observation_id、resolved_object_id、resolved_object_revision_id ID 可空；reviewed_at 时间 | `(change_id,reviewed_version)` 唯一；命令非空时 `(actor_id,command_id)` 唯一；索引 verified_observation_id、resolved_object_id、resolved_object_revision_id。只追加，原观察与本次核实的解析身份均可追溯。人工核实依据、受影响事实和原命令在同一事务提交 |
| `ds_change_impact_ref` | change_id ID；ref_kind CODE（GOVERNANCE_ITEM／KNOWLEDGE_WORK／USAGE_CONTROL）；ref_id ID；linked_at 时间 | 主键 `(change_id,ref_kind,ref_id)`，反向索引 `(ref_kind,ref_id,change_id)`。实际使用控制和业务处理状态各由所属模块维护；事实事务记录需即时生效的控制及影响引用，下游按当前结果回写来源阶段 |

`ds_change` 的证据字段固定前后各侧的结构及字段修订 ID（可空）、原路径、缺席原因和适配器事实。按需要从结构或字段反查的直接引用使用关联字段及索引；其他来源快照或观察回看走本表的编号，不取对象或字段的最新版。

人工与自动核实取得当前源、变化版本、历史观察及使用控制依据后再提交。成功重读对仍待核实的 ACCESS_LOST 项追加 READ_RESTORED 系统证据，并结束待核实状态；已排除删除的访问丢失项只补可见性恢复引用，原核实结论照常回看。已确认移除的身份不走可见性恢复。

## 事务对照

| 操作 | 同一事务内的权威记录 |
| --- | --- |
| 接收人工／定时采集 | 源占位、命令、任务、候选快照及 Outbox；定时再写计划周期游标 |
| 采集成功 | 快照及成员固定、必要结构修订、结构变化及同步使用控制、目录指针和版本、任务终态、首次计划或新鲜度、审计以及 Outbox |
| 采集失败或取消 | 原候选与终态、确认的源侧执行证据、释放占位、必要审计与通知；仍有未知执行时只记录核实进度 |
| 修改实际采集范围 | 配置修订、范围变更时间、目录版本、审计与目录变化事件；当前成功快照指针保留 |
| 保存结构核实 | 变化版本、追加证据、解析对象及必要结构修订、目录投影与同步使用控制、影响引用、审计和 Outbox |
| 提交／完成凭据替换 | 接收时保存操作、候选密文和停止意图；确认停止后才写生效配置修订、替换终态、审计和 Outbox。已停但重验失败则保留原配置引用并记录失败 |
| 计划暂停／恢复与陈旧 | 计划设置或源新鲜度标记、当前版本、审计与必要通知；不写虚构任务或成功快照 |
