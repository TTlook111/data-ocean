# DataOcean 后台界面设计规范

本规范用于后台管理的页面骨架、空间、字体和组件尺寸。查询、权限、审批状态及数据量规则见[前端交互设计](前端交互设计.md)。项目业务规则以[产品方案](产品方案.docx)和项目负责人的后续决定为依据。

每页功能和按钮先按[页面功能清单](前端交互设计.md#页面功能与必要动作清单)确定，再套用本规范。样张中的复制、多操作及更多菜单用于验证组件，不代表业务页必须有这些功能；没有业务动作时省去操作列。每个实际按钮须对应方案中的任务、当前操作权限与对象状态，并明确操作结果。

适用范围为 PC 桌面浏览器。页面布局、交互和验收以 PC 窗口、鼠标、键盘及浏览器缩放为准，主要检查 1024、1280、1440、1536px 宽的窗口。

统一尺度应用于[规范样张](../prototypes/后台管理/规范样张.html)和[后台业务原型](../prototypes/后台管理/index.html)。行操作与浮层共用 `prototypes/后台管理/admin-system.css`，业务页通过同一组颜色 token 保持一致。查询、日期范围及分页通过 `RecordControls` 挂载同一套本地 Element Plus 组件，表格框架采用 `RecordTable` 统一骨架；样张调用相同入口，业务页只提供字段、列、数据、状态和回调。文末列出复核范围。

## 参考与采用方式

2026 年 11 月 8 日，从用户提供的 MonsterONE 分类进入真实预览，检查了 Bluedox、Arise 的数据表页面及 Arise 表单页面，并对照 Tabler 的列表与布局。研究关注同一产品在不同页面重复使用的结构、间距与组件关系。[MonsterONE 后台模板目录](https://monsterone.com/html-templates/admin-templates/)

| 参考 | 本轮用途 | 入口 |

| Arise | 从 MonsterONE 进入，比较同一套后台的数据表、表单、侧栏及卡片间距 | [数据表实页](https://www.bootstrapget.com/demos/templatemonster/arise-admin-dashboard/data-tables.html) |
| Bluedox | 从 MonsterONE 进入，对照侧栏、工具区与列表的组织方式 | [后台预览](https://www.bootstrapget.com/demos/bluedox-admin-dashboard/index.html) |
| Ant Design | 字体层级、布局单位、统一卡片尺度的原始依据 | [字体](https://ant.design/docs/spec/font/)、[布局](https://ant.design/docs/spec/layout/)、[卡片](https://ant.design/components/card/) |
| Carbon | 间距 token、父级排布和完整数据表结构的原始依据 | [间距](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)、[表格](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/specifications) |

Ant Design 的字体规范以 14px 与 22px 行高为基础，并建议普通界面控制字号种类。其亲密性规范用 8、16、24px 区分信息组的距离。Tabler 使用统一的间距档位与卡片结构。DataOcean 据此确定下文的项目取值。[Ant 字体规范](https://ant.design/docs/spec/font/)、[Ant 间距规范](https://ant.design/docs/spec/proximity/)、[Tabler 间距](https://docs.tabler.io/ui/utilities/margins)

本轮实页测量显示，Arise 的相邻卡片间距为 24px，多个卡片正文重复采用上下 16px、左右 20px 的内距；Bluedox 又有自己的固定尺度。可复用的原则是同一体系内按组件角色统一取值。下表中的 24px 面板内距等属于 DataOcean 的决定。

本机参考截图与 DOM 测量位于 `output/design-research/admin-reference/`。所有数值采用 CSS 像素，实测样本注明页面与视口。

本轮按项目负责人要求使用本地 `design-taste-frontend` 技能，采用其中适用于现有 PC 后台的原则：同一套 token 与组件、相等的内容边界、按信息角色固定字号、以中性色承载内容、主操作集中强调，并为鼠标悬停、按下和键盘聚焦提供明确反馈。项目既定的后台模板和尺寸继续作为实现依据。技能中的营销页首屏、摄影、整屏章节和展示动效不属于本项目后台；手机不在适配与验收范围。

## 统一设计尺度

### 空间

采用 4px 基础单位，常用档位固定为 4、8、12、16、24、32、48px。

| Token | 项目取值 | 使用位置 |
| --- | --- | --- |
| space-1 | 4px | 标记与短说明的紧密关系 |
| space-2 | 8px | 标签到控件、相邻按钮、图标到文字 |
| space-3 | 12px | 表格行上下内距、分页上下内距 |
| space-4 | 16px | 表单行列间距、表格中间列左右内距 |
| space-6 | 24px | 桌面工作区四边、同级主要区块间距、面板四边内距 |
| space-8 | 32px | 明确独立的大章节之间 |
| space-12 | 48px | 展示型空态或特殊阅读区的留白档位 |

同一角色的空间在各页使用同一个 token。相同卡片的上下内距对称，左右内距对称。页面容器负责区块之间的距离，面板负责内部边距，字段组负责标签和值之间的距离。

一个相邻间隔由一个父层负责。例如页面使用 `gap: 24px` 时，查询区和结果面板的相邻外边距为 0；面板已经提供 24px 内距时，直接子元素使用内部排布规则。组件默认的标题、段落、表单外边距在组件内统一归零，再由父层的 gap 排列。

### 字体

使用当前系统字体回退链，中文优先保证稳定、清楚的渲染。常规界面固定以下五档，行高也随角色固定。

| 角色 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 次要编号、时间、补充说明 | 12 / 18px | 400 |
| 正文、菜单、字段标签、表格、按钮、输入 | 14 / 22px | 400，强调时 500 |
| 区块标题、关键信息 | 16 / 24px | 500 或 600 |
| 页面标题 | 24 / 32px | 600 |
| 审批单主标题 | 28 / 36px | 600 |

表格采用 14 / 24px 的行内文字尺度，双行内容的辅助行采用 12 / 16px，便于与固定的行密度配合。数字、时间和页码采用等宽数字。正文、字段和说明遵循共同左轴，数值列按业务需要统一右对齐。

页面主标题承担页面定位，具体业务问题或当前办理结论承担任务重点。单个页面保留一个主要操作的主色强调，其余操作使用次级样式。

### 颜色、边框与圆角

| 角色 | 项目取值 |
| --- | --- |
| 页面底色 | #f5f7fa |
| 面板、表单控件 | #ffffff |
| 正文 | #1f2937 |
| 辅助文字 | #5b6575 |
| 分隔线与普通边框 | #e5e7eb，1px |
| 主操作 | #2f63d5 |
| 控件圆角 | 6px |
| 面板圆角 | 8px |

状态使用文字说明并配合克制的浅底色。菜单选中沿用已确定的背景高亮。焦点样式与选中样式各自表达当前交互状态，标题的程序化聚焦使用细左标记，按钮与链接保留可见的键盘轮廓。

表格、查询、分页、详情和浮层共用上述颜色与圆角。页面主体以中性色为主，主色用于当前主要动作、记录查看入口和焦点；复制等次要动作采用中性色。悬停使用浅底与边框反馈，颜色过渡为 120–150ms。焦点轮廓即时出现，减少动态效果时保留全部内容与反馈。

## 全局后台骨架

| 区域 | 尺度与行为 |
| --- | --- |
| 顶栏 | 高 64px，品牌与当前登录账号位于固定区域 |
| 左侧导航 | 宽 216px，组别和模块层级明确，桌面常驻 |
| 导航行 | 高 40px，保持常驻侧栏和清楚的当前项 |
| 工作区 | 四边 24px，所有同类列表页共用左右边界 |
| 内容顺序 | 页面标题、查询区、结果面板 |
| 区域之间 | 统一 24px，由工作区父容器控制 |

页面标题区使用 32px 行高，辅助入口与其垂直居中。相邻页面的标题顶边、查询卡外边、结果卡外边、页脚底边应能直接叠图比较。

后台导航负责模块切换，待处理、已办属于当前页面的数据分组。点击整个用户区域展开个人管理，有后台模块权限时再显示后台管理入口。问数、个人管理与后台使用同一登录账号，菜单中不提供人员、角色或“原型视角”选择。运行图、选稿及重置等评审工具另行组织。

后台侧栏按当前账号实际权限显示模块；读取记录、审批及执行授权分别核验对应操作和资源范围。手工输入后台地址、刷新页面或当前权限失效时也须重新检查，无权时停止展示受限内容并反馈原因。企业可配置角色与授权，角色名称不决定菜单和按钮。个人管理概况沿用同一字体、控件和间距体系；资料编辑、认证恢复及会话管理仍待单独设计，不用空按钮占位。

## 共用页面模板

### 管理列表

```text
后台外壳
└─ 工作区，四边 24
   ├─ 页面标题
   ├─ 间距 24
   ├─ 查询面板，四边 24
   ├─ 间距 24
   └─ 完整结果面板
      ├─ 按需出现的分组或操作工具区
      ├─ 表头
      ├─ 数据行、空态及面板内留白
      └─ 分页页脚
```

查询与结果面板外边对齐。查询内部的首列、实际操作工具区与分页文字以面板内 24px 为共同起点；表格首末列外侧也采用 24px。

### 审批收件箱

复用管理列表的外壳、查询面板与底部分页。结果主体采用 256px 队列和自适应单据区，以一条分隔线区分。

队列条目四边 16px，条目内部使用 8px 排布。单据中的概况、授权决定、申请资料和处理记录共用 24px 内容内距，相邻完整章节之间由 24px 排布或一个带分隔线的章节容器统一承担距离。

常规长表单的阅读宽度上限为 800px。跨页共享页面外边界，表单内容在指定阅读区内排列。

## 共用组件

### 组件来源与原型边界

本轮静态 HTML 原型使用本地 Element Plus 2.14.0 的实际组件。查询行使用 `ElInput`、`ElSelect`、`ElDatePicker`（`daterange`）与 `ElButton`，分页使用 `ElPagination`；统一中文 locale，默认 `large` 尺寸，对应 40px 控件。下拉、日期范围面板、输入、清空、键盘操作、焦点与图标沿用组件库行为，项目通过品牌色、字号及圆角 token 配置视觉。

`RecordControls` 是样张与业务页实际挂载查询和分页的共同入口，`RecordTable` 提供共享表头、表体、空态及结果框架。页面布局继续遵循下述空间和密度规则。组件采用局部挂载服务本轮原型，不据此锁定正式前端技术栈；正式选型仍在原型确认后完成。

### 查询表单

- 查询面板四边使用 24px，同一行和相邻行的间隔使用 16px。
- 查询区不外露“提交日期”“生效日期”等字段名称，业务日期含义保留在隐藏的可访问标签中。同一查询行的控件顶边及底边一致。
- 日期范围使用 `ElDatePicker` 的 `daterange`，空值分别显示“开始日期”“结束日期”，有值及提交值统一为 `YYYY-MM-DD`。开始与结束成对提交，清空时不限定日期；不完整或非法区间在控件附近说明。日期面板、输入、清空及键盘交互沿用组件库。
- 关键词通过占位内容标明搜索范围，状态通过选中项表达，日期范围通过开始、结束占位表达。查询控件保留隐藏的可访问标签。
- 新增、编辑和审批表单按字段需要显示标签，标签到控件间距为 8px。
- 输入框、下拉框、日期范围、查询及重置按钮统一使用组件库 `large` 尺寸，高 40px。
- 关键词框宽度为 280–400px，状态宽 160px，日期范围宽 320px；宽度不足时整组换行。
- 按钮之间使用 8px。按钮与输入的底边对齐。
- 已应用条件、错误输入和清空入口保持可见、可理解。

### 页面文案

页面标题承担模块名称。结果区直接呈现表头或数据分组，工具栏承载查询、批量处理等实际操作。当前列表样张省去“申请列表”重复标题及其数量条。

记录总数在底部分页处集中显示一次，文案为“共 N 条”。分页同时提供每页条数与页码状态，省去“当前第几至几条”的范围说明。查询控件保留原生标签或可访问名称，读屏可以识别用途。

### 结果面板、表格与分页

| 区域 | 尺度 |
| --- | --- |
| 面板工具区 | 四边 24px，同组控件间距 8px |
| 表头 | 高 48px，文字垂直居中 |
| 单行数据 | 最小高 48px |
| 双行数据 | 最小高 64px |
| 单元格内距 | 上下 12px，中间列左右 16px |
| 首列左侧、末列右侧 | 24px，与面板内容轴一致 |
| 分页页脚 | 桌面高 64px，左右 24px，上下 12px，控件高 40px |

表头与表体共享列宽和内距，文字列左对齐、数值列右对齐。列宽依据字段类型分配预算，所有文本列都执行下列长内容规则。授权记录及后续管理表格在无数据、筛选无匹配时仍保留表头和列预算，空态放在表头以下的表体区域；保留相同结果外框及框内底部分页。

### 全列长内容

| 字段类型 | 列表展示 | 完整内容入口 |
| --- | --- | --- |
| 题目、申请事项、资源名称 | 主标题一行省略 | 桌面悬停提示，记录详情保留全文 |
| 原因、用途、范围说明 | 与标题合排时辅助文字一行省略，独立描述最多两行 | 记录详情完整展示并保留换行 |
| 姓名、部门、业务范围 | 在指定列宽内单行省略 | 悬停辅助查看，鼠标和键盘均可打开记录详情 |
| 申请编号、来源编号、连续英文 | 单行省略，显示节点受列宽约束 | 编号或查看入口打开整条记录，详情内连续字符串可断词并可选择复制 |
| 状态 | 使用受控枚举文字与匹配的列宽 | 完整保留状态含义 |
| 日期、时间 | 使用固定格式和足够的列宽 | PC 窄窗口保留列宽，通过表格区域横向滚动查看完整日期与时间 |
| 金额、数量、比例 | 统一精度、单位和数值对齐，列宽覆盖有效数字 | 表格设置适合字段的最小宽度，横向滚动查看完整值 |

截断只作用于展示节点。搜索使用原始字段，详情从同一条原始记录取值。内容通过文本节点渲染，包含方括号、尖括号和换行时仍按原文显示。

桌面双行记录由标题 24px 行高、辅助文字 16px 行高和上下各 12px 内距组成，保持约 64px 的行密度。字段超过预算后显示省略号，完整记录入口仍可操作。原生悬停提示用于快速核对，鼠标和键盘均有明确的记录详情入口。

规范样张的人员、时间、状态、操作列预算分别为 128、176、112、224px，主事项保留至少 240px，表格最小宽度为 880px。PC 窄窗口在表格区域内横向滚动，表头与表体始终按同一列预算对齐。字段列名保留，完整内容由“查看”或来源编号入口打开。

记录详情采用统一的 24px 内距、8px 标签间距和 16px 字段间距。正文保留换行，连续英文和编号允许断词；内容超过视口时在详情内部滚动，关闭后焦点返回触发按钮。

### 操作列

操作列先确定优先级和列宽，再决定可见数量。桌面保留一至两个最常用的短文字操作，其余放入“更多操作”。操作来自当前用户权限和记录状态，办理后同步更新可执行项。

| 项目 | 规则 |
| --- | --- |
| 优先级 | 查看、处理等常用操作前置，低频操作收纳进更多 |
| 可见数量 | 确有多个业务动作时前置一至两个常用操作，其余按需收纳；无其他动作时省去更多入口 |
| 操作列宽 | 按完整按钮文字、8px 间距和单元格内距计算；当前多操作样张为 224px |
| 对齐 | 同列使用相同次序、同一行排布，按钮文字完整可读 |
| 溢出 | 列宽不足时收纳次要操作，保持固定的表格行密度 |
| 文字与图标 | 文字 14px，线图标 16px，同一语义使用同一图形与线宽 |
| 动作样式 | 查看采用主蓝，复制等次要动作采用中性色；同列使用同一组组件 |
| 交互面积 | 行内文字操作高 32px、左右内距 8px；更多入口使用 32 × 32px 省略号按钮，保留可访问名称及展开状态。表单与分页控件仍为 40px |
| 菜单层级 | 使用原生 popover 顶层浮层，滚动容器不会裁切菜单 |
| 状态反馈 | 复制实际成功后才显示已复制；失败保留查看全文及手动复制入口，办理反馈遵循真实执行状态 |

当前规范样张使用查看全文、复制编号及更多复制操作演示多按钮布局。实际审批、执行、撤销等动作按业务页面配置，危险操作的确认和后果说明按产品规则提供。键盘可打开更多操作、逐项访问并关闭浮层，关闭后焦点回到相应入口。

操作列预算包括按钮本身、相邻间距和单元格内距。当前两个文字按钮与省略号按钮，加上两处 8px 间距，需要约 168px 的净宽；再计入单元格左右共 40px 内距，采用 224px 列宽保留余量。

更多菜单采用宽 200px、四边 8px 内距、8px 圆角、1px 浅边框和轻阴影。菜单项高 40px、左右内距 12px，16px 图标与文字相隔 8px；图标、文字分别沿同一纵轴排列。悬停和键盘聚焦均有浅底反馈，焦点轮廓保持可见。

浮层默认与触发按钮右边对齐，垂直相距 8px。下方空间不足时向上展开，距离视口边缘至少 16px；菜单过高时仅菜单内部滚动。鼠标可点击选项，键盘可用 Tab 逐项访问，Escape 关闭后焦点回到触发按钮。滚动相关内容区域或调整窗口时收起菜单，避免浮层脱离对应记录。

PC 窗口变窄或浏览器缩放后，表格仍保留列结构、字段名称和 224px 操作列预算。横向溢出由表格区域承接，来源记录及全部操作入口可通过鼠标和键盘到达。分页位于表格横向滚动区域之外，位置和操作保持稳定。

表头、表体、空态、面板内留白和分页共用一个完整外框。分页位于外框内部底部，与结果等宽，通过一条分隔线建立关系。桌面正文溢出时仅内容区滚动，页脚位置稳定。

### 详情、折叠区与处理记录

- 详情标题区、正文区和操作区使用同一组 24px 内距。
- 字段标签到值使用 8px，字段之间使用 16px，独立章节之间使用 24px。
- 折叠栏高 48px，左右 24px，展开内容四边 24px。
- 时间线每条事件的时间与办理人使用 12 / 18px，事件正文使用 14 / 22px，事件之间为 16px。
- 操作区的主要按钮、次要按钮与表单内容采用相同的阅读轴。

## 数据状态与适配

有权访问的表格在零数据、无匹配、单条、多页、加载、失败与办理后状态变化时使用相同表头、列预算、外框和间距。空态内容在表头以下的表体区域居中，以图标、标题、说明和实际可执行的下一步组成，内容组间距采用 8 / 16px，分页继续属于面板页脚。加载与失败在表体明确反馈，不替换成“暂无数据”。

无权状态先于表格渲染处理。受限列、记录和数量不展示，页面给出允许公开的访问反馈及去向；不能用“共 0 条”或正常空态代替权限拒绝。

PC 采用统一工作区模式。顶栏、侧栏及外层视口稳定，结果内容按余高分配，真实溢出区域滚动。极矮窗口采用工作区单层滚动，具体边界通过原型验证确定。侧栏在各 PC 窗口宽度下保持可见，表格以最小列宽和区域内横向滚动承接空间不足。

| CSS 视口宽度 | 规则 |
| --- | --- |
| 1280px 及以上 | 侧栏 216px，工作区四边 24px，查询按栅格排布 |
| 1024–1279px | 侧栏和工作区边距保留，查询整组换行，表格按最小列宽在区域内横向滚动 |
| 小于 1024px 的 PC 窗口 | 保留侧栏与表格列结构，工作区承接缩小后的可用宽度，必要的横向滚动限制在表格内 |

## 实施与验收

实现时先建立共享 token、后台外壳和结果面板，通过 `RecordControls` 挂载查询、日期范围与分页组件，通过 `RecordTable` 渲染表格骨架，再让页面选择既定模板与密度。新增页面从这些组件组合，组件的尺寸与状态行为在共用定义中完成。规范样张与业务页调用同一渲染入口，页面重绘时清理旧挂载及遗留浮层，保留生效条件和合理焦点。

同一页相邻空间由父级排布控制，所有标准尺寸来自 token。需要新增变体时，先在本规范列出适用场景、取值和其他页面影响，再进入页面实现。

视觉验收使用相同视口、相同状态并排核对。

1. 两个列表页的标题顶边、工作区四边、查询卡内边和结果框起点一致。
2. 同一张卡片上下内距相等，左右内距相等。相邻组件间距仅计算一次。
3. 表头与表体列边对齐，分页和结果面板等宽，页脚上下留白对称；无数据和筛选无匹配时也保留表头。
4. 使用 0、1、10、11、100 条以上隔离记录，检查列预算与外框一致性、自然行高、翻页和结果总数。
5. 展开长用途、申请资料和处理记录，检查阅读轴、章节间距和最后内容可达。
6. 检查 PC 的 1024、1280、1440、1536px 宽窗口，以及常见的 768、900px 高窗口。
7. 检查键盘焦点、输入错误、查询与翻页、当前菜单、125% 缩放与小高度窗口。
8. 测量 token 的实际使用值。标准间距与定义一致，接受 1px 以内的绘制误差。
9. 将长中文标题、数百字原因、长姓名与范围、无空格英文和长编号同时放入各列，核对行高、列宽、全文可达与搜索；鼠标和键盘均须能查看完整原文。
10. 分别检查单个、两个和需要收纳的多个行操作，核对 224px 操作列预算、完整文字、顺序、更多浮层、鼠标与键盘操作，以及办理后的可执行项变化。

## 当前原型的统一套用与复核清单

本轮统一调整访问申请、授权记录及规范样张，以下项目须在修改后使用相同 PC 视口与数据状态复核。此处记录修改目标，浏览器结果另记。

- 外壳使用 64px 顶栏、216px 常驻侧栏，工作区四边及主要区块间隔统一为 24px，两页标题、查询区和结果框外轴一致。
- 查询与分页通过 `RecordControls` 统一挂载本地 Element Plus 2.14.0，表格框架使用 `RecordTable`；规范样张调用相同入口。核对中文 locale、`large` 40px 尺寸及库原生交互，关键词、状态和日期保留隐藏的可访问标签，日期空值显示开始、结束占位，待本轮实页复核。
- 结果区省去重复列表标题及数量条，分页仅集中显示一次“共 N 条”，并包含于完整结果外框底部。
- 授权记录采用 48px 表头、64px 双行密度，0 条、少量和多条状态以及筛选无匹配均保持表头、列预算及完整结果外框，待本轮实页复核。长内容使用摘要与完整详情入口；PC 窄窗口保留侧栏和表格列结构，横向溢出限制在记录区域。
- 行操作、图标和更多菜单按共用组件核对尺寸、色彩、对齐、悬停、键盘焦点及浮层避让；复制反馈须与实际结果一致。
- 使用空数据、单条、多条、超长内容和长详情核对滚动归属，并回归查询、分页、审批、权限与详情返回行为。
