## 实现链路

GovernanceWorklist 经 governanceWorkflow API 发起操作；GovernanceTaskServiceImpl 发现并排队，GovernanceTaskWorker.tick 调用后台处理。字段任务进入 FieldSemanticServiceImpl，业务知识任务进入 BusinessKnowledgeServiceImpl；复查由 SemanticCheckServiceImpl 提供。

## 关键约束与关联影响

AI 结果是候选，不能覆盖人工确认和审核。新修订通过不等于原负向反馈已结案，后者见[反馈与使用档案](反馈归因与使用档案.md)。发布与 build 生效继续遵守知识/RAG 模块合同。

必要知识按对象类型与适用性核对，不强迫不适用的单位、币种、枚举或关系；未知项保留待确认。受控事实变化回到修订/审核链，不覆盖人工正文。动态参考分绑定对象、来源与语义修订，不给公共标签复制权威分；低分的必需字段应澄清或复核，不能换业务含义凑答案。

资料不足不由系统自证业务真值。双人强制审核、业务样本读取、任意规模调度或自动业务回放都不是旧草案附送的已实现能力或操作授权。

## 当前前端工作面

任务以精确对象、阶段/原因和下一步为主，仍由Java提供分页总数、处理状态和能力。任务操作按单独的查看、检查、维护及业务知识能力核验，暂停不额外要求知识维护权；部分复查不报整批完成。五个Tab保留原范围：源级反馈/旧来源记录不依赖快照，依赖快照的子工作面先验证上下文。

字段解释由「候选与草稿 / 人工审核 / 来源与历史」承载，左侧始终区分原始注释与当前有效解释。基本/进度为field:view，明细/收录另需knowledge:view；术语为field:view+glossary:view，不附加knowledge:view。表/字段目录仍需metadata:view，最小治理角色合同缺口明确无权提示，不向后端隐式补权。

每次保存冻结表单expectedVersion，审核冻结revisionId和审核版本；普通重试保留未保存输入。新版本回读不会静默抬高脏表单基准，旧保存回读不能将新字段输入标为已保存。审核展示真实已保存待审修订，409保留资料引用与意见。确认框、异步读取和批量弹窗按对象/范围/代次隔离；切换或无效URL取消旧写动作。来源批量确认保留逐项版本、失败原因与未完成选择。知识链接只做同源导航，审核和复查不触发文档发布或RAG。
