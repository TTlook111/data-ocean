## 实现链路

图生成候选 SQL 并做本地 AST 预检 → Java authorize → Python 按精确授权快照再校验 → Java 执行状态确认 → Python 只读执行 → Java protectResult → Java complete。已受保护尝试可复用原结果，但必须匹配当前 attemptId 与 SQL hash；以实际调用处核对失败分支。

## 关键约束与关联影响

不能放宽 COMPLETED 的 attemptId、精确 SQL hash 与 PROTECTED 合同。修改字段保护时核对投影、过滤、连接、分组排序与历史 SQL/CSV 读取，而不只检查结果表格。

### 协议、来源与使用位置

Python S1 请求模型只接受 `IAM-SIMPLE-1`，禁止额外字段及旧别名；安全字段不得缺省放行。Java 生成请求级授权快照；记录条件原值只在一次性 `executionBindings` 中用于参数化执行，不进入任务授权快照、查询上下文或模型输入。Context Firewall 同时约束 schema、RAG/兜底、样例、术语、历史与摘要，不能借另一种上下文把隐藏字段或不完整来源送入模型。

`usage` 八个协议值与 Java 枚举保持一致：`PROJECTION/FILTER/JOIN/ORDER/GROUP/HAVING/FUNCTION/SUBQUERY`。当前 AST 明确强制前三种使用位置，不能将“协议接受八值”写成“已分别强制八种权限”。Java/Python 与前端的默认使用集合同步；服务端注入的记录条件由连接语义决定位置，不靠请求方声明获得授权。

### SQL 作用域与参数化条件

- 表别名、CTE 和派生表只在所属作用域解析；内层同名别名不能改变外层真实来源。跨数据库或目录限定引用拒绝。
- 集合运算以第一分支确定输出列名，按列位置汇总全部分支的来源；嵌套集合、CTE 和派生表同样处理，任一方向的分支列数不一致均拒绝。无法证明的来源不能靠首分支或输出别名补足；明确 COUNT 等技术形状仍按现行专门校验，不能恢复旧的无来源宽松路径。
- 记录条件只注入真正读取物理表的作用域。LEFT JOIN 右侧条件放入已有 ON；RIGHT JOIN 保留侧条件放 WHERE、FROM 侧放相应 ON；无 ON 的连接不凭空补 ON。需要注入条件的 FULL JOIN 拒绝。
- 同表授权仅在单条授权完整覆盖本次使用字段时参与行条件合并；部分字段授权不能扩大其他字段的记录范围。原始 SQL 先按 usage 校验，再参数化重注入；执行前严格核对重写 SQL 与 `validatedSql`，不得另换 SQL 或绑定参数。
- 行数上限检查最外层 LIMIT，不能用子查询或集合分支 LIMIT 代替；任何 LIMIT 节点超过上限都拒绝，应用层仍按当前上限截断并标记。

### 当前权限与读取通道

任务、历史、SQL、CSV、反馈与 SSE 复用当前权限复查及最终保护路径，不能从持久化结果直接组装 SSE 载荷。撤销 `query:use` 后，即使仍有数据授权也不得返回结果；读取拒绝只公开安全错误。失败或取消任务没有结果字段时保留真实终态与错误，不能误报为权限变更。输出列的多来源脱敏合同见[字段保护](字段保护与脱敏候选.md)。
