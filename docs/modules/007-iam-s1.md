# 007 IAM-SIMPLE-1 权限

> 文档类型：现行模块说明；核对日期：2026-10-17；代码基线：`619bca6`。本轮静态核对，运行验收见[项目现状](../项目现状.md)。

## 管理员需要理解的模型

角色管功能；部门默认数据与个人/角色数据授权管可查数据；后台角色绑定的负责源管管理范围。同一个角色绑定上的功能与负责源必须同时满足，不能把不同绑定的功能与源做并集相乘。

系统管理员负责后台管理，不自动获得业务查询数据。查询、查看 SQL 和导出功能在角色配置，数据授权不重复这些开关。记录条件、有效期与禁止规则按需展开，不重新引入旧策略数字优先级或复杂委派。

## 必须保留的决定

- 授权只读独立 S1 事实；不读取、映射、回填旧角色、旧 JWT 权限或旧缓存。没有双读双写或拒绝后的旧权限回退。
- B6 已退休旧权限专用链，不能按历史 RBAC/Policy 方案恢复。账号、部门、资产、会话、审计等业务数据继续保留。
- 54 项固定功能目录是消费边界，前端不能自造权限码。
- 注解切面 `IamS1AuthorizationAspect`必须同时保留 `@Aspect`与 `@Component`；显式 Guard 的专用 S1 接口仍需保留。
- 当前仍使用 JWT 黑名单与令牌版本。没有替代机制的执行证据前，不删 tokenVersion；历史冻结清单里的目标名不是已实现事实。
- 跨环境迁移、bootstrap、授权初始化和 B6 删除必须独立核对；旧手册中的准备轮授权不延续到今天。

## 执行和读取

Java 在提交、每次候选 SQL 执行前、最终结果保护以及任务/历史/SQL/CSV/反馈/SSE 读取时按相应动作检查当前权限。Python 消费请求级绑定快照，执行检索过滤、SQL AST 和参数化行条件；不维护第二套权限事实。

前端通过能力摘要控制可见性和提示，能力摘要失败要显示错误。管理 `/api/iam-s1/datasources`与业务 `/api/iam-s1/query-resources/datasources`用途不同，不混用来扩大查询范围。

字段解释继续使用现有功能码：查看 `governance:field:view`，创建/编辑/AI/采纳/提交/撤回需要同一数据源上的 `governance:field:manage` 与 `knowledge:manage`，审核需要 `governance:field:view` 与 `knowledge:approve`，撤销需要 `governance:field:manage` 与 `knowledge:approve`。引用已审核术语另需 `glossary:view`；语义复查用 `governance:check`，问题处理用 `governance:issue:manage`。本轮没有新增权限码或改账号绑定；前端显隐不取代 Java 每项实际源校验。
