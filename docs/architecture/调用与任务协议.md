# 调用与任务协议

Java 与 Python 使用 HTTP JSON 传递命令和受控工具调用，任务由后台执行器运行，进度与可见内容通过 SSE 推送，断线后通过事件重放和任务快照恢复展示。任务生命周期独立于 HTTP 请求和 SSE 连接，连接中断不触发重新执行。

应用职责见[服务职责与数据流](服务职责与数据流.md)，存储、用户会话请求层级及 LangGraph 线程映射见[存储与会话状态](存储与会话状态.md)。本页以问数说明任务生命周期；治理生成、索引构建等 AI 任务复用通信、幂等、事件与接管规则，各自业务状态和预算仍由所属模块定义。协议确认不表示真实接口、执行器或故障恢复已经实现。

## 通信通道

| 方向 | 方式 | 用途 |
| --- | --- | --- |
| React → Java | HTTP JSON | 创建请求、补充回答、取消、重试解释和查询任务快照 |
| Java → Python | 内部 HTTP JSON | 启动、恢复、取消及查询 AI 任务 |
| Python → Java | SSE 事件流 | 阶段进度、澄清、解释片段及任务变化通知 |
| Python → Java | 受控 HTTP JSON | 读取依据、提交成果、申请 SQL 执行和查询执行状态 |
| Java → React | SSE 事件流 | 经当前权限与输出限制核验后的用户可见事件 |

Java 通过 UserContext 从可信认证上下文取得当前用户，核对用户、会话和请求归属。内部调用同时核验服务身份和任务资格，不因位于内网而跳过认证，也不信任调用方自行填写的用户编号。登录会话、服务 JWT、身份传递及凭据文件注入统一遵守[认证方案](认证与身份上下文.md)，具体接口与运行配置随实现验证。

执行与交付放行、权威权限版本、撤权中断、秘密引用及审计失败处理统一遵守[安全执行与审计](安全执行与审计.md)。事件重放和任务恢复不能复活已失效授权，命令接收成功不代替安全校验。

普通 JSON 请求按[Java 参数细则](../backend/编码规范.md#参数与请求体)使用 DTO、Query 和明确的响应类型；SSE 使用事件协议，不套用普通 JSON 返回包装。接口须支持命令与状态查询独立使用，订阅事件本身不启动或重启任务。

## 任务接收与后台执行

1. Java 核对身份、范围、请求条件及可接受的资源限额，在 MySQL 中一致保存请求和待派发状态，返回 `202 Accepted` 与 `requestId`。前端展示实际派发状态，不把接收请求当作已开始或已完成。
2. Java 后台向 Python 派发命令。Python 完成接收记录和 Redis Streams 入队后确认接收；接收记录与入队须保持一致，失败时不能返回已接收。
3. Python 任务执行器从队列取得任务，核对当前执行资格并运行 LangGraph。任务接收、HTTP 响应及 SSE 输出均不承担整个图运行的生命周期，不只依赖 FastAPI 进程内 `BackgroundTasks` 保存待执行工作。
4. Python 通过 Java 业务接口提交关键成果与业务状态，Java 校验并写入 MySQL，再提供结果或变更通知。业务写入与对应任务状态保持一致；事件发布失败时通过已提交记录补发或任务快照核对，不以 SSE 是否送达作为唯一完成依据。
5. 等待用户澄清时保存检查点和等待状态，释放执行资源；补充命令再次进入待执行流程，沿用原请求及 `thread_id`，按任务上下文继续。
6. Java 重启后继续核对待派发任务；Python 执行器退出后依据队列待处理记录、执行资格和检查点接管。Stream 消费确认不等于业务完成，待处理消息不能直接作为从头重跑的依据。

Redis 中的任务触发与队列不替代 MySQL 中的业务请求、派发事实和数据库执行记录。Redis 持久化与隔离继续遵守[存储边界](存储与会话状态.md#redis-检查点的持久化与恢复边界)。

## 标识与一致性

| 标识 | 用途 | 重复与恢复规则 |
| --- | --- | --- |
| `requestId` | 稳定业务请求编号，问数时同时作为 LangGraph `thread_id` | 网络重试和合法恢复保持不变；新一轮问数、重新查询及到期后继续另建请求 |
| `commandId` | 一次启动、补充、取消或重试解释命令的幂等编号 | 网络重发沿用原编号和内容，返回原接收结果；同编号不同内容拒绝处理 |
| `runVersion` | 当前有效执行代次 | 接管恢复时递增，旧执行器不能继续推进业务状态、取得新的执行许可或交付迟到结果 |
| `eventId` | 所属事件流中的稳定游标 | 重放保持原编号，接收方按编号去重；内部与前端事件流各自管理游标 |
| `executionId` | Java 管理的数据库执行任务编号 | 恢复和状态核实保持原关联；同编号的 SQL 与参数不可变，不能因命令重发或执行代次变化新建一笔 SQL 执行 |

命令和事件允许重复递送，由接收方幂等处理；不能以网络恰好递送一次作为正确性前提。业务状态变更和工具调用同时检查请求状态、执行代次与必要修订，迟到响应不得覆盖新状态或已确定终态。Java 管理的已有数据库任务仍按 `executionId` 核实真实结果。

正常产生新的 SQL 候选时，按本次候选重新核验并建立对应执行任务；原执行任务状态未知时先核实，不能借新候选、新会话或新编号绕过重复执行保护。

## 流式输出与断线恢复

事件覆盖阶段变化、需要澄清、结果可用、解释片段、解释结束、取消进度和任务终态。每条事件关联 `requestId`、`runVersion` 和稳定 `eventId`；具体事件名称、字段及顺序约束随接口结构确定。

- Java 订阅 Python 内部事件，再生成面向前端的受控事件，不将内部事件原样透传。订阅、重连、回放和内容交付均核对当前身份、归属与权限；撤权后阻断相关输出。
- 前端保存最后收到的 `eventId`，重连时携带 `Last-Event-ID` 或客户端支持的对应游标。Java 与 Python 之间采用相同的重放原则，各自按所属事件流游标补发；接收方去重并按顺序应用事件，参见 [SSE 重连游标](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-last-event-id-header)。
- 短期事件和文字片段缓存在 Redis，关键状态、结果和最终答案保存在 MySQL。游标已过保留窗口时返回当前任务快照，前端据此恢复展示，不为补齐文字重新执行任务。
- 阶段进度可实时发送，结构化结果核验通过后先交付，解释后续补充。每个解释片段关联明确的解释修订，重复片段不重复拼接；发现缺口时补发或使用完整快照，不能静默保留缺字正文。
- 模型原始文本先经过输出限制核验。可独立核验的完整片段逐步交付；涉及整体语义的限制时，先完整生成、检查，再交付。提示词、内部推理、原始诊断日志及普通用户无权查看的 SQL 不进入普通事件流。
- 解释生成中断后的重生成使用新的解释修订，替换未完成草稿；不能把重新生成的文字继续拼到旧修订上，也不承诺从模型中断的某个字继续生成。
- 心跳与有限缓冲用于保持连接、发现断线和控制慢客户端。缓冲不足时合并可合并的进度或结束订阅，由客户端重连、补发或取快照；慢连接不能阻塞后台任务。
- SSE 连接关闭不代表业务结束。建立连接前的错误通过普通 HTTP 响应表达；开始流式响应后使用可披露的错误事件及任务状态表达，连接已断开时由快照查询核实，不能假定错误事件必达。

前端流订阅复用 Cookie 登录会话，Java 订阅 Python 内部流使用服务 JWT；凭据不放入 URL。持续交付、认证失效及重新订阅统一遵守[SSE 认证规则](认证与身份上下文.md#sse-认证与失效)。SSE 重连恢复的是展示，不自动触发图恢复、重试解释或重新查询。

## 任务取消与完成竞争

取消区分请求取消和确认停止，不将 HTTP 返回成功当作模型或数据库已经停止。

1. Java 核对归属与当前状态，在 MySQL 记录取消意图，并阻断该请求的新工具执行与后续结果交付。
2. Java 向 Python 发送可重复提交的取消命令。HTTP 超时或确认丢失时查询原命令状态，必要时重发同一命令，不撤销已经保存的取消意图。
3. Python 停止后续节点并尝试中断在途模型调用；Java 对运行中的 SQL 发起取消，并继续核实实际执行状态。
4. 前端先显示正在取消，收到实际停止确认后更新状态；SQL 或外部调用停止情况未知时保留待核实事实，不声称已停止。

Java 使用业务状态版本处理取消与完成的竞争，避免双方各写一个终态。先记录取消意图并阻断交付后，迟到的运行事件或结果不能再次向用户交付；执行已经发生的事实仍如实记录。结果已经交付后，停止只影响后续解释，不覆盖原结果、查询时间或已交付事实。

客户端关闭页面、刷新、丢失 SSE 连接、正常退出或登录过期不等同于取消已接收的后台任务；任务继续核验业务身份、当前权限、状态及预算。账号停用与实际撤权主动阻断受影响任务，用户主动取消使用取消命令。暂停等待、任务到期、权限撤回与主动取消分别按实际原因记录，登录与任务时限不能混用。

## 超时与预算

超时分层管理，HTTP 超时、请求终态和数据库真实状态分别记录。问数预算沿用[产品方案第 6 章](../product/modules/06-query.md)第 9 节运行状态与数据契约、第 14 节运行配置与实施要求；下表引用其初始预算，不另维护一套业务配置。

| 层次 | 已确认的处理原则 | 初始值或待定项 |
| --- | --- | --- |
| HTTP 命令 | 秒级响应；超时先查是否接收，再重发原 `commandId` | 连接与响应超时具体数值待容量评估 |
| SSE 连接 | 心跳、断线检测和重连；断流不直接判任务失败 | 初始心跳 15 秒，代理及连接参数须配套验证 |
| 问数活动处理 | 所有节点、回环和重试共享剩余活动预算 | 方案初始总时限 120 秒 |
| SQL 执行 | 受单次上限与请求剩余总预算共同约束；超时后尝试取消并核实 | 方案初始单次默认 30 秒 |
| 等待用户澄清 | 保存检查点、释放执行资源、暂停活动计时；等待有效期继续计时 | 方案初始 30 分钟，到期原请求终结，继续时新建关联请求 |
| 排队与模型单次调用 | 分别设上限，实际处理不得越过剩余活动预算，不形成无限等待 | 具体数值、排队与执行容量待定 |

恢复不重置累计次数、已耗活动时间或原意图的固定时间区间。网络重发不因重复确认而额外计作新 SQL 候选，实际调用和重试仍受资源、次数及总时限约束。临时网络错误或模型限流只在允许重试及剩余预算内退避重试；无进展的相同失败提前停止。

预算耗尽后停止后续调度与交付，尝试取消在途操作并保留真实执行状态。结果已经交付后的解释超时只更新解释状态，不能将已交付结果改写为查询失败。

## 失败恢复

| 故障位置 | 处理方式 | 保留边界 |
| --- | --- | --- |
| 前端断线或刷新 | 重新订阅并读取任务快照 | 不创建新请求或重发 SQL |
| Java 重启 | 读取 MySQL 中待派发及在途任务，核对接收状态、恢复事件订阅或获取快照 | 已提交请求、成果和执行事实不依赖原流连接 |
| 启动或补充命令响应丢失 | 查询接收状态，必要时重发原命令 | 同一命令不得重复启动或重复消费补充 |
| Python 执行器退出 | Java 核验归属、请求与恢复资格，取得新的执行代次，从 Redis 检查点继续 | 沿用原请求和 `thread_id`，拒绝旧代次继续推进，不清零预算 |
| SQL 已完成但回调丢失 | 按原 `executionId` 取得真实状态与结果 | 不重新执行，不更改原查询时间 |
| 模型临时限流或网络错误 | 在剩余次数和时间内退避重试 | 不无限循环，不自动切换未配置提供方 |
| 解释生成中断或失败 | 复核当前权限与结果有效性，复用原结果；需要重生成时使用新解释修订 | 不重发 SQL，不拼接不同修订，不覆盖已交付事实 |
| 权限撤回、用户取消或等待到期 | 停止原执行流程并按实际原因记录 | 不因 Redis 中仍有检查点而自动恢复 |
| Redis 检查点暂不可用或写入失败 | 停止依赖该检查点的流程推进，保留实际状态；服务恢复后在仍有资格时核验续作 | 不降级为仅内存运行，不返回虚假的可恢复或完成状态 |
| 检查点不可恢复地丢失 | 核实已有执行事实并安全结束；后续按新关联请求办理 | 不假装能从原节点续作，不盲目重跑已发生的数据库操作 |

LangGraph 可能重入整个节点，外部调用的幂等仍由稳定任务编号和业务端核实保证，参见 [LangGraph 重试与幂等](https://docs.langchain.com/oss/python/langgraph/fault-tolerance#retry-boundaries-and-idempotency)。图恢复与事件重放分别处理，不能把可补发事件等同于可重新执行业务。

知识发布、回退与 Embedding 切换后的在途绑定按[知识版本与索引一致性](知识版本与索引一致性.md#在途查询与产物保留)处理。普通切换不使恢复任务偷偷改用最新版，暂停、禁止、撤权及模型停用仍按当前状态阻断。

## 状态表达与待落实项

问数请求终态沿用方案已有八种互斥终态。派发、当前图阶段、取消进度、数据库执行、结果交付和解释状态分别表达，不混成一个成功或失败值。特别保留正在取消、执行状态未知、等待用户，以及结果已交付但解释失败等可核实状态；具体原因只向有权限者披露。

协议与[认证基线](认证与身份上下文.md)已确定。仍需落实逐接口路径、DTO 与事件结构、错误码、认证过滤链与配置、执行代次与租约控制、具体重试参数、Redis 队列和事件保留参数、代理配置及容量；这些是实现细化项，不表示协议或认证方式仍待重新选择。

实现验收至少覆盖重复命令与内容冲突、丢失接收响应、事件重复及游标过期、慢客户端、取消与完成竞争、Java/Python 重启接管、旧执行器迟到事件、SQL 完成但回调丢失、解释重生成，以及 Redis 写入失败和检查点丢失。静态文档核对不替代上述真实运行验证。
