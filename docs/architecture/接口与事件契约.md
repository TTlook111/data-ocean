# 接口与事件契约

本页细化已确认的[调用协议](调用与任务协议.md)、[认证](认证与身份上下文.md)和[安全边界](安全执行与审计.md)。状态为设计首版，尚未接入正式服务。模块接口引用本页；公共字段、错误码和事件信封只维护一份。模块实施顺序见[详细设计与验收](../backend/详细设计与验收.md)。

## 路径与类型

| 项目 | 契约 |
| --- | --- |
| 浏览器 API | `/api/v1`；前端统一访问 Java |
| Java 内部工具 API | `/internal/v1`；仅接受获准 Python 服务身份及可信任务关联 |
| Python 任务 API | `/internal/v1/tasks`；仅接受获准 Java 服务身份 |
| 字段 | JSON 使用 lowerCamelCase；数据库使用 snake_case；禁止未知输入字段，避免误以为状态或权限字段已被采用 |
| 标识 | BIGINT 实体 ID 对外为十进制字符串；请求、命令及事件 UUID 为规范小写字符串；不得转换为 JavaScript Number |
| 修订与版本 | `version`、`revision`、`runVersion` 为正整数，物理 INT；`version` 是可变聚合的并发版本，`revision` 是不可变内容修订，不能互换 |
| 时间 | 时刻返回带 `Z` 的 ISO 8601 UTC 字符串，精度毫秒；数据库 DATETIME(3) 按 UTC 读写。日期用 `YYYY-MM-DD`，业务时区另传 IANA 标识，不把日期转成 UTC 午夜代替业务日 |
| 数值 | 金额、需要精确计算的小数用十进制字符串及明确单位；普通计数为安全整数，超界计数用字符串；NULL、0、未知分别表达 |
| 空值 | 返回约定的可空字段用 `null`，集合用 `[]`；PUT 是声明字段的完整替换，遗漏必填字段报错；不以空字符串隐式删除秘密 |
| 缓存 | 身份、受限详情、任务和结果返回 `Cache-Control: no-store`；前端业务缓存仍须在失权时清理，不能恢复旧浏览器缓存绕过当前核权 |

示例仅说明结构，不代表实际业务接口已实现：

```json
{
  "code": 200,
  "message": "人员已创建",
  "data": { "id": "12001", "version": 1, "commandId": "19145d6b-b416-423d-a7b0-3c4e8d783927" }
}
```

普通 JSON 使用既定 `Result<T>` 的 `code`、`message`、`data`；`code` 沿用基础代码的整数类型，成功为 `200`；具体失败码见下表。HTTP 状态表达协议结果，业务码表达具体原因。创建成功 201，异步接收 202，普通读取与同步修改成功 200；接收不等于执行完成。SSE 与文件不套 Result。`X-Trace-Id` 为服务端生成或校验后的诊断关联，和业务 `requestId` 分开，不含秘密。

## 列表与查询

`PageQuery` 接收前端传入的 `pageNum`、`pageSize`、`sortBy`、`isAsc`（布尔值），后端不把界面的条数选项作为请求白名单。沿用现有分页类的兜底及保护：缺省或小于 1 时页码取 1、每页取 10，单页上限 100，偏移量溢出拒绝；合法分页参数以实际请求为准。前端初始页码及每页条数按[界面分页规则](../frontend/交互规则.md#分页与排序)维护并随请求发送。模块声明排序白名单及默认顺序，最后以稳定 ID 消除同值排序歧义。过滤、权限范围、总数和分页使用同一条件；无权限返回拒绝，不返回零条假装空列表。

`PageVO<T>` 为 `{items:T[],total:number,pageNum:number,pageSize:number}`。筛选结果减少导致页码越界时，服务端在同一一致性读取中返回最后有效页；零条时 pageNum 为 1。前端应用响应中的页码。`total` 超安全整数的情况不在普通后台列表容量承诺内，发生时返回容量错误，不能静默丢精度。

文本查询只匹配模块声明字段，去首尾空白后按字面包含匹配；SQL 的 `%`、`_` 等不作为用户通配符。组合条件取交集。日期筛选使用 `fromDate`、`toDate` 与 `timeZone`，两端均为界面选中的日期；服务端转换成 `[首日开始,末日次日开始)`，按声明的时间列查询。排序字段不能直接拼入 SQL。

人员、角色及审批人的联想选项接口与列表共用权限和可见性规则；选项只返回必要身份、状态与版本。申请人不通过选项接口获得无权表字段、对象数量或连接信息。

## 修改、核对与幂等

1. 可变对象提交 `expectedVersion`。角色分配等多对象操作同时提交所选角色修订。版本不匹配返回 409，保留前端输入，重新读取并核对差异，禁止自动覆盖或静默重试。
2. 管理修改和业务命令使用 `Idempotency-Key` UUID，响应中称 `commandId`。作用域为服务认证主体或当前用户、操作代码和该 UUID；同键不同规范化内容返回 `COMMAND_CONTENT_CONFLICT`。重发前重新认证、核对当前读取资格，不把旧成功响应作为继续访问许可。
3. 同步修改的命令记录、业务变化、审计和 Outbox 在同一 MySQL 事务中提交。异步命令在接收事务中保存业务任务和待派发记录；对方接收丢失先查原命令，不创建新任务。数据库唯一键串行化相同键的并发提交。
4. 命令记录只保存安全的最小结果引用。包含密码的请求指纹采用服务端受控密钥 HMAC-SHA-256，并记录密钥版本；不保存请求正文、明文密码、可离线枚举的普通密码哈希或会话 Cookie。秘密请求不进入通用日志和追踪序列化。登录和本人改密不使用通用成功响应重放；登录重新认证，改密回包不明时按原登录失效事实重新登录。
5. 需要预览的操作使用所属资源的 `/impact-preview`。更新输入为 `{action,expectedVersion,proposal}`，创建预览只有 proposal、没有基础对象版本；proposal 为该动作 DTO 中的拟变更业务字段，不含密码。`ImpactPreviewVO` 为 `{action:string,targetId:string|null,baseVersion:number|null,securityVersion:string,reviewToken:string,changes:ChangeVO[],affected:ImpactCountVO[],warnings:string[]}`；`ChangeVO={field:string,label:string,before:ChangeValue,after:ChangeValue}`，ChangeValue 仅允许该动作白名单中的字符串、布尔、数值、其数组或 null；`ImpactCountVO={kind:string,count:number}`。可见内容按当前权限裁剪。
6. `reviewToken` 是服务端签名的不透明核对凭据，绑定操作者、动作、对象、拟变更摘要、基础版本及依赖版本，短时有效（初始 5 分钟）。提交携带同一 token，服务端重新核验当前依据；失效返回 `REVIEW_STALE` 并重新预览。token 不包含秘密，不构成授权，不替代事务内检查。预览和取消不产生业务变化。
7. 人员角色分配沿用直接保存的紧凑弹窗，不额外增加预览步骤或原因字段；提交所选角色版本和人员版本，服务端完成完整能力与上限检查。敏感恢复、共享角色修改及危险状态操作按既定页面核对。
8. 空变更不递增内容修订或生成重复成功审计；返回当前版本。批量操作必须声明整批事务还是逐项办理；未声明者不得提供批量写接口。

幂等记录保留不能短于对应任务恢复及业务重试窗口；清理后仍须保留防重墓碑或由不可变业务唯一键阻止重办。具体保留期限按[未决部署参数](../backend/详细设计与验收.md#实施前需落实的配置)确定，不能先定 TTL 再容忍重复批准、重复执行或重复发布。

## 错误响应与错误码

失败仍为 Result，`data` 为 `ErrorVO`：`{fieldErrors?:FieldErrorVO[],commandId?:string,retryAfterSeconds?:number}`。`FieldErrorVO={field,code,message}`，field 为已公开的 DTO 字段路径。无对应信息时 data 为 null。`message` 是可披露的中文反馈；内部原因仅进入受控诊断，不把数据库异常、对象存在性或模型原文直接回显。

| HTTP | 代码名称 | code 整数值 | 含义及客户端处理 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_FAILED`  | 400001 | 字段、未知枚举、日期或排序非法；聚焦首个字段，保留输入 |
| 401 | `AUTH_REQUIRED` / `AUTH_EXPIRED` / `AUTH_INVALID_CREDENTIALS`  | 401001 / 401002 / 401003 | 未登录、登录失效或登录凭据不正确；停止重连，清理受限缓存，不自动重放写操作 |
| 403 | `CSRF_INVALID`  | 403001 | 令牌缺失或失效；重新取得令牌并由用户重试，写操作不自动重发 |
| 403 | `PASSWORD_CHANGE_REQUIRED`  | 403002 | 受限改密会话只能完成必要改密和退出 |
| 403 | `PERMISSION_DENIED`  | 403003 | 缺少当前操作能力；不向普通用户披露内部配置 |
| 403 | `GRANT_LIMIT_EXCEEDED` / `PROTECTED_FLOW_REQUIRED`  | 403004 / 403005 | 功能授予越界或必须走受保护流程；不增加数据源／规则白名单上限 |
| 404 | `RESOURCE_NOT_FOUND`  | 404001 | 不存在或不可向当前身份披露；不返回受限对象数量 |
| 409 | `VERSION_CONFLICT` / `REVIEW_STALE`  | 409001 / 409002 | 对象或核对依据已变化，重新读取、核对 |
| 409 | `COMMAND_CONTENT_CONFLICT` / `COMMAND_IN_PROGRESS`  | 409003 / 409004 | 同键内容不同，或原命令尚在办理；查询原命令，不能换键强行重办 |
| 409 | `STATE_CONFLICT` / `REFERENCE_IN_USE`  | 409005 / 409006 | 当前状态不允许，或归档前仍有关联 |
| 409 | `IAM_LOGIN_NAME_EXISTS` / `IAM_ROLE_NAME_EXISTS` / `IAM_DEPARTMENT_CODE_EXISTS`  | 409101 / 409102 / 409103 | 对应管理输入重复；仅向具备相应管理权者披露 |
| 409 | `IAM_LAST_RECOVERY_PATH` / `IAM_DEPARTMENT_CYCLE`  | 409104 / 409105 | 会清空最后有效恢复途径，或组织成环；原事务不变 |
| 409 | `IAM_PASSWORD_UNCHANGED`  | 409106 | 本人新密码与当前密码相同 |
| 400 | `IAM_CURRENT_PASSWORD_INVALID`  | 400101 | 已认证本人修改密码的当前密码错误，定位字段 |
| 409 | `APPROVAL_ROUTE_STALE` / `APPROVAL_SELF_REVIEW`  | 409201 / 409202 | 当前办理责任变化或本人审批，重新分派 |
| 409 | `DEPENDENCY_STALE` / `KNOWLEDGE_NOT_READY`  | 409301 / 409302 | 精确修订或发布绑定不符合当前操作条件 |
| 409 | `TASK_TERMINAL` / `STALE_RUN` / `EXECUTION_UNCERTAIN`  | 409401 / 409402 / 409403 | 任务已终结、旧代次或数据库执行尚待核实，不重新执行 |
| 429 | `RATE_LIMITED` / `CAPACITY_EXCEEDED`  | 429001 / 429002 | 频率或接收容量限制，按 Retry-After 提示；不得把超限命令当作已接收 |
| 503 | `DEPENDENCY_UNAVAILABLE`  | 503001 | 权威认证、平台存储或必要服务不可用，拒绝放行 |
| 500 | `INTERNAL_ERROR`  | 500001 | 未知错误，提示用 traceId 核查，不泄漏堆栈 |

HTTP 错误不是问数八种终态。已接收任务随后发现无权、知识不足或技术故障时，保存其准确业务终态和原因，通过快照及获准事件提供；不能靠一次 HTTP 500 覆盖已交付结果。事件里的 errorCode 使用本目录及模块新增的稳定码；新增码先在所属契约登记，再实现。


## 领域事件与可靠通知

Java 业务变更产生 `DomainEvent`：

```json
{
  "schemaVersion": 1,
  "eventId": "534d44a9-6d2a-45bd-a66d-ef152b99bc1f",
  "eventType": "iam.authorization.changed",
  "aggregateType": "user",
  "aggregateId": "12001",
  "aggregateVersion": 3,
  "occurredAt": "2026-11-16T03:00:00.000Z",
  "commandId": "19145d6b-b416-423d-a7b0-3c4e8d783927",
  "payload": {
    "securityVersion": "18",
    "changeKind": "USER_DISABLED",
    "subjectRefs": [{ "kind": "USER", "id": "12001" }],
    "sourceIds": [],
    "impactMode": "ALL_OF_SUBJECTS"
  }
}
```

`securityVersion` 是 MySQL 单调 BIGINT 版本的十进制字符串；示例版本没有实际运行含义。subjectRefs 是用户、角色或部门的稳定引用，由 Java 按当前关系计算实际影响，不把大量人员快照塞入一条事件。sourceIds 为空时由 impactMode 明确表达全部主体范围或要求回源计算，不能把空集合误作“没有影响”。

Outbox 随业务事务写入；投递允许重复。delivery_state=DELIVERED 只表示已向约定通道完成投递，不表示所有消费副作用完成。消费端按 `(eventId,consumer)` 去重，成功后保存回执；租约到期可接管，旧租约不能确认新工作。不能在 Redis 注销或外部取消尚未完成时提前记消费成功；实际副作用失败继续补偿及核实。事件失败不回滚已经提交的业务事实，也不延迟权威核权生效。通知丢失时通过 Outbox 补投及受影响任务扫描补偿。仍为单 Java 应用加 Redis Streams，不引入新的消息基础设施。

首批事件类型：

| eventType | payload | 消费及补偿 |
| --- | --- | --- |
| `iam.authentication.invalidated` | userId、authenticationVersion、reason | 注销该用户旧会话和关闭旧订阅；每次访问另核权威版本，删除延迟不继续放行 |
| `iam.authorization.changed` | securityVersion、changeKind、subjectRefs、sourceIds、impactMode | 缓存失效、重算实际访问及定位在途任务；未失权的其余来源保留 |
| `iam.organization.changed` | departmentId、membershipUserIds、securityVersion、changeKind | 更新成员关系相关视图、重算直属来源，不继承父部门数据访问 |
| `datasource.availability.changed` | sourceId、version、reason、availability | 阻断或复核受影响流程，不自动解除治理禁止 |
| `knowledge.binding.changed` | sourceId、scopeIds、bindingVersion、operationId | 新请求读取新清单，普通在途保持原绑定；安全限制另行检查 |
| `feedback.completion.recorded` | issueId、completionRound、recipientUserIds、conclusionRevision | 完成轮次与接收人去重，站内提示与业务结案状态分开 |

后三类是模块间事件字段预留，精确枚举和操作条件在对应模块详细设计中补齐后实施；不能据此宣称后续模块逐接口设计完成。

## 任务与 SSE 事件

任务统一信封 `TaskEvent<P>`：`{schemaVersion:1,eventId,requestId,runVersion,stateVersion,eventType,occurredAt,payload:P}`。eventId 为 `<streamEpoch>:<sequence>` 字符串：streamEpoch 是流代次 UUID，sequence 是该流内单调递增的十进制整数；客户端将整个 ID 视为不透明游标。内部和前端流各自管理代次与序号，不复用领域事件 UUID。SSE 的 `id` 与 JSON eventId 一致，`event` 与 eventType 一致；跨流游标不能混用。`stateVersion` 是对应权威快照版本，不能用接收时间覆盖状态。

流代次记录在所属任务的可信元数据中。Redis 事件数据丢失或还原后，不能在原流代次内从头复用序号；无法证明旧游标有效时建立新流代次并发送获准快照，原任务和业务执行不因此重开。请求与内部工作流的具体流元数据落点在对应任务模块物理设计中落实。

| 前端 eventType | payload 类型与字段 | 约束 |
| --- | --- | --- |
| `task.snapshot` | `TaskSnapshotVO`，见下文 | 首次连接、游标过期或展示缺口时发送完整获准快照 |
| `task.phase` | `{phase,phaseLabel}` | 仅进度，不构成执行完成事实 |
| `task.clarification` | `{clarificationId,revision,question,options:ClarificationOptionVO[],expiresAt}` | 选项为 `{id,label}`，不包含无权对象和内部诊断 |
| `task.result.ready` | `{resultId,answerId,answerRevision,deliveredAt}` | Java 已持久保存且完成交付检查；内容经受控结果接口读取 |
| `task.explanation.delta` | `{answerId,explanationRevision,chunkIndex,text}` | 同修订内 chunkIndex 从 0 连续；只发布已核验片段，重放不重复拼接 |
| `task.explanation.finished` | `{answerId,explanationRevision,status}` | status 为 COMPLETED/FAILED/STOPPED，完整解释由答案接口读取 |
| `task.cancellation` | `{status,executionState}` | status 为 REQUESTED/CONFIRMED/VERIFYING，不将未知执行写成已停止 |
| `task.finished` | `{terminal,reasonCode,resultId,explanationStatus}` | 八种终态之一，之后只允许合法的解释状态变化，不能重开 SQL 流程 |
| `task.notice` | `{code,message,retryable}` | 仅披露给当前用户的通知，不代替持久状态 |

`TaskSnapshotVO` 明确包括 requestId、runVersion、stateVersion、streamEpoch、dispatchStatus、phase、terminal（未终结为 null）、reasonCode、cancellationStatus、executionState、clarification（或 null）、resultRef（或 null）、explanation（或 null）、lastEventId（尚无事件为 null）。`resultRef={resultId,answerId,answerRevision,deliveredAt}`；`explanation={answerId,revision,status,text,nextChunkIndex}`，text 为该修订已核验的完整累计正文。快照同样逐次核权，不能把全部内部图状态直接返回。

内部 Python 流使用 `internal.task.phase`、`internal.task.clarification.ready`、`internal.task.artifact.ready`、`internal.task.explanation.delta`、`internal.task.run.finished` 及 `internal.task.notice`，分别携带阶段、已提交的澄清修订引用、成果引用、解释片段及修订、图执行结论或诊断代码。关键成果先通过 Java 内部接口保存，事件引用其 ID；图执行结束不直接设置 Java 查询终态。各工作流的成果 DTO 在对应模块补齐，不能接受无类型的任意 JSON 业务写入。

Java 校验 runVersion、任务及当前资格，必要时核验输出并提交持久状态后，生成独立前端事件；不原样透传内部事件。普通用户流不含 SQL、参数、模型提示词、内部推理、凭据或详细错误栈。

连接和恢复顺序：先核权 → 取一致快照及其游标 → 在该游标后订阅／补发；状态提交到事件写入间的空隙由 Outbox 和定期快照核对补偿。游标过期或不可用时发送 `task.snapshot`，客户端整份替换展示，再处理其后事件；不能因快照与增量竞态丢字。新解释修订替换旧草稿，旧代次／旧修订迟到片段丢弃。心跳用 SSE 注释，不生成业务事件或续长登录空闲时限。

建立流前的拒绝使用 HTTP Result；建立后认证失效时尽力发送可披露通知并关闭，不保证最后事件送达。重连遇到 401/403 必须停止；网络断线只恢复展示，不自动创建任务、恢复图或重新执行 SQL。

## 可核验的实现条件

实现前对模块逐接口定义请求、返回、枚举、校验、权限、版本和错误；实现后从所属服务生成 OpenAPI，校验类型及示例。未知事件 schemaVersion 触发停止应用增量并读取可支持快照，不猜测字段含义。破坏性字段或枚举变化升级协议，不能仅提高 runVersion。

MySQL 约束细节参考 [CREATE TABLE](https://dev.mysql.com/doc/refman/8.0/en/create-table.html) 和 [CHECK](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html)；SPA 登录与退出后重新取 CSRF 令牌参考 [Spring Security CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)。兼容版本仍归各端版本基线，本页不重选框架或复制版本表。
