# 安全执行与审计

Java 统一提供执行前检查和交付前检查，Python 提供语义分析依据，业务数据库使用最小只读权限，关键变更与审计可靠提交。前端、Agent 工具、任务恢复、历史回看和下载均遵守这些边界，模型输出不能产生或扩大授权。

业务依据见[人员权限](../product/modules/02-people-access.md)、[数据源接入](../product/modules/03-datasources.md)、[智能问数](../product/modules/06-query.md)和[模型管理](../product/modules/09-models.md)。应用职责、身份及任务机制分别见[服务职责](服务职责与数据流.md)、[存储与会话状态](存储与会话状态.md)和[调用与任务协议](调用与任务协议.md)。本页维护已确认架构，不表示安全执行或审计服务已经实现和验收。

## 统一校验边界

Java 通过 UserContext 从 Spring Security 认证上下文取得当前用户，核对用户、会话、请求及办理归属。登录会话、退出失效、请求线程生命周期及服务 JWT 统一遵守[认证方案](认证与身份上下文.md)。Spring Security 负责入口认证和功能访问，业务服务及执行、交付入口核验当前数据源访问、适用输出规则、知识有效性、暂停禁止和资源预算。内部服务身份不能替代本次任务的业务资格。

角色控制功能，部门提供直属及直属兼任成员的初始访问来源，不从所属部门自动追加业务记录过滤。用户明确提出的业务条件按原意处理。当前有效授权来源的限制全部适用，同内容去重；撤回一个来源后重算剩余来源，不借其他来源直接解除仍适用的限制。授权者的授予上限、受保护能力及审批归属继续按权限方案核验。

生成前、SQL 生成后、实际执行前、任务恢复及结果交付检查相应边界；运行中响应授权和禁止状态变化。身份、来源、规则或必要依据无法核实时不放行，旧检查快照、有效登录令牌和前端隐藏按钮均不能替代当前授权。

## SQL 只读校验

| 层次 | 执行规则 |
| --- | --- |
| 数据库权限 | 同一数据源沿用一套企业专用只读账号，仅具备必要读取能力，不授予写入、执行过程及向外部文件写出等能力；业务库凭据由 Java 管理 |
| SQL 结构 | 解析完整输入并确认单条允许的只读查询，递归检查 CTE、子查询、UNION、函数和视图，不只检查首个 SELECT 或首条语句 |
| 对象与范围 | 从实际 SQL 识别全部依赖，核对所选单一数据源、可信目录、对象身份、知识版本和当前禁止状态，不信任模型自报对象名单 |
| 参数与标识符 | 值使用参数绑定，表字段等标识符来自可信目录并正确引用，不能将用户输入直接拼成可执行片段 |
| 资源 | 同时限制运行时间、返回行数、字节量、并发、连接和总预算；LIMIT 不代表扫描成本低，限制不能悄悄改变问题的核心计算口径 |

拒绝多语句、写操作、DDL、过程调用、文件导出、锁定查询及有副作用函数。解析失败、不支持语法或真实依赖无法可靠追溯时停止执行，不能忽略未解析片段。出现 `SELECT *` 时根据可信目录展开并重新核验实际字段，不能绕过输出检查。

JSqlParser 为 Java AST 解析的优先评估对象，正式依赖版本及方言覆盖须按适配器验收。解析成功只提供结构分析依据，不等于安全通过。元数据采集由系统受控适配器提供，不以采集能力放行模型提交的任意管理语句。

只读事务与 JDBC 只读标记作为补充，不能代替数据库权限和 SQL 校验；只读标记存在驱动及数据库语义差异，参见 [JDBC 只读说明](https://docs.oracle.com/en/java/javase/21/docs/api/java.sql/java/sql/Connection.html#setReadOnly(boolean))。数据库类型与版本只承诺已适配验证的能力。

Java 固定实际执行 SQL、绑定参数及指纹，关联 `requestId`、`runVersion`、`executionId`、数据源、知识绑定和检查依据。SQL、参数或依据变化后重新检查，不允许检查文本与实际执行文本不同；重试与未知执行状态遵守[任务协议](调用与任务协议.md#标识与一致性)。

校验通过后自动执行，不增加逐条 SQL 人工确认。可等价修复的问题在原意及预算内重生成并完整复检；要求写操作、真实无权、知识缺口、禁止状态、安全失败和预算耗尽分别记录准确原因，不能统称权限不足。

## 输出限制与交付

中文规则沿用既定维护方式，执行分析关联实际规则修订，不由模型改写人工规则。校验依据形成以下关联：输出项、实际来源字段、计算或指标含义、同版治理依据、当前适用规则，以及判定和原因。Python 辅助识别，Java 结合真实 SQL 依赖、可信治理事实和当前规则决定执行与交付。

- 输出限制约束实际返回的信息，受限字段仍可用于 WHERE 等合法条件；治理禁止状态、只读安全和源授权仍约束全部依赖。
- 直接列、别名、计算、聚合、JSON 包装、视图、子查询和联合查询均追溯实际来源与含义。改名或包装不能绕过限制，也不因涉及某字段就机械禁止所有派生计算。
- 输出限制不删除生成和校验所需的必要治理定义；身份证、电话等实际敏感值按本次获准任务、采样预算及模型发送规则使用，不能借 AI 处理扩大读取或外发范围。
- 文字、表格、图表、流式解释、历史和下载使用一致的交付约束，不能只在前端隐藏列。流式片段经过检查再释放，涉及整体语义时先完整生成并检查，具体交付见[流式输出](调用与任务协议.md#流式输出与断线恢复)。
- 命中限制时，在原问题目的内有限重生成；原问题必须返回受限信息时说明无权。必要标签缺失或语义无法判断时，按知识或规则解释缺口处理，停止相关执行，不能把不清楚当作允许。
- 共享规则保存后，所有有效引用使用最新内容。当次审批和查询保留实际采用的快照；历史回看重新核验当前限制，不改写旧事实、不自动重查或沿用原交付资格。

自由中文规则的可靠判定须通过真实题集和边界样例验证。模型给出允许结论不足以放行，必须有可核验依据；不能只靠提示词承诺覆盖任意表达。

普通用户仅看到可披露的原因，不暴露无权对象名称、数量、连接地址或内部规则明细。SQL、详细参数和诊断通过对应权限读取，处理或诊断权限不自动授予全部业务原文。

## 实时撤权与权限版本

1. Java 在 MySQL 中可靠提交授权变化、受影响权限版本、审计及待通知记录，避免变更成功但缺少可核对的审计或通知依据。
2. 变更事件使相关缓存失效，按实际依赖定位在途请求，通知 Python 停止并取消相关数据库执行；账号停用同时处理登录态失效。
3. 工具读取、实际执行、恢复和交付核对当前权威版本，不能等待 Redis TTL 或令牌自然到期。事件用于加速中断，不替代权威版本检查及在途核对。
4. 单项来源撤回后重算其余有效来源，只阻断实际失权或不再满足当前规则的路径；共享规则变化同步作用于全部有效引用，不要求重建知识。
5. 取消未确认时保留中断处理中和真实执行状态，继续核实；权威状态未知或读取失败时不放行，不能只隐藏结果就声称后台已停止。

实现须为撤权提交与执行、交付放行定义明确顺序，旧授权不得继续产生新的放行。重新启用按权限方案复核，不自动续跑旧任务或复活失效下载入口。已有知识快照不提供豁免，参见[在途查询](知识版本与索引一致性.md#在途查询与产物保留)。

已发出的内容无法承诺追回，在途数据库和外部模型调用也须核实实际停止情况。此边界不削弱主动取消要求；取消处理遵守[任务取消协议](调用与任务协议.md#任务取消与完成竞争)。每个入口持续核权的依据参考 [OWASP 授权检查](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html#validate-the-permissions-on-every-request)。

## 凭据保护与轮换

业务库秘密仅由 Java 取得并用于受控连接，Python 不取得业务库密码。模型秘密由模型适配器在必要调用层按受控引用解析，服务身份和本次任务资格分别核验，实际秘密不进入图状态、提示词或业务上下文。

连接密码和模型密钥以密文及密钥版本保存，主密钥与密文分开管理；基础设施凭据、服务私钥和主密钥优先按[凭据注入规则](认证与身份上下文.md#凭据注入与保存)通过受限只读文件提供。初期采用成熟的 AES-GCM 实现，按实现要求管理加密参数和轮换，不自行拼装加密算法；具体文件权限、备份及部署配置在工程实现中落实，参见 [OWASP 秘密加密与密钥分离](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html#7-encryption)。

- 编辑与详情仅返回已配置等必要状态，旧秘密不回显；更新沿用既定留空保留与明确替换规则，不从普通详情接口取得原值。
- 请求日志、异常、对象 `toString`、调用追踪和任务序列化统一脱敏，秘密不进入前端、SSE、浏览器缓存、Milvus、普通日志或导出。
- 模型目的地和节点配置只取服务端配置，用户问题、资料或模型输出不能改变目的地、凭据、节点分配和权限；不自动切换未配置提供方。
- 轮换后更新受控引用，并按策略处理旧连接或客户端失效；审计记录替换行为、引用和版本，不记录秘密值。
- 连接、采样及模型处理继续按原权限和预算运行，不新增逐次 AI 读取审批；模型传输边界与用户输出限制分别核验。

## 审计记录与可见性

| 记录 | 主要内容 | 最小内容边界 |
| --- | --- | --- |
| 管理审计 | 账号、角色、部门、审批授权、撤权、规则、发布回退、凭据替换及重要拒绝 | 实际操作者、目标、必要差异、原因、结果和权限版本，不保存秘密或完整业务结果 |
| 查询与安全记录 | 原请求引用、实际依赖、SQL 与参数指纹、规则和知识版本、检查结论、执行状态及结果引用 | 完整 SQL、参数及业务原文经受控引用按权限读取，不复制到普通审计或诊断日志 |
| 模型调用记录 | 来源任务、节点、实际模型及配置修订、状态、耗时、已知用量与失败原因 | 保留当次配置事实，未知用量明确未知，不默认保存完整提示词和业务结果 |

各记录关联实际发起与执行身份、目标、明确时区的时间、请求或任务编号及必要的 `executionId`，支持跨端追溯。不因自动任务而伪造人工操作者，不将后来的配置或角色回填为历史事实。内部详细原因与用户可见反馈分开授权。

审计查看、技术诊断及业务原文读取分别核验。日志输入需正确编码和脱敏，防止外部文本破坏日志结构；只记录必要关键节点和判定，不逐 token 复制流式文本，参见 [OWASP 日志内容保护](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html#data-to-exclude)。

## 审计提交与失败处理

- 每次批准的审批结论、当次授权结果和审计在同一可靠事务中完成，由实际批准人名下的一条记录表达，不另建授权激活或重试阶段。联合申请必要审批未齐时如实记录子项结论；全部必要项通过时按既定门槛整组生效，不伪造提前生效。
- 关键管理审计写入失败时不能宣称变更成功。角色、授权、规则或发布等关键变化与其审计保持一致提交，失败按原操作编号核实，不通过重复点击生成多笔变更。
- SQL 执行前建立持久执行记录；执行已经发生但收尾写入失败时，按原 `executionId` 核实补录，不重发 SQL，也不把真实未知状态写成未执行。
- 普通业务操作不能编辑或删除历史审计。纠错追加关联的新记录，清理使用单独授权的保留机制；审计、查询过程和历史结果分别沿用所属方案的保留政策，不默认永久保存或在本页另设期限。
- 问数结果能查看即可导出，下载仍核验当前身份、结果权限和保留状态；只保留查询记录，不新增独立导出权限或单独导出日志。

## 待落实与验收

执行与交付检查、当前权限版本、秘密引用和审计一致性机制已确定。仍需落实解析器及驱动兼容版本、方言与视图函数覆盖、中文规则可核验能力、资源与取消能力、权限并发控制、密钥托管轮换、审计物理结构及保护清理实现，不能以静态解析或文档确认代替安全验收。

验收至少覆盖多语句与嵌套副作用、星号及视图真实依赖、别名计算聚合绕过、语义不足时拒绝、SQL 检查后篡改、流式中途撤权、剩余来源重算、取消未确认、恢复沿用旧授权、审批审计提交失败、SQL 收尾记录失败，以及凭据意外进入日志或检查点。测试使用受控数据，不以真实秘密或完整业务结果作为普通测试输出。
