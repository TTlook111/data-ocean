# 系统架构

跨前后端的正式系统架构和接口契约尚未定案。当前维护职责边界和设计输入，不把业务流程图当作已实现的服务拓扑。

## 共用范围

| 内容 | 归属 |
| --- | --- |
| 页面结构、组件、交互和原型状态 | [前端设计](../frontend/README.md) |
| 业务规则执行、身份与权限、持久化和任务实现 | [后端设计](../backend/README.md) |
| 系统边界、跨端数据流、接口契约、错误与状态语义、认证协作及部署关系 | 本目录共用一份，各端引用，不重复维护 |

## 确定架构时的依据

[产品方案与解说](../product/README.md)规定单企业、多源单次上下文、业务库只读及跨模块衔接。[人员权限](../product/modules/02-people-access.md)规定服务端校验和来源边界；[知识发布](../product/modules/05-knowledge-release.md)、[问数](../product/modules/06-query.md)及[反馈](../product/modules/07-feedback.md)规定版本、执行与复验关系。

技术栈按前后端分别维护；影响双方的协议和系统约束在这里维护。确认架构后再增加必要专题和图示，不先假定服务数量、数据库结构或具体部署方式。真实实现说明待重构开始后建立。

个人角色定义页面、按钮和功能；部门用于人员归属及初始数据源访问分配。数据源授权选择数据源和可复用的中文输出限制规则，不设置授权期限；额外访问审批通过即生效，审批决定、授权来源和必要审计在同次提交中完成，批准人与生效结果合并为一条审批审计。平台不依据所属部门为业务查询追加行过滤。输出限制只约束交付信息，相关字段仍可参与合法查询条件；SQL 校验结合输出来源、实际含义及治理标签匹配规则，必要时补取标签并在原意内重生成。前端分别表达，服务端真实实现时共同核验。不从原型推定权限引擎、数据库结构或审批服务已经实现。 同一数据源的输出限制取当前有效来源限制的并集，内容相同的限制去重；来源记录保持独立，失效来源不参与当前集合。
