# 认证与身份上下文

用户登录采用 Spring Security 与 Spring Session Redis，浏览器通过 Cookie 携带服务端登录会话；Java／Python 通过 HTTPS 与短时非对称签名 JWT 验证服务身份。Java 业务代码统一通过 `UserContext` 读取当前请求的登录用户。

本页维护已确认的认证方案、退出失效、身份传递及凭据注入规则，真实重构尚未开始。账号业务规则见[人员权限页面](../frontend/pages/people-access.md#登录与首次改密)，服务边界见[应用职责](服务职责与数据流.md)，任务及权限检查分别见[调用与任务协议](调用与任务协议.md)和[安全执行与审计](安全执行与审计.md)。

## 用户登录与服务端会话

- 沿用登录名与密码登录。管理员创建初始密码，首次登录或管理员重置后先改密，再重新登录；改密前只允许完成必要改密及退出，不开放普通业务能力。不新增自助注册、统一登录或独立登录会话管理页面。
- Spring Security 负责认证及安全过滤链，Spring Session Redis 保存登录态并支持按用户定位、注销关联会话。浏览器只持有随机会话 ID，用户登录不采用浏览器自行保存及刷新的 JWT。
- 前端与 Java API 优先同源部署，正式环境使用 HTTPS。会话 Cookie 设置 `HttpOnly`、`Secure`、`SameSite=Lax`，限定必要作用域；前端不读取会话 ID，也不将其写入本地存储或 URL。
- 登录成功后更新会话 ID，防止沿用未认证阶段的会话标识。基于 Cookie 的登录、退出及业务修改请求启用 CSRF 保护；SPA 在登录前取得所需 CSRF 令牌，认证成功及退出后按框架要求重新取得。CSRF 令牌与登录会话 ID 分开处理，SameSite 不替代 CSRF 校验。
- 登录会话只维护必要身份及认证关联，不保存完整业务结果或长期固定的数据权限快照。账号状态、功能权限和数据访问继续由 Java 按当前权威状态核验；Redis 或必要认证依据不可用时不能降级放行。

登录会话与业务对话分别管理：前者控制当前浏览器访问资格，后者由 `conversationId` 关联消息和历史。登录失效不删除业务对话、任务或结果记录，具体归属见[用户会话与请求层级](存储与会话状态.md#用户会话与请求层级)。

依据：[Spring Security 会话管理](https://docs.spring.io/spring-security/reference/servlet/authentication/session-management.html)、[SPA CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)、[Spring Session Redis](https://docs.spring.io/spring-session/reference/configuration/redis.html)。

## 退出与失效

| 场景 | 服务端与前端处理 |
| --- | --- |
| 普通退出 | 服务端注销当前登录会话，清除对应 Cookie；前端关闭订阅、清除受限展示与缓存并回到登录页 |
| 登录空闲或达到最长时限 | 服务端判定会话失效并拒绝继续访问；前端结束当前订阅与自动重连，重新登录后重新核验访问资格 |
| 本人改密或管理员重置密码 | 使该用户此前的全部登录会话失效；按既定改密流程使用新密码重新登录 |
| 账号停用 | 使全部登录会话失效，并按安全协议阻断访问、主动中断受影响任务；重新启用不恢复旧登录态或自动续跑任务 |
| 功能权限或数据授权变化 | 按当前权限更新访问与可执行动作，阻断实际失权范围；不能等会话或缓存自然过期才生效 |

退出和失效以服务端注销及核验为准，不能只清除页面状态或 Cookie。改密、重置和停用后，即使会话删除通知延迟，也不能继续放行此前的登录资格。重新登录不自动重放审批、发布、取消或查询命令。

正常退出或登录过期不自动取消已接收的后台任务，任务继续按业务身份、当前权限、状态及预算核验；用户主动取消使用取消命令。账号停用及实际撤权按[实时撤权规则](安全执行与审计.md#实时撤权与权限版本)主动阻断受影响任务。

## 请求线程与异步身份

每次用户请求的生命周期为：校验登录会话 → 建立 Spring Security 认证上下文 → 通过 `UserContext` 读取当前用户 → 请求结束清理。线程上下文只在本次请求有效，不能只在登录接口设置一次后假定后续请求仍处于同一线程。

`UserContext` 是现有认证上下文的统一访问入口，不另建一套并行的 ThreadLocal 登录状态。上下文保留用户 ID、登录名、姓名及必要的登录会话关联和权限版本，不保存密码、完整令牌或业务结果；具体编码、清理和线程池约束统一见[Java 当前用户与线程上下文](../backend/编码规范.md#当前用户与线程上下文)。

异步任务和 Java／Python 调用显式传递并验证必要业务身份，不依赖请求线程继续存活。持久后台任务从可信任务关联重建业务归属并复核当前资格；服务身份不能冒充登录用户。LangGraph `thread_id` 继续复用 `requestId`，不使用用户 ID 代替，也不将登录会话或完整认证上下文保存到检查点。

## SSE 认证与失效

- 浏览器到 Java 的 SSE 使用与普通 API 相同的 Cookie 会话认证，订阅地址不携带登录凭据；CSRF 按请求方法及用途执行，不为使用 SSE 全局关闭保护。
- 建立连接、重连及持续交付均核验对应登录资格与当前权限。退出、会话过期或账号停用时关闭关联订阅，不能只在握手时认证后无限交付；SSE 心跳不作为用户活动续期。
- 前端遇到认证失效时停止自动重连并清除受限展示，重新登录后通过事件游标与任务快照恢复获准展示，不重新执行任务。普通网络断线与认证失败分别处理。
- Java 订阅 Python 内部 SSE 时使用服务身份令牌。令牌到期或信任密钥失效后不继续沿用旧认证交付；换取当前服务令牌后重新订阅，事件恢复继续遵守[流式输出协议](调用与任务协议.md#流式输出与断线恢复)。

## Java／Python 服务身份

| 调用方向 | 认证与业务身份边界 |
| --- | --- |
| Java → Python | Java 使用自己的私钥签发短时 JWT，Python 使用预置信任的 Java 公钥验证；用于命令、状态查询及内部事件订阅 |
| Python → Java | Python 使用自己的私钥签发短时 JWT，Java 使用预置信任的 Python 公钥验证；受控工具、结果提交等接口继续核验可信任务关联与当前资格 |

服务 JWT 通过 `Authorization: Bearer` 请求头传递，固定可信签发者、目标接收方及允许的签名算法，验证签名与有效期；不能按令牌自报信息任意选择算法或信任密钥。双方分别持有各自私钥，不共用签名私钥，不转发浏览器 Cookie 代替机器认证。

服务身份只允许访问明确的内部接口，不自动取得用户、数据源或任务权限。内部调用按任务标识及有效执行代次查得业务归属，不信任调用方自填用户编号，也不把机器主体写成 `UserContext` 的登录用户。令牌到期重取只恢复服务访问，不重置任务预算或产生新的业务执行。

签名密钥按版本管理，轮换时更新预置信任公钥并停止接受已撤销密钥；令牌生命周期与签名密钥轮换分别处理。具体 JWT 库、算法及密钥加载配置在兼容验证时固定，签发与验签复用成熟实现，不自行实现密码学算法。依据见 [Spring Security JWT 验证](https://docs.spring.io/spring-security/reference/servlet/oauth2/resource-server/jwt.html)及 [OWASP REST 安全](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)。

## 凭据注入与保存

- 基础设施凭据、服务签名私钥及加密主密钥通过受限只读文件注入：本地应用从外部文件读取，容器依赖按需只读挂载，只授予需要使用的进程读取权；配置保留路径或受控引用。运行方式见[本地启动约定](../engineering/工程组织与版本基线.md#本地运行与依赖环境)。真实秘密不写入源码、镜像、前端构建变量、启动命令或普通配置样例。
- Java 与 Python 分别取得本服务所需凭据，不交换签名私钥。业务库密码仅由 Java 取得；模型密钥由必要调用层按受控秘密引用取得，不进入任务消息、图状态或提示词。
- 业务库密码及模型密钥沿用密文与密钥版本保存、主密钥分离的既定规则；具体加密与替换语义统一见[凭据保护与轮换](安全执行与审计.md#凭据保护与轮换)。
- 文件权限、挂载、备份和轮换按实际部署落实，开发与测试使用各自凭据。认证头、Cookie、密码及密钥不进入普通日志、异常、审计正文、调用追踪或导出；轮换记录行为及版本，不记录秘密值。

注入方式参考 [OWASP 秘密管理](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)。本页不预建或替换秘密管理基础设施。

## 初始时限

| 参数 | 已确认初始值 | 约束 |
| --- | --- | --- |
| 登录空闲时限 | 30 分钟 | 服务端判定，SSE 心跳不续期 |
| 单次登录最长时限 | 8 小时 | 从本次登录起计算，普通请求及续期不突破上限 |
| 服务 JWT 有效期 | 5 分钟 | 到期使用新令牌；不改变业务请求和执行代次 |

这些数值是实施初始配置，不代表容量或安全验收通过。时限由服务端执行，具体参数只在本节维护；会话超时原则参考 [OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。
