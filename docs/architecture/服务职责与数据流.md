# 服务职责与数据流

正式应用由一个 Spring Boot 业务应用和一个 Python AI 应用组成。Java 内部按业务模块组织；Python 使用 FastAPI 提供内部接口，使用 LangGraph 编排 Agent，API 与 Worker 同工程分进程运行。前端统一访问 Java，Python 不直接承接浏览器业务请求。目标组织见[工程基线](../engineering/工程组织与版本基线.md)，当前以[本地启动](../engineering/工程组织与版本基线.md#本地运行与依赖环境)为主：应用在宿主机运行，基础依赖通过 Docker Compose 启动。

技术栈维护在[后端设计](../backend/README.md#已确认的技术栈)，Java 分层、对象分类和文件名后缀见[Java 编码细则](../backend/编码规范.md)，存储落点与身份层级见[存储与会话状态](存储与会话状态.md)，通信与任务生命周期见[调用与任务协议](调用与任务协议.md)。本页定义跨端职责，不重复产品规则或预定物理表结构。

## 模块职责

| 范围 | Java 负责 | Python 负责 |
| --- | --- | --- |
| 人员、角色、审批、授权 | 完整业务流程、权限判断和审计 | 按任务取得必要上下文 |
| 数据源 | 连接配置、连接测试、元数据采集和结构变化检测 | 使用采集成果辅助分析 |
| 数据治理 | 记录、修订、人工确认和依赖关系 | 表字段解释、关联和指标建议 |
| 知识与发布 | 文档及修订、候选、审核裁定、发布切换、暂停和恢复 | 文档规划与生成、切片、向量化和索引构建 |
| RAG 检索 | 获准范围、发布版本和同版治理详情 | 向量检索、重排和候选证据组装 |
| 智能问数 | 请求接入、权限检查、受控 SQL 执行、结果保存和交付 | 理解、追问、检索、SQL 生成、语义核对和结果解释 |
| 反馈与看板 | 分派、处理、复验、结案和统计 | 相似问题召回等 AI 辅助能力 |
| 模型管理 | 配置、节点分配、启停、凭据管理和调用记录 | 接口适配、连接测试和实际模型调用 |

Python 生成的建议和文档通过 Java 接口校验、保存，再按原有权限执行确认、审核和发布。AI 生成成功、索引构建成功不代替人工决定，也不自动解除暂停或禁止。模型配置和分配由 Java 维护，Python 使用本次配置修订和受控秘密引用调用；原始凭据不进入图状态、提示词、业务上下文或普通日志。

知识发布切换、Embedding 匹配、暂停、回退及在途版本绑定统一遵守[知识版本与索引一致性](知识版本与索引一致性.md)。Java 决定 MySQL 生效清单，Python 提前准备匹配产物并按请求的确切绑定检索，不自行切换正式业务版本。

## 数据访问与执行边界

业务数据库连接、凭据、元数据采集、只读采样和 SQL 执行统一由 Java 管理。Python 通过受控工具接口请求对象信息、必要样本及查询执行，不持有业务库连接凭据。

Java 工具接口根据可信任务关联核对身份、当前授权、数据源、知识有效性、只读语义、输出限制和资源预算。内部调用按[认证方案](认证与身份上下文.md#javapython-服务身份)核验服务身份，再核本次业务操作资格，不能仅凭调用方填写的用户编号放行，也不将服务主体作为 UserContext 的登录用户。工具结果继续按获准范围裁剪，不能因供 AI 使用而扩大读取或信息发送范围。

Python 提供 SQL 候选、输出含义、字段来源、意图匹配及规则匹配依据；Java 结合实际 SQL 对象、可信治理事实、当前权限和可验证检查结果决定是否执行和交付。SQL、参数或检查依据变化后重新核验，不能沿用旧通过结果；仍无法确认满足限制时停止交付。

只读校验、输出规则、权限版本与实时撤权、秘密保护及关键审计提交统一遵守[安全执行与审计](安全执行与审计.md)，前端、Agent 工具及恢复入口不各自维护放行逻辑。

Java 统一提供版本明确、支持批量读取的上下文接口，避免逐表字段反复往返。Python 检索使用本次获准发布范围，补取详情时保持同版；检索命中和索引过滤不替代后续权限与禁止状态检查。

## 流程与状态归属

完整 AI 流程只由 Python 的 LangGraph 编排。Java 创建业务任务、启动任务、提交用户补充、请求取消及查询进度；Python 管理节点路由、追问暂停、补检索、有限重试及流程检查点。Java 不另建一套问数节点编排。

Java 管理业务记录、会话历史、问数请求及数据库执行事实并写入 MySQL；Python 管理 Redis 中的 LangGraph 检查点及 Milvus 向量索引。缓存与临时协调数据使用 Redis，具体内容与隔离要求统一见[存储分工](存储与会话状态.md#存储分工与写入归属)。

两端使用统一任务编号关联，Java 保存业务任务状态，Python 保存图执行细节，不把两端状态混成可相互覆盖的一列。请求终态、结果交付、解释状态和数据库任务实际状态继续按[问数方案](../product/modules/06-query.md)分别记录。

Python 通过 Java 接口读取业务依据并提交生成成果，不直接写 Java 管理的 MySQL 业务表；Python 直接写自己管理的 Redis 检查点和 Milvus 向量索引。两端的命名空间、账户和写入职责分开。用户、会话、请求的归属与 LangGraph 线程映射见[身份层级](存储与会话状态.md#用户会话与请求层级)，具体版本和部署参数继续在[架构待定事项](README.md#需要继续讨论的架构问题)中确定。

## 恢复与重复执行保护

Python 恢复流程前，通过 Java 复核当前用户、会话与请求归属，以及请求未终结、等待未到期、当前授权、数据源、知识及禁止状态、既定时间条件和剩余预算。恢复不能重置原预算、漂移原时间区间或重新取得已经失效的执行许可。

Python 携带稳定的执行任务编号请求 Java 执行 SQL。连接中断或恢复后，先查询原任务实际状态：已完成时读取原结果，未知状态先核实，不能盲目重发。取消请求与数据库实际停止分别记录；解释失败复用原结果重试，不重发 SQL。

LangGraph 的检查点与节点重试不能替代 Java 执行任务的幂等和状态核实；节点重入仍可能重复触发外部调用，参见 [LangGraph 重试与幂等说明](https://docs.langchain.com/oss/python/langgraph/fault-tolerance)。Redis 检查点要求见[持久化与恢复边界](存储与会话状态.md#redis-检查点的持久化与恢复边界)，幂等标识、执行代次、取消、超时及恢复遵守[调用与任务协议](调用与任务协议.md)。

## 一次问数的数据流

1. React 提交问题，Java 从登录上下文取得用户，核对会话归属及访问范围，创建本次请求。
2. Java 启动 Python 任务，Python 完成理解、必要追问和知识检索；用户补充由 Java 转交原任务。
3. Python 通过 Java 工具接口补取同版详情或必要的受控样本。
4. Python 生成 SQL 并完成语义分析，提交 Java 核验与执行。
5. Java 保存限量结果，Python 基于获准结果生成解释和图表建议。
6. Java 核对交付条件、保存答案，并向前端返回结果和进度。

接口覆盖任务启动、补充、取消、状态查询，以及上下文读取、受控执行和结果提交。HTTP JSON、后台执行、SSE 及任务标识已按[调用与任务协议](调用与任务协议.md)确定，服务身份与凭据注入见[认证方案](认证与身份上下文.md)；逐接口结构、认证配置、错误码和运行参数继续落实，不将方案确认当作实际机制已实现。
