# 知识版本与索引一致性

知识内容与检索产物分别版本化，由 Java 在 MySQL 中管理唯一的生效清单。单次问数固定一组兼容绑定，暂停、禁止及权限按当前状态实时检查。Python 构建和读取 Milvus 检索产物，不自行决定正式版本或解除限制。

业务范围、发布门槛及回退目标沿用[知识发布方案](../product/modules/05-knowledge-release.md)第 5 章第 7、8、9 节，模型分配沿用[模型方案](../product/modules/09-models.md)。应用职责见[服务职责与数据流](服务职责与数据流.md)，存储见[存储与会话状态](存储与会话状态.md)，幂等及任务恢复见[调用与任务协议](调用与任务协议.md)。本页维护已确认架构，不表示真实发布、索引或切换已经验收。

## 版本与当前使用控制

| 对象 | 固定内容 | 变更边界 |
| --- | --- | --- |
| 知识版本 | 发布范围、文档与治理事实的确切修订、依赖及发布依据 | 发布后不可原地修改；内容或采用依据变化时按业务规则形成新候选与修订 |
| 索引代次 | 对应内容、片段、向量、片段映射、构建配置和 Milvus 位置 | 表示平台管理的一批检索产物，不等同于知识内容版本；未完成产物与正式代次隔离 |
| Embedding 配置身份 | 实际模型及版本、维度、影响向量结果的参数和预处理规则 | 标识匹配的向量空间；相同维度不证明两个模型生成的向量兼容 |
| 当前使用控制 | 暂停、禁止、原因、证据、影响对象及解除记录 | 独立于历史版本，即时核验；历史清单和回退不能覆盖当前限制 |

同一知识版本可以有不同 Embedding 配置下的索引代次。索引重建或模型变更形成新的检索产物及生效绑定，不自动产生新的知识内容版本，不改写原发布记录或直接上一知识版本。

## 生效清单与请求绑定

MySQL 生效清单明确关联数据源及发布范围、知识发布版本、文档与治理事实修订、必要依赖、索引代次及位置，以及匹配的 Embedding 配置身份。来源对象使用稳定身份、世代与结构依据，不以展示名称或“最新版”替代确切引用。

一次发布只切换清单纳入的完整范围，其他范围维持原绑定；必要协同范围及合并拆分的新旧替代组合一起切换。同源跨范围问数取得一组兼容版本，依赖冲突或必要部分缺失时阻断，不拼接未经核验的组合。

Java 为新请求取得明确的生效绑定，Python 的关键词召回、向量召回和同版治理详情补取使用同一组引用。Redis 可以缓存带版本的不可变清单，缓存不成为另一份生效权威。请求持有明确的 Collection、代次和配置引用，不能在运行中通过会被重绑的“最新”别名切到另一组产物。

Milvus 别名可用于运维，但不承担 MySQL 业务清单的生效决定，参见 [Milvus 别名](https://milvus.io/docs/manage-aliases.md)。

## 知识发布切换

1. Java 固定本次候选，记录目标范围、基础版本、文档及治理修订、依赖、题单、测试身份和模型配置；未确认的必要内容阻断候选，不由模型补猜。
2. Python 在隔离的候选代次生成片段、向量及检索产物，保留当前正式产物。普通内容发布在匹配向量空间内新增不可变代次，Embedding 空间变化时准备新的 Collection。
3. 核对片段与来源完整性、向量配置、依赖及实际可检索性，运行该候选相关测试。无题、失败、未裁定、取消或执行异常均不算通过；候选或验证依据变化后重新核验，不沿用旧成绩。
4. 临切换前，Java 再核对当前权限、暂停与禁止、结构、基础版本、依赖、模型配置及测试依据，防止构建期间的变化或较早任务覆盖新决定。
5. Java 在一个 MySQL 事务中切换本批完整范围的生效绑定，并一致记录旧版、新版、目标范围、操作人和处理结果。不逐条部分切换或逐步放量；没有就绪的必要产物时不开始切换。
6. 切换后核对实际入口与完整组合，分别记录准备完成、切换提交及切换后验证结果。响应丢失或结果不明确时，按原操作编号查询实际生效清单，不能盲目重复切换或宣称成功。

Milvus 产物先构建、验证并就绪，再提交 MySQL 生效切换；不把两个系统的写入假设为同一个事务。切换前失败保留仍有效的旧入口；切换后通知失败通过已提交记录和清单核对恢复，不能再把旧入口当作当前版本。

初期知识检索明确使用 Strong 一致性，候选验证与正式读取均检查目标代次的可见性，不以写入响应成功或固定等待几秒代替就绪校验。先验证正确性和容量，再评估优化；Milvus 默认有界陈旧一致性的可见性不能直接当作正式切换保证，参见 [Milvus 一致性](https://milvus.io/docs/consistency.md)。

## Embedding 模型变更

反馈相似候选目前按人工请求为同源近期事项批量计算向量，全部候选使用同一次固定的模型修订。向量只在当次请求使用。以下索引切换约定适用于有持久索引的检索路径。

节点的已选择配置与当前生效配置分别保存，配置选择即保存目标；实际生效通过索引更新任务核验匹配路径后切换，不新增模型审批流程。

- 更新任务固定目标模型身份、应覆盖的完整检索范围和当前内容版本，使用新配置在隔离向量空间构建。新产物未完成或验证失败时，继续使用仍可用的旧匹配路径；没有匹配路径时明确不可用。
- 切换前补齐应覆盖的必要范围，由 Java 一起切换索引绑定及问题向量化的生效配置，不能仅因部分范围成功就宣布该节点全部就绪，也不能让问题向量先切到新模型。
- 更新期间发生内容发布或回退时，临切换重新核对目标内容，变化范围补建并验证后再切。目标配置或当前选择已变化的旧任务不能覆盖新选择，任务结果关联原候选及执行代次。
- 知识索引与反馈问题库索引分别更新，各自使用匹配配置；不能直接复用另一索引空间的问题向量。
- 更换生成模型本身不重建知识向量。仅改名称或轮换凭据时，核对实际向量生成身份是否变化，不机械重建；配置修订与实际调用快照仍完整保留。
- 清空、明确停用或失效使相关匹配路径不可用时，不能绕过该决定继续使用旧路径。重新选择只使用已知匹配且仍有效的产物，不因索引文件存在就恢复服务。
- 模型变更任务同时核验直接上一知识版本的回退路径，明确保留的旧代次与需补齐的匹配产物，避免内容可回退但索引不兼容。

更新只改变检索产物与其生效绑定，不修改知识正文、绕过知识发布或重置知识回退链。

## 暂停禁止与显式恢复

暂停和禁止保留原知识及索引引用，按实际依赖阻断受影响的新请求和在途路径。运行中的 SQL 按任务协议取消、核实，返回前继续检查交付资格；旧片段仍能召回不构成使用许可。

- 业务含义仅有疑点时保持待复核，不自动当作已确认错误或暂停。
- 对象删除或结构已确认不兼容时立即禁止，并沿依赖暂停受影响知识，不等待文档重新发布。
- 重连、索引重建成功、知识发布、Embedding 切换及回退均不自动解除暂停或禁止，也不恢复已撤销权限。
- 原风险消除、对象及依赖兼容、业务依据确认并通过必要验证后，由有权限者显式解除，记录原因、证据、对象和操作人。内容未变时可验证并复用原版本及索引，不强制重建。

修复可以使用受控隔离候选验证并发布，生产限制继续保留；验证资格仅适用于已审核修复对象及必要依赖，不扩大数据权限或进入普通问数。修复候选满足发布检查后可以在生产仍受限时发布，直到有权限者显式解除，避免以“先解除禁止才能测试”绕过生产控制。

## 完整范围回退

回退固定到当前知识版本的直接上一版及其完整范围组合，不任选历史版本、不跳版或只回退部分条目。合并拆分的替代关系一起回退，原稿、新稿及必要引用不能只恢复一边。

1. Java 固定当前基础版本、直接上一版目标和完整范围，核对回退权限及操作依据。
2. 重新检查当前结构、对象身份及依赖、权限、暂停与禁止、关键题单和索引可用性。上一版缺失或不兼容、必要项失败或部分目标已被后续发布替换时整批阻断，保留当前入口并说明原因。
3. 确认目标内容具备与当前生效 Embedding 配置匹配的索引后，在 MySQL 中一次切换完整绑定，并记录原操作结果。重复提交返回原结果，切换情况不明时先查实际入口。
4. 保留问题版本、回退记录和仍被引用的产物，供核查与修复；回退不覆盖历史查询使用记录。

例如当前模型为 E2，而上一知识版本只保留 E1 索引时，先为目标内容补齐 E2 匹配索引并验证，再办理回退；不能使用 E2 问题向量查询 E1 索引，也不能借知识回退隐式回滚模型分配。

回退只改变知识解释及检索入口，不回滚业务库、不修改权限或解除暂停。问题版本已确认不安全时，先暂停受影响路径再回退；回退成功后仍按原风险与证据办理显式恢复。

## 在途查询与产物保留

请求固定知识、索引和 Embedding 的兼容绑定，Redis 检查点及 MySQL 使用记录保留这组引用。普通发布、回退或 Embedding 切换后，新请求使用新绑定，已开始请求使用仍有效的原组合完成，不强制重启所有任务。

详情读取使用该绑定中的确切治理修订，不能偷偷补入最新定义或将新模型的问题向量用于旧索引。恢复先核对原绑定、剩余预算和当前状态；连接重建或事件重放不重新选择知识版本，具体任务规则见[失败恢复](调用与任务协议.md#失败恢复)。

撤权、暂停、禁止、结构不兼容及所需模型停用即时生效，原快照不提供豁免。生成前、SQL 生成后、执行前及交付前核验相应边界，运行中按状态变化阻断受影响路径；不能为了让在途任务完成而恢复失效内容。

权威权限版本、检查入口、实际停止确认及发布回退审计的提交规则统一见[安全执行与审计](安全执行与审计.md)，知识绑定不能替代当前授权或审计事实。

清理旧产物前核对当前生效绑定、在途任务引用、现存直接上一版和调查保留要求，再按企业容量与期限策略处理。会话关闭、SSE 断开或缓存过期不能单独作为删除索引的依据。历史审计与索引产物分别保留，不因保留审计就永久保存所有向量，也不自动删除仍在使用或回退保留中的产物。

## 故障与实现细化

| 情况 | 处理边界 |
| --- | --- |
| 构建或验证失败 | 不切换，保留失败依据及仍有效旧入口；首次发布没有旧版时明确不可用 |
| 切换前基础版本或配置变化 | 阻断旧候选覆盖，核对差异并对变化范围补建、重验 |
| 切换提交后回包丢失 | 查询原操作及 MySQL 实际生效清单，不能以 HTTP 超时当作未提交 |
| 切换后索引服务故障 | 如实表达不可用，修复或按受控流程回退，不静默使用另一内容版本或不匹配模型 |
| 暂停或撤权与发布并发 | 当前限制继续生效，发布不能清除限制或向失权请求交付 |
| 回退目标缺少当前模型的匹配索引 | 补齐并验证后再回退，保持当前模型分配不变 |

上述机制已确定。物理表及清单字段、对象与代次标识、Embedding 身份判定、Milvus Collection 与筛选布局、构建校验、切换并发控制、引用追踪、清理参数和 Strong 检索性能仍需在实现设计中细化。

验收须覆盖并发发布、部分构建失败、过期 Embedding 任务晚到、切换回包丢失、跨范围依赖冲突、暂停与在途任务竞争、回退模型不匹配，以及保留期内产物不被提前清理。静态文档核对不代替真实 MySQL/Milvus 切换、检索与恢复验证。
