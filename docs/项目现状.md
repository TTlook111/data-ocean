本机隔离环境只读复核显示：快照保留历史评分，但没有可核验的来源/语义检查批次；新治理候选尚未批准，活动 RAG 和完成问数仍属于旧流程时期。现有数据不足以证明当前数据质量或新治理闭环已通过；详细观察仅在[复核记录](acceptance/2026-10-25-语义中心复核记录.md)维护。

本页只维护当前状态。多轮修改、旧测试数量、旧迁移和启动记录已移入[项目状态历史](archive/status/2026-10-24-项目状态历史.md)，不能作为当前实施指令。治理主体实施目标已[归档](archive/plans/completed/字段语义治理与问数反馈闭环改造目标.md)，原确认要求保留追溯，遗留缺陷和验收在后续开发跟踪；当前行为以[模块说明](modules/README.md)为准。

## 已知限制

- RAG 与问数仍存在纯表级知识准入、新业务关系补键的适配缺口；当前定向查询 Java 测试未全通过。原因与影响见[问题分析](development/RAG与问数治理适配问题.md)，修复及验收归后续开发第 6 项。
- 知识页统计、快照与 RAG 列表存在旧请求覆盖新数据源范围的问题，已函数级复现，尚未修复或做浏览器验收；归后续开发第 12 项。
- 当前 S1 完成路径未将受保护来源写入查询血缘；旧入口无调用者，隔离库也未见完成任务的查询血缘记录，归后续开发第 14 项。质量检查和业务关系审核不应自动生成数据流边。

- 当前修复验收是绑定原情景/预期结果的明确人工核验；没有自动业务回放引擎，也不把程序合同检查称为业务真值证明。
- 评分政策 2 合并规范化 SQL 样例，仍需业务校准；旧政策事件保留追溯，不自动转为新证据。未实施复杂跨场景评分或独立性证明。
- 一键治理限制为 200 字段、100 表、100 关系，单次最多新增 200 项任务；超预算转单对象工作面。未实施任意规模分片调度。
- 历史业务知识缺少人工依据确认时需重新核对；知识复查、文档发布、RAG 生效和原问题验证是不同阶段。
- 完整新链路、多角色、撤权/失效、在途替换、大范围及页面视觉仍需独立验收；没有生产验收结论。
- Redis 默认开发加密密钥告警及一项历史静态测试对缺失脚本的引用仍需处理。Browser 早期 iframe 报错和默认 Milvus 集合归属仅保留为历史待复核问题，不宣称已复现或是当前主链阻断。

剩余动作只在[后续开发](development/后续开发.md)维护，不在历史方案里重开任务。
