本轮起点为远端分支 `feat/frontend-conversation-v2-20261029` 的 `2dc0a1e76f03c1e4d95ee76fb99b69844d29dfe0`；核对时 main 为 `b8cc641d0ae98c050b83fdbc168f3f100660b081`。只改前端及交付/验收文档，不改 Java、Python、数据库或 IAM 规则，不合并 main、不部署。品牌沿用既有 Logo，沿用已认可的暖白/墨色/铜橙后台设计；UIUXProMax 官方 2.15.0 的表格、筛选、键盘与焦点建议用于本轮工作面，不据通用建议新增业务能力。

## A：关系图谱与实际查询来源

入口仍是 `/admin/assets/lineage?datasourceId=…&entityId=…`，保留菜单及路由权限。`entityId` 是元数据实体 ID；不把字段元数据 ID、内部数字任务 ID 或快照 ID 混用。

| 现有能力 | 新入口与行为 | 权限/接口事实 |
| --- | --- | --- |
| 对象搜索、焦点、方向、深度与图谱 | 可见页标题、范围控件、关系画布、键盘对象列表；节点/搜索回写 URL，返回可恢复精确焦点 | 目录/搜索独立需要 metadata:view；增强图谱需要实际根源 lineage:view |
| 无目录权限的精确对象 | 有精确 entityId 时直接读增强图谱，并核对返回根的实际源；辅助目录失败不补权 | lineage:view 不额外要求 metadata:view；无精确对象时明确缺目录辅助能力，可转查询来源按精确表名读取 |
| 无效/不存在的精确链接 | 显示错误并停止，不回退偏好源或第一张表；增强响应的明确源不能被旧目录同 ID 覆盖 | 修正旧页面及旧测试的隐式对象替换行为，不改后端能力 |
| 关系与字段链 | 结构 FOREIGN_KEY、存储的 LINEAGE ETL/MANUAL/QUERY 标记、字段 DERIVED_FROM 分别标注；来源缺失不冒称 MANUAL | QUERY 标记不是本次执行证据；不根据两表同时出现推断 JOIN 或加工边 |
| 创建、列映射 | 顶栏记录关系、节点添加下游、Shift 拖动预填；普通拖动只移动；更换表清旧列/映射，所有映射必须完整且属于精确两表 | 实际两端各自 lineage:manage；搜索/预填/列选项需对应 metadata:view；跨源合法绑定分别核验，不额外要求图谱根的维护权 |
| 删除及级联选择 | 关系列表和右键按唯一关系 ID 选择；先确认是否连同列映射删除，只发一次 DELETE | 只允许 LINEAGE；后端 DELETE 不是只读预检查。原实现确认前已删除的缺陷已修复 |
| CSV/JSON 批量导入 | 保留原文件入口，冻结文件内容摘要，等待摘要时切源/撤权不再发写入 | 文件内容不由页面源重新限定，后端仍逐项校验实际端点；不宣称事务或逐项返回语义超出接口 |
| PNG | 导出当前画布，冻结真实尺寸，失败/超时结束，旧身份/范围完成的导出不触发下载 | Chromium 实际 PNG 宽高非零；不读取脱离 DOM 的 clone.clientWidth |
| 影响分析、表/字段查询证据 | 独立“查询使用与输出来源”工作面；精确源/表/字段、影响总数、最多 100 行明细、近期最多 10 个内部数字任务 ID | 仅需实际源 lineage:view；摘要与明细分开报错。字段无输出 alias 是查询使用，带 alias 才是结果派生；表类型真实为 USAGE |
| 单条问数依据 | 按需依据中补实际 DTO 的快照、RAG build/来源快照、attemptId 与 sqlHash | 不输出原始 sourceTrace；接口没有投影状态，明确“未提供”，不伪造 PENDING/COMPLETED。原 SQL/CSV/历史读取及反馈仍走受保护接口 |

图谱、列抽屉、搜索、导出按当前身份/IAM/源与单调请求代次隔离；同源筛选在途变化也会使旧结果失效。删除和导入增加范围代次，A→B→A 的旧成功/错误/finally 不关闭新目标或解除新操作锁。创建、删除、导入的网络/408/5xx 未知结果按真实目标在内存保留，跨工作区导航阻止同类重复；创建不因切换 ETL/MANUAL 绕锁，文件不因切页面源绕锁。横幅显示原关系/端点/文件摘要，不显示令牌。

本轮不使用兼容的一跳关系响应冒充增强图谱深度。空来源类型明确提示未选，不发送省略 lineageType 的兼容请求。没有关系、没有目录、读取失败与无权分别显示。

- 独立只读审查发现并推动修复了删除预检查、平行边 ID、根源冲突、字段使用/输出误标、跨源预填、未知锁与 ABA 写回等问题；最后未发现阻断提交的 P0/P1。详细最终计数及后续两批在下文记录。

### A 的限制

真实 Java/查询投影/模型/数据库未重跑。影响覆盖历史快照，没有精确快照/时间过滤；coverageStartAt 与 pendingDatasourceQueryCount 属整个数据源，不能解释为所选对象自身。成功结果不证明投影完成，页面没有重跑 SQL 或投影恢复写接口。内部数字任务 ID 不能拼公开问数 taskId 链接。

后端列映射服务的“列必须属于请求两端表”校验完整性仍需独立后端核对；前端已按实际 source/FQN/table_name 验证选项，但不能替代服务端约束。本轮未修改后端。指导录入依赖目录辅助权限，缺能力明确说明，不隐式补权。未知锁仅内存生效，不跨整页刷新；没有幂等键或事务预览接口，网络结果未知时先人工核对，不自动重发。

## B：查询分析、慢查询与审计详情

`/admin/operations/queries` 保留“查询审计 / 性能分析”两 Tab，只挂载当前 Tab；未知 tab 回落审计，不提前读取隐藏性能页。

审计工作面把近 30 天数据源统计、列表筛选、审计证据详情分层。统计只发 `datasourceId/days:30`，不随问题关键词、成功或慢标记筛选改变；口径是已落库审计行，包含旧记录，不是所有问数成功率或业务正确率。状态 null 显示“未记录”，缺耗时不补 0。慢标记取服务端，不以固定前端阈值重算，也不称为纯数据库执行时间。

| 保留能力 | 验收后的表现 |
| --- | --- |
| 源、关键词、成功/慢筛选和分页 | 源选项直接使用 S1 的 audit:view 负责源摘要，不调用无权 datasource:view 辅助 API；显式非法或无权源停止，不退全部。只有明确改/清源才解除非法源；普通关键词操作不会扩大范围。URL 前进后退恢复条件和 pageNo，total 使用后端 |
| 统计 | 读取/失败/空统计分开，刷新入口独立；换身份或源后旧统计不覆盖 |
| 审计详情 | 精确审计 id 和实际源核对；失败按冻结原 id 重试；关闭、换对象、筛选、身份或撤权清旧详情和 SQL，晚回包失效 |
| 原审计 SQL | 默认从界面状态剥离，点击后再次 getAuditLogDetail，由现行服务端 audit:view/实际源合同重验；不额外加普通问数 query:sql:view，也不把 audit SQL 冒称普通问数受保护 SQL 接口 |
| 慢查询与 SQL | 只按 page/pageSize 合并当前有权源，按服务端耗时降序；没有假单源筛选或默认 SQL 列。逐行可按真实 audit id/source 打开对应审计详情，再按需重读 SQL，未丢失原能力 |

普通问数 SQL/CSV/历史接口保护不变。审计 id、内部数字 queryTaskId 与公开 UUID taskId 是不同标识；没有 public taskId 的响应不伪造问数链接。页面没有新增 CSV 导出、重跑查询或投影恢复接口。
