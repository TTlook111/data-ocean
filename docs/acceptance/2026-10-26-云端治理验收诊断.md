### 失败项与静态发现

1. **G1，治理交接阻塞，实际复现**：两处 Java `lineageDependencies` 对 `ds.db.orders → ds.db.rollups` 返回 `[table:db]`。四段字段 FQN 对照正常。Python 缺显式依赖兜底也误判三段表 FQN；正常 Java 路径优先使用传入依赖。
2. **R1，RAG 准入阻塞，实际复现**：Java `loadKnowledgeChunks` 把空列的 `TABLE_STRUCTURE/LINEAGE` 排除；Python 接受五类结构/业务纯表事实，却拒绝空列 `LINEAGE/DERIVED_FROM`。不能只改一端。
3. **Q1，问数消费阻塞，实际复现**：新 `BUSINESS_RELATION` 已能经过通用 RAG；补键 helper 仍要求旧 `factType=JOIN_PATH`，新类型在同权限/依赖下不补连接键。
4. **Q3，完成副作用，部分实际复现**：CAS=0 仍调用审计的反例失败。事务中先派发异步审计、后由另线程读取状态，及审计直接 insert/普通 task 索引均静态确认；真实提交竞态、回滚及并发重复回调没有运行证据。
5. **Q2，查询血缘接线，静态确认**：`saveLineage` 在生产 Java 中仅声明/实现，无调用者；S1 保存 `iam_source_trace` 不能等同写入 `query_lineage_table/column`。旧 FROM→JOIN 方向推断不得恢复。
6. **R2，当前血缘来源门禁，静态缺口**：查询读取和在途精确引用仅见字段/业务等事实的对应复核，未见 LINEAGE/DERIVED_FROM 当前确认/绑定复核。活动 build 的旧 APPROVED metadata 不足以证明当前有效；真实撤销/改端点/解绑后的新查询及在途用例未执行，须补。
7. **问数现有基线未通过**：6 项错误均为 `本任务业务知识引用并发变化，请重新发起`；1 项断言预期一次 `queryTaskMapper.update`，实际包含新业务引用冻结和失败更新两次。Mockito 默认更新 0 且未回读已冻结引用与 `buildPythonRequest` 新 CAS 合同不匹配，是直接测试原因；本轮未改测试掩盖失败，也不据此断言真实数据库必然失败。

非阻塞项：治理本身不必等前置动态重排或向量复用才产出有效知识；旧 `field_confidence` 与新版事件机制并存需要保持口径区分；管理端范围乱序问题沿用原章节，本轮未重新执行页面测试。没有新建全面重构、多跳图推理或第二套对话存储需求。
