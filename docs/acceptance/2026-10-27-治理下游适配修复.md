# 治理下游适配修复与验证

日期：2026-10-26～27。范围为 G1、R1/R2、Q1–Q4、读取乱序，以及后续审查发现的三项修复及回归；不包含真实应用库迁移、模型业务质量、新 RAG 激活或浏览器验收。

## 推导、红队审查与最终方案

从基本目标推导，必须分别证明来源质量、业务依据、版本有效性、当前权限、结果正确性和来源可追溯；一个阶段通过不替代另一个阶段的证据。六类知识是能力范围，每问只需与其口径有关的事实。

据此采用最小持久方案：Java 核验血缘真实端点、当前发布快照和完整依赖，生成并冻结来源摘要；Python 按事实类型二次过滤，在当前 JOIN usage 内原子补键。结果只来自同一 PROTECTED 尝试；权威来源与待处理标记同事务提交，提交后独立事务投影审计和使用索引，失败保留待处理并有限批次恢复。不新增外部消息平台，不由 JOIN 书写顺序制造物理数据流。

红队对同 ID 原地修改、跨源同名、空列字段派生、补键部分修改、取消/重复回调、锁顺序、提交前读取、部分投影失败、丢失通知、坏任务阻塞、JSON 整数表现型、统计截断/重复及旧 UI 响应逐项复核。对应修正和当前代码入口集中在[适配分析](../development/RAG与问数治理适配问题.md#修正后的最终方案与红队审查)，不在本记录复制整套设计。

## 复现与修复

- 修改前实际运行 Java 查询/尝试/审计基线：44 项，37 通过、1 失败、6 错误。直接原因是 Mockito 夹具没有模拟新增业务引用冻结 CAS；更新夹具后仍保留真实零行并发冲突拒绝用例，没有删除生产校验。
- 新增 Java 血缘依赖反例在旧代码失败：两端表被解析为 `table:db`。新增 Python 交接正反例 7 项在旧代码失败；修复后纳入最终回归。原诊断空列 `DERIVED_FROM` 的错误正向期望继续保留勘误，未通过放宽字段依赖换取绿灯。
- 旧 Python 夹具使用两段表 FQN、新关系补键用例沿用旧 `JOIN_PATH`，已改为当前真实三段表身份及新类型；保留异常 FQN 和旧类型拒绝对照。
- 实施中新事务用例发现 JSON 小整数与 Java Long 节点表示不同会误拒绝身份，改为精确整数比较，不截断小数；完成、尝试和恢复统一任务→尝试锁顺序。知识失效提示改为覆盖字段、业务及血缘的“知识已变化”。
- 删除无调用者的旧 `saveLineage` 物理桥接和独立异步审计写入口；当前成功审计与查询使用索引通过同一投影事务写入，失败不伪报为权限变化。

## 复审三项：先反例，再修复

以下三项均先在修复前实际运行新增测试并观察到断言失败，再修改生产代码；不是仅把审查意见改写成说明。

| 问题与反例 | 修复前实际结果 | 当前修复及补充反例 |
| --- | --- | --- |
| Java 列表保留旧描述，精确来源读取已返回同 ID 新版本 | `generationNeverPairsAnOldBodyWithANewerSourceFingerprint` 失败：应为新描述却生成旧描述；该文件当时 1 失败、3 通过 | `currentSnapshot` 从同一份关系记录产生内容与摘要，列表只提供候选身份；生成新正文/新摘要，之后再次修改仍使该摘要失效 |
| Python 买方关系合法，额外召回同表对的卖方关系但卖方键不允许 JOIN | `test_planner_uses_only_the_selected_relation_not_other_same_table_candidates` 失败：预期 PROCESSING，实际 CLARIFICATION_REQUIRED；该文件当时 1 失败、8 通过 | `selectedRelationIds` 只选择当前审核事实身份，补键和 SQL 上下文都只保留所选关系；未知/未审核 ID、错误类型、所选关系缺 JOIN 权限与部分修改继续拒绝 |
| 前端主图加载未完成，实体展开递增了共享请求序号 | 新增加载反例失败：两请求结束后 loading 仍为 true，刷新不再发请求；该文件当时 1 失败、5 通过 | 主图与 loadEntityLineage 两入口统一接管/清理 loading；额外覆盖旧增强成功/失败晚到，不能覆盖新展开或清理其 loading，也不执行过期回退 |

`schema_linking` 的固定输出合同及 Java 场景目录增加 `selectedRelationIds`，值来自已审核 BUSINESS_RELATION 的 `factSourceIds[0]`。它只是规划选择，不等于 SQL 实际采用；Java 原有候选来源冻结、IAM、JOIN usage、尝试身份和完成合同未放宽。无需新增迁移、修改模型配置或让用户手动选择内部 ID。

三项最小失败复跑入口分别是 Java `mvn '-Dtest=LineageFactServiceTest' test`、Python `pytest tests/test_governance_adaptation.py -q`、前端 `npm run test:run -- src/views/admin/semantics/KnowledgeScopeRequests.test.ts`；修复后的这三组及上方扩大回归均通过。来源交错读取和前端时序为受控函数/Mock 反例，未据此宣称真实 MySQL 并发或浏览器交互已验收。
