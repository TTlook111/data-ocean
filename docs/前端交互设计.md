# DataOcean 前端交互设计

本文记录新方案与 HTML 原型的交互约束，供后续页面设计、技术实现和评审共同使用。产品业务规则以[产品方案](产品方案.docx)和项目负责人的后续决定为依据。当前原型入口为[问数工作台](../prototypes/app/index.html)和[后台管理](../prototypes/后台管理/index.html)。

DataOcean 的使用端为 PC 桌面浏览器。交互以鼠标、键盘、PC 窗口大小和浏览器缩放为依据，主要验收 1024、1280、1440、1536px 宽的窗口。

本文规定目标行为。原型的实际验证范围与证据记录在[原型验证说明](../prototypes/app/design-qa.md)。选型与接口实现进入对应阶段后再确定。

后台页面的布局、间距、字号和组件尺寸统一按[后台界面设计规范](后台界面设计规范.md)核对，业务交互与数据状态继续按本文执行。

现有 PC 后台的美化复用统一 token、页面模板和操作组件，保持相同内容边界与文字层级。主操作集中强调，次要动作使用中性色，鼠标与键盘均有明确反馈。`design-taste-frontend` 中适用于这些目标的原则纳入后台规范；营销页首屏、摄影、整屏章节及手机适配不属于后台交互范围。每次修改的实页与交互结果按文末要求复核，并记录实际范围。

## 先按方案定义页面功能

HTML 原型用于确认产品功能、页面关系和完整操作流程。设计顺序为产品方案与后续决定、页面功能清单、各状态下的交互、视觉表达。组件样张只验证排版与组件表现，不能据此要求业务页增加复制、更多、批量处理等动作。

每个页面开始设计前，先明确页面目的、使用者、前置权限、数据范围、可见字段、查询条件、状态、必要动作及其去向。每个按钮逐一说明“触发 → 输入或必要确认 → 权限与状态检查 → 状态变化及成功反馈 → 失败或取消后的去向”，并注明方案依据和原型完成度。可直接点击记录完成查看时，无需再重复放置查看按钮；没有真实业务动作时不放操作列。

菜单与按钮按当前登录账号的操作权限、资源范围、记录归属和对象状态生成。店长、业务负责人、治理人员和管理员等称谓表示业务职责。企业可以调整预设角色、创建角色、按部门和个人来源分配；同一账号可有多个角色。问数、个人管理和后台管理始终使用同一账号，进入后台不切换人员或职责，也不扩大权限。依据为产品方案第 1 章“业务角色与对象”和第 2 章“角色与职责配置”。

下面的页面分组从方案归纳，用于逐页核对功能，不代表最终侧栏菜单或必须拆成独立路由。动作来自对应方案章节；按钮位置、弹窗或独立页面等表达方式在该页设计时确定。方案明确的功能不得因当前示例尚未实现而被省略。

| 个人管理 | 本人账号、部门、角色及当前访问范围概况，返回原工作区 | 资料编辑、认证恢复、会话管理及其成功、失败、失效状态；不在本人页面变更角色或自行增加授权 |

“模拟负责人处理”“模拟执行校验失败”等只属于原型验证控制。业务页应呈现真实操作及由流程产生的状态；受控失败样例不能伪装成负责人日常业务按钮。

## 账号菜单与原型评审入口

账号区的头像、姓名和所属部门或门店组成一个可点击区域，直接展开业务入口，使用键盘也能聚焦与展开，不再要求点击独立三个点。菜单展开、关闭和焦点返回有明确状态。问数、个人管理和后台展示同一个登录账号的姓名与归属，不出现人员选择、职责切换或“原型视角”。

| 当前账号能力 | 用户菜单 | 进入后的约束 |
| --- | --- | --- |
| 本人账号有效，无后台模块权限 | 个人管理 | 只管理本人允许的资料与会话；没有后台入口 |
| 本人账号有效，具有至少一项后台模块访问权限 | 个人管理、后台管理 | 进入当前账号有权访问的后台模块，侧栏仅显示对应菜单 |
| 后台权限被撤销或范围失效 | 更新菜单，并停止访问已失权页面或记录 | 提示当前不可访问，清除受限展示；本人仍有效且有权使用的个人管理和问数入口继续可用 |

进入后台后，菜单可见、记录读取、批准申请、驳回、要求补充及执行授权分别核验对应操作权限、资源范围、归属和状态。具有后台入口不代表具有全部后台操作，具有读取或审批能力也不代表可以执行授权。角色名称用于展示企业已分配的配置，不作为前端推断权限的依据。

手工输入、收藏或刷新后台地址时继续检查当前账号权限；无权限时展示明确反馈，不渲染受限页面、记录及数量。不能只靠隐藏菜单限制访问，也不能因保留历史页面或请求而继续使用已撤销权限。

有权与无权账号通过独立测试场景预置账号和授权来验证，测试配置不进入产品用户菜单。项目运行图、视觉选稿和重置演示集中在独立的“原型评审”工具区，仅通过 `?review=1` 显示；重置只影响当前标签页的演示数据，执行前保留影响确认。尚未设计的资料编辑、认证恢复和会话管理动作不放无目标按钮。

## 记录数量与查询范围

所有会持续积累记录的页面，都要同时考虑只有少量数据、已有数百条数据和长期使用后的查询体验。设计列表时一并确定搜索字段、筛选条件、排序、分页、详情往返和办理后的状态变化。

正式实现的查询顺序如下。

1. 核验当前身份，以及本次操作可访问的数据范围。
2. 在获准范围内按关键词、状态、日期等条件过滤记录。
3. 使用稳定的排序规则。
4. 计算相同条件下的结果总数，再取指定页。
5. 前端接收并渲染当前页，以及总数、页码和每页条数。

总数、菜单计数和搜索提示同样受数据权限约束。无权记录不能通过总量、候选词、模糊搜索结果或翻页暴露。打开详情、执行办理、查看历史答案及导出时，继续核验当时的权限和实际生效范围。

当前独立 HTML 使用当前标签页内的离线数据模拟查询与分页。原型按同一组条件先过滤、排序，再计算总数与页数据，页面只渲染当前页。正式实现由服务端完成上述查询，前端提交查询条件和分页参数。

本轮静态 HTML 原型的查询与分页统一挂载本地 Element Plus 2.14.0 实际组件。`RecordControls` 组合 `ElInput`、`ElSelect`、`ElDatePicker`（`daterange`）、`ElButton` 和 `ElPagination`，业务页与规范样张调用相同入口。采用中文 locale 和 `large` 尺寸，查询控件与分页控件高 40px；交互、键盘操作、浮层及图标沿用组件库，项目只配置品牌色、字号和圆角 token。局部挂载组件用于本轮原型，正式前端技术栈仍在原型确认后选定。

## 搜索与筛选

| 项目 | 交互规则 |
| --- | --- |
| 关键词 | 去除首尾空白，统一全角与半角字符，英文大小写不敏感 |
| 模糊匹配 | 在页面明确告知的字段中执行包含匹配，允许只输入编号、姓名、用途或范围的一部分 |
| 多个关键词 | 空白分隔的多个词须同时命中，可以分别命中同一记录的不同搜索字段 |
| 特殊符号 | 加号、括号、方括号等按字面搜索，不把输入当成正则表达式 |
| 提交查询 | 搜索按钮与 Enter 使用同一组条件，中文输入法选字时应能正常完成输入 |
| 日期 | 按 Asia/Shanghai 的业务日期处理，包含开始日和结束日的全天 |
| 错误日期 | 起始日晚于截止日时，在日期控件附近说明错误，保留输入供修改 |
| 清空条件 | 清除关键词、精确状态和日期，页码回到第 1 页 |
| 查询结果 | 结果总数对应当前生效条件，无匹配时可直接清空条件重新查询 |

关键词、状态和日期范围使用隐藏的可访问标签，分别保留搜索范围、状态及业务日期含义。查询区不外露“提交日期”“生效日期”等字段名称。日期使用 `ElDatePicker` 的 `daterange`，空值分别显示“开始日期”“结束日期”；已选日期及提交值统一为 `YYYY-MM-DD`。范围选择、输入、清空、键盘操作及图标使用组件库原生交互，非法区间在控件附近说明并保留待修改条件。

查询控件统一高 40px，查询面板四边内距 24px，各字段组相隔 16px；关键词、状态、日期范围与查询操作共用顶边和底边。PC 窄窗口按字段组整体换行，日期范围中的开始、结束输入保持成组。

例如输入“周店长 经营周报”，应找到由周店长提出、且用途等可搜索字段包含经营周报的记录。输入“SQ-01”可以匹配编号中含有这段字符的记录。

查询和清空操作应有明确反馈。新查询完成前，旧内容仍被保留时需清楚标示加载状态，防止用户把它当成本次结果。连续发起查询时，只应用最新请求的返回结果。

## 分页与排序

| 项目 | 交互规则 |
| --- | --- |
| 默认每页 | 10 条 |
| 每页选择 | 10、20、50 条 |
| 分页信息 | 面板底部集中显示一次“共 N 条”、当前页与总页数，省去“当前第几至几条”的范围说明 |
| 边界 | 第 1 页禁用上一页，最后一页禁用下一页 |
| 空结果 | 总数显示 0，翻页操作禁用 |
| 改查询条件 | 关键词、精确状态、日期或分组改变后回到第 1 页 |
| 改每页条数 | 回到第 1 页，按新的条数重新查询 |
| 结果减少 | 办理或数据变化使当前页超过末页时，校正到有效末页 |
| 排序相同 | 时间相同的记录继续按稳定编号排序，保证跨页结果可重复核对 |

默认采用时间降序、编号降序。变更排序功能时，需同时规定次级排序。前后翻页不能随机重复或遗漏同一条记录。

收件箱队列在自身区域内滚动。分页入口应保持可找到，不能因数百条队列将操作推到整页底部。PC 窄窗口和浏览器缩放下保留可访问名称、禁用状态与完整分页入口；表格根据列预算设置最小宽度，横向滚动由表格区域承接。

## 高度与滚动归属

桌面后台由导航、查询区和统一结果面板组成。结果面板铺满查询区下方的可用工作区，外框统一包住表头、数据内容或空态、剩余留白和底部分页。数据行和空态按实际内容占高，分页作为面板底部区域。布局使用可收缩的容器分配高度，查询条件换行、窗口尺寸变化和缩放都需要重新适配。

| 场景 | 空间与滚动规则 |
| --- | --- |
| 桌面后台 | 顶栏、侧栏和外层页面固定在视口内，工作区承载当前模块 |
| 表格无数据或条件无匹配 | 保留表头与原列预算，在表头以下的表体区域显示空态，分页仍属于同一外框底部 |
| 申请收件队列为空或无匹配 | 保留必要分组，在结果主体内显示紧凑提示，外框仍包住面板底部分页 |
| 单条或少量记录 | 数据行按实际行高占用空间，剩余留白在同一个结果面板内，分页位于面板底部 |
| 多条收件队列 | 当前页的队列超过可用高度后，队列区域独立滚动 |
| 长申请详情 | 详情超过可用高度后，在自己的阅读区域内滚动，末条记录与操作入口可达 |
| 多条授权记录 | 分页保持在工作区底部，表头可见，超出的当前页表体在结果区域滚动 |
| 极矮桌面窗口 | 工作区统一滚动，内部列表与详情自然展开，保留固定顶栏和侧栏 |

空态提示按实际内容排布，表体继续承接表头与分页之间的可用空间。无数据和无匹配不移除表头，不改用另一套无列结构的结果容器。数据区域仅在实际内容溢出时出现滚动条，PC 记录区域滚动时，外层文档保持在视口内。少量数据时，留白和分页处于同一个完整外框内，翻页入口的位置稳定。极矮 PC 窗口采用工作区单层滚动时，分页随当前结果自然排列，并可滚动到达。

## 后台页面

桌面后台保留常驻左侧菜单。当前已绘制的“权限管理”页面包含“访问申请”和“授权记录”，按登录账号实际具备的对应权限显示。企业实际分配的操作权限和资源范围决定可见菜单、可读记录及可办理动作，不按店长、负责人或管理员等名称固定配置。

访问申请使用收件箱布局。PC 队列与单据并排，默认预览当前结果页的第一条真实记录，侧栏持续可见。当前菜单仅使用背景表示选中，PC 窄窗口通过表格区域内的横向滚动保留列结构。

访问申请与授权记录共用 216px 常驻侧栏、24px 工作区边距和区块间距。表格使用 48px 表头与 64px 双行密度。结果直接从必要的分组或表头开始，省去重复列表标题和数量条，底部分页包含于完整结果外框中。

查询、日期范围和分页通过 `RecordControls` 挂载同一套 Element Plus 组件，表格框架通过 `RecordTable` 保持统一骨架。业务页传入字段、列、数据、状态及操作回调。规范样张也使用相同入口；样张与业务页的差异只来自配置，组件尺寸及状态行为在共用定义中修改。页面重绘保留生效查询值及合理焦点，旧组件实例与浮层在卸载时清理。

### 访问申请

下表描述当前单项示例的列表行为。完整目标还包括需补充、撤回、分项与部分生效等状态，按前文待补项继续设计；当前分组与按钮不能被当作完整方案的状态全集。

| 项目 | 页面约定 |
| --- | --- |
| 搜索字段 | 申请编号、申请人、业务用途、业务范围，以及该记录已获准展示的标题与原问题 |
| 分组 | 待处理包含待审批、已批准待执行，已办包含已生效、已驳回、执行未生效和已到期 |
| 状态筛选 | 在当前分组允许的状态中精确筛选，切换分组时重置精确状态 |
| 日期条件 | 按申请提交日期筛选 |
| 默认排序 | 提交时间降序，申请编号降序 |
| 详情重点 | 原问题、业务用途、申请人和期望期限，其后是匹配资源、核定期限与当前可执行动作 |
| 当前页预览 | 仅从当前页结果默认选择记录，翻页后预览新页首条 |

分组数量按当前关键词和日期计算。精确状态改变当前结果总数，切换分组后按新分组的全部状态重新查询。分组计数和分页总数应让使用者能够解释其对应条件。

负责人根据用途匹配企业允许授予的资源和期限。审批通过后仍显示待执行，执行复核成功才显示已生效。驳回须填写可向申请人公开的原因。

办理后应同步更新状态、分组数量、结果总数和当前页。申请从待处理转入已办时，保留当前申请的办理结果，并清楚展示它所属的新分组。不能无提示地把右侧换成另一张申请。

### 授权记录

| 项目 | 页面约定 |
| --- | --- |
| 数据范围 | 已执行生效的授权及其后续到期记录 |
| 搜索字段 | 来源申请编号、申请人、获准资源的业务名称与适用范围 |
| 状态筛选 | 已生效、已到期 |
| 日期条件 | 按授权实际生效日期筛选 |
| 默认排序 | 实际生效时间降序，来源申请编号降序 |
| 列表内容 | 获准范围、申请人、有效截止、状态及来源申请 |
| 来源入口 | 打开对应申请的办理详情，返回后恢复授权记录的查询条件和页码 |

待审批、待执行、驳回及执行失败的申请不进入授权清单。授权期限届满后更新可用状态，保留当时的办理事实与回告。

授权记录在真实无数据和筛选无匹配时均保留“获准范围、申请人、有效至、状态、来源申请”表头、列宽及同一结果外框，空态出现在表头以下的表体区域，分页仍位于框内底部。后续管理表格沿用此规则。

## 详情、回退与筛选联动

- 每个后台模块独立保存已经提交的查询条件、页码和每页条数，切换菜单后能够恢复。
- 从列表打开详情，再返回列表，应恢复原查询和页码。继续分页或重新查询时，不再把旧选中记录强留在新结果中。
- 从回告或授权来源打开具体申请时，可能落在当前页或筛选条件之外。应明确提示这一点，并提供回到当前结果的入口。显示该申请前仍须核验当前查看权限。
- 普通查询无匹配时不默认展示上一轮的详情。外部来源显式打开的记录，可以在说明来源后保留，避免让使用者误认为它命中了当前筛选。
- 所有文本列按字段预算显示摘要，详情和搜索仍使用完整原始值。长标题、原因、姓名、范围和编号遵循[全列长内容规范](后台界面设计规范.md)，鼠标和键盘均能打开完整记录。
- 刷新时恢复查询与已保存记录，审批、执行、发布或重查等动作须由用户主动触发。恢复页面不重放这些动作。
- 处理完成后向申请人显示真实回告。店长从原问题重新查询会产生新的问数记录，原回答继续保留其当时的依据与结果。

### 行操作与更多菜单

先确定当前页面真实需要的操作，再决定是否展示操作列。存在多个操作时，行内优先展示一至两个最常用操作，其余才收纳于 32 × 32px 的省略号入口；只有一个动作时直接操作，没有其他动作时省去更多。文字操作高 32px、左右内距 8px，表单与分页控件仍为 40px。查看等主要入口使用主蓝，必要的次要动作使用中性色；动作按操作权限、资源范围、记录归属及当前状态生成，处理后同步更新。图标按钮提供可访问名称、关联浮层和展开状态。规范样张中复制编号、用途、申请人是组件验证示例，不代表业务页标配。样张的 224px 操作列与 880px 表格最小宽度也不自动成为所有页面的列预算；各页按已确定的动作计算，尺寸、图标与文字对齐按[操作列规范](后台界面设计规范.md)复用。

更多菜单使用原生 popover 顶层浮层，避免被表格滚动区域裁切。默认与触发按钮右边对齐、垂直相距 8px，下方空间不足时向上展开，保留至少 16px 视口边距。菜单项可由鼠标点击及 Tab 逐项访问，Escape 关闭后焦点回到触发按钮；相关内容滚动或窗口变化时收起菜单。

确有业务需要时才提供复制，使用完整原始字段，实际成功后才显示已复制。失败时说明未完成，并保留查看全文及手动复制入口。办理、撤销等动作按产品规则提供权限校验、危险操作提示与真实结果反馈。

## 必须区分的页面状态

| 状态 | 页面反馈 |
| --- | --- |
| 真实无数据 | 管理表格保留表头，在表体说明记录何时产生，提供当前账号可执行的下一步 |
| 条件无匹配 | 保留表头，在表体明示当前条件无结果，显示清空或修改条件的入口，结果总数为 0 |
| 加载中 | 保留查询条件、已有表头及列预算，标示正在更新，避免误操作仍在刷新的列表 |
| 查询失败 | 保留表头、条件与输入，在表体显示失败信息和重试入口，不显示为正常空结果 |
| 无查看权限 | 先阻止受限页面渲染，显示允许公开的权限反馈；受限列、记录、数量与下载入口均不展示，不显示“暂无数据”或“共 0 条”冒充空结果 |
| 数据办理中变化 | 重新核验当前状态，更新结果与可执行动作，保留使用者刚填写的有效输入 |
| 授权到期 | 展示当前可用状态与原办理事实，继续查数或查看历史结果时重新核验权限 |

空态按真实数据状态显示，不能为了填满页面伪造任务。数据筛选失败或加载失败也不能被显示成正常的空结果。

## 原型评审与验收要求

每个持续积累数据的列表，在原型评审时至少覆盖 0、1、10、11 和 100 条以上的隔离数据夹具。测试数据仅用于对应验收环境，不能混入正常业务记录或未经说明地预置到产品页面。

需逐项检查以下场景。

1. 默认页、第二页、最后一页和无效页码，核对范围、总数、重复与遗漏。
2. 在后续页搜索编号、姓名和用途片段，核对多词、全角英文、特殊符号和无结果。
3. 联合关键词、状态与日期筛选，核对组件库的中文展示、开始和结束占位、已选日期、日期范围面板、键盘输入、日期首尾边界及非法区间；修改和清空后回到第 1 页。
4. 切换 10、20、50 条，确认页面只渲染当前页的数据。
5. 打开详情、切换模块、返回和刷新，核对查询条件、页码及选择记录。
6. 从其他来源打开筛选之外的申请，核对提示、返回路径和当前权限。
7. 办理当前页最后一条记录后，核对记录移动、计数、页码收缩和详情归属。
8. 分别查看待审批、待执行、生效、驳回、执行失败和到期状态。
9. 在 PC 的 1024、1280、1440、1536px 宽窗口实际操作搜索、翻页与常驻菜单，核对内部滚动、焦点、按钮尺寸及表格区域内的横向滚动。
10. 分别用空数据、筛选无匹配、单条、长详情和大量记录检查表头是否保留、列预算及外框是否一致、滚动归属、末条内容与分页可达，以及外层文档高度与视口一致。窗口高度变化和 125% 缩放也要检查查询栏、操作列与分页的可达性。
11. 先按方案核对本页必要操作及每种状态下的可执行项；存在更多菜单时，再核对鼠标悬停、键盘聚焦、Tab 访问、Escape 回焦、视口边缘避让与滚动收起。实际提供复制时分别验证成功与失败，办理后核对动作和状态变化。

查询逻辑测试、真实接口验证和浏览器交互检查分别记录结果。查询算法通过不能代替页面视觉检查，离线原型通过也不能作为正式接口或整项目验收结论。
