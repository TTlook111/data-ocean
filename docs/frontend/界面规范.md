# DataOcean 后台界面设计规范

本页规定前端视觉尺度和布局模板。交互语义见[交互规则](交互规则.md)，业务来源见[产品方案与模块解说](../product/README.md)，实际覆盖见[原型状态](原型状态.md)。

## 统一设计尺度

### 空间

采用 4px 基础单位，常用档位固定为 4、8、12、16、24、32、48px。

| Token | 项目取值 | 使用位置 |
| --- | --- | --- |
| space-1 | 4px | 标记与短说明的紧密关系 |
| space-2 | 8px | 标签到控件、相邻按钮、图标到文字 |
| space-3 | 12px | 表格行上下内距、分页上下内距 |
| space-4 | 16px | 表单行列间距、表格中间列左右内距 |
| space-6 | 24px | 桌面工作区四边、同级主要区块间距、面板四边内距 |
| space-8 | 32px | 明确独立的大章节之间 |
| space-12 | 48px | 展示型空态或特殊阅读区的留白档位 |

同一角色的空间在各页使用同一个 token。相同卡片的上下内距对称，左右内距对称。页面容器负责区块之间的距离，面板负责内部边距，字段组负责标签和值之间的距离。

一个相邻间隔由一个父层负责。例如页面使用 `gap: 24px` 时，查询区和结果面板的相邻外边距为 0；面板已经提供 24px 内距时，直接子元素不再叠加一份。项目容器负责布局，组件内部优先通过库的主题与公开配置统一，不随意清零其内部间距或重写交互。

### 字体

使用当前系统字体回退链，中文优先保证稳定、清楚的渲染。常规界面固定以下五档，行高也随角色固定。

| 角色 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 次要编号、时间、补充说明 | 12 / 18px | 400 |
| 正文、菜单、字段标签、表格、按钮、输入 | 14 / 22px | 400，强调时 500 |
| 区块标题、关键信息 | 16 / 24px | 500 或 600 |
| 独立任务页标题 | 24 / 32px | 600 |
| 审批单主标题 | 28 / 36px | 600 |

表格采用 14 / 24px 的行内文字尺度，双行内容的辅助行采用 12 / 16px，便于与固定的行密度配合。数字、时间和页码采用等宽数字。正文、字段和说明遵循共同左轴，数值列按业务需要统一右对齐。

页面主标题承担页面定位，具体业务问题或当前办理结论承担任务重点。单个页面保留一个主要操作的主色强调，其余操作使用次级样式。

### 颜色、边框与圆角

| 角色 | 项目取值 |
| --- | --- |
| 页面底色 | #f5f7fa |
| 面板、表单控件 | #ffffff |
| 正文 | #1f2937 |
| 辅助文字 | #5b6575 |
| 分隔线与普通边框 | #e5e7eb，1px |
| 主操作 | #2f63d5 |
| 控件圆角 | 6px |
| 面板圆角 | 8px |

状态使用文字说明并配合克制的浅底色。菜单选中沿用已确定的背景高亮。焦点样式与选中样式各自表达当前交互状态，标题的程序化聚焦使用细左标记，按钮与链接保留可见的键盘轮廓。

表格、查询、分页、详情和浮层共用上述颜色与圆角。页面主体以中性色为主，主色用于当前主要动作、记录查看入口和焦点；复制等次要动作采用中性色。悬停使用浅底与边框反馈，颜色过渡为 120–150ms。焦点轮廓即时出现，减少动态效果时保留全部内容与反馈。

## 全局后台骨架

后台入口、原型范围和导航位置遵守[设计约定](设计约定.md)。本节规定布局尺度，当前代码是否落实见[原型说明](原型状态.md)。

| 区域 | 尺度与行为 |
| --- | --- |
| 顶栏 | 高 64px，品牌与当前登录账号位于固定区域 |
| 左侧导航 | 宽 216px，组别和模块层级明确，桌面常驻 |
| 导航行 | 高 40px，保持常驻侧栏和清楚的当前项 |
| 工作区 | 四边 24px，所有同类列表页共用左右边界 |
| 内容顺序 | 顶栏面包屑；工作区查询与列表工具区、结果面板 |
| 区域之间 | 统一 24px，由工作区父容器控制 |

顶栏面包屑使用正文尺度并垂直居中，工作区不重复展示大标题。相邻页面的查询卡、结果卡和页脚边界应能直接叠图比较。独立任务页确需标题时使用统一标题尺度。

后台导航负责模块切换，待处理、已办属于当前页面的数据分组。问数保持独立页面，其账号菜单为所有有效账号提供后台管理入口。个人页面和管理页面共用后台顶栏及常驻侧栏，没有管理权限的账号只显示本人菜单，有相应权限再增加管理菜单。问数与后台使用同一登录账号，菜单中不提供人员、角色或“原型视角”选择。运行图、选稿及重置等评审工具另行组织。

正式导航权限与访问反馈见[页面交互规则](交互规则.md)。当前原型固定超级管理员展示，不能据菜单可见推断服务端权限已实现。

## 共用页面模板

### 管理列表

```text
后台外壳
├─ 顶栏，品牌、面包屑、问数入口与当前账号
└─ 工作区，四边 24
   ├─ 查询面板，四边 24
   ├─ 间距 24
   └─ 完整结果面板
      ├─ 按需出现的分组或操作工具区
      ├─ 表头
      ├─ 数据行、空态及面板内留白
      └─ 分页页脚
```

查询与结果面板外边对齐。查询内部的首列、实际操作工具区与分页文字以面板内 24px 为共同起点；表格首末列外侧也采用 24px。

### 审批收件箱

复用管理列表的外壳、查询面板与底部分页。结果主体采用 256px 队列和自适应单据区，以一条分隔线区分。

队列条目四边 16px，条目内部使用 8px 排布。单据中的概况、授权决定、申请资料和处理记录共用 24px 内容内距，相邻完整章节之间由 24px 排布或一个带分隔线的章节容器统一承担距离。

申请编号与提交时间在队列中同一行排布，单据的申请人、部门与时间使用紧凑摘要。需要的数据和已知数据源在足够宽的阅读区并排，较窄 PC 窗口自然改为上下排列；保留字段标签与完整原文，不靠缩小字号或截断规则全文压紧版面。最近办理结果的状态与回看入口放在分组栏右侧，固定底栏在多子项时保留当前数据源。

常规长表单的阅读宽度上限为 800px。跨页共享页面外边界，表单内容在指定阅读区内排列。

## 共用组件

### 组件来源与原型边界

原型复用本地 Vue 3 与 Element Plus，资源版本和许可见[组件资源说明](../../prototypes/shared/vendor/README.md)。表单、日期、下拉、面包屑、树、分页与弹窗优先采用现成组件；项目只负责布局、主题和内容，不自行实现日历、菜单浮层或同类控件。

共用挂载与既有查询分页入口继续复用。存量 `RecordTable` 是当前骨架，不要求后续另建原生表格替身；后续统一组件时保留已有查询、状态和回退能力。已引入组件库不等于每个控件已完成替换，实际差距见原型说明。

### 查询表单

- 查询面板四边使用 24px，同一行和相邻行的间隔使用 16px。
- 查询区不外露“提交日期”“生效日期”等字段名称，业务日期含义保留在隐藏的可访问标签中。同一查询行的控件顶边及底边一致。
- 日期范围使用 `ElDatePicker` 的 `daterange`，空值分别显示“开始日期”“结束日期”，有值及提交值统一为 `YYYY-MM-DD`。开始与结束成对提交，清空时不限定日期；不完整或非法区间在控件附近说明。日期面板、输入、清空及键盘交互沿用组件库。
- 关键词通过占位内容标明搜索范围，状态通过选中项表达，日期范围通过开始、结束占位表达。查询控件保留隐藏的可访问标签。
- 新增、编辑和审批表单按字段需要显示标签，标签到控件间距为 8px。
- 输入框、下拉框、日期范围、查询及重置按钮统一使用组件库 `large` 尺寸，高 40px。
- 查询字段根据所在容器的可用宽度伸缩，随工作区一同调整。文字框以单项 280px、多项 200px 为排布基准，通常保留 200px 的可读宽度并吸收行内剩余空间；嵌入成员查询可采用 140–180px 的紧凑预算。
- 数据源等下拉在 180–320px、状态在 160–240px、日期范围在 280–400px 内伸缩；较窄成员区的状态可采用 112px 保底。内容不足以容纳下一组时自动换行，保持表头对应顺序，不压缩控件高度或让查询区横向溢出。
- 日期与查询操作成组换行；没有日期时，末项状态与查询操作成组，避免按钮孤立。查询、重置位于所在行末端，按钮之间使用 8px，与输入底边对齐。
- 已应用条件、错误输入和清空入口保持可见、可理解。

成员列表等嵌入结果面板的紧凑查询带可采用上下 16px、左右 24px 内距及 12px 组间距；独立查询卡仍用四边 24px。同类页面使用相同变体，不重复叠加标题、工具区或空白行。

### 页面文案

顶栏面包屑承担页面定位。结果区直接呈现表头或数据分组，工具栏只承载该页确有的操作，不添加重复的列表标题、数量条或无业务依据的批量动作。

变更核对只列当前对象、实际修改及影响；不添加无关字段“保持不变”的保证行，不重复讲解正常业务规则。需要明确目标或操作性质时优先写入标题或标签，例如“添加兼任成员 · 总部”；阻塞原因、危险操作的具体影响及恢复条件继续明确展示。

记录总数在底部分页处集中显示一次，文案为“共 N 条”。分页同时提供每页条数与页码状态，省去“当前第几至几条”的范围说明。查询控件保留原生标签或可访问名称，读屏可以识别用途。

### 结果面板、表格与分页

| 区域 | 尺度 |
| --- | --- |
| 面板工具区 | 四边 24px，同组控件间距 8px |
| 表头 | 高 48px，文字垂直居中 |
| 单行数据 | 最小高 48px |
| 双行数据 | 最小高 64px |
| 单元格内距 | 上下 12px，中间列左右 16px |
| 首列左侧、末列右侧 | 24px，与面板内容轴一致 |
| 分页页脚 | 常规最小高 64px，窄容器按两行自适应；左右 24px，上下 12px，控件高 40px |

表头与表体共享列宽和内距，文字列左对齐、数值列右对齐。列宽依据字段类型分配预算，所有文本列都执行下列长内容规则。授权记录及后续管理表格在无数据、筛选无匹配时仍保留表头和列预算，空态放在表头以下的表体区域；保留相同结果外框及框内底部分页。

列表与查询区保持工作区全宽，不用缩窄或居中外框来解决列间留白。操作列固定宽度并位于最右；其余信息列以内容预算作为保底宽度，按信息量弹性分配剩余空间。避免首列独吞空白，也不把全部列固定挤到左边。我的申请显示事项、申请数据源、时间、状态和操作，给实际识别有用的信息留出宽度，不添加无关字段凑表格。

### 全列长内容

| 字段类型 | 列表展示 | 完整内容入口 |
| --- | --- | --- |
| 题目、申请事项、资源名称 | 主标题一行省略 | 桌面悬停提示，记录详情保留全文 |
| 原因、用途、范围说明 | 与标题合排时辅助文字一行省略，独立描述最多两行 | 记录详情完整展示并保留换行 |
| 姓名、部门、业务范围 | 在指定列宽内单行省略 | 悬停辅助查看，鼠标和键盘均可打开记录详情 |
| 申请编号、来源编号、连续英文 | 单行省略，显示节点受列宽约束 | 编号或查看入口打开整条记录，详情内连续字符串可断词并可选择复制 |
| 状态 | 使用受控枚举文字与匹配的列宽 | 完整保留状态含义 |
| 日期、时间 | 使用固定格式和足够的列宽 | PC 窄窗口保留列宽，通过表格区域横向滚动查看完整日期与时间 |
| 金额、数量、比例 | 统一精度、单位和数值对齐，列宽覆盖有效数字 | 表格设置适合字段的最小宽度，横向滚动查看完整值 |

截断只作用于展示节点。搜索使用原始字段，详情从同一条原始记录取值。内容通过文本节点渲染，包含方括号、尖括号和换行时仍按原文显示。

桌面双行记录由标题 24px 行高、辅助文字 16px 行高和上下各 12px 内距组成，保持约 64px 的行密度。字段超过预算后显示省略号，完整记录入口仍可操作。原生悬停提示用于快速核对，鼠标和键盘均有明确的记录详情入口。

各页依据字段和实际操作确定列预算，同类页面保持一致。PC 窄窗口在表格区域横向滚动，表头与表体始终按同一预算对齐，保留字段名称与完整内容入口。

记录详情采用统一的 24px 内距、8px 标签间距和 16px 字段间距。正文保留换行，连续英文和编号允许断词；内容超过视口时在详情内部滚动，关闭后焦点返回触发按钮。

### 操作列

先按业务决定动作，再按完整文字、组件内距、8px 按钮间隔和单元格留白计算列宽。常用一至两个操作前置，其余用“更多”加下拉箭头；部门级使用具名“部门操作”。无其他动作时不放更多，无动作时不放操作列。

表头与实际按钮文字共用左轴，各行顺序一致，不换行、不截断。行内操作高 32px，表单、查询、日期和分页为 40px；保留完整点击区域及可见焦点。对齐按实际组件的文字和内距计算，不对所有页面使用同一像素补偿。

下拉使用组件库 `ElDropdown`，配置适当方向、分隔和危险动作样式；定位、滚动避让与键盘交互由组件处理。浮层不被表格裁切，关闭回到触发入口。操作后的反馈与对象真实状态对应，危险操作保留后果确认。

PC 窄窗口和缩放时保留表格列结构，用表格区域横向滚动承接；分页位于横向滚动区域之外。

分页按所在容器适配，嵌入部门、详情与独立列表使用同一规则。窄容器第一行显示总数和每页条数，第二行显示上一页、可输入的当前页与总页数、下一页；输入后按 Enter 或移开焦点提交。查询和重置后回到首个查询条件，翻页、调整每页条数及页码提交后恢复对应控件的焦点，不能因列表重绘落到页面根部。

查询与分页换行后，嵌入列表至少保留表头和一条记录的阅读空间。剩余空间不足时由工作区滚动承接，不能把表体压成零高或把分页裁掉。页签旁的操作与审批底部按钮同样按容器换行，保持完整文字、主次顺序和可见点击区域。

审批责任等以行操作为主要任务的列表，右侧操作列固定在可见区，背景遮住滚动内容并保留分隔；不要求先横向滚动才能执行主要动作。

### 详情、折叠区与处理记录

- 详情标题区、正文区和操作区使用同一组 24px 内距。
- 字段标签到值使用 8px，字段之间使用 16px，独立章节之间使用 24px。
- 单行折叠栏高 48px；同时展示名称和来源的双行折叠栏高 64px。独立区块左右与展开内容采用 24px，嵌入详情的紧凑清单可采用 16px 内距。
- 时间线每条事件的时间与办理人使用 12 / 18px，事件正文使用 14 / 22px，事件之间为 16px。
- 操作区的主要按钮、次要按钮与表单内容采用相同的阅读轴。

## 数据状态与适配

有权访问的表格在零数据、无匹配、单条、多页、加载、失败与办理后状态变化时使用相同表头、列预算、外框和间距。空态内容在表头以下的表体区域居中，以图标、标题、说明和实际可执行的下一步组成，内容组间距采用 8 / 16px，分页继续属于面板页脚。加载与失败在表体明确反馈，不替换成“暂无数据”。

无权状态先于表格渲染处理。受限列、记录和数量不展示，页面给出允许公开的访问反馈及去向；不能用“共 0 条”或正常空态代替权限拒绝。

PC 采用统一工作区模式。顶栏、侧栏及外层视口稳定，结果内容按余高分配，真实溢出区域滚动。极矮窗口采用工作区单层滚动，具体边界通过原型验证确定。侧栏在各 PC 窗口宽度下保持可见，表格以最小列宽和区域内横向滚动承接空间不足。

| CSS 视口宽度 | 规则 |
| --- | --- |
| 1280px 及以上 | 侧栏 216px，工作区四边 24px，查询按容器宽度伸缩并成组排布 |
| 1024–1279px | 侧栏和工作区边距保留，查询整组换行，表格按最小列宽在区域内横向滚动 |
| 小于 1024px 的 PC 窗口 | 保留侧栏与表格列结构，工作区承接缩小后的可用宽度，必要的横向滚动限制在表格内 |

## 实施与验收

数据访问配置按数据源分组，每组内排列选择控件及所选规则全文，组内 16px、组间 16px，不再追加重复汇总表。部门配置只读展示受影响成员与配置状态；本人访问列表直接展示数据源、规则和来源，不增加部门记录范围区块。规则正文、来源与操作分别表达，详情沿用固定底栏抽屉。规则清单及访问范围的补充正文单行省略，不增加展开操作；只读数据访问表、授权来源及申请回看只显示规则名称，申请的范围与结果集中在办理情况中。规则维护、配置编辑与审批核对保留全文。来源操作区右对齐，与正文以 16px 间距和分隔线区分。

角色功能配置沿用 24px 间距与既有控件，左侧浏览或搜索页面，右侧选择操作并阅读用途；两侧内容独立滚动，正常 PC 窗口内底部操作可见。角色详情的成员筛选、表头、分页及底部操作保留，表体独立滚动；极矮窗口由工作区承接。较多角色的人员分配使用名称搜索与有界滚动，不展开功能明细。
