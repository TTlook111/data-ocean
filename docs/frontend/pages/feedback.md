# 用户反馈与持续改进页面

业务含义见[模块解说](../../product/modules/07-feedback.md)及方案第 7 章。下表只负责前端页面、动作和状态表达；当前进度见[原型状态](../原型状态.md)，共用控件与布局见[设计约定](../设计约定.md)。

提问人的反馈入口、进度和回告就近放在独立问数工作台；后台负责问题队列及处理流程，不能用后台办理入口取代员工侧进度。

| 页面或区域 | 使用者职责 | 必要动作与流转 | 权限与状态边界 |
| --- | --- | --- | --- |
| 反馈与问题队列 | 具备对应任务处理或分流权限者 | 搜索、筛选与查看线索 → 核对归属并分流 → 进入获派的治理或技术处理 | 点踩、知识缺口、技术失败和巡检区分来源，分派不扩权 |
| 核查、处理与验证详情 | 对应业务或技术处理者、验证者 | 查看有权证据 → 记录核查与处理 → 关联治理修订或技术修复 → 复验 → 结案并回告可公开结论 | 反馈是线索，先核实再修改；解释结案不冒充修复，未验证不能声称完成 |
| 重点检查与历史注意事项 | 具备策略配置或核实权限者 | 配置观察窗口、有效样本等规则 → 历史样本验证 → 启用；核实后的注意事项按版本和场景供给 | 样本不足只显示线索，不因提醒自动扣分、改知识或改排序 |
