# 人员角色与权限页面

业务含义见[模块解说](../../product/modules/02-people-access.md)及方案第 2 章。下表只负责前端页面、动作和状态表达；当前进度见[原型状态](../原型状态.md)，共用控件与布局见[设计约定](../设计约定.md)。

| 页面或区域 | 使用者职责 | 必要动作与流转 | 权限与状态边界 |
| --- | --- | --- | --- |
| 人员与部门 | 具备人员或组织管理权限者 | 创建账号、维护归属 → 填写身份与来源 → 预览确认；停用或恢复 → 核对影响或当前适当权限；归档前处理关联 | 创建后待首次登录；停用、复核恢复和归档分别表达，保留历史 |
| 角色与功能权限 | 具备角色管理及对应授予能力者 | 创建或修改角色 → 配置页面、按钮和功能 → 预览受影响人员 → 校验后保存；向个人分配角色 | 角色不绑定业务数据源或数据范围，部门不分配角色；受保护管理能力另行核验 |
| 授权执行与撤销 | 具备执行或撤销权限者 | 根据获批申请核对对象、数据源、输出限制规则和申请版本 → 执行并回告；撤销 → 核对数据来源和影响 → 提交 | 额外数据访问必须有关联申请，审批与执行分开，不提供岗位直接授予入口 |
| 员工访问申请及进度 | 具有申请资格的本人 | 申请访问 → 填用途、需要的数据和可选的已知数据源 → 提交；需补充 → 修改相关业务信息后重新提交；未生效子项可撤回；查看已生效范围与回告 | 不要求知道表字段；草稿、待审批、需补充、撤回、驳回、待执行、部分生效等分别表达；问数申请与后台办理相互关联 |
| 访问申请审批与执行 | 各责任范围内的有权负责人、授权执行者 | 查看用途 → 核定数据源与输出限制规则 → 分项批准、要求补充或说明理由驳回；批准后由有权执行者复核并执行 → 回告实际结果 | 本人申请采用替代审批；独立子项可分别生效，联合组合须整体满足条件；审批与执行分别表达 |
| 授权记录 | 具有对应记录可见性者 | 查询范围、人员与日期 → 查看实际授权来源、数据源、输出限制规则和办理详情；撤权等变更进入有权授权管理流程 | 待批准或待执行不冒充已生效；来源失效保留原办理事实，技术对象按目录权限展示 |
| 权限审计 | 具有对应审计可见性者 | 按操作者、目标与时间查询 → 查看必要前后差异、原因、结果和权限版本 → 追溯关联授权或任务 | 审计不复制整份业务查询结果，敏感诊断另行授权 |
| 本人资料与申请 | 当前登录本人；他人资料管理在有权后台页面办理 | 从后台个人管理查看本人账号、我的申请及访问范围；问数保持独立 | 本人资料、申请及范围在后台；不设独立账号安全或登录会话页面 |

## 功能权限与数据访问

个人角色控制页面、按钮和功能。数据源访问来自部门初始配置或已执行生效的申请，使用对应的中文输出限制规则。部门只分配访问，不形成问数记录过滤；页面不展示自动部门范围。

后台顶栏整块头像、姓名及部门区域打开个人菜单，可前往账号信息、我的申请及我的访问范围；Esc 关闭并返回触发按钮。侧栏在路由切换后将当前项滚动到可见位置。菜单入口不代表账号信息等待制作页面已完成。

| 页面或区域 | 界面表达与操作 | 边界 |
| --- | --- | --- |
| 输出限制规则 | 在“人员与权限”下搜索、新增、编辑及查看规则名称与中文限制内容 | 维护可复用规则，不生成业务范围，不要求知道表字段 |
| 部门初始数据访问 | 每项选择一个数据源及一个或多个输出限制规则；选择项和预览展示全文，顶部显示受影响成员 | 影响直属及直属兼任成员，下级成员不继承；不配置期限或个人角色 |
| 人员分配角色 | 紧凑弹窗直接勾选角色名称，可多选或清空后保存；不设置时长，不展开页面、按钮功能，也不填分配原因或增加预览步骤 | 不改变数据源访问及输出限制规则；从人员详情进入时保存或取消均返回该人员详情 |
| 人员详情 | 个人角色只显示角色名称，不展开页面、按钮功能或有效时长；数据访问来源独立展示完整规则 | 部门访问到部门维护，额外访问通过申请；不合并计算权限 |
| 我的访问范围 | 按来源展示数据源、输出限制规则，可查看全文和关联申请 | 同一数据源的不同来源分别保留，不显示授权期限 |
| 我的申请 | 填业务用途、需要的数据，已知数据源选填；核对、提交、回看及撤回待审批申请 | 负责人核定数据源与规则，批准并执行后才生效；不选业务范围模板或期限 |

## 输出限制规则

规则保存名称和中文内容，例如“用户信息限制：不允许返回用户的身份证号码、电话号码”“产品成本限制：不允许返回产品成本信息”。授权时可同时选择多条，搜索匹配名称及全文。选择前能读到完整内容，预览和详情继续展示全文。

清单通过名称查看详情，行内保留编辑；正文最多两行，详情保留全文及换行。新增后清空会遮挡新记录的筛选条件。查看型详情使用统一抽屉，管理动作位于固定底栏。

规则仅限制交付信息，受限字段仍可用于 WHERE 等合法条件；治理“禁止使用”与输出限制分别核验。原型只展示规则，不解释中文、解析 SQL 或计算有效权限。共享规则修改对已有授权的生效方式、多来源限制的合并方式仍待确定，原型不模拟这两项策略。

## 部门配置与申请

配置变更先预览数据源、完整规则及影响成员；取消不修改示例，确认后更新。清空保存或结束部门初始访问后显示未配置，其他来源和个人角色保留。调岗更新初始来源，申请不改写组织归属；恢复部门后仍须复核保留配置。部门层级用于组织和成员管理，不自动限制源中的业务记录。

编辑时将受影响成员放在顶部，以文字展示；每个数据源的选择与所选规则全文放在同一组，不再追加重复汇总表。核对标题明确目标部门，返回修改保留原选择。

个人申请不要求知道表字段，未知数据源也能提交。核对使用业务摘要，提交后进入“我的申请”并打开待审批详情，不进入当前访问来源。审批与执行分别表达，当前办理页面仍按原型状态保留待制作，不制作审批引擎。

问数中的“申请访问”复用后台申请表单，带入当前事项卡对应的原问题和已知数据源，不直接提交或增加访问。问数和后台复用示例人员与数据源目录，该跳转仍不代表真实登录身份、跨页面申请记录和权限结果已接通。

## 我的访问范围

每笔来源下的一个数据源为一条，展示所选规则、来源和详情；来源停用或待复核状态保留。关键词匹配数据源、规则名称、中文内容及来源名称或编号，可筛选部门初始访问与申请授权。

结果面板直接展示数据源、规则名称、来源类型与编号，使用行内详情入口回看完整规则。

查询、分页和详情回退复用共用规则；零条、无匹配和少量记录保留相同表头、结果外框及分页。详情显示完整规则，申请来源可继续查看原申请，不在前端计算或合并有效授权。
