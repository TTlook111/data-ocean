# 人员角色与权限页面

业务含义见[模块解说](../../product/modules/02-people-access.md)及方案第 2 章。下表只负责前端页面、动作和状态表达；当前进度见[原型状态](../原型状态.md)，共用控件与布局见[设计约定](../设计约定.md)。

| 页面或区域 | 使用者职责 | 必要动作与流转 | 权限与状态边界 |
| --- | --- | --- | --- |
| 人员与部门 | 具备人员或组织管理权限者 | 创建账号、维护归属 → 填写身份与来源 → 预览确认；停用或恢复 → 核对影响或当前适当权限；归档前处理关联 | 创建后待首次登录；停用、复核恢复和归档分别表达，保留历史 |
| 角色与功能权限 | 具备角色管理及对应授予能力者 | 查询角色 → 新增或编辑 → 按页面配置操作 → 核对功能差异及已分配人员 → 确认保存；详情回看功能和人员，状态变更核对影响 | 角色不绑定数据源或输出限制；停用保留分配关系，不供新分配；归档前先停用且无当前分配人员，归档后只读；受保护管理能力另行核验 |

| 员工访问申请及进度 | 具有申请资格的本人 | 申请访问 → 填用途、需要的数据和可选的已知数据源 → 提交；需补充 → 修改相关业务信息后重新提交；未生效子项可撤回；查看已生效范围与回告 | 不要求知道表字段；草稿、待审批、需补充、撤回、驳回、已生效、生效失败及部分生效等分别表达；问数申请与后台办理相互关联 |
| 访问申请审批与自动生效 | 各责任范围内的有权负责人 | 核定数据源与输出限制规则 → 分项批准、补充或驳回 → 系统自动生效并回告 | 本人申请采用替代审批；独立项分别生效，联合组合全部必要项通过后一起生效，失败不能显示为已生效 |
| 权限审计 | 具有对应审计可见性者 | 按操作者、目标与时间查询 → 查看必要前后差异、原因、结果和权限版本 → 追溯关联授权或任务 | 审计不复制整份业务查询结果，敏感诊断另行授权 |
| 本人资料与申请 | 当前登录本人；他人资料管理在有权后台页面办理 | 从后台个人管理查看本人账号、我的申请及访问范围；问数保持独立 | 本人资料、申请及范围在后台；不设独立账号安全或登录会话页面 |

## 功能权限与数据访问

个人角色控制页面、按钮和功能。数据源访问来自部门初始配置或已自动生效的申请，使用对应的中文输出限制规则。部门只分配访问，不形成问数记录过滤；页面不展示自动部门范围。

后台顶栏整块头像、姓名及部门区域打开个人菜单，可前往账号信息、我的申请及我的访问范围；Esc 关闭并返回触发按钮。侧栏在路由切换后将当前项滚动到可见位置。菜单入口不代表账号信息等待制作页面已完成。

| 页面或区域 | 界面表达与操作 | 边界 |
| --- | --- | --- |
| 输出限制规则 | 在“人员与权限”下作为独立二级入口，搜索、新增、编辑及查看规则名称与返回限制内容 | 与角色功能管理并列；维护可复用规则，不生成业务范围，不要求知道表字段 |
| 部门初始数据访问 | 每项选择一个数据源及一个或多个输出限制规则；选择项和预览展示全文，顶部显示受影响成员 | 影响直属及直属兼任成员，下级成员不继承；不配置期限或个人角色 |
| 人员分配角色 | 紧凑弹窗直接勾选角色名称，可多选或清空后保存；不设置时长，不展开页面、按钮功能，也不填分配原因或增加预览步骤 | 不改变数据源访问及输出限制规则；从人员详情进入时保存或取消均返回该人员详情 |
| 人员详情 | 个人角色只显示角色名称，不展开页面、按钮功能或有效时长；数据访问来源独立展示，规则正文仅作单行补充摘要 | 部门访问到部门维护，额外访问通过申请；不合并计算权限 |
| 我的访问范围 | 相同数据源一行，展示当前有效限制的并集合并结果与有效来源数；详情展开来源及原申请 | 撤销、停用或待复核来源不参与当前限制；不改变原来源记录或设置期限 |
| 我的申请 | 填业务用途、需要的数据，已知数据源选填；核对、提交、回看及撤回待审批申请 | 负责人核定数据源与规则，批准后自动生效；不选业务范围模板或期限 |

## 输出限制规则

规则保存名称和返回限制内容，内容用中文维护，例如“用户信息限制：不允许返回用户的身份证号码、电话号码”“产品成本限制：不允许返回产品成本信息”。授权时可同时选择多条，搜索匹配名称及全文。配置与核对保留全文。

规则清单和访问范围的正文只作单行补充摘要，超出宽度直接省略，不增加展开／收起按钮。规则清单通过名称查看完整规则，行内保留编辑；规则详情、配置编辑与审批核对保留全文及换行。只读数据访问表和授权来源只显示规则名称，不重复铺开正文；申请回看将数据源、状态和规则名称集中在办理情况中，不另设重复的已生效范围表。来源中的“查看申请”放在独立操作区靠右，与正文留出间距。新增后清空会遮挡新记录的筛选条件。查看型详情使用统一抽屉，管理动作位于固定底栏。

规则仅限制交付信息，受限字段仍可用于 WHERE 等合法条件；治理“禁止使用”与输出限制分别核验。同一数据源当前有效来源的限制全部适用，中文内容相同的项合并去重，不同内容均保留。共享规则修改对既有来源的生效方式仍待确定。原型合并展示示例限制，不解释中文规则、解析 SQL 或接入真实权限校验。

## 部门配置与申请

配置变更先预览数据源、完整规则及影响成员；取消不修改示例，确认后更新。清空保存或结束部门初始访问后显示未配置，其他来源和个人角色保留。调岗更新初始来源，申请不改写组织归属；恢复部门后仍须复核保留配置。部门层级用于组织和成员管理，不自动限制源中的业务记录。

编辑时将受影响成员放在顶部，以文字展示；每个数据源的选择与所选规则全文放在同一组，不再追加重复汇总表。核对标题明确目标部门，返回修改保留原选择。

个人申请不要求知道表字段，未知数据源也能提交。核对使用业务摘要并说明提交后进入待审批还是待分流，提交后进入“我的申请”并打开详情。各入口的申请详情都明确显示申请人；待处理子项按数据源显示审批负责人，正常分派不追加规则说明，替代审批或无法分派时才显示必要原因。多个已知源分别生成子项，规则仍待负责人核定。审批页提供队列与办理单据；自动生效只联动页面内示例，不制作真实审批或授权服务。

访问申请、我的申请及授权来源回看的人员与时间口径一致：待处理显示当前审批负责人的姓名及登录名；已批准显示办理时保存的批准人和批准时间，生效失败或后续撤销仍保留原批准事实；补充与驳回显示办理人及办理时间，不能称为批准人。撤回和已结束联合申请中未办理的子项不虚构批准人，也不继续展示当前分派。申请人是这次额外访问的目标人员，批准操作不把访问授给批准人；待审批和生效失败均不能作为已生效访问。

审批页复用后台查询、状态、提交日期与分页，分为“待我审批”“待分流”和“我已审批”。前后两组只显示当前账号负责或已办理子项，未取得对应功能不展示受限单据或数量；待分流由核定分派权限控制。申请人、申请编号分别匹配，数据源与结果状态按可见子项筛选，日期按提交时间查询，分组数量与列表范围一致。联合单据只将本人负责子项列为待办，保留必要的整体办理约束。

单据保留申请人、用途、需要的数据、已知数据源、当前子项负责人及处理记录。待分流队列直接标明待核定源、缺审批责任或责任需复核；核定时实时预览匹配的办理人。缺少有效责任时直接打开当前源配置，取消仍在原申请，保存后回看原申请与新负责人，再返回保留的队列。已分派子项改源须走“重新核定数据源”，核对新的负责人并清除原源规则；批准表单只读显示已核定源，选择完整输出限制规则。批准、要求补充或驳回先核对再确认，取消不修改。核对表使用“核对内容”和“确认后状态”，明确当前办理子项，不把预计结果写成已完成事实。

办理后保留各项条件、日期、分组与有效页码，定位剩余本人待审子项或相邻申请；结果回看入口位于分组栏右侧。只读结果抽屉保留申请人、原申请、子项结果与处理记录，关闭后回到原队列位置，不提供代他人撤回的入口。多子项的固定操作区始终显示当前子项与数据源。批准后自动联动申请的数据访问来源；本人申请明确交替代负责人，停用账号不能批准。独立与联合子项的办理结果分别展示；责任来自[数据源配置](datasources.md)，路由遵循[审批责任与分派](../../product/modules/02-people-access.md#审批责任与分派)，仅模拟页面行为，覆盖边界以[原型状态](../原型状态.md)为准。

问数中的“申请访问”复用后台申请表单，带入当前事项卡对应的原问题和已知数据源，不直接提交或增加访问。问数和后台复用示例人员与数据源目录，该跳转仍不代表真实登录身份、跨页面申请记录和权限结果已接通。

独立子项批准后立即联动对应访问来源；其他子项未处理或未通过时可显示部分已生效。联合组合首个批准只显示已批准，最后一个必要审批通过后整组生效。已生效内容进入本人访问范围及人员详情；部分生效申请只允许撤回未处理子项，不收回已经生效的来源。自动生效失败显示原因，正常流程没有人工执行按钮。

## 授权管理

授权来源的查看与撤销在同一页面完成。列表明确区分被授权人和批准人，展示数据源与规则、授权来源、状态及生效时间；两类人员分别按姓名或登录名查询，再与数据源、来源名称或编号、状态及生效日期取交集，数量与分页按相同条件计算。查看权限与撤销权限分开，未获查看权不展示记录和数量；只读人员没有撤销入口。

申请来源的申请人即被授权人，详情合并标注身份，展示原申请、提交时间、所选规则及实际批准人和批准时间；联合组合逐数据源列出批准记录。批准人取办理时保存的身份，不用当前审批责任配置反推，缺少历史记录显示未记录。待处理申请的审批负责人只表示当前分派；批准后由系统自动生效，没有单独的人工授权执行人。撤销事实另行展示，不改写批准记录。从原申请返回时恢复当前授权详情、查询与页码；从审批结果可直达该申请对应的授权。独立项按所选数据源撤销，联合组合在核对中列出所有受影响数据源并一组结束；其他申请和部门来源分别保留。原因必填，核对显示剩余来源及实际限制变化；取消不修改，返回修改保留草稿，重复或过期操作须重新核对。

部门初始访问展示被授权人和来源部门，不套用申请人或批准人；由有权人员进入对应部门的初始访问配置调整，不能在授权管理中任意修改单人的部门派生授权。页面内保留已结束部门来源的快照；真实审计、失权中断及持久化未实现。

## 我的访问范围

按数据源展示一行，汇总该源所有当前有效来源的输出限制，内容相同的项去重，其他限制全部保留。列表只查询数据源名称及限制规则名称，计数按数据源计算。状态和有效来源数另列；不可用来源不加入当前限制集合。

详情明确被授权人为当前本人，先展示合并后的当前限制，再按需展开每笔来源的规则名称、状态与原申请。申请来源分别显示该数据源的历史批准人与批准时间，部门来源不套用申请或批准身份。从本人来源打开原申请沿用“我的申请详情”，不切换为管理办理入口；返回时保留原来源展开位置。来源已撤销或结束后保留历史记录，当前有效来源及限制随之更新。人员管理中的来源追溯仍保留逐笔记录，不能把聚合展示当作删除来源或合并存储。
