# 人员角色与权限页面

业务含义见[模块解说](../../product/modules/02-people-access.md)及方案第 2 章。下表只负责前端页面、动作和状态表达；正式实现见[前端入口](../README.md#当前实现与验证边界)，离线示例见[原型状态](../原型状态.md)，共用控件与布局见[设计约定](../设计约定.md)。

正式授权合并、输出限制、撤权中断及审批审计提交的服务边界见[安全执行与审计](../../architecture/安全执行与审计.md)，离线页面状态不代表真实权限或审计服务已接入。

| 页面或区域 | 使用者职责 | 必要动作与流转 | 权限与状态边界 |
| --- | --- | --- | --- |
| 人员与部门 | 具备人员或组织管理权限者 | 创建账号、维护归属 → 填写身份与来源 → 预览确认；停用或恢复 → 核对影响或当前适当权限；归档前处理关联 | 创建后待首次登录；停用、复核恢复和归档分别表达，保留历史 |
| 角色与功能权限 | 具备角色管理及对应授予能力者 | 查询角色 → 新增或编辑 → 按页面配置操作 → 核对功能差异及已分配人员 → 确认保存；详情回看功能和人员，状态变更核对影响 | 角色不绑定数据源或输出限制；停用保留分配关系，不供新分配；归档前先停用且无当前分配人员，归档后只读；受保护管理能力另行核验 |
| 授权管理 | 具有相应记录查看权者；撤销另核对操作权限 | 在同页查询来源、回看规则和原申请，核对影响并撤销 | 只展示实际产生过的授权，待审批不作为授权；部门来源到部门配置调整，撤销不提供直接授予旁路 |
| 员工访问申请及进度 | 具有申请资格的本人 | 申请访问 → 填用途、需要的数据和可选的已知数据源 → 提交；需补充 → 修改相关业务信息后重新提交；未生效子项可撤回；查看已生效范围与回告 | 不要求知道表字段；草稿、待审批、需补充、撤回、驳回、已生效及部分已生效等分别表达；问数申请与后台办理相互关联 |
| 访问申请审批 | 各责任范围内的有权负责人 | 核定数据源与输出限制规则 → 批准成功即形成访问来源并回告；或要求补充、驳回 | 本人申请采用替代审批；独立项审批通过即生效，联合组合全部必要项通过时整组生效；提交失败保留原申请状态 |
| 权限审计 | 具有对应审计可见性者 | 按操作者、目标与时间查询 → 查看必要前后差异、原因、结果和权限版本 → 追溯关联授权或任务 | 审计不复制整份业务查询结果，敏感诊断另行授权 |
| 本人资料与申请 | 当前登录本人；他人资料管理在有权后台页面办理 | 账号信息查看本人资料、编辑联系方式及修改密码；从个人管理查看我的申请及访问范围 | 本人联系方式和密码维护不要求人员管理权限；组织、角色及身份信息只读；不设独立账号安全或登录会话页面 |

## 登录与首次改密

登录使用登录名与密码，姓名、手机号和邮箱只作资料。管理员设置初始密码，首次登录或重置后先改密，再重新登录；忘记密码由有权管理员核实身份后重置，不增加统一登录、激活或独立登录会话页面。重置不改变角色、部门、访问来源或授予上限。密码与本人联系方式的具体校验见本页账号信息，演示存储边界见原型状态。

正式登录采用 Cookie 服务端会话，首次及重置后改密限制、退出、全部会话失效与时限统一见[认证方案](../../architecture/认证与身份上下文.md)；页面的退出和认证失效反馈遵守[共用交互](../交互规则.md#登录退出与失效反馈)。原型覆盖不表示已接入真实登录态或会话注销。

## 人员、部门与角色列表

人员按姓名、登录名、所属部门、状态查询；嵌入的部门成员和角色成员按姓名、登录名、状态查询。角色列表按角色名称和状态查询，不把说明作为通用搜索字段。条件顺序按实际表头排列。

选中上级部门时默认汇总下级成员，可切换仅直属；人数按人员去重，明确主兼任关系。查看汇总不产生业务权限继承。新增根部门归组织架构区；新增子部门、编辑、启停和归档归选中部门的操作菜单。成员操作归当前成员页签。

人员、部门和角色的短任务弹窗以动作作为标题，完整对象名称、状态及必要识别资料在摘要区归组；危险后果保留一条必要提醒，原因标签使用停用、恢复、归档等当前操作名称。需要预览的任务填写后进入“核对影响”，同一对象摘要贯穿核对页，输入弹窗暂时隐藏，返回修改保留草稿；状态及数量采用业务中文和单位，实际执行使用具名确认按钮。人员角色分配继续直接保存，不增加核对步骤。标题、对象、表单与底栏共用统一阅读轴，长内容在正文滚动。

登录名、部门编号和角色名称冲突就近标明并聚焦字段，保留其他输入。创建成功后清除会遮挡新记录的条件并定位新对象，编辑则保留原查询。角色候选读取失败提供重试，未就绪时禁止提交；搜索无匹配不清除原选择，保存或取消后恢复原入口与焦点。

## 功能权限与数据访问

个人角色控制页面、按钮和功能。数据源访问来自部门初始配置或已自动生效的申请，使用对应的中文输出限制规则。部门只分配访问，不形成问数记录过滤；页面不展示自动部门范围。

后台顶栏整块头像、姓名及部门区域打开个人菜单，可前往账号信息、我的申请及我的访问范围；Esc 关闭并返回触发按钮。侧栏在路由切换后将当前项滚动到可见位置。正式前端尚未接入的申请和访问入口保持禁用，覆盖分别见[正式实现](../README.md#当前实现与验证边界)及[原型状态](../原型状态.md)。

## 账号信息

账号信息使用一个连续的白底面板，按基本信息、联系方式、登录密码三组组织；分组标题、资料及操作分列对齐。基本信息集中显示姓名与账号状态、登录名、主兼任部门和角色名称；联系方式缺失显示未填写，兼任部门为空时显示无兼任部门。较宽 PC 窗口的字段分两列，窄窗口按行排列并保留常驻侧栏。姓名、登录名、主兼任部门、角色、账号状态和管理备注由有权管理员维护。

联系方式组右侧提供“编辑联系方式”，紧凑弹窗只编辑本人手机号和邮箱，均可清空，邮箱沿用人员表单的格式校验。无实际变化时禁用保存；修改后取消、关闭、遮罩或 Esc 须确认放弃，继续编辑保留输入。保存后更新同一条人员记录并刷新本人展示，返回原入口；不另建本人资料副本。

登录密码区提供“修改密码”，紧凑弹窗填写当前密码、新密码及确认新密码，支持显隐。新密码为 8–32 位且包含字母和数字，不能与当前密码相同；当前密码错误、规则不符和两次输入不一致均在字段旁提示并聚焦首个错误，修正后清除已解决的错误。取消、关闭、遮罩和 Esc 退出时清空本次密码输入。提交中阻止重复操作；成功后转到登录页显示改密结果，使用新密码重新登录，旧密码失效。该操作不依赖管理员重置密码权限。

原型仅在当前标签页会话保存随机盐与演示摘要，密码原文不进入人员数据、URL、日志、预览或存储；关闭标签页后恢复默认示例密码。联系方式仍按原型会话规则保留，刷新后台恢复初始人员示例。正式前端已接入本人资料与改密接口，真实身份核验、持久化及旧会话失效按[首批验收](../../backend/iam/验收.md#当前验证范围)核对。

## 权限审计

列表依次展示操作者、操作类型、目标对象、结果及操作时间。操作者姓名或登录名、操作类型、目标名称或编号、结果、操作日期分别查询并取交集，查询项与对应表头顺序一致；分页与返回保留当前条件。成功、失败与已拒绝分别表达，无权限反馈不显示记录或数量。

只读详情展示历史操作者与目标、时间、原因、结果、必要前后差异、关联编号及权限版本。每次批准在实际批准人名下用一条记录同时展示审批结论及生效结果，列表直接显示已生效；联合申请尚待其余必要审批时如实记录该次子项结论。拒绝操作没有实际变更时不伪造差异。历史记录不提供普通编辑或删除入口，不含密码、密钥或完整业务结果。

关联申请按本人或实际审批办理归属另核对查看能力，关闭后回到原审计详情。授权来源独立核权，按原申请编号或被撤销的授权编号定位；返回审计时恢复查询条件、页码和详情。正式 React 读取真实操作类型和审批时的生效结果，原型使用固定历史示例和本标签页内模拟的审批审计。

| 页面或区域 | 界面表达与操作 | 边界 |
| --- | --- | --- |
| 输出限制规则 | 在“人员与权限”下作为独立二级入口，搜索、新增、编辑及查看规则名称与返回限制内容 | 与角色功能管理并列；维护可复用规则，不生成业务范围，不要求知道表字段 |
| 部门初始数据访问 | 每项选择一个数据源及一个或多个输出限制规则；选择项和预览展示全文，顶部显示受影响成员 | 影响直属及直属兼任成员，下级成员不继承；不配置期限或个人角色 |
| 人员分配角色 | 紧凑弹窗直接勾选角色名称，可多选或清空后保存；不设置时长，不展开页面、按钮功能，也不填分配原因或增加预览步骤 | 不改变数据源访问及输出限制规则；从人员详情进入时保存或取消均返回该人员详情 |
| 人员详情 | 个人角色只显示角色名称，不展开页面、按钮功能或有效时长；数据访问来源独立展示，规则正文仅作单行补充摘要 | 部门访问到部门维护，额外访问通过申请；功能角色与数据访问来源分别回看 |
| 我的访问范围 | 相同数据源一行，展示当前有效限制的并集合并结果与有效来源数；详情展开来源及原申请 | 撤销、停用或待复核来源不参与当前限制；不改变原来源记录或设置期限 |
| 我的申请 | 填业务用途、需要的数据，已知数据源选填；核对、提交、回看及撤回待审批申请 | 负责人核定数据源与规则，审批通过即生效；不选业务范围模板或期限 |

## 输出限制规则

正式 React 已接入规则、审批责任、本人申请、部门配置与授权来源。访问申请保留原型的左侧队列、右侧单据和独立办理底栏，授权管理同表显示申请与部门来源。验证与对照见[授权验收](../../backend/access/验收.md)。

规则保存名称和返回限制内容，内容用中文维护，例如“用户信息限制：不允许返回用户的身份证号码、电话号码”“产品成本限制：不允许返回产品成本信息”。授权时可同时选择多条，搜索匹配名称及全文。配置与核对保留全文。

规则清单和访问范围的正文只作单行补充摘要，超出宽度直接省略，不增加展开／收起按钮。规则清单通过名称在居中弹窗查看完整规则，行内保留编辑；规则详情、配置编辑与审批核对保留全文及换行。只读数据访问表和授权来源只显示规则名称，不重复铺开正文；申请回看将数据源、状态和规则名称集中在办理情况中，不另设重复的已生效范围表。来源中的“查看申请”放在独立操作区靠右，与正文留出间距。新增后清空会遮挡新记录的筛选条件。人员、访问范围和授权来源等上下文详情保留抽屉，管理动作位于固定底栏；不将简单规则详情一并套成抽屉。

规则仅限制交付信息，受限字段仍可用于 WHERE 等合法条件；治理“禁止使用”与输出限制分别核验。同一数据源当前有效来源的限制全部适用，中文内容相同的项合并去重，不同内容均保留。共享规则保存后，所有有效引用立即使用最新内容；修改前核对内容差异及统一生效范围，历史审批和查询仍保留当次快照。原型合并展示示例限制，不解释中文规则、解析 SQL 或接入真实权限校验。

## 部门配置与申请

配置变更先预览数据源、完整规则及影响成员；取消不修改示例，确认后更新。清空保存或结束部门初始访问后显示未配置，其他来源和个人角色保留。调岗更新初始来源，申请不改写组织归属；恢复部门后仍须复核保留配置。部门层级用于组织和成员管理，不自动限制源中的业务记录。

编辑时将受影响成员放在顶部，以文字展示；每个数据源的选择与所选规则全文放在同一组，不再追加重复汇总表。核对标题明确目标部门，返回修改保留原选择。

个人申请不要求知道表字段，未知数据源也能提交。核对使用业务摘要并说明提交后进入待审批还是待分流，提交后进入“我的申请”并打开详情。各入口的申请详情都明确显示申请人；待处理子项按数据源显示审批负责人，正常分派不追加规则说明，替代审批或无法分派时才显示必要原因。多个已知源分别生成子项，规则仍待负责人核定。审批页提供队列与办理单据；批准成功即联动页面内访问来源和合并审计，不制作真实审批或授权服务。

访问申请、我的申请及授权来源回看的人员与时间口径一致：待处理显示当前审批负责人的姓名及登录名；已批准显示办理时保存的批准人和批准时间，后续撤销仍保留原批准事实；补充与驳回显示办理人及办理时间，不能称为批准人。撤回和已结束联合申请中未办理的子项不虚构批准人，也不继续展示当前分派。申请人是这次额外访问的目标人员，批准操作不把访问授给批准人；待审批不能作为已生效访问。

审批页复用后台查询、状态、提交日期与分页，分为“待我审批”“待分流”和“我已审批”。前后两组只显示当前账号负责或已办理子项，未取得对应功能不展示受限单据或数量；待分流由核定分派权限控制。申请人、申请编号分别匹配，数据源与结果状态按可见子项筛选，日期按提交时间查询，分组数量与列表范围一致。联合单据只将本人负责子项列为待办，保留必要的整体办理约束。

单据保留申请人、用途、需要的数据、已知数据源、当前子项负责人及处理记录。待分流队列直接标明待核定源、缺审批责任或责任需复核；核定时实时预览匹配的办理人。缺少有效责任时直接打开当前源配置，取消仍在原申请，保存后回看原申请与新负责人，再返回保留的队列。已分派子项改源须走“重新核定数据源”，核对新的负责人并清除原源规则；批准表单只读显示已核定源，选择完整输出限制规则。批准、要求补充或驳回先核对再确认，取消不修改。核对表使用“核对内容”和“确认后状态”，明确当前办理子项，不把预计结果写成已完成事实。

办理后保留各项条件、日期、分组与有效页码，定位剩余本人待审子项或相邻申请；结果回看入口位于分组栏右侧。只读结果抽屉保留申请人、原申请、子项结果与处理记录，关闭后回到原队列位置，不提供代他人撤回的入口。多子项的固定操作区始终显示当前子项与数据源。批准成功即形成申请的数据访问来源并追加一条合并审计；本人申请明确交替代负责人，停用账号不能批准。独立与联合子项的办理结果分别展示；责任来自[数据源配置](datasources.md)，路由遵循[审批责任与分派](../../product/modules/02-people-access.md#审批责任与分派)，仅模拟页面行为，覆盖边界以[原型状态](../原型状态.md)为准。

问数中的“申请访问”复用后台申请表单，带入当前事项卡对应的原问题和已知数据源，不直接提交或增加访问。问数和后台交接同标签页已保存的人员、规则、申请、授权及审批审计。申请保留原对话和原问题定位，详情可返回原问题；获批后重新查询使用当前访问及最新限制，撤销后重新检查剩余来源。刷新后台恢复初始示例，仍未接真实身份与授权服务。

需补充的本人申请在列表直接打开重提表单，详情也保留入口及原办理要求。表单修改需要的数据、业务用途和本次补充说明，核对显示本次实际数据源和预计分派状态。返回修改保留输入，实际修改离开时保护草稿。独立申请只重提需补充子项，已生效来源及其他子项资料保留；联合尚未生效组合整组重新核定，不沿用旧批准。重提后按当前责任重新分派，经办人仍可按原决定回看历史。

有核定分派权限者可在尚未有办理结论的单据内打开“拆分与联合设置”，按数据源增减审批子项，并选择整份申请独立办理或联合办理。同一源不重复建项，联合至少含两个源；核对时展示前后范围、方式、当前负责人和依据。取消不写入，确认后保留原范围快照与调整记录，继续保留查询、分组及有效页码；已有办理结论不能直接修改组合。

独立子项审批通过即形成对应访问来源；其他子项未处理或未通过时可显示部分已生效。联合组合首个子项通过时仍在申请审批过程中，最后一个必要审批通过时整组生效。已生效内容进入本人访问范围及人员详情；部分生效申请只允许撤回未处理子项，不收回已经生效的来源。提交校验未通过时就近显示原因，保留原申请状态。

## 授权管理

授权来源的查看与撤销在同一页面完成。列表明确区分被授权人和批准人，展示数据源与规则、授权来源、状态及生效时间；两类人员分别按姓名或登录名查询，再与数据源、来源名称或编号、状态及生效日期取交集，数量与分页按相同条件计算。查看权限与撤销权限分开，未获查看权不展示记录和数量；只读人员没有撤销入口。

正式页面在单行工具栏保留被授权人、数据源和状态。来源名称或编号、批准人和生效日期从「更多筛选」展开，窄桌面窗口也将状态收入浮层。按钮显示已应用的隐藏条件数量。生效日期使用中文双月范围日历，支持键盘输入和清除，重置会清空全部条件。

申请来源的申请人即被授权人，详情合并标注身份，展示原申请、提交时间、所选规则及实际批准人和批准时间；联合组合逐数据源列出批准记录。批准人取办理时保存的身份，不用当前审批责任配置反推，缺少历史记录显示未记录。待处理申请的审批负责人只表示当前分派；审批通过即生效，审计记录沿用实际批准人。撤销事实另行展示，不改写批准记录。从原申请返回时恢复当前授权详情、查询与页码；从审批结果可直达该申请对应的授权。独立项按所选数据源撤销，联合组合在核对中列出所有受影响数据源并一组结束；其他申请和部门来源分别保留。原因必填，核对显示剩余来源及实际限制变化；取消不修改，返回修改保留草稿，重复或过期操作须重新核对。

部门初始访问展示被授权人和来源部门，不套用申请人或批准人；由有权人员进入对应部门的初始访问配置调整，不能在授权管理中任意修改单人的部门派生授权。页面内保留已结束部门来源的快照；真实审计、失权中断及持久化未实现。

## 我的访问范围

按数据源展示一行，汇总该源所有当前有效来源的输出限制，内容相同的项去重，其他限制全部保留。列表只查询数据源名称及限制规则名称，计数按数据源计算。我的申请按申请事项、编号和状态查询。状态和有效来源数另列；不可用来源不加入当前限制集合。

详情明确被授权人为当前本人，先展示合并后的当前限制，再按需展开每笔来源的规则名称、状态与原申请。申请来源分别显示该数据源的历史批准人与批准时间，部门来源不套用申请或批准身份。从本人来源打开原申请沿用“我的申请详情”，不切换为管理办理入口；返回时保留原来源展开位置。来源已撤销或结束后保留历史记录，当前有效来源及限制随之更新。人员管理中的来源追溯仍保留逐笔记录，不能把聚合展示当作删除来源或合并存储。

## 布局尺度

数据访问配置按数据源分组，每组内排列选择控件及所选规则全文，组内 16px、组间 16px，不再追加重复汇总表。部门配置只读展示受影响成员与配置状态；本人访问列表直接展示数据源、规则和来源，不增加部门记录范围区块。规则正文、来源与操作分别表达，详情沿用固定底栏抽屉。规则清单及访问范围的补充正文单行省略，不增加展开操作；只读数据访问表、授权来源及申请回看只显示规则名称，申请的范围与结果集中在办理情况中。规则维护、配置编辑与审批核对保留全文。来源操作区右对齐，与正文以 16px 间距和分隔线区分。

角色功能配置沿用 24px 间距与既有控件，左侧浏览或搜索页面，右侧选择操作并阅读用途；两侧内容独立滚动。“取消／核对变更”放在功能权限卡片内部右栏底部，采用白底与顶部边线，按钮靠右并保留 24px 内距；页面外层不再设置操作栏。左侧目录保持完整高度，右侧清单滚动时操作区独立占位，不遮挡末项内容；受保护调整的操作原因放在同一操作区内。角色详情的成员筛选、表头、分页及底部操作保留，表体独立滚动；极矮窗口由工作区承接。较多角色的人员分配使用名称搜索与有界滚动，不展开功能明细。
