# 数据治理与业务知识审核页面

业务含义见[模块解说](../../product/modules/04-governance.md)及方案第 4 章。下表只负责前端页面、动作和状态表达；当前进度见[原型状态](../原型状态.md)，共用控件与布局见[设计约定](../设计约定.md)。

治理编辑、审核和发布分别授权；同一有权限者可以处理自己整理的内容，不强制另一人复核。

| 页面或区域 | 使用者职责 | 必要动作与流转 | 权限与状态边界 |
| --- | --- | --- | --- |
| 治理工作台与主题归类 | 具备对应源治理权限者 | 查看待治理、待确认与变化 → 选择对象；确认、调整 AI 主题建议或保留待归类 → 保存归类 | 主题归类不替代表关系确认，待归类不阻塞已确认知识 |
| 表字段、关系与指标详情 | 具备对应对象编辑或审核权限者 | 生成 AI 建议 → 查看来源与缺口 → 修改、确认或保留待确认 → 保存详细治理标签；缺资料时补充后回到原项 | AI 不替代业务确认；重新生成不覆盖已确认内容，读取遵守当前权限与预算 |
| 业务范围 | 具有对应治理查看与范围确认能力者 | 选择数据源 → 检查治理依据和缺口 → 仅基于已确认子集生成候选 → 核对范围与敏感限制 → 确认后供部门配置或申请选用 | 没有可信依据时先治理、不生成；候选依据变化或缺失时不能确认；确认范围不授予人员数据访问 |
| 治理审核与复核 | 具备对应审核权限者 | 对照建议、人工修订及依据 → 确认或要求补充 → 更新治理状态；确认内容进入知识文档生成 | 审核通过不等于发布，也不授予数据访问权 |

## 业务范围页面

数据源、关键词与候选状态集中在筛选区。结果分为“待核对”和“已确认”，生成候选放在结果工具栏右侧；待核对列表区分可核对项与需补充项，已确认列表回看确认人和确认时间。

生成前查看治理版本、确认人、确认记录及对象缺口。使用对象的业务含义与粒度、字段含义和开放限制、记录限制及所需关联必须已确认；没有可用依据则阻断生成，部分已确认时只使用完整子集，不要求等待整库其余对象。缺失对象不借用其他表的含义生成虚假候选。相同数据边界已有定义时复用已有范围，重复生成不覆盖人工核对；新增候选可表达同一治理对象下更小的开放字段集合。

核对任务采用左右对照：左侧呈现范围名称、数据内容说明、可见数据项、记录限制、排除项及核对说明；右侧展示治理版本和对象含义，字段映射按需展开。已完整呈现的定义直接在固定底栏勾选并确认，不重复跳入同义预览表格。核对说明与人工勾选仍为必需，确认本身不授予数据访问。

候选名称描述数据集合，不以“日报”“月报”等名称暗示业务能力已验证。技术字段区分开放数据、记录限制、对象关联和不开放字段。已生成候选的治理依据变化或不再完整时，以只读缺口视图呈现并阻断确认。确认后定位到已确认清单中的该项，仍只登记范围定义。
