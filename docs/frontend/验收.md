# 原型验收

只读取与本次改动有关的条目。目标功能见[页面功能清单](pages/README.md)，交互与状态见[页面交互规则](交互规则.md)，尺度见[后台规范](界面规范.md)。实际结果写入[原型说明](原型状态.md)并链接证据，不把规范清单写成已经通过。

## 页面和流程

1. 按方案核对入口、字段、必要动作、权限条件和状态，不用测试数量替代功能覆盖。
2. 走通触发、输入、预览或确认、结果、取消及返回；预览和取消不改变数据，回退保留输入。
3. 操作后重读当前状态，更新按钮、列表、计数和详情；停用、恢复及归档有可到达的后续去向。
4. 打开详情再返回，核对查询和分页；页面恢复不重放审批、执行、发布或重查。
5. 当前原型只检查显示和简单交互；真实身份、服务端权限与数据执行在正式阶段单独验证。
6. 部门只选择初始数据源与中文输出限制规则，可多选规则、查看全文，不选业务范围、表字段或期限；配置、预览和详情不出现自动部门范围，个人角色独立维护。
7. 个人申请填写用途和需要的数据，已知数据源可选填；预览和取消不生成记录，提交为待审批，详情可回看和撤回，不立即进入访问来源。问数入口带入当前事项卡的原问题和已知数据源并复用该表单，不误带合并事项的其他问题。
8. 规则维护核对必填、同名提示、搜索、新增、编辑、取消及详情；选用时可看全文，新规则保存后可在数据源配置中选用。原型不模拟共享规则变更传播或多来源合并。
9. 部门配置仅影响直属及直属兼任成员，下级成员不继承。部门层级与成员列表照常工作，不生成业务记录过滤。核对多数据源、空配置、预览、保存及来源停用或待复核。
10. 人员详情和本人访问按来源、数据源回看完整规则，不显示部门记录范围或数据授权期限；角色变更不改数据访问。
11. 问数设计验收覆盖有源授权而部门不同、不具备源授权、用户主动指定门店、别名或计算表达受限信息、受限字段仅作合法条件，以及撤销一项来源后其他合法来源保留。真实 SQL 与权限结果须在正式实现阶段验证，原型只验展示及交互。
12. 切换数据源分开对话、结果和草稿；历史恢复当次源，不能把其他源的固定样例当成本源结果。没有可用示例时明确反馈，不生成假结果。
13. 问数流程保留九个主节点；逐步阅读的前后节点顺序与源图一致，首尾按钮状态正确。补缺项回原节点、阶段与待完成任务，改变原意才重新理解，不依“已有 SQL”猜测返回位置。
14. 人员详情只展示已分配的角色名称；多个角色完整列出，未分配角色有明确状态，不展示页面、按钮功能明细或角色有效时长。
15. 列表和详情均可分配角色；弹窗标明目标，选项直接可见，多选或清空后直接保存，不设置时长、不显示页面或按钮功能、不填分配原因。取消与 Esc 不修改角色，列表入口返回原按钮，详情入口返回原人员详情；保存后回看新角色，部门和数据访问来源保持不变。新增与恢复人员也不出现角色期限或功能明细。
16. 角色维护核对名称必填与重名、页面和操作联动、功能差异与已分配人员、取消及返回修改；切页后草稿可恢复，明确取消后不残留草稿。保存重命名后人员引用与默认角色选择一致，数据访问来源不变。
17. 停用角色保留分配关系，不供新分配；启用重新可选；已分配人员未移出时不可归档，归档后只读。受保护项不可通过页面全清、重命名或普通状态操作绕过；真实授权上限在正式服务阶段验证。
18. 输出限制规则是“人员与权限”下的独立二级菜单。角色操作目录覆盖对应页面，操作用途在配置区可读；查询、重置、分页不重复配置，可见问数结果导出不单设权限。成员搜索和零结果保留表头，回看后保留角色查询及页码。

## 控件和布局

1. 新增控件先核对组件库，检查文字“更多”、中文日期和顶部面包屑是否遵循已定规则。
2. 表头、表体、空态、剩余留白及分页处于统一外框；操作表头与实际按钮文字对齐，不截断动作。
3. 主次操作清楚，范围切换与查询紧凑，标题迁移不留下空白操作行。
4. 检查 Tab、Enter、Escape、焦点回到原入口、下拉避让、日期输入及清空；危险动作有对象和后果。
5. 根据变更覆盖 PC 的 1024、1280、1440、1536px 窗口，以及缩放与较矮窗口。表格横向滚动不带走分页，末条内容和操作可达。等效视口不能记作真实浏览器缩放验证。
6. 账号区域整体可操作，菜单支持 Esc 返回焦点；当前侧栏项可见。人员角色与数据访问均不设置期限。

## 列表与示例

默认约 15 条示例，覆盖不同人、内容长度、状态及第二页。检查 0 条、1 条、无匹配、跨页搜索、末页、每页条数变化、办理后结果减少和长内容。不要为普通原型自动生成上百条记录或建立业务模拟系统；确有容量问题时再单独使用隔离夹具并记录用途。

关键词、状态、日期组合使用同一生效条件；清空条件回第 1 页。空结果、失败、加载与无权限分别表达，受限数量不可泄露。正式接口的服务器分页和权限范围另行验证。

## 证据与状态

- 界面证据放 `output/playwright`，写清页面、视口、场景及实际观察。
- 分别报告静态检查、自动测试、浏览器交互与实际 API。未做的检查明确留空，不沿用旧截图或旧测试结论。
- 确认规则后先标“已确定待落实”；源码和本次验证支持后才改为“已实现”或“已验证”。
