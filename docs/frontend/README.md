# 前端开发与设计

本目录是 React 正式前端与 HTML 原型共用的开发入口，负责页面结构、交互、视觉、组件使用及各自的实现状态。业务含义来自[产品方案与解说](../product/README.md)，真实服务职责来自[后端设计](../backend/README.md)，跨端约定统一见[系统架构](../architecture/README.md)。

## 开发前必读与完成验收

适用于前端新增、修改、重构、接口接入及共用组件调整。执行者须在写代码前主动完成以下阅读和核对；框架迁移或接入真实接口不改变已确认的界面规则，不等待负责人逐次提醒。

1. 先读[三端共用总则](../engineering/代码风格与项目组织规范.md)，明确代码组织、复用、注释和检查要求；目录及构建定位按[工程基线](../engineering/工程组织与版本基线.md#前端工程)核对。
2. 阅读[设计约定](设计约定.md)、[交互规则](交互规则.md)和[界面规范](界面规范.md)，提取本次涉及的布局、控件、查询、状态、返回与视觉尺度约束；技术实现沿用本页已确认选型。
3. 从[页面专题](pages/README.md)进入本模块，核对对应业务规则、原型页面及脚本，并区分[离线原型覆盖](原型状态.md)与[正式实现范围](#当前实现与验证边界)。正式页面按已确认原型保留导航、主要分区、信息层级、办理流程及页面承载方式。
4. 开发 React 页面前，先从[源码定位](../source-map/README.md)检查同类页面和现有共用组件，再按[组件选型](#组件与配套库)核对 Ant Design 的主题与组件能力。优先复用已有实现；确需新增的业务组件先放在所属模块，有稳定跨模块用途后再提取。修改共用组件时同时核对受影响页面。
5. 新建页面或打磨界面需要设计参考时，按[设计约定](设计约定.md#原型基准与界面打磨)从 Awwwards 查找案例，围绕本次要解决的排版、表格密度、筛选反馈等问题，结合原型和后台规范取舍。
6. 动手前按[验收要求](验收.md)选定本次相关场景；完成前逐项对照规则、原型和实际页面，检查交互、状态与 PC 布局，并按共用总则完成代码自查。构建或测试通过不能代替原型对照和浏览器交互验收。

交付时分别说明静态检查、自动测试、实际 API 与浏览器验证的结果及未覆盖项，界面证据放在 `output/playwright`。发现实现偏差时按既定规则修正；涉及已定设计或业务含义的改变，按[维护权限](../README.md#维护权限)处理，不将偏差回填为新规则。

## 当前实现与验证边界

React 已接入登录与身份权限、数据源管理、采集、目录、结构变化与企业业务说明，以及审批责任、共享规则、访问申请、授权管理、部门初始配置与个人访问范围。源码见[首批正式实现](../source-map/README.md#首批正式实现)、[数据源](../source-map/README.md#数据源接入与采集)和[数据访问授权](../source-map/README.md#数据访问授权)。

现有 HTML 原型继续独立保留，作为布局、信息层级与交互的对照基准。首批页面仍须按[验收要求](验收.md)逐项核对；源码存在、依赖安装或局部验证不代表全部页面、真实业务和跨端链路已验收。原型覆盖只维护在[原型状态](原型状态.md)，正式实现与验证边界维护在本节。

正式页面复用统一主题、导航、查询、状态和表格尺度，操作列及窄窗口固定列按实际文字对齐。读取失败、无匹配和无权限分别处理；矮窗口由工作区承接主列表纵向滚动。人员、部门和角色的短任务共用对象摘要及字段错误定位，角色分配保留原人员详情与焦点，创建成功定位新对象。角色编辑操作区位于功能权限卡片内部右栏底部；具体交互与布局见[人员权限页面](pages/people-access.md)。

正式界面与真实操作证据见[UI/UX 对照与验证](../../output/playwright/2026-11-17-ui-ux-pass2/report.html)，角色卡片内部操作区的尺寸、滚动及键盘检查见[布局验证](../../output/playwright/2026-11-17-role-footer/in-card-report.md)。静态检查、自动测试、真实 API、浏览器覆盖及缺少本机证据的项目统一见[首批验收](../backend/iam/验收.md#当前验证范围)，不以 CSS 视口检查代替原生浏览器缩放，也不从局部交互推定全部管理动作已通过。

B 批前端已复查 PC 桌面页面、浏览器原生缩放以及访问申请、授权和审计的实际操作。页面和交互的验收证据见[B 批验收记录](../backend/access/验收.md#可复验入口)。

C 批治理详情已接入表说明、字段、关联、指标及状态与依据。系统配置提供生成模型维护、治理节点分配、连接测试与历史调用回看。来源定位、固定资料回看、生成、人工修改和确认的已验证范围见[治理验收](../backend/governance/验收.md#当前验证)。

当前正式页面的原型、外部参考与前后对照见[页面和操作对照](../../output/playwright/2026-11-20-all-pages/report.html)。字段状态使用等宽分段，字段与部门成员范围均以浅底表达当前筛选，沿用原查询条件。

## 前端技术选型

正式前端采用 React、TypeScript 和 Vite，目标为单工程包含后台与问数布局，使用 npm 管理依赖；组织方式见[工程基线](../engineering/工程组织与版本基线.md#前端工程)。下列选型已确认，实际接入范围见[当前实现](#当前实现与验证边界)。

当前以本地启动为主，Node 由开发者在宿主机安装，前端通过本地开发服务运行；基础依赖及运行边界见[本地启动约定](../engineering/工程组织与版本基线.md#本地运行与依赖环境)。

当前 HTML 原型使用本地 Vue 3、Element Plus 及 ECharts，版本与许可见[组件资源](../../prototypes/shared/vendor/README.md)。现有业务前端代码可在正式重构时整体替换，不承担复用或兼容要求；承接的是已确认原型的布局、信息层级、业务流程和交互。重构边界与打磨原则见[设计约定](设计约定.md#原型基准与界面打磨)。

### 组件与配套库

| 范围 | 已确认选择 | 职责与约束 |
| --- | --- | --- |
| 基础组件 | [Ant Design](https://ant.design/docs/react/customize-theme) | 日期、下拉、树、分页、弹窗与抽屉等复用组件库；通过统一主题定制颜色、字体、圆角与尺寸 |
| 路由 | [React Router，Data Mode](https://reactrouter.com/start/modes) | 后台与问数布局、详情地址、导航及未保存离开保护；业务数据缓存统一交给 TanStack Query |
| 客户端共享状态 | [Zustand](https://zustand.docs.pmnd.rs/learn/getting-started/introduction) | 管理确需跨组件共享的交互状态；表单、弹窗等局部状态就近管理，不复制服务端数据缓存 |
| 接口数据状态 | [TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview) | 列表与详情请求、缓存、加载和错误状态，以及办理后的受影响数据刷新 |
| 表格 | [Ant Design Table](https://ant.design/components/table) | 普通业务列表使用服务端分页、筛选与排序；统一列预算、长文本、操作列、空态与分页 |
| 表单 | [Ant Design Form](https://ant.design/components/form) | 统一字段布局、联动、动态字段与校验反馈，优先使用同一套表单状态及校验机制 |
| 图表 | [Apache ECharts](https://echarts.apache.org/handbook/en/basics/import/) | 覆盖概览与问数图表，按需加载；统一字体、色谱、图例和提示样式 |
| SSE 客户端 | [eventsource-client](https://github.com/rexxars/eventsource-client) | 基于 Fetch 订阅事件，支持自定义认证头、重连及初始事件游标；业务恢复由项目按任务协议落实 |
| 样式 | CSS Modules 与统一设计变量 | 页面布局由项目维护，共用尺度集中管理；组件外观优先通过主题与公开配置调整 |

生产构建按页加载登录表单和后台业务页面。应用入口提供 404、登录核验失败和后台导航，404 直接呈现，进入有效入口后再核验身份。后台路由通过权限检查后渲染并按需加载页面。React 运行时单独成块，便于跨业务版本复用缓存。实现见[路由入口](../../frontend/src/app/Application.tsx)和[构建配置](../../frontend/vite.config.ts)。

列表查询区分待提交输入与已应用条件，按[交互规则](交互规则.md#详情回退与筛选联动)恢复查询、页码和每页条数。TanStack Query 管理接口数据；已应用条件参与缓存标识，连续查询只应用最新上下文，不能由多个状态容器各存一份结果。

任务创建、补充与取消通过普通 HTTP 命令完成，SSE 只订阅事件。普通 API 与前端 SSE 统一使用 Cookie 服务端会话，配合 CSRF 保护，凭据不放入 URL；登录失效后停止订阅和自动重连、清除受限展示，规则见[认证方案](../architecture/认证与身份上下文.md)。客户端之上需落实游标恢复、事件去重及快照衔接，断线或重新登录不重新执行任务；具体语义统一引用[调用与任务协议](../architecture/调用与任务协议.md#流式输出与断线恢复)，不把库的重连能力当作业务恢复已实现。

### 工程版本与验证边界

| 内容 | 已认可的工程基线 | 约束 |
| --- | --- | --- |
| Node.js | 22.22.2+（22.x）或 24.15+（24.x） | 两台设备可分别选择兼容版本；具体补丁及安装路径只记在本机环境说明 |
| npm | 10.9.9 ≤ 版本 < 12 | 使用同一 `package-lock.json` 执行 `npm ci` 安装，不随设备切换改写锁文件 |
| React / React DOM | 19.3.1 | 两者保持相同版本，类型包选择匹配系列 |
| TypeScript | 6.0.3 | 按当前 typescript-eslint 支持范围选择，不仅按最新主版本升级 |
| Vite | 8.3.8 | React 插件和测试工具选择匹配版本并一起锁定 |
| 代码与格式检查 | ESLint、typescript-eslint、Prettier | 分开代码质量与格式职责，兼容补丁及规则配置随实际检查验证 |
| 组件测试 | Vitest、React Testing Library | 精确依赖随锁文件固定，测试布局见工程基线；浏览器验收仍走 ego-lite |

上述版本是正式前端工程的验证基线，已使用的依赖和精确版本由 [package.json](../../frontend/package.json) 与 [package-lock.json](../../frontend/package-lock.json) 固定，构建和检查入口已建立。新增或调整依赖时核对兼容性，分别验证生产构建、组件交互及实际接入的能力；SSE 恢复等后续能力按实现范围单独验收。版本依据参考 [Node.js 发布状态](https://nodejs.org/en/about/previous-releases)、[React 版本](https://react.dev/versions)、[typescript-eslint 兼容范围](https://typescript-eslint.io/users/dependency-versions/)及 [Vite 要求](https://vite.dev/guide/)。具体版本只在本节维护，其他工程文档引用本页。

仓库不固定某台电脑的 `.node-version` 或 npm 精确补丁；需要时可在本机创建被 Git 忽略的 `frontend/.node-version`。在当前终端通过 nvm、fnm 或已有会话脚本选择项目运行时，先用 `node --version`、`npm --version` 核对实际生效版本，再执行 `npm ci`。保留 `.npmrc` 的 `engine-strict=true`，不满足范围时先切换项目版本，不修改系统其他项目的环境，也不关闭版本检查。跨设备复用代码和锁文件，各自安装 `node_modules`；兼容范围不等于另一台设备已验收，仍须各自完成构建与测试。
