# DataOcean 设计约定

本页维护 React 正式前端与 HTML 原型共同遵守的跨页面设计决定。模块的字段、筛选、状态和办理细则见[页面专题](pages/README.md)，布局尺度见[界面规范](界面规范.md)，共用操作见[交互规则](交互规则.md)；开发必读路径及正式实现范围见[前端入口](README.md)，离线演示覆盖见[原型状态](原型状态.md)。

## 使用范围

- 仅面向 PC 桌面浏览器，保留常驻侧栏、鼠标与键盘操作及桌面表格。
- 页面按完整用户任务组织，同一对象的查看、核对和办理优先在同页完成；有真实职责或记录归属差异时才拆分。
- 业务含义来自[产品方案](../product/README.md)。界面或原型实现不能自行增加、缩减或改写业务规则；原型依赖不自动成为正式选型。
- 后台按页面与按钮操作控制；办理归属、对象状态及业务证据读取继续按方案检查。隐藏按钮不能替代正式服务端校验。具体权限流程见[人员权限专题](pages/people-access.md)。

## 原型基准与界面打磨

- 正式前端以已确认的现有原型为基准，保留导航、主要内容区、信息层级、业务流程及页面承载方式，布局不大改。已确认文档与原型的差异按负责人最新决定核对，不把原型缺陷固化为规则。
- 现有业务前端代码可在正式重构时整体替换，不承担复用或兼容要求；离线原型继续作为设计及交互依据。真实重构须有明确实施任务，文档同步不代表已经开始重构。
- 允许在原布局内精修字体、色彩、间距、对齐、控件尺寸、表格密度、长内容及状态反馈；“更多筛选”可以优化展开收起、字段换行、日期与按钮对齐和已应用条件反馈，沿用既有条件、匹配规则与查询顺序。
- 改变主要分区位置、导航层级、页面承载方式或办理流程，须先说明影响并由负责人明确决定；已授权范围内的局部打磨自主完成。
- 视觉参考优先从设计作品网站和成熟产品界面案例中主动搜索，重点看企业后台、表格、表单、筛选及详情；官方设计系统和组件文档用于补充交互与核对实现能力。结合当前任务判断取舍，不照搬其他网站整体布局，不因参考增加业务功能、筛选项或辅助文案。
- 精致程度纳入[界面验收](验收.md#原型对照与界面打磨)。先以“问题队列与处理”打磨样板页，在 PC 窗口、浏览器缩放与键盘操作下多轮核对，再推广真正稳定的共用组件与规则。

## 导航与页面结构

- 后台使用常驻菜单，问数保持独立；个人功能放在后台。账号菜单及直接访问反馈见[共用导航](交互规则.md#账号菜单与原型评审入口)。
- 页面定位放在顶栏面包屑，使用真实层级和可返回的上级；没有独立页面的菜单分组不制作空跳转。
- 内容区移除重复的大标题，主操作归入对应列表、页签或区域工具栏，不留只有按钮的空行；保留程序化页面名称。
- 页签明确内容时不再增加同义标题。作用于整个页签的操作放在页签栏右侧，记录级及独立区块操作就近放置。
- 查看型详情的对象管理动作集中在底部固定操作区，主要操作在右端，低频动作归入更多；正文负责阅读。

## 组件与文案

- 原型统一使用已引入的 Element Plus，正式前端采用 Ant Design；日期、下拉、面包屑、表单、树、分页和弹窗优先复用所选库。完整选型见[前端选型](README.md#前端技术选型)。
- 行操作采用文字“更多”及下拉箭头，部门级采用“部门操作”，不用三个点。常用一至两个动作前置，剩余只有一个直接显示，无剩余动作则不显示更多。
- 原型单日期及日期范围使用 ElDatePicker，顶部层级使用 ElBreadcrumb，下拉使用 ElDropdown；正式前端分别采用 Ant Design 的 DatePicker／RangePicker、Breadcrumb 与 Dropdown。尺寸与主题由界面规范统一，不自行实现同类浮层和控件。
- 查询采用次级样式，主色突出当前主要业务操作。必填字段使用组件红色星号，选填字段直接展示名称，不重复标“选填”。
- 标签、人员、状态及视觉结构已能表达的信息不再补解释；仅保留权限反馈、异常恢复、危险后果和决策必需提示。实现说明与评审控制不混入业务流程；登录页保留“填入示例账号”。
- 列表按实际查找任务设置必要条件，不为每列机械增加过滤。查询项按对应表头从左到右排列，换行后顺序延续；各条件只匹配声明字段并取交集。具体列表条件归各页面专题，共用行为见[列表查询](交互规则.md#列表查询)。
- 校验失败聚焦首个错误字段，并关联就近说明；修正后清除已解决错误。危险操作明确对象与后果，取消不写入。

## 页面承载方式

按任务取舍，不按“查看／新增／编辑”名称统一套用容器。先判断是否围绕单个对象集中完成、是否需要同时操作主列表、是否需要持续编辑或宽表空间，以及是否会反复进入。

| 方式 | 适用任务 | 当前采用 |
| --- | --- | --- |
| 原页分区 | 连续筛选、比较、办理；需要同时操作队列和内容 | 审批收件箱、部门成员、治理工作台 |
| 居中弹窗 | 围绕当前对象的集中配置、短任务或少量信息核对，完成后回到原入口 | 数据源新增与连接编辑、角色分配、规则及审批责任详情、密码更新、核实结论、危险确认 |
| 右侧抽屉 | 主列表任务中的上下文查看、状态追踪与来源回看 | 人员、角色详情、授权来源、数据源概况、采集任务、结构变化证据、业务说明回看、审计记录 |
| 独立页面 | 宽表、持续编辑，或需要稳定地址和完整操作空间的完整任务 | 对象结构、业务说明新增／编辑、角色功能配置、治理详情 |

- 独立任务保留后台外壳与真实面包屑；表单阅读宽度不超过 800px，固定底栏与表单对齐。结构表格使用完整工作区，窄 PC 窗口由表内横向滚动承接。
- 长编辑页内离开时，仅实际修改才提示；继续编辑为默认动作，Esc 不丢弃输入。明确放弃或保存后才离开，不把未保存修改写入业务记录。刷新仍遵守离线原型恢复初始数据的边界。
- 数据源新增和连接编辑使用居中宽弹窗，填写、测试、核对在同一弹窗内完成；内容内部滚动，标题与底部操作保持可达。取消、关闭、遮罩和 Esc 统一保护实际未保存修改；继续编辑不清空输入，明确放弃后才关闭。
- 数据源次级详情在同一个抽屉内逐级查看，不叠加遮罩；返回上一级或 Esc 恢复前一层滚动与焦点，关闭按钮退出整个抽屉。
- 抽屉、弹窗和独立页面均保留明确对象、可访问名称、完整长内容和原入口回退；不是只改变尺寸或从屏幕哪一边出现。

取舍参考 [Atlassian Panel](https://atlassian.design/components/panel/usage) 与 [Carbon Dialogs](https://www.carbondesignsystem.com/building-blocks/core/patterns/dialogs)，具体界面依现有后台规范执行。
