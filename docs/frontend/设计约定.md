# DataOcean 设计约定

本页收录负责人已确认、后续设计必须沿用的决定。具体尺寸见[后台规范](界面规范.md)，交互细节见[页面交互规则](交互规则.md)。代码是否落实另见[原型说明](原型状态.md)，不能据本页推断已实现。

## 原型边界

- 面向 PC 桌面浏览器，保留常驻侧栏及桌面表格，不增加手机适配任务。
- 当前用超级管理员视图展示完整后台入口，主要列表约 15 条示例，足以观察多条、跨页和不同状态。
- 表达页面、按钮、输入、确认、返回及状态变化；只需简单交互，不建设权限计算、认证服务、审批执行或业务模拟系统。
- 示例修改只在页面内存保留，刷新恢复初始数据。正式数据持久化和刷新恢复策略按业务方案实现。

## 登录与权限

- 登录账号为登录名，配合密码；姓名、手机和邮箱只作人员资料。
- 管理员创建初始密码，首次登录和重置后修改密码并重新登录；没有统一登录或额外激活流程。
- 忘记密码由有权管理员核实身份后重置；重置密码不改变部门、角色、数据范围或授予上限。
- 页面查看、按钮操作、对应数据范围和记录归属分别表达；对象状态也约束动作。审批通过即生效，能查询不等于能审批或撤销。
- 审批决定、授权来源和必要审计在同次提交中完成；权限审计由实际批准人名下的一条记录包含审批和生效结果。联合申请全部必要审批通过时整组生效；提交失败时保留原申请状态并提示。
- 原型不写入真实密码，不把密码放进人员示例、预览、日志或本地存储。

## 后台入口与导航

- 页面按完整的用户任务组织，不按“记录”和“动作”机械拆分；同一对象的查看、核对和处理优先在同页完成。菜单清单不是强制页面边界，有真实职责或数据范围差异时才拆开。
- 访问申请服务审批工作；授权管理在一页查看实际授权来源并按权限撤销。本人在我的申请看进度、我的访问范围看按数据源聚合后的当前限制，不混入全员管理操作。

- 问数保持独立，用户菜单仅提供后台管理入口；个人功能放入后台，不另设账号安全、登录会话页面。
- 当前超级管理员原型默认进入置顶总览 Dashboard，内容未制作时也保留占位；不据此推定其他角色的看板权限。其他模块入口不因当前未细做而省略。
- 当前页面定位放到顶栏面包屑，用 `/` 分隔。真实上级页面可返回，当前页只作定位；没有独立页面的菜单分组不制作空跳转。
- 标题上移后移除内容区重复的大标题行；新增等主操作放到相应列表或区域工具栏，不能留下只有按钮的空行。保留必要的程序化页面名称。

## 组件选用

- 优先使用已引入的 Element Plus 现成组件；原型阶段继续统一这一套，不混搭控件风格，不据此提前锁定正式技术栈。
- 行操作使用文字“更多”加下拉箭头，不使用三个点；部门级操作使用明确的“部门操作”。使用 `ElDropdown`，不再自行搭建菜单和浮层定位。
- 单日期及日期范围使用 `ElDatePicker`，不使用原生日期输入代替；中文日历、格式、输入、清空及键盘行为保持一致。人员角色分配不设置期限。
- 顶部层级使用 `ElBreadcrumb`。其他表单、树、分页、弹窗等也先查现成组件；项目代码负责布局、主题和业务内容。
- 常用的一至两个操作前置，低频操作收进下拉；剩余动作只有一个时直接显示该动作，没有剩余动作则不显示更多。危险操作保留后果说明和确认，菜单内的危险操作保留分隔。
- 查询与新增或申请操作同屏时，查询采用次级样式，主色突出当前主要业务操作；说明文字只补充标签与当前上下文无法表达的必要信息，示例填入和评审标记留在显式评审模式；登录原型首页保留“填入示例账号”，便于直接进入演示。
- 页签已明确当前内容时，不再添加同义区块标题。作用于整个页签的操作统一放在页签栏右侧，随当前页签切换；记录级和独立区块的操作留在对应内容旁，多区块保留必要标题。
- 查看型详情抽屉的对象管理动作集中在底部固定操作区，正文保留信息展示；主要操作位于右端，低频动作收进“更多”，不因按钮与内容相关就移入正文区块。
- 表单校验失败时聚焦首个错误字段，输入与就近错误说明保持可访问关联；错误修正后同步清除关联。部门访问配置标题直接标明目标部门。
- 必填字段使用组件的红色星号；选填字段直接展示字段名称，不加星号，也不在标签或占位中重复标注“选填／非必填”。
- 审批办理保留查询条件、分组和有效页码，继续定位待审子项或相邻申请；办理结果通过只读抽屉回看，关闭后返回原入口。多子项的固定操作区标明当前子项与数据源；核对文案区分当前事实和确认后状态。
- 数据源审批责任在数据源管理内配置，角色审批功能与责任对象分开。待处理申请和办理详情直接展示当前审批负责人；已批准显示历史批准人及批准时间，补充和驳回显示办理人及办理时间，各入口口径一致。正常分派不附加规则解释，只在替代审批或无法分派时说明影响办理的原因。改源后重新匹配，批准表单只读显示当前源。业务路由见[审批责任与分派](../product/modules/02-people-access.md#审批责任与分派)。
- 面向使用者的原型不展示内部实现说明、正常流程解释及与当前决策无关的“不改变其他数据”等保证。已有标签、人员和状态能表达的信息不再加辅助句；仅保留异常恢复、权限反馈、危险后果及决策必需的提示。
- 列表按实际查找任务拆分必要条件，不把数据源、人员、说明等混入一个通用搜索框，也不为每个展示列机械增加查询。查询项按对应表头从左到右的顺序排列；只提供部分列的查询时，仍保持对应列的相对顺序，换行后顺序延续。各条件只匹配对应字段并取交集，范围、筛选、数量和分页保持一致；具体条件见[列表查询](交互规则.md#列表查询)。
- 审批收件箱按当前账号展示“待我审批”和“我已审批”；后者保留原审批结论，当前授权状态另行显示，撤销不改写审批结论。核定分派权限单独控制待分流。先限制办理范围，再筛选和统计；联合申请只把本人负责的子项列为待办。
- 我的访问范围按数据源一行展示；当前有效来源的限制全部适用，内容相同的限制合并去重，来源保留在详情。停用、待复核或已撤销来源不参与当前限制合并；撤销核对须说明剩余来源及实际限制变化。

## 页面承载方式

按任务取舍，不按“查看／新增／编辑”名称统一套用容器。先判断是否围绕单个对象集中完成、是否需要同时操作主列表、是否需要持续编辑或宽表空间，以及是否会反复进入。

| 方式 | 适用任务 | 当前采用 |
| --- | --- | --- |
| 原页分区 | 连续筛选、比较、办理；需要同时操作队列和内容 | 审批收件箱、部门成员、治理工作台 |
| 居中弹窗 | 围绕当前对象的集中配置、短任务或少量信息核对，完成后回到原入口 | 数据源新增与连接编辑、角色分配、规则及审批责任详情、密码更新、核实结论、危险确认 |
| 右侧抽屉 | 主列表任务中的上下文查看、状态追踪与来源回看 | 人员、授权来源、数据源概况、采集任务、结构变化证据、业务说明回看、审计记录 |
| 独立页面 | 宽表、持续编辑，或需要稳定地址和完整操作空间的完整任务 | 对象结构、业务说明新增／编辑、角色功能配置、治理详情 |

- 独立任务保留后台外壳与真实面包屑；表单阅读宽度不超过 800px，固定底栏与表单对齐。结构表格使用完整工作区，窄 PC 窗口由表内横向滚动承接。
- 长编辑页内离开时，仅实际修改才提示；继续编辑为默认动作，Esc 不丢弃输入。明确放弃或保存后才离开，不把未保存修改写入业务记录。刷新仍遵守离线原型恢复初始数据的边界。
- 数据源新增和连接编辑使用居中宽弹窗，填写、测试、核对在同一弹窗内完成；内容内部滚动，标题与底部操作保持可达。取消、关闭、遮罩和 Esc 统一保护实际未保存修改；继续编辑不清空输入，明确放弃后才关闭。
- 数据源次级详情在同一个抽屉内逐级查看，不叠加遮罩；返回上一级或 Esc 恢复前一层滚动与焦点，关闭按钮退出整个抽屉。
- 抽屉、弹窗和独立页面均保留明确对象、可访问名称、完整长内容和原入口回退；不是只改变尺寸或从屏幕哪一边出现。

取舍参考 [Atlassian Panel](https://atlassian.design/components/panel/usage) 与 [Carbon Dialogs](https://www.carbondesignsystem.com/building-blocks/core/patterns/dialogs)，具体界面依现有后台规范执行。

## 人员与部门

- 选中上级部门时默认包含下级成员，可切换仅直属；人数按人员去重，展示实际部门与主兼任关系。汇总查看不产生上下级业务权限继承。
- 当前部门的配置与下级配置分开；加入、移出、主部门调岗分别表达，不能把结束一个来源误报为收回全部权限。
- 部门只配置初始数据源和所选输出限制规则，不选择业务范围、不逐项勾选表字段、不设置授权期限。规则由有权限人员统一维护名称和返回限制内容，授权时可多选并查看全文。部门用于人员归属及访问分配，不决定业务记录可见范围；页面不显示自动部门范围或逐级业务明细权限，部门不分配角色。
- 个人角色独立控制页面、按钮和功能；变更角色不新增数据访问，部门变化不自动改角色。额外数据访问通过申请，审批通过即生效并可使用。
- 输出限制规则放在“人员与权限”下，作为与“角色与功能权限”并列的独立二级菜单。角色编辑按页面选择可执行操作；操作用途直接在配置区显示，查询、重置、分页随页面访问开放，可见问数结果导出不单设权限。
- 人员分配角色只选择角色名称，可多选或清空，直接保存；不设置时长，不展开页面、按钮功能明细，也不额外要求分配原因或预览步骤。从人员详情进入时，保存或取消均回到该人员详情；新增与恢复人员的角色选择沿用同一边界。
- 部门配置只关联直属及直属兼任成员，下级成员不隐式继承配置。额外申请核定数据源及输出限制规则。
- 人员详情的个人角色只显示已分配的角色名称，不展示页面、按钮功能明细或角色有效时长。数据访问来源另行展示；部门初始访问与已生效申请分列，结束一个数据来源保留其他合法来源。具体规则见[人员权限页面](pages/people-access.md#功能权限与数据访问)。
- 新增根部门放组织架构区，新增子部门、编辑、停用恢复及归档归入选中部门的操作菜单。
- 范围切换和查询紧凑排布，加入成员归当前成员页签；表头与实际操作文字对齐，列宽按完整动作组合预留。

## 数据源接入

- 数据源接入菜单按数据源管理、采集记录、元数据目录、企业业务说明排序。采集记录为独立页面；元数据目录与结构变化在同一页面以两个页签组织，共用数据源上下文，各自保留查询、分页和对象定位。页面合并不扩大目录查看或变化核实权限。
- 采集详情按状态组织：排队中保留等待状态和基本任务信息；采集中显示当前阶段、进度及任务信息；采集成功才显示已采集对象数、结构分析结论及结果入口；采集失败只展示实际失败原因和基本任务信息，不展示读取统计、失败阶段、受影响对象清单、候选快照或未执行分析区块；已取消显示取消原因及任务信息。失败记录保留重新采集操作。

- 采集任务只使用排队中、采集中、采集成功、采集失败、已取消；读取不全统一为采集失败，具体原因及已读内容留在任务内。只有采集成功才更新目录并分析结构变化；首次成功建立初始基线，后续成功与可比的成功快照对照。失败或取消不推进结构分析及治理；重新采集覆盖当前数据源的全部配置范围，原任务保留。系统能明确判定的差异直接确认，事实不明才交人工核实。

- 结构变化列表展示变化对象、变化类型、发现时间、处理阶段及下一步操作；阶段为待核实、待治理、治理中、知识处理中、已完成。可靠差异直接待治理，证据不足才待核实；列表分别提供核实、进入或继续治理、处理知识更新和查看结果。事实结论、来源依据、实际禁用范围及完成结果放入详情，不与处理阶段重复列示。治理禁用不作为本次问数输出限制结论；目录访问异常不因事实核实或业务处理结束而消失。
- 每条变化保留前后内容、检测证据和核实记录。待核实详情直接说明需要查证的问题；目录对象未读到时明确确认对象已删除或对象仍存在，记录依据。确认删除后禁用对象并进入治理，对象仍存在则排除结构变化。已知原因作为来源说明回看，未知原因不阻挡可靠差异；不另设原因维护任务或变更原因与核对事项区块。业务问题放在对应治理条目，避免技术核实与业务判断混在同一任务。
- 变更知识更新沿用已审核治理修订，继续草稿整理与确认、固定候选、相关验证、发布和必要的显式解除禁止。候选或治理依据变化后重新检查，验证未通过不发布，删除字段只停用依赖知识并保持字段禁止；完成后自动回写来源结果，不另办结案。

- 治理与知识目录按数据源及对象组织，不区分业务主题、业务分组或业务场景，不设置主题筛选、归类、AI 归类建议及待归类状态；表字段含义、关联和指标口径继续逐项维护。字段使用“业务含义、取值说明、使用注意、核对依据”，使用条件写入字段说明，不另建业务场景分类或场景审核条目。

- 元数据目录以“目录状态”表达对象关注项，结构变化和属性缺失可同时展示、同时参与筛选；访问丢失独立保留到成功读取恢复，待核实数量另行表达，标签区与数量区保持统一布局；没有注释、无权读取、不支持读取分别表达。普通视图不套用普通表的主键、物理索引和生成默认值。
- 治理进度与变更后待核对项分开：待治理、治理中、已治理仅汇总表说明与字段，直接展示范围及确认数量；关联、指标分别审核，知识发布单独表达。受影响条目标为业务定义待核对并直接进入治理，展开具体来源的变化前后内容及需要核对的业务事项，不把待复核混作进度或提示重复核实元数据。接入概况与治理工作台沿用同一口径；元数据目录列表及对象结构页聚焦结构、采集和访问状态，不展示治理进度、确认数量或待核对项，治理入口继续保留。治理工作台保留已确认的“变更后待核对项”列及具体条目入口，受影响对象数量可以与三种进度重叠；部分已确认知识可独立发布，不因此改成整表完成。数据源侧“变化核实”只记录事实与证据核对，不等于治理确认或发布。
- 数量对保留斜杠形式，发现数在前、处理数在后，例如发现 7 项、处理 4 项显示为“7 / 4”，零项显示“0 / 0”。治理中的表说明与字段、关联和指标使用“已发现 / 已处理”，处理数仍按当前确认口径统计，保存但未确认不计入；采集记录成功时显示本次对象数量，采集中按进度显示已尝试读取；失败只显示原因，原始读取计数仍可保留在任务记录中。
- 采集成功的结果汇总本次表和视图数量及结构分析结论，不暗示业务数据质量或治理完成。排队和运行中的任务不展示成功结果；失败直接显示实际原因，取消显示取消信息，任务结束后不保留进度条。
- 采集任务保留启动时的配置修订；变化记录关联发现任务及前后快照，后续采集不改写旧记录来源。数据源概况中的采集状态和时间随任务更新，更新不得清空查询或移动焦点。
- 变化事实只在数据源侧核实一次，可靠差异自动确认，来源不明按需核实；无法下结论时取消或返回，保留待核实。同一张表及字段的待核实项全部确认或排除后，主动进入表治理，其他已核实对象可继续办理。工作台仅保留表治理列表，通过待处理内容列和处理内容筛选直接定位受影响条目；来源结论、证据和前后差异只读沿用，不再核实或另填无需修改结案。实际受影响或影响未明的业务内容在原条目补充、修改、审核，未受影响条目保留原确认；目录可见性改变不重置业务定义。条目审核自动回写来源进度，需要更新知识时保留知识处理中，不自动发布或解除禁止。来源往返保留数据源、条件、有效页码、滚动与焦点。
- 结构变化中的对象和变化项分开：对象只包含真实表、视图或字段路径，表注释、目录可见性等属性不拼成字段名；列表、详情、查询和复核核对保持一致。
- 企业业务说明按数据源供该源治理人员和获准治理任务共享，不选择额外可使用人员；原始附件按后台资料权限查看和下载，正式发布的通用知识按当前源问数授权取用，不继承原始资料逐人名单。
- 治理生成建议时自动取用当前源获准且有效的业务说明最新修订；生成范围仍由治理任务确定，资料清单只读，不逐份勾选。预览和取消不留引用，实际生成绑定当次修订并与资料引用记录联动；采用建议与人工确认分开，新任务不改绑旧来源。
- 业务说明仅在所有修订均未被治理任务取用或成果引用时允许删除；历史及在途引用同样阻止删除。已使用资料通过撤下停止后续取用，可恢复并保留操作记录；删除、撤下、恢复分别按操作权限核验。列表直接显示编辑、撤下／恢复与删除，删除受阻时禁用，并在悬停或键盘聚焦时就近显示原因。
- 配置与资料只在内容实质变化时新增修订；启停、撤下和采集记录各自的状态变化，采集快照不代表结构修改次数。必要操作原因在核对与处理后详情中保留，自动失败原因只读展示。
- “对象世代”保留在来源与采集信息中，标签右侧问号仅在悬停或键盘聚焦时解释含义。说明适用于表、视图等对象；普通采集或修改定义不自动换代。确认同名对象重建且待核对时，在详情顶部提示；疑似重建不能当作已确认。
- 数据源详情的用途、表或视图注释、结构变化证据及影响说明按整行阅读，短字段可双列；长文本保留换行并允许连续英文断行。长标题省略显示时在正文保留完整名称，抽屉边界、关闭入口和底栏保持固定。
- 元数据目录使用“解释”，不限定中文；来源注释按原文保留。详情按对象类型标为“表注释”或“视图注释”，字段列表使用“字段注释”，明确注释所属层级。
- 数据源详情用“已禁止使用的知识”展示数量，有记录时可打开具体知识内容、依赖对象和禁止原因；当前有效配置修订归入“配置记录”，不混入采集与知识摘要。
- 常规接入表单不设置“网络与加密”配置区，不要求填写 TLS 校验、证书引用或连接超时；加密、服务器证书信任与超时由平台连接策略处理，连接测试继续展示对应检查结果。
- 数据源不设置生产／测试“环境”标签，连接表单、详情、列表及配置数据均不保留该字段。
- 技术联系人和业务联系人均为选填，默认不选，可清空；未指定时显示“未指定”，不阻止连接测试、启用或采集。联系人仅供使用者通过企业现有渠道自行联系，不触发系统通知或任务分派，也不用于授予权限、分派业务说明填写或决定访问审批责任。
- 当前连接表单明确使用“数据库”“数据库只读账号”“数据库密码”，新增时不预填示例数据库账号；已设置的密码保持不回显，编辑时留空沿用已有密码。
- 连接启用后进入当前源的目录，提供首次采集入口；元数据采集只核对一次范围和账号，不再用重复的变更前后表增加步骤。危险状态操作继续保留影响核对。
- 对象详情优先显示字段与业务解释，来源标识、对象世代等调查信息收在可展开的来源区。编辑现有连接保留原查询，任务实时结束后更新适用操作并保留可重试入口。
- 数据库版本由连接测试识别，只读展示；识别前显示“测试后识别”，失败显示“未识别”，不设置手填的“版本线索”。修改连接参数或切换数据库类型后清除旧识别结果。
- MySQL 不显示 Schema 字段；PostgreSQL 的“Schema 范围”在测试后从返回的可见列表中多选，首次选中全部返回项，启用前至少保留一项。调整选择不重复测试连接，核对与采集记录保留所选范围；采集中不可调整范围，已采集源改变范围后标为待重新采集。目录与治理交接保留 Schema 身份，区分同名表。
