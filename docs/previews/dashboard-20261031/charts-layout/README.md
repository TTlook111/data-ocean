仍采用紧凑顶部横带＋主任务区＋右辅助区。顶部条形分布表达数据源的准备状态，右侧横向条形图比较治理问题数量；主区保留具体待办、下一步及准备就绪的来源。手机优先展示来源概览与待办，治理问题图放在后面，不需要横向寻找主动作。

## 图表数据与边界

| 图形 | 可依据的现有数据 | 演示值及限制 |
| --- | --- | --- |
| 来源准备分布 | 数据源列表和readiness返回的askable、blockReasons，以及缺失的读取结果 | 正常态2个来源：可问数1、已确认需处理1；准备中与未知独立分类 |
| 治理问题数量 | DashboardStats.openIssues、resolvedIssues | 正常态未解决3、已解决9；同一时点计数，不是治理完成率 |

来源分类沿当前工作台逻辑：askable为可问数；不可问数且有阻断原因归需处理；不可问数且无阻断原因归准备中；列表中未成功读取readiness的来源归未知。未知不分摊到就绪或已确认阻断，已确认阻断为0不代表未知来源没有阻断。

治理问题、审核、文档发布、RAG索引是独立状态，**没有合并成一个完成率**。当前工作台接口只有当前统计和事件列表，没有提供时间序列；因此未画折线趋势，也没有把最近动态伪装成趋势数据。

数据形状依据：[工作台统计接口](../../../../frontend/src/api/admin/dashboard.ts)、[数据源准备接口](../../../../frontend/src/api/admin/datasource.ts)、[现有工作台状态派生](../../../../frontend/src/views/AdminHomeView.vue)。正式采用仍需沿用各项能力和范围判定；本样稿没有新增接口或权限。

## 可体验内容

场景选择器可切正常、无待办、无来源、准备中、读取失败、部分未知、无工作台权限。来源分布可打开数据表或聚焦来源待办；治理图可聚焦治理待办；已有下一步只显示路由去向预览。所有动作在本地模拟，不请求API、模型，不写业务数据。

图形有文字数量、状态标签和未知纹理，不只依赖颜色；来源图提供可展开数据表，治理图保留直接数值与可读摘要。支持键盘操作、Esc关闭预览和返回焦点。

已在Chromium桌面/390px检查七场景共14组，并实际查看截图；包括筛选、数据表、图形聚焦、正确血缘菜单去向、空/失败/未知/无权限、长名称、窄屏溢出与控制台检查。全部是独立合成演示，不能视作真实服务或角色验收；未重复执行正式前端测试/构建。

采用现有UI UX Pro Max 2.15.0本地指引，核对分类比较条形图、直接标签、颜色之外的状态表达和可读数据。保留项目现行配色、字体、Logo；图标Lucide的ISC/MIT许可包含于HTML。

菜单保持：**数据资产→关系与影响（分组）→数据血缘（二级）**，没有另加Dashboard或修改正式导航。
