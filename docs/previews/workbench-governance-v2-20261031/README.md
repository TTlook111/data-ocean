## 两页各自负责什么

**工作台是工作入口。** 当前接口能证明可访问范围和若干摘要，却不能证明“这项工作分配给我”“我最近做过它”或“上次编辑停在这里”。因此本版不用个人待办、最近访问或继续上次的说法。

主区集中一个按现有能力组合选择的工作入口：治理维护示例进入字段治理；审批查看示例进入申请与审批；只读观察示例进入治理总览。主区底部只保留一条与能力有关的摘要，下方最多两个其他工作入口。右侧承载已核验的本机范围偏好，或审批所用的负责范围说明。范围偏好不是任务进度，打开目标工作区仍须重新验证。

不放全系统统计、问题清单、活动流水或图表墙。工作台的目的在于降低开始工作的成本；数量只是帮助确定关注方向，处理留在专页。无摘要事项时直接转为开始入口，不保留空待办容器；摘要失败时数量未知，已核验入口仍可用。审批查看者不额外依赖元数据快照。

**治理总览是当前来源＋明确快照的分析页。** 用一个统一外框组织三种不同问题，而非复制工作台：

- 主图“未解决问题集中度”：以横向堆叠条比较各表问题数量，同时呈现待处理、已确认、重新打开三种互斥处理状态。
- 右区“问题来源构成”：解释同一问题集合中 SOURCE 与 SEMANTIC 的分域，不能解释为质量评分。
- 下方“来源校验执行覆盖”：独立呈现最近校验批次中规则的执行情况。执行成功可以同时发现问题，不能解释为质量通过。

页头只显示问题条数与涉及表数，并明确来源和快照。总览不放完整问题/待办列表、编辑表单或处理按钮；点击图形预览既有问题页的真实筛选目的地。没有时间序列合同，不画折线；不把审核、复查、文档发布、RAG 构建或收录资格揉成一个完成率。

表集中度需要完整分页聚合，现有摘要无法直接提供。样稿因此同时提供“聚合不完整”状态：保留权威总数、分域和处理状态，撤下表排行与涉及表数。有关范围、权限和筛选的支持程度见 [METRICS.md](METRICS.md)。

## 空间与交互

沿用当前暖白、墨色、铜色及已有品牌资产。工作台采用主工作区＋右辅助区；治理总览采用集中度分析主画布＋构成分析侧区＋横向校验带，避免两页只换标题。页头、正文与底部共用边界，内部按内容自然排布，不用固定等高卡片填空。

仅设计 PC。截图分别以 **1280×720、1440×900** 渲染；没有制作或测试手机布局。图表有直接数值、单位、状态文字及可访问名称，颜色仅辅助区分。原生按钮支持键盘，原生对话框支持 Escape、关闭与焦点返回。

安全交互均为本地演示：入口和图形只打开目的地预览，不导航到真实服务，不调用业务写入、模型或任何 API。顶部可切换能力组合与读取状态；这些是能力示例，不是新增角色或权限政策。来源/快照切换清除旧图与弹层，晚到的演示回调不会覆盖新范围。

## 数据与验证边界

全部数量、来源名称、快照与批次均为构造示例。工作台 15 条是演示角色可查看范围的跨范围问题摘要；治理总览默认 12 条只属于来源 #2、快照 #31，另一演示范围有 3 条。它们分母不同。来源阻断数、申请数和问题数不相加成总任务数。

本轮 Chromium 本地浏览器检查 **54 组通过**：工作台 3 种能力示例×6 种状态×2 种桌面宽度，治理总览 9 种状态×2 种宽度。覆盖加载、确认的 0、失败、无权、部分读取、来源/快照切换、旧回调丢弃、图形筛选目的地、键盘及焦点返回；两页均无问题表格或编辑输入。实际查看了两页两种宽度截图，以及审批、部分读取和读取失败等代表状态。图表分段数值的文字对比度经计算为 5.03、5.28、5.01。

这是静态合成场景验证，**不是当前真实后端、IAM、数据聚合或业务流程验收**。本轮未修改或重新运行正式前后端单测、构建和模型链路，未声称远端 CI 通过。正式采用仍需用户确认，再接真实数据并由真实环境验收；当前合同缺口不得通过猜测数量、补宽权限或虚构筛选来掩盖。

实际使用已安装的官方 UI UX Pro Max CLI 2.15.0 技能，读取 SKILL.md 并查询 `comparison ranking bar`（chart）、`empty state next action`（ux）、`keyboard focus navigation`（html-tailwind）。采用其比较图直接标签、明确空态、主动作与键盘焦点建议；按本次用户要求仅做桌面。HTML 保留内嵌 Lucide 图标许可。
