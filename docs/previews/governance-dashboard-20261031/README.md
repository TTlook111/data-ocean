## 这个总览回答什么

1. 当前来源与明确快照，有多少未解决问题，来源问题和语义问题各多少？
2. 问题集中在哪些表、处于哪些处理状态？
3. 最近来源校验是否完整，哪些规则仍失败、不适用或未执行？

环图表达同一问题集合的两类构成，旁边保留精确条数与可用键盘操作的分类按钮；表排行用条形图比较数量。选择分类、处理状态或表，可以组合筛选下方明细，随后查看完整说明。图形保持快照整体分母，筛后数量另标；清除筛选、分页和只读详情均可操作。

来源校验用独立覆盖条呈现，PARTIAL/complete=false不会显示本次完整评分；规则执行成功不等于质量无问题。审核、复查、发布、索引不合成为完成率，也没有编造时间趋势。

## 哪些数据可支持

问题总数、SOURCE/SEMANTIC分域、OPEN/CONFIRMED/REOPENED状态数可直接取现有问题摘要。表排行与涉及表数需读取完整问题分页后聚合，本版仅演示该派生能力；现有摘要没有总体对象排行。若分页不全或期间发生变更，不能拿一页凑总体，样稿会保留摘要并隐藏排行。正式采用前仍需确定完整读取的上限/取消/变更检测或后端聚合方案，不能将此样稿当成已增加接口。

没有展示表/字段治理状态分布或待审核积压：前者属于对象准入且需要额外目录权限，后者要核对完整任务/修订范围，不能借当前问题数代替。没有时间序列合同，故不绘折线。

## 演示与验证

默认12条未解决问题：来源8、语义4；待处理7、已确认3、重新打开2；涉及products/orders/customers/inventory四表，分别5/4/2/1条。记录、规则和数值均为构造数据，不定义真实业务规则或指标。

场景可切正常、无未解决问题、读取失败、缺问题查看权、缺校验查看权、无可核验批次、明细不完整、无总览权限。可以换来源/快照；旧选择、页码与详情随范围清理，不复用旧对象。

Chromium在1280/1440两个桌面宽度检查八场景共16组，通过组合筛选、分页、键盘Enter/Esc与焦点、详情、切源和快速切换、失败恢复、独立权限、完整/不完整明细、血缘菜单去向、控制台与整页横向溢出检查；已实际查看桌面及关键错误截图。全部是独立HTML的合成演示，没有业务API、模型或写入，不替代真实前后端/角色验收，未重复运行正式工程构建。

沿用当前字体、暖白/墨色/铜橙及Logo，使用云端已安装UI UX Pro Max 2.15.0的分类比较、构成图和可读标签指引。图标为Lucide，许可嵌入HTML。环图有数字/文字摘要，状态不只依赖颜色。

导航沿现有配置，数据血缘仍在「数据资产→关系与影响→数据血缘」二级位置。没有新增Dashboard导航、修改正式前后端、权限或业务数据，也未发布网站或GitHub Pages。首页已有两版预览保持原样，均不代表已获正式落地批准。
