## 为什么继续改工作台

审视用户指定的 [V2 工作台截图](../workbench-governance-v2-20261031/workbench-1280.png) 和 HTML 后，有三个具体问题：

1. 大块说明和入口占主位，缺少当前要工作的具体对象；用户仍要到下一页才能判断从哪里下手。
2. “本机范围偏好”与跨范围摘要并排，却没有把对象、状态、下一步连接起来。
3. 主要内容仍像菜单的文字展开，信息价值偏薄。继续调整颜色或放大按钮不能解决。

V3 采用一个**来源准备预览＋聚焦下一步**的工作区：左侧比较负责范围内最多三个来源的准备回执，选中后在右侧显示该来源的具体阻断、已发布/最新采集依据，以及一个有权进入的下一步。底部仅保留一条范围内问题摘要；不是个人分派，也不是完整任务清单。

它和数据源管理页的区别在于范围与动作：这里只展示有限预览、理解阻断和进入专页；不放完整管理列表、编辑/删除/启停、测试连接、发布或批量处理。它和治理总览也不同：总览分析问题分布，工作台围绕具体来源连接后续工作，不搬治理图表到首页。

## 按真实能力组织内容

- **数据准备示例**：三份来源准备回执，选中来源后核对版本、连接或知识准备。字段治理和知识文档是当前来源的次级入口，不能指向另一个来源。
- **准备查看、无版本权限示例**：仍能读准备回执，但对应版本入口禁用并明确原因；不借数据源查看权补宽版本查看权。
- **字段核对、无数据源查看权示例**：不展示或读取来源准备矩阵。使用已核验的范围偏好进入字段工作区；范围未核验时不传旧来源/快照，进入专页选择。
- **审批查看示例**：只预览最多两条现有审批队列数据及其总数，说明对象和用途，处理留在审批专页。无需元数据辅助读取；队列可见不等于可以批准，也不等于分派给我。

以上是合成能力组合，不是新增角色或真实账号。全部能力仍应来自正式 S1 摘要及同绑定负责源，目标页面和后端重新核验。

## 两个容易误解的边界

**后台准备条件满足，不代表当前账号能问数。** 已核对管理员 readiness 实现：授权配置读取的是是否存在有效查询授权，不是调用者个人的业务查询权。因此页面不放“你可以问数”或直接发问按钮，明确实际提问还需独立核验。

**知识索引单独展示。** 当前 readiness 的基础判定不把 `knowledgeReady` 新加为硬门禁。示例商品库的基础条件满足，但没有活动索引，界面保留两个事实。治理列只核对已发布快照的高危阻断；没有发布版时显示“无发布版”，不把布尔占位当质量通过。详见 [合同核对](CONTRACTS.md)。

## “需重新处理”是什么

治理图表原“重新打开”对应 `REOPENED`。本版改为 **“需重新处理”**，点击“状态说明”可阅读完整解释，支持键盘打开、Escape 关闭及焦点返回。

它表示：**此前已经结束处理的问题，又回到需要确认、处理的范围。** 可能由人工重新开启，也可能由语义复查触发，不能统一说成复查失败或再次发现。只改样稿文案，不改正式枚举、状态机、统计或接口。图表仍传 `status=REOPENED`，没有转换成另一类问题。
