# DataOcean 后台产品体验优化建议

日期：2026-10-03。目标是让数据管理员更快判断“哪里需要处理、下一步去哪里”，同时保持现有业务和授权边界。本文是设计建议，不替代[后台重构状态与整改计划](completed/DataOcean后台重构状态与整改计划.md)中的项目状态与导航决策。

## 1. 已明确的设计要求

- 左侧保留工作台、数据接入、数据资产、数据治理、语义中心、权限与组织、运营与平台七个业务域；当前域的二级工作区仍在左侧。
- 账号头像、姓名、账号菜单固定在侧栏左下角，与问数端一致。顶部只保留页面上下文和通知等必要动作。
- 后台外壳和工作台不单列“进入智能问数”；全局切换放进账号菜单，是否显示读取 IAM-SIMPLE-1 的 `queryUse`。管理员身份标签不能代替功能授权。
- 维持当前蓝色视觉语言、系统字体和已有 CSS 变量；不增加新导航层、角色模型、业务接口或装饰性图表。

账号入口要求落到 `AdminShell.vue`。数据源详情主动作按后端阻断原因决定，已就绪时进入数据资产；全局问数切换通过账号菜单。知识文档中原有的对象验证入口仍保留，不能把移除外壳入口表述成所有后台页面入口都已移除。

## 2. 从用户任务出发简化

| 用户当下的问题 | 页面应优先回答 | 当前主要负担 | 建议处理 |
| --- | --- | --- | --- |
| 今天要处理什么？ | 哪个数据源有阻断，去哪里解决 | 工作台多块零值卡片和重复就绪度 | 将阻断项放前面；全部就绪时给出简短说明；数据源只出现一个摘要 |
| 这个数据源准备到哪一步？ | 当前条件、阻断原因、下一步动作 | 流程、百分比、就绪面板、当前阶段反复说同件事 | 一个准备条件清单，保留具体阻断和工作区链接 |
| 怎样找到并管理一个数据源？ | 搜索、状态、查看详情 | 行内多个平级操作、英文内部状态码 | 主动作保留“查看详情”；低频操作进“更多”；中文状态优先 |
| 数据质量是否需要处理？ | 所选数据源和快照的校验结果、问题 | 两处快照选择和默认展开的全部规则 | 共用一个范围；结果与问题优先；规则配置通过已有工作区进入 |
| 知识能用于问数了吗？ | 文档审核发布、索引是否生效、下一步 | 构建记录、模型信息、Join 配置挤在主流程里 | 主流程先呈现文档状态和构建状态；技术记录通过展开区查看 |

前端文案应说明用户可以做什么，例如“查看准备条件”“当前没有阻断项”。“来自 readiness，不在前端重新拼装业务结论”这类实现说明放进开发文档。实现仍必须读取后端 readiness，不能因为隐藏技术文案而改由前端推导业务状态。

## 3. 视觉与交互规则

1. 每页一个主标题。外壳显示简短路径或上下文，业务页面显示标题和主动作，避免两处同样的 H1。
2. 每页突出一个主要动作，次要动作靠近对应对象；用分组、间距和细分隔线组织内容，减少层层套卡片。
3. 正常、阻断、加载、失败分别使用明确文字；颜色是辅助，不能只靠红绿点判断状态。
4. 继续使用 `--do-primary`、`--do-primary-strong`、`--do-primary-soft`、`--do-line` 和现有字体。常规正文 14–16px，主要区块间距约 24px，行内间距约 8–12px。
5. 保留键盘操作、清晰的焦点边框和图标按钮名称。侧栏折叠后账号仍可打开，菜单关闭后焦点应能继续操作。
6. 空状态简短说明原因并给出适用动作；没有任务时不占用大块插图和多个空卡片。接口失败不能显示成“没有问题”。
7. 技术细节可以折叠，影响正确操作的业务规则必须保留。特别是“发布知识文档”和“授权人员明确确认知识索引构建”仍是两个独立动作。
