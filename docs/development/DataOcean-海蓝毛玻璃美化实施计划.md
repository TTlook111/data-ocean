## 1. 目标与范围

将现有 Vue 应用统一为：**海蓝重点区＋浅色毛玻璃＋清晰的白色内容区**。

效果应同时具备辨识度和日常可用性。第一眼能看到明确的重点，侧栏与面板有通透的材质和前后层次，表单、对话、图表与表格保持清晰。

| 页面 | 视觉任务 | 材质与重点 |
| --- | --- | --- |
| 登录 `/login` | 建立品牌印象 | 左侧海蓝玻璃品牌区与小角色，右侧更厚的乳白玻璃表单 |
| 问数 `/query` | 提问、阅读、分析 | 玻璃集中在外壳和输入栏；消息、图表、表格使用更接近白色的底 |
| 后台工作台 `/admin/workbench` | 发现待处理事项 | 海蓝任务重点区＋开放数字摘要＋数据源与活动分栏 |
| 其他现有后台页面 | 管理对象与执行操作 | 共用玻璃外壳；列表、详情、治理、知识等内容保持安静、清晰 |

本轮包括视觉令牌、材质、背景、布局协调、控件状态、登录角色互动保留、响应式兼容和必要的样式适配。整体覆盖现有前端，核心三页先完成，再巡查其他后台页面。

沿用现有 Vue 3、Element Plus、ECharts、GSAP、Lucide、API 和组件。不新建原型应用、不切换 UI 框架、不升级依赖、不改变 Java/Python 职责、权限模型或数据库。新增功能和业务逻辑整改不属于这份美化任务。

## 3. 共用视觉系统

### 3.1 统一项

三个入口共用品牌标识、品牌蓝、文字色、字体、按钮、图标笔画、圆角层级、细边框、焦点状态和账号入口样式。

- 基础背景是浅冰蓝与白色。海洋光影作为边缘背景，问数阅读区最淡，后台适中，登录品牌区最明显。
- 侧栏和顶栏采用乳白半透明玻璃，细亮边和柔和阴影体现层次。
- 主内容面板更厚、更白；图表、表格和长文阅读区接近实白。
- 海蓝重点区承载当前主要任务或品牌内容，每页控制数量。普通列表、详情和设置页不复制工作台的大型蓝色任务块。
- 通过对齐、间距、字体和分隔组织内容，不给每条记录、每个指标都套玻璃卡片。
- 背景与材质保持静态。常规 hover、focus、切换使用短过渡；持续鼠标互动只发生在登录角色。

### 3.2 令牌建议

以下为实现起点，允许根据实际画面对照微调，但必须集中管理。避免各页各写一套透明度、阴影和色值。

| 类别 | 建议值/原则 |
| --- | --- |
| 品牌蓝 | 延续 `--do-primary-strong: #2563eb`；常规动作可统一为 `#2d68cc` |
| 文字 | 保留 `--do-ink: #172033`、`--do-muted: #64748b` |
| 语义色 | 继续使用项目的成功、警告、危险色，不把状态颜色改成装饰色 |
| 玻璃外壳 | 乳白透明度约 65%～78%，背景模糊约 16～20px |
| 内容面板 | 乳白透明度约 82%～92%，背景模糊约 10～16px |
| 数据区域 | 白色透明度约 96%～100%，无需明显背景模糊 |
| 边缘与阴影 | 1px 半透明白/浅蓝边；低强度冷色阴影，不使用厚重发光轮廓 |
| 圆角 | 外壳/重点面板约 16～18px；普通面板约 12～16px；控件约 8～10px |
| 字体 | 复用现有系统字体与中文 fallback；正文 14～16px、说明不小于 12px |
| 标题 | 登录品牌与工作台可有展示尺度；问数工具栏、图表标题保持紧凑，不把所有页面标题都放大 |
| 间距 | 主区块约 24～32px；行内约 8～12px；窄屏有明确收敛规则 |

扩展 `frontend/src/styles/variables.css`，必要时新增一份共用材质样式。示例语义名：`--do-glass-shell-bg`、`--do-glass-panel-bg`、`--do-glass-data-bg`、`--do-glass-border`、`--do-glass-shadow`、`--do-glass-blur`。

`--do-surface` 仍是可靠的白色内容底，不能全局替换成透明底导致所有表格和弹窗失去可读性。材质类应用在真实外壳或面板上，模糊只影响背后背景，前景文字、控件和图表保持锐利。

CSS 渐变、毛玻璃、边缘和背景光影用于真实容器样式。优先复用现有资源与可互动角色。不得把整页效果图作为页面底图，不把表单、导航、图表或文字切成图片冒充应用。图片来源和存放遵守根 AGENTS.md 的本地环境规则；不把参考原稿、试验素材或临时文件加入仓库。

### 3.3 兼容与性能

- 不支持背景模糊时使用更厚的乳白背景与细边框，依然可读可用。
- 无需多层嵌套模糊；滚动列表不逐行加 `backdrop-filter`，不持续动画模糊半径或全屏背景。
- 尊重 `prefers-reduced-motion`，触摸设备不强制跟随鼠标。
- 检查玻璃创建的层叠关系，特别是 Element Plus 下拉、Tooltip、弹窗和 Teleport；菜单不能被面板裁切或遮挡。

## 4. 各页面的具体要求

### 4.1 登录

保留左右分区，左侧品牌区与角色约占 45%～50%，右侧表单居中。左侧海蓝玻璃使用共同背景光影；右侧乳白面板集中呈现账号、密码、验证码和登录动作。

**2026-10-04 用户补充约束：桌面左右面板必须等高，上下边缘对齐。** 参考图中的右面板较短是原方案需要修正的部分，不再作为布局目标。两侧共用同一高度规则，由父网格拉伸；右侧表单只在面板内部居中，不能再通过 `78svh` 等独立高度制造错位。窄屏上下排列时各面板按内容高度展示。

**用户进一步明确：两侧应无缝连接为同一面板，中间不留 gutter。** 仅在整体外沿保留圆角，内部蓝色/乳白材质连续分界。实际玻璃要能透出背景层次，不能只保留普通蓝色块和实白面板；登录玻璃可比通用内容面板更通透，输入框仍保持清楚。

现有 `LoginView.vue` 已有角色、按各眼睛位置计算的视线、身体轻微偏移与倾斜、离开回位、帧合并和减少动态效果支持。直接复用，不重写另一套角色或动画库。

必须保留：

- 眼睛自然看向光标，身体小幅跟随，不越出品牌区；文字、表单和背景不随鼠标漂移。
- 移开、窗口失焦或页面隐藏后回位；卸载时清理动画、监听器和待执行帧。
- 密码显示/隐藏、Enter 提交、登录中防重复提交、真实验证码 key、刷新、失败与重试。
- 验证码刷新按钮可键盘操作；验证码失败不能展示假的成功图片，不能通过假登录完成视觉验收。
- 用户名按现有规则处理，密码内容不得为美化而 trim、改写或输出到日志。

参考图中的 `K7M2` 不写进正式代码。角色沿用现有可互动结构，调整颜色、尺寸和光影时保持分层能力，不能合成一张静态截图。

### 4.2 问数

保留现有历史侧栏、顶部数据源选择、自然语言输入、并排对话/结果结构。玻璃强度比登录和工作台更轻；主要动作在输入区，结果区域使用更白、更厚的底。

宽屏维持并排工作区；中等宽度沿用现有对话/结果切换；窄屏保留历史入口与持续可达的输入框。对话、结果各自滚动，不能把结果面板改回覆盖输入的抽屉。

必须保留：

- 数据源 readiness、不可询问原因、切换数据源后的会话范围与 URL 上下文。
- 新建/搜索/切换/删除历史会话、消息 ID 分页、追问、停止、澄清、失败重试与恢复等待。
- 图表、表格、SQL、可信依据、CSV 与反馈始终关联当前显示任务；查看旧结果不能混入最后一次结果。
- 真实权限控制和最终保护状态；无权 SQL/导出保持原有隐藏或禁用，图中绿色保护提示不得固定渲染。
- 空结果、失败、拒绝、澄清、历史不可再读和图表失败回退的现有状态分支。
- 柱/折/饼切换、数据明细、resize 与图表销毁；图表坐标和值必须来自结果，不能为参考图写死 Furniture/180/30。

新会话可使用较淡的海蓝强调输入入口；已有消息和结果时收起大面积装饰。不要增加 SQL 输入框、新的推荐接口或装饰性统计。

### 4.3 后台工作台

保留选定图的“蓝色任务重点区＋开放数字摘要＋左数据源、右活动”的关系。五项准备条件继续使用真实 readiness，数据源数量不为图稿硬编码。

- 有阻断：重点区显示真实数量、原因和已有管理入口；大号数字只强调真实待处理数量。
- 无阻断：改为轻量就绪摘要，不继续显示红/橙色警报或虚构任务；无需为了版式保留大号 `01`。
- 接口失败、部分失败、未知状态：明确展示，不能伪装成零阻断或全部就绪。
- 数据源 rows 用两层排列为状态与五项准备条件留出空间，长名称、多个阻断原因不能挤掉操作。
- 最近活动是辅助内容，只展示真实活动；无活动时简短说明，不编造时间线填空。

大号 `01`、图中的 3/2/1/4 与蓝色强度是示例状态的视觉表达。真实状态和数据正确性优先于示例图文字。

### 4.4 其他后台页面

七个业务域、当前域的二级工作区继续位于左侧。头像、姓名、账号菜单保持左下角。问数切换继续位于账号菜单，读取真实功能能力。

先适配数据源列表、数据源详情、治理总览、语义知识；随后巡查其余现有后台页面。共用 `AdminShell`、`TaskPageHeader`、`BusinessStatusBadge`、`ReadinessPanel`，必要时做局部样式适配。

- 列表：范围条、过滤、搜索、分页和记录可读；表格整体一层内容面板，低频操作沿用现有“更多”。
- 详情：对象摘要与主操作清楚；准备清单保持一份，长内容使用分组和分隔。
- 治理/知识：问题和当前任务优先，规则配置和技术记录沿用按需展开。
- 权限/平台等页面：使用同一玻璃外壳与控件样式，保持授权事实、禁用原因和危险动作提示。
- 不能丢失 `datasourceId`、`snapshotId`、路由高亮、Tab 恢复、前进/后退和直接 URL 行为。
- 知识发布与明确确认索引构建仍是两个独立动作；不能因为整理布局而合并或绕过确认。

后台本轮以桌面为主要设计和验收范围。1024px 必须可用；390px 检查结构、菜单、输入和横向溢出，不能仅凭小屏结构检查宣称完成后台移动产品设计。

## 8. 独立验收标准

开发模型负责实现与自检。用户把改动所在工作区/分支、实施摘要和证据交回后，由本轮方案制定者独立复核；开发者的自报完成不直接替代验收。

### 8.1 视觉验收

逐页把最终参考图和最新真实页面放入同一对照材料，在相同视口、缩放与相应状态下检查：

1. **整体构图**：登录左右关系、问数工作区、工作台蓝色重点区与分栏成立；真实数据不同不会破坏布局。
   登录桌面两侧的顶边、底边与高度差均不超过 1 CSS px；验证码加载/失败、表单焦点与鼠标互动不会改变面板对齐。窄屏上下布局不适用等高要求。
2. **材质**：可感知玻璃边缘与背景层次；数据区足够白。只换蓝色背景或只在纯白底上加模糊不算完成目标。
3. **字体与节奏**：中文/数字/英文协调，标题尺度和正文比例合理，留白、对齐、行距与控件尺寸统一。
4. **颜色与细节**：品牌蓝统一，语义色准确；边框、阴影、图标、选中与焦点状态协调，没有过量发光、描边或套卡片。
5. **三页一致性**：从登录进入问数再到后台，品牌、材质与控件属于同一系统，各页的重点仍符合用途。

比较不仅看整页，也检查登录表单/角色、问数输入/图表/表格、后台导航/任务区/长名称等局部。真实用户名、源名称、数量、时间和合法状态与图稿不同属于正常差异；示例图中的错误或缺失功能不能被复制。

### 8.2 判定

- P0：无法登录/提问/读取结果，权限或数据保护回归，主要操作不可达。
- P1：核心视觉方向明显偏离、布局大面积破坏、重要功能被删除或数据/状态被伪造。
- P2：遮挡、溢出、难读、玻璃层级失控、跨页样式明显不一致、角色未正确跟随/回位等需要修复的问题。
- P3：不影响任务和主要视觉关系的细节，可列后续优化。

有未解决 P0/P1/P2，或缺失核心浏览器/图像对照证据时，结论为 `blocked`；修复后复验。无此类问题可为 `passed`，仍需写明 P3 与覆盖边界。实测流畅性按实际设备记录，不仅凭 CSS 写了动画或单元 mock 通过判断。
