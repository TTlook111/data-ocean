## 准备路径的真实含义

页面以“连接→采集→治理→发布→索引→问数”解释操作分工，但不把它实现为一套新的前端串行门禁。

- 连接：服务端要求启用且健康；测试成功不等于完成采集和治理。
- 采集：展示 latestCollectedSnapshot；没有采集记录时不能把“快照待发布”直接变成可执行发布。
- 治理：governanceReady 目前表示发布快照没有阻断问题；没有发布范围时不声称所有字段含义已经审核完成。
- 发布：分别展示正式元数据快照、最近已发布业务知识的证据。最近一篇文档不能代表整组覆盖。
- 索引：knowledgeReady 实际来自存在活动 build；无活动 build、已有活动 build 和来源落后分别呈现，不能混成“知识审核完成”。
- 问数：当前实现的 askable 由 connectionReady、metadataReady、governanceReady、permissionReady 决定，**不包含 knowledgeReady**。RAG 未构建/落后可与可问数同时出现，必须如实展示；要改变此合同需另行确认后端需求。

业务解释放在准备路径中，低频技术记录收起，阻断原因和下一步优先于通用清单。第一主动作仍以服务端首要原因及当前能力执行；读取不到事实时明确“未确认”，不猜测已完成或未配置。

## 视觉与实施顺序

继续使用官方 UI UX Pro Max 2.15.0，暖白画布、墨色内容、铜橙交互色，品牌 Logo 保持蓝色原资产。保留后台任务工作区布局；先提交共享外壳，再提交数据源页，均保留回滚点。后台其余业务页面仅继承共享外壳，不宣称已逐页重设计或验收。

实际基线截图已在改动前由 Chromium 捕获，API 为合成响应。之后分别验证布局、导航、权限、正常/加载/空/失败、切换与迟到响应、连接测试与表单、分页、窄屏，再回归问数。真实 Java/数据库/模型环境未核验，本阶段不连接生产或创建基础设施。
