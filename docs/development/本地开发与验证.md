### 配置本机应用

Java 配置统一放在 `backend/DataOcean/src/main/resources/`：`application.yml` 维护公共配置，并通过 `optional:classpath:application-local.yml` 导入本机覆盖；`application-local.yml` 保存实际连接信息和密钥，由 Git 忽略；`application-local.example.yml` 是可提交的填写模板，不参与运行。不再维护 `application-dev.yml` 或默认激活 `dev`，本地启动也不需要额外激活 `local`。

公共 `application.yml`、`frontend/vite.config.ts` 和配置示例应纳入 Git，不能作为本机密钥文件忽略。实际 local、`.env`、依赖目录、构建产物与脚本 Python 缓存按下文[Git 忽略与版本跟踪](#git-忽略与版本跟踪)处理。

Maven 资源处理仍将 local 复制到开发运行的 classpath，JAR 插件在归档阶段排除 local 和 example，普通 JAR 与 Spring Boot 可执行 JAR 都不携带它们。部署时通过环境变量或显式外部配置提供实际连接与密钥；缺少必填密钥仍由原校验拒绝启动。模板示例不自动提供有效密钥。

local 中的具体值会覆盖公共文件里的环境变量占位符：已设置 `dataocean.internal.token` 或 `dataocean.datasource.encrypt-key` 时，简写变量 `INTERNAL_TOKEN`、`DATAOCEAN_ENCRYPT_KEY` 不会覆盖这些值。确需通过环境变量覆盖 Java 本机配置时，分别使用完整属性名对应的 `DATAOCEAN_INTERNAL_TOKEN`、`DATAOCEAN_DATASOURCE_ENCRYPT_KEY`；`JWT_SECRET` 可直接覆盖 `jwt.secret`。Python 仍读取 `INTERNAL_TOKEN`，两侧实际令牌必须保持一致。

第一次克隆后，从示例创建下面两个本地配置文件；已有配置直接编辑，不要覆盖。以下命令从仓库根目录执行，`cp` 可用于 Bash 或 PowerShell：

```bash
cp backend/DataOcean/src/main/resources/application-local.example.yml backend/DataOcean/src/main/resources/application-local.yml
cp python-service/.env.example python-service/.env
```

Java 模板中的 `dataocean` 用户、库名和本机端口只是示例，必须改为实际应用库的连接信息；Python 的 Redis、checkpoint、Milvus 和 Java 地址也要与实际环境一致。

仅为新建独立环境生成应用密钥；复用已有应用库时沿用该环境的原密钥，不重复生成。新环境可在自己的终端执行：

```bash
uv run --no-project --python 3.13 python -c "import base64,secrets; print('INTERNAL_TOKEN='+secrets.token_urlsafe(48)); print('JWT_SECRET='+secrets.token_urlsafe(48)); print('DATAOCEAN_ENCRYPT_KEY='+base64.b64encode(secrets.token_bytes(32)).decode())"
```

该命令可由 uv 准备 Python 3.13，不依赖系统 `python` 命令指向哪个版本。将 `INTERNAL_TOKEN` 分别填入 Java 的 `dataocean.internal.token` 和 Python 的 `INTERNAL_TOKEN`；将 `JWT_SECRET` 填入 Java 的 `jwt.secret`，将 `DATAOCEAN_ENCRYPT_KEY` 填入 Java 的 `dataocean.datasource.encrypt-key`。数据源加密密钥保存后保持稳定，修改 JWT 密钥会令已有登录令牌失效。

实际密钥只保存在被忽略的配置文件或环境变量中，不提交或贴到日志、截图中。AI 供应商、模型和 API Key 可在应用启动后通过后台设置，缺少模型 Key 不应阻止应用启动。

## Git 忽略与版本跟踪

仓库只维护根目录一份 `.gitignore`，统一覆盖前端、Java、Python、依赖、缓存和本机文件；已合并并删除 `frontend/.gitignore`。依赖工具在已忽略目录内自动生成的忽略文件不属于项目维护规则，不需要逐个删除。

`frontend/vite.config.ts` 是共享的前端工程配置，当前包含 Vue 插件和开发服务器的 `/api` → Java 8080 代理，不含密钥，应保留版本跟踪。`npm run dev` 与构建会使用它；其中 `server.proxy` 仅负责开发期转发。以后若需要按本机改变代理地址，可以在配置中显式接入 `loadEnv`，将差异值放到被忽略的 `.env.local`；当前配置尚未接入该覆盖，单独新增 `.env.local` 不会自动改写代理目标。参考 [Vite 配置说明](https://vite.dev/config/)和[开发服务器代理](https://vite.dev/config/server-options.html#server-proxy)。

| 内容 | 版本控制边界 |
| --- | --- |
| Java `application.yml`、前端 `vite.config.ts` | 共享运行配置，需要跟踪；实际密钥放入本机 local 或环境变量 |
| `application-local.example.yml`、`.env.example`、本机环境示例 | 无真实密钥的模板，需要跟踪 |
| Java `application-local.yml/.yaml`、遗留 `application-dev.yml/.yaml` | 本机私有配置，忽略；当前启动不再依赖 dev profile |
| 实际 `.env`、`.env.*`、`.dataocean/local-environment.md` | 忽略，示例和 template 文件按明确例外保留 |
| `node_modules/`、Python 虚拟环境、`__pycache__/`、字节码 | 依赖和缓存，忽略；仓库脚本缓存也在范围内 |
| Maven `target/`、前端 `dist/`、coverage 和临时构建文件 | 生成结果，忽略 |
| 本机 `.mvn/maven.config`、`.mvn/settings.xml` | 忽略并取消既有跟踪，保留本机文件；`pom.xml` 及未来共享 Maven Wrapper 文件继续跟踪 |
| 本机启动包装、`*.local.ps1/.cmd/.bat/.sh`、进程记录和 PID 文件 | 忽略；本机启动脚本和日志优先放在本机环境文件记录的仓库外运行目录 |
| `.vscode/extensions.json` | 可共享的扩展推荐，允许跟踪；其余 `.vscode` 内容忽略 |
| 业务源代码、数据库迁移和正式文档 | 保留版本跟踪，不能用整目录忽略隐藏问题 |

检查时分别确认忽略结果和跟踪状态：`git check-ignore -v --no-index <路径>` 显示规则匹配，`git ls-files --error-unmatch -- <路径>` 确认是否已纳入索引，`git ls-files -ci --exclude-standard` 排查已跟踪却命中忽略规则的文件。

恢复文件且移除忽略规则后，文件可能仍显示 `??`，需要显式添加该文件才能恢复版本跟踪；这与文件已存在是两回事。对已经跟踪的生成缓存，仅修改 `.gitignore` 不够，应逐文件 `git rm --cached -- <路径>`，保留本地文件。此时 Git 的 `D` 表示待提交的取消跟踪，不代表删除了本机副本。不要执行全仓库清索引再添加的操作。

上层忽略整个目录会阻止下层例外生效，因此编辑器规则采用忽略目录内容、再放行 `extensions.json` 的方式。规则行为参考 [Git 官方说明](https://git-scm.com/docs/gitignore)。

本机启动包装使用的 `start-backend.ps1`、`start-semantics-backend.ps1`、一次性 `start-backend-v*.ps1` 和三个 `*-process.json` 记录已明确忽略，防止误复制进仓库。原文件位于仓库外时，本身就不在 Git 管理范围内；新增共享启动工具应使用明确的共享入口，不能整体忽略所有脚本。

## 依赖环境准备

先确认 MySQL、Redis、Milvus 的实际位置、账号、端口和用途。有可用依赖环境时，直接填写应用连接配置；下面的 Compose 分支可以跳过。

### 可选 Compose 配置

仓库根目录的 [docker-compose.yml](../../docker-compose.yml) 仅用于一键准备依赖，不构建或运行 Java、Python、Vue。需要它时，安装并启动 Docker Engine / Docker Desktop，使用 Compose V2（2.20+）；Windows 使用 WSL 2 / Linux containers 模式。

新环境首次使用时，在仓库根目录执行：

```bash
cp .env.example .env
```

填写根目录 `.env` 的 `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`MINIO_ROOT_PASSWORD`，MinIO 密码至少 8 字符。可以在自己的终端生成随机值：

```bash
uv run --no-project --python 3.13 python -c "import secrets; print('MYSQL_ROOT_PASSWORD='+secrets.token_hex(24)); print('MYSQL_PASSWORD='+secrets.token_hex(24)); print('MINIO_ROOT_PASSWORD='+secrets.token_hex(24))"
```

然后准备依赖：

```bash
docker compose up -d --wait --wait-timeout 300
docker compose ps
```

该分支包含六个服务，默认发布端口如下；etcd 和 MinIO 只在 Compose 网络内部访问：

| 依赖 | 本机地址 | 应用配置 |
| --- | --- | --- |
| MySQL | `127.0.0.1:3306`，库/用户均为 `dataocean` | Java 数据库密码填写根目录 `.env` 的 `MYSQL_PASSWORD` |
| 缓存 Redis | `127.0.0.1:6379` | Java 和 Python 的缓存 Redis 地址，模板密码留空 |
| checkpoint Redis | `127.0.0.1:6380`，DB 0 | Python 的 `LANGGRAPH_CHECKPOINT_REDIS_URL`；健康检查包含 JSON/Search |
| Milvus | `127.0.0.1:19530` | Python 的 `MILVUS_HOST` / `MILVUS_PORT` |
| Milvus 健康检查 | `http://127.0.0.1:9091/healthz` | 仅检查向量服务状态 |

**根目录 `.env` 只供 Compose 使用，不会自动配置宿主机 Java 或 Python。** 选择这套依赖后，仍需按上表同步两份应用本地配置。端口冲突时修改根目录 `.env` 的发布端口，再同步应用地址，不删除已有容器来腾端口。运行前确认 `COMPOSE_PROJECT_NAME` 没有指向其他在用编排；它同时影响容器和命名数据卷的归属。

该编排仅绑定 `127.0.0.1`，使用项目命名卷。日常停止依赖可在根目录执行 `docker compose down`，保留数据卷；不要添加 `--volumes` / `-v` 或删除 checkpoint 来绕过错误。MySQL 初始化变量只对空数据卷生效，修改 `.env` 不会自动更改已有数据库账号密码。

Milvus standalone 的[官方要求](https://milvus.io/docs/v2.6.x/prerequisite-docker.md)为至少 8 GB 内存，推荐 16 GB；同时运行其余依赖和本机应用时还需额外预留资源。镜像下载需要访问 Docker Hub 和 Quay。

先准备可用依赖、内部令牌、JWT 签名密钥和数据源加密密钥。Java 启动会执行尚未应用的 Flyway 迁移；启动前核对目标库及 `flyway_schema_history`。当前代码最新脚本为 V69，本机隔离库已迁移核验到 V69，不代表其他目标库已到 V69；V53 永久留空。本机隔离库通过受保护入口启动；版本落后时入口会拒绝启动，需先按获授权流程核对该库。新建空库请先完成下文“首次使用：新建应用库”，已有环境直接使用原账号和授权。

在三个独立终端执行：

```powershell
# 仓库根目录下，Java 网关，默认 8080
Set-Location backend/DataOcean
mvn spring-boot:run
```

```powershell
# 仓库根目录下，Python AI 服务，默认 8000
Set-Location python-service
uv sync --locked --python 3.13

```

Maven 不在 PATH 时，核实本机环境文件中的路径后使用，不将单台机器的 Maven 绝对路径写入共享文档。

访问 [http://localhost:5173](http://localhost:5173)，使用所在环境的账号登录。Python 的进程健康接口是 [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)；返回 `ok` 不代表模型、RAG 或 checkpoint 已可用。

## 首次使用：新建应用库

本节只处理新建应用库的账号初始化，日常启动无需重复执行。已有数据库沿用原账号、密钥和授权流程，不使用这里的 SQL 重置账号。

使用已有 MySQL 服务时，先通过自己的管理工具准备独立的空应用库和专用应用账号，并给予该库迁移所需权限；这与用于业务问数的只读账号不同。可选 Compose 在首次创建空数据卷时会准备 `dataocean` 库和应用账号。Flyway 负责表结构迁移，不负责创建 MySQL 服务或数据库。

新环境首次启动 Java 会通过 Flyway 顺序创建和迁移应用表。先执行一次初始化运行：

```bash
cd backend/DataOcean
mvn spring-boot:run
```

确认日志出现应用已启动、没有 Flyway 失败后，用 `Ctrl+C` 停止 Java，再回到仓库根目录。后续的管理员初始化步骤只适用于已经确认的新建应用库；已有环境使用原账号和授权流程，不重置密码或重复提权。Flyway 的工作树最高版本与目标库版本需要分别核对，不能手工批量重跑历史 SQL。

### 设置首次管理员密码和权限

迁移会保留 `id=1`、用户名为 `admin` 的初始账号；仓库没有提供可核实的初始明文密码。对新库先在本地生成自己选择的密码哈希：

```bash
cd python-service
uv run --no-project --python 3.13 --with bcrypt python -c "import bcrypt,getpass,re; p=getpass.getpass('Initial admin password (8-32 ASCII chars, letters and digits): '); assert p.isascii() and 8<=len(p)<=32 and re.search('[A-Za-z]',p) and re.search('[0-9]',p), 'Use 8-32 ASCII chars with letters and digits'; print(bcrypt.hashpw(p.encode(),bcrypt.gensalt()).decode())"
cd ..
```

`bcrypt` 通过 uv 临时提供，不写入项目依赖或锁文件。密码通过交互输入，终端只显示哈希。

使用已有 MySQL 客户端，连接 Java 本地配置中的同一个应用库。若使用了可选 Compose，可在仓库根目录执行下面命令，提示密码时输入根目录 `.env` 的 `MYSQL_PASSWORD`：

```bash
docker compose exec mysql mysql -u dataocean -p dataocean
```

把 `<刚生成的 BCrypt 哈希>` 替换为完整哈希，在 MySQL 客户端执行：

```sql
UPDATE sys_user
SET password_hash = '<刚生成的 BCrypt 哈希>', password_changed = 0
WHERE id = 1 AND username = 'admin' AND password_changed = 0
  AND password_hash = '$2b$10$Z4VL2owmJAjp02aND9yituM3FCnD1pQFbxTC8.MjkTV6XJYm9hS8K'
  AND EXISTS (SELECT 1 FROM iam_s1_bootstrap_state WHERE state = 'PENDING');
```

只应更新 **1 行**。条件限定了原始账号哈希和未完成的 bootstrap；若更新为 0 行，停止此步骤并核对是否连接了已有环境，不移除保护条件强行重置。执行 `exit` 退出客户端。

再运行现有 IAM-SIMPLE-1 bootstrap，把这个明确账号初始化为系统管理员：

```bash
cd backend/DataOcean
mvn spring-boot:run "-Dspring-boot.run.arguments=--iam.s1.bootstrap.enabled=true --iam.s1.bootstrap.user-id=1"
```

bootstrap 模式不启动 HTTP。命令完成后，重新连接同一应用库查询：

```sql
SELECT state, target_user_id FROM iam_s1_bootstrap_state;
```

确认 `COMPLETED` 且 `target_user_id=1`；若 Java 进程仍在运行，用 `Ctrl+C` 退出。不要把 bootstrap 参数带到日常启动命令中。管理员拥有管理功能，业务问数范围仍需另行授权。回到仓库根目录后，按“启动应用”一节运行三个应用，首次登录按页面提示修改初始密码。

## 准备第一次问数

1. 打开后台「运营与平台 → AI 配置」（`/admin/platform/ai`），设置模型供应商、LLM 和 Embedding，确认模型接口可用。
2. 接入实际要查询的 MySQL 数据源，使用只读账号。应用自身的持久化库不自动成为业务数据源；仓库未内置演示业务库。
3. 采集元数据、处理阻断问题并审核发布快照。
4. 生成、审核、发布 `skills.md`，再显式确认 RAG 构建；文档发布不等于向量索引已就绪。
5. 配置查询功能和数据授权，待数据源就绪后进入问数页面。

## 按改动选择验证

| 改动 | 适用检查 |
| --- | --- |
| 仅文档 | 本地链接/锚点、代码路径与状态冲突检查；`git diff --check` |
| 前端行为 | 在 frontend 运行相关 Vitest；`npm run test:run`、`npm run build`按范围执行 |
| Java 生命周期、权限或查询 | 在 backend/DataOcean 运行对应测试，需要时 `mvn test` |
| Python RAG、SQL 或图编排 | 在 python-service 运行定向 `uv run pytest <测试路径>`，必要时全量 |
| 可见交互或真实链路 | 使用当次可用的正式 Browser，在 `output/playwright/`保存实际证据与范围 |

Java 测试的 H2/Flyway-disabled 环境不能证明 MySQL 迁移成功；测试配置仍须提供内部令牌和 JWT 密钥。Python Redis 集成测试是否启用应单独记录。构建、单测、接口和浏览器通过属于不同证据。

### Java 对象分层与分页回归

目录职责、分页参数及各业务查询的排序白名单统一见[Java 对象目录与分页查询](../技术栈与模块职责.md#java-对象目录与分页查询)。仅调整分页条件、排序或用户导出时，在 `backend/DataOcean` 运行定向回归：

```powershell
mvn "-Dtest=PageQueryTest,MyBatisPlusConfigTest,OperationLogServiceImplTest,UserControllerExportTest" test
```

这些用例覆盖默认值与大小上限、页码别名绑定与优先级、偏移量溢出、排序白名单、拦截器顺序，以及用户导出跨页读取。迁移 PO 包等涉及多个模块的改动使用干净构建，避免旧包的 class 文件残留影响判断：

```powershell
mvn clean test
```

测试输出在 `backend/DataOcean/target/surefire-reports/`，下一次 clean 会重建该目录；已执行结果及覆盖限制记录在[项目现状](../项目现状.md#已有验收证据)，不在本指南复制测试数量。仅修改文档时检查链接、锚点和 `git diff --check`，不将既有测试记录写成重新运行的结果。

## 排查顺序

可先按下表定位问题，日志从对应应用终端或所在环境的运维入口查看。使用可选 Compose 时，可在仓库根目录用 `docker compose logs -f <服务名>` 查看依赖日志。

| 现象 | 检查位置 |
| --- | --- |
| Java 无法连接数据库 | 本地配置中的实际地址、端口、库名、账号和密码；只有选择 Compose 时才与根目录 `.env` 对照 |
| Java / Python 拒绝启动或内部 403 | 内部令牌长度与两侧取值、Java JWT 与数据源加密密钥 |
| Python 正常但问数拒绝执行 | checkpoint URL、DB 0、JSON/Search 能力及 Python 日志，不以 `/health` 代替能力判断 |
| Node engines 错误 | Node 是否同时满足当前锁文件中的 Vite 和 Babel 要求 |
| 供应商欠费、限流或认证失败 | 后台 AI 配置与模型供应商状态 |
| 无可查询数据源 | 只读连接、快照、阻断问题、知识发布、RAG 构建和当前数据授权 |
| 可选 Compose 无法连接引擎或提示变量缺失 | Docker Engine / Desktop 是否运行，根目录 `.env` 的三个密码是否填写 |
| 可选 Compose 端口冲突 | 修改根目录 `.env` 的发布端口，并同步应用连接配置 |

1. 根据当前机器核对服务与端口，避免使用另一环境的账号和示例密码。
2. 内部 401/403 先检查两侧令牌配置和鉴权日志，不输出密钥、不将日志降为 debug 掩盖故障。
3. readiness 阻断按后端原因处理；不改授权或伪造就绪状态来准备截图。
4. 模型欠费、限流、认证、超时和响应格式失败应显示服务故障；业务信息不足才澄清。
5. Browser 初始化前，如果本机文件记录了 preflight，则先只读运行并使用验证后的 pluginRoot；不通过旧版本别名或降低权限绕过问题。
