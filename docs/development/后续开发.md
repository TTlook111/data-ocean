# 后续开发

本项目按个人本地开发和演示定位，后续优先处理实际使用问题和问数正确性。日常拉取、配置与启动见[本地开发与验证](本地开发与验证.md)，V74 等版本状态见[项目现状](../项目现状.md)。多环境部署、容灾演练、长期容量及生产交付不属于当前必做范围。已修复问题和运行结果留在[验收记录](../acceptance/README.md)。

## 如何理解这份清单

当前主链及所列七角色验收已经完成，不需要因为本文仍有条目而全部重跑。各项工作性质如下：

| 类型 | 对应内容 | 含义 |
| --- | --- | --- |
| 补充验收 | 真实业务闭环、页面与角色边界、Prompt 场景 | 已有实现，补业务资料、独立预期或未覆盖场景；发现问题后再修复回归。 |
| 未交付需求 | 历史 SQL 解析入口 | 属于开发项，不能靠联调完成；具体实现范围按当前需求确定。 |
| 可选扩展 | 条件性扩展 | 未纳入当前必做队列，明确需要后再设计实施。 |

## 真实业务闭环

- 使用自己能解释、能独立计算预期的一套业务样例，核对字段含义、指标、关系及查询结果，并验证审核/发布/build流程。当前不要求接入企业真实库或安排业务人员验收；以后接实际数据时再核对相应口径。
- 扩展同库多表、聚合重复计数、指标、多轮上下文与缺口澄清题。检验必要关系撤回、JOIN usage收紧、同名对象及复杂日期口径，缺资料不推测真值。
- 继续校准政策2使用参考分与规范化SQL样例，验证原反馈情景和修复证据。新修订复查不等于原问题VERIFIED，真实业务核验和程序合同分开。
- 扩展大字段表分页、大快照预算、来源撤回、批量逐项失败和有在途引用的build替换；不恢复旧JOIN_PATH直通、未经审核的历史SQL示例或跨库问数。

## 页面与角色边界

- 对话主导 V2 已先迁移问数页；接入已有隔离后端后补真实登录、任务进度、停止/恢复、撤权重读、CSV/反馈闭环。本阶段云端 API 为合成浏览器响应，不抵扣此前联调成绩。后台按后续页面逐个迁移验收，不推定全站已重做。
- 后台共享壳和数据源接入/就绪 V2 已迁移；补真实只读连接测试、创建后的负责源配置、采集触发/记录、版本入口与实际编辑保存、多页分页。当前 RAG 不是 askable 的硬门禁；若需要改变此业务合同，应单列后端需求。
- 采集任务/全局计划、目录/结构/对象详情 V2 已迁移；补真实采集与并发冲突、调度开关/Cron、长任务断网恢复、标签取消实际写入、多页分页/大快照及完整键盘焦点回归。显式源/历史快照和最小元数据权限在合成浏览器与单测中已保护，不能抵扣真实后端验证。
- 治理任务与字段解释/审核 V2 已迁移；补真实候选质量、保存/审核并发冲突、来源批量落库、语义复查及知识发布/build衔接。云端已覆盖迟到AI/旧保存回包保护人工草稿、只读审核、409与部分成功；不能从合成API推定真实服务通过。业务知识、标签、使用档案与反馈内部保留原能力，后续分别设计验收。
- 元数据版本/详情/差异 V2 已迁移；补真实检查/审核/发布/撤回并发与不同客户端交错。当前快照写无客户端幂等键，前端未知记录及审计基线只提供有限核对，不能代替后端原子并发或跨整页刷新恢复。知识文档/详情/候选/新建及显式构建V2已迁移；补真实乐观锁、审核发布预检后的并发窗口、候选质量和同源文档组覆盖/hash资格、历史build有效性与指针切换。内存未知记录不跨整页刷新，不能将旧ACTIVE作为新确认成功的证明。
- 血缘/实际查询来源、查询分析/慢查询及操作审计 V2 已迁移；补真实投影延迟/恢复、实际审计SQL服务端重验、跨客户端并发、大图长文本、后端列映射归属完整校验。未知写内存锁不替代幂等或跨刷新恢复。后续逐页范围见[第六阶段剩余页面清单](前端第六阶段-血缘审计映射.md)，不从共享壳推定全站已重做。

## Prompt 场景

已验证SQL生成及部分内置回退的真实调用，不等于9场景全部业务正确。补其余草稿审核激活、后台版本/内置回退、回执与输出校验，以及候选人工采纳、摘要质量和相应页面交互。MODEL_RETURNED与合成预览不作业务通过。

- 会话替代机制若另行确认再设计，完成验收前保留tokenVersion、JWT黑名单及在用失效键。
- P9告警评估/去重/恢复/历史持久化尚未实现；P12告警历史前端依赖P9。现有规则CRUD不等于完整告警闭环，不从旧计划自动新建迁移、一级菜单或恢复旧API。
- 自动业务回放、双人强制审核、任意规模分片、跨build向量复用与前置使用分重排均属独立需求，按需明确范围后再实施。

## 原明确需求与未验证的历史目标

清理旧规格不代表取消原需求。原模块 003 在 2026-05-16 明确将“解析历史 SQL，发现 Join Path 和高频字段”纳入 MVP，BI 报表导入留到后续；当前受保护查询血缘及停止自动提升未验真 SQL 样例，不等于该历史 SQL 解析入口已经交付。若继续实现，应先确定导入来源与授权、只读解析范围、候选人工审核及验收，不能把历史执行成功直接当正确业务事实。

旧规格中的容量、时延、准确率等数字未形成统一验收口径，不作为当前个人项目的承诺或开发门槛。以后确需论文实验或性能对比，再按实际样例和机器确定测量标准；原始指标可从 Git 历史回溯。

PNG 导出的旧目标不能覆盖当前首期隐藏未交付入口的决定；现行问数专题已明确其尚未交付。安全的零越权、禁止字段不被使用、草稿不进入可信 RAG 和审计可追溯性继续按现行模块维护，不因旧规格删除而放宽。
