## 真实业务闭环

- 以自己能解释并独立计算预期的样例，核对用途、粒度、字段含义、指标和关系，贯通审核/发布/build、查询及反馈原情景验证；当前不要求接企业真实库或安排业务人员验收，接实际数据时再核对相应口径。
- 办公室真实合成闭环已有记录，继续核对模型规划偶发无关关系、合成用途误拒及重试稳定性。Python 启动同步已在 Java 先就绪的新进程实测；Java 暂不可达后无自动重试，冷启动顺序按[启动指南](本地开发与验证.md)执行。见[办公室补验](../acceptance/2026-10-29-关键页面与多角色验收.md#2026-10-30-办公室当前-develop-真实闭环补验)。
- 独立云端已完成无外部模型的真实采集与审核发布；仍需获准且可用的模型/Embedding、向量依赖和独立数据授权，才能补真实检索、问数、停止/恢复、CSV、血缘与反馈。见[云端边界](../acceptance/2026-10-30-云端真实联调与问题修复.md)。
- 扩展同库多表、聚合重复计数、指标、多轮上下文、缺口澄清和复杂日期题；核对必要关系撤回、JOIN usage 收紧、同名对象及原反馈情景。继续校准政策 2 与规范化 SQL 样例，新修订复查不等于原问题 VERIFIED。

## 原明确需求与未验证的历史目标

清理旧规格不代表取消原需求。原模块 003 在 2026-05-16 明确将“解析历史 SQL，发现 Join Path 和高频字段”纳入 MVP，BI 报表导入留到后续；当前受保护查询血缘与停止自动提升未验真 SQL 样例不等于该入口已交付。继续实现时先确定导入来源与授权、只读解析、候选人工审核及验收，不能把历史执行成功直接当正确业务事实。

旧容量、时延、准确率指标未形成统一验收口径，不作为当前个人项目承诺；论文实验或性能对比需要时，再按实际样例与机器定标准，原始目标从 Git 历史回溯。PNG 导出的旧目标不覆盖当前首期隐藏未交付入口的决定。安全的零越权、禁止字段不被使用、草稿不入可信 RAG 和审计可追溯性继续按现行模块维护。
