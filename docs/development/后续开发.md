## 恢复、业务语义与容量

- **问数中断和会话。** 验证取消后供应商调用和 SQL 实际停止的时刻，以及进程被强制终止、回执丢失、多客户端竞争下的恢复。补真实摘要模型调用，评估旧长期摘要的批量修正。工作台现有秒数截至服务端答案就绪；如需衡量用户首次看到答案的时间，需补浏览器侧采集。
- **质量检查和问题处理。** 复现检查器断连、SQL 超时和检查进程崩溃后遗留 `RUNNING` 的情况，验证安全接管及大型规则库的行为。独立评估问题处理的持久操作回执、配置写锁吞吐和已消费操作标识的保留期，保证重试不会重复写入。跨历史快照的全量自动关闭随上表第 3 项验收。
- **知识与 RAG。** 验证构建中断后的接管、仍有任务引用时的索引替换、来源撤回、历史构建的使用资格，以及完整文档组的覆盖、哈希与有效索引指针。需要在云端补检索、问数恢复、CSV、血缘和反馈链路时，先确认该环境的模型和 Embedding 授权、向量依赖、数据授权和 Java 冷启动配置同步。[知识](../modules/006-knowledge.md) · [RAG](../modules/009-schema-rag.md)
- **业务口径与反馈。** 补齐数据用途、表粒度、指标公式和单位、关系基数的独立预期，覆盖同库多表重复计数、多轮上下文、复杂日期和缺口澄清。验证无关关系、用途误拒、原题安全重试、必要关系撤回、JOIN 使用限制及同名对象隔离。校准政策 2 参考分和规范化 SQL 样例，分别留下修订复查与原反馈情景人工验收的证据。
- **Prompt 场景。** 对尚未实测的场景，核对草稿审核生效、切换版本或回退内置、模型回执与输出校验、人工采纳、摘要质量和页面恢复。
- **大规模使用。** 量化大数据、长任务、长会话下的容量与时延，补灾备和目标部署环境验证。容量、时延与准确率的统一验收口径待确定；论文性能对比另按样例和机器定义。

## 后端待确认合同

这些问题来自历史源码复核。先对照当前实现复现，再按真实产品规则修复或结项。静态报告可从[验收索引](../acceptance/README.md)追溯。

- **通知。** 确认全局通知的已读状态是否按用户独立。用两个账号分别操作单条及批量已读，核对列表和未读数。
- **功能与对象授权。** 核对字段保护、查看他人有效权限和最小治理角色所需的辅助目录。分别验证主功能准入与目录权限。确认普通用户维护者可操作哪些管理账号，并用服务端可信的目标身份校验。
- **组织并发。** 按真实落库结果核对清空主部门或父部门时的 `NOT_NULL` 更新行为、部门默认启用及多个管理员并发修改。问题确认前，清空已有值的操作保持受限。检查用户、角色、字段策略和候选确认等接口的客户端版本条件及写入结果恢复。
- **模型配置。** 核对只保存 Chat 时对 Embedding 待生效配置的影响、重建后的全局切换、维度检测对应的供应商、Provider 新建或更新的语义，以及多步配置的竞争和部分失败恢复。
- **反馈审核。** 核对反馈 DTO 的逐行数据源归属及 approve/reject 的服务端版本条件。保留多授权源汇总和逐条验权，验证两个管理员同时审核的结果。

## 仍需按实际问题推进的基础整治

- 在其余写入工作区验证切源、撤权、晚回和未知结果恢复；按实际消费者逐步退出旧主题别名。
- Java 查询编排和 Python 问数图仍有职责需要梳理。结合具体故障或改动拆分，验证任务归属、预算与 checkpoint 恢复约束。
- 明确来源变化何时使已审核字段绑定失效、谁触发更新及并发规则，再决定如何拆分字段工作区读取和状态更新。
