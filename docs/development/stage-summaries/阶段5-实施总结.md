**URL 状态恢复**（§15）：术语页与 Prompt 页在补齐前**完全不进 URL**（两文件连 `useRoute` 都未引入），刷新即丢选中对象。现已把选中术语表/术语、选中模板、当前 Tab、分析天数写入查询参数，并加 watcher 响应浏览器前进后退。Tab 切换统一改用 `push`，使后退能回到上一个 Tab。

**统一壳层组件**：五个页面全部使用 `TaskPageHeader` / `LoadingState` / `ErrorState` / `EmptyState`；`KnowledgeDocView` 与 `KnowledgeDocCreateView` 使用 `ObjectContextSummary`；状态徽标统一为 `BusinessStatusBadge`。

> 术语页与 Prompt 页**未使用** `ObjectContextSummary`：它是「路由锁定对象的摘要 + 返回入口」，而这两个页面是「列表 + 详情」的主从工作区，选中对象属于工作区内选择、不是路由锁定对象，用它语义不符。选中对象进 URL 已满足「可恢复」的目的。

## 剩余风险

1. **无任何运行时验证。** 阶段 5 的全部页面、状态机分支、错误态与 URL 恢复逻辑均只有静态阅读与构建验证。
2. **`V51` 迁移未在真实 MySQL 执行过。** 阶段 5 的审核记录与来源快照依赖该迁移回填的 `review_status` 数据。
3. **URL 状态改动引入了新的加载路径。** 术语页与 Prompt 页新增了「由 URL 恢复选中对象」的分支，其中术语页涉及「术语不属于当前术语表时清空并回写 URL」的判定，存在竞态可能，需实机确认。
4. **`push` 代替 `replace` 改变了浏览器历史行为。** Tab 切换现在会写入历史记录；后退会回到上一个 Tab。这是为满足 §15「后退恢复」而做的取舍，需实机确认不会让用户感到历史被污染。
5. **两个后端缺口的展示是「如实标注」而非「已解决」。** 若后续补齐后端列，前端需同步改为展示真实数据。
