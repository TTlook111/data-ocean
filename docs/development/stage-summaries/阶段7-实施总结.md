## 验证结果

### 构建和类型检查

- `cd frontend && npm run build`（`vue-tsc -b && vite build`）：**通过**。
- 结构断言：运行监控 3 个 Tab 与 §7.18 逐字一致；查询分析 2 个 Tab 与 §7.16 逐字一致。
- 结构断言：`views/admin/system/` 与 `views/admin/audit/` 下已无裸 API URL。
- 结构断言：纯图标按钮均补 `aria-label`；其余按钮自带可见文字，符合 §11.4「`aria-label` **或**可见文字」。
  > **该断言在审查中被推翻，它的验证边界需要写明**：`AiConfig.vue` 有 4 处纯图标按钮未补 `aria-label`（供应商卡的「编辑」「删除」各两处，`HEAD` 版本 `:598` / `:601` / `:726` / `:729`），已随 2026-09-12 的修复补上。更重要的是——**构建通过完全验证不了这类断言**：`aria-label` 有没有都不影响 `vue-tsc` 与打包结果。此类断言只能用覆盖全部 `.vue` 的脚本重跑，或按 §11.4 在浏览器无障碍树中实测。

- **「构建通过」的边界**：`frontend/tsconfig*.json` 未配置 `vueCompilerOptions.strictTemplates`，该项默认关闭，因此 **`vue-tsc` 不检查模板中的组件解析**——模板引用了未导入的组件不会让构建失败（本阶段的 `LoadingState` / `ErrorState` / `ChevronDown` 即实例）。所以**构建通过只能证明类型与打包无误，不能证明模板引用的组件都存在**，也不能证明任何「结构断言」成立；上面的结构断言是独立的只读脚本核对结果，不以构建为依据。详见 `阶段8-实施总结.md` 的「验证结果 → 构建和类型检查」。

## 剩余风险

1. **无任何运行时验证。** 五个工作区的全部改动只有静态阅读与构建验证。
2. **运行监控是一次结构性重写**（从扁平单页到三 Tab + 新增告警规则区），交互在真实数据下需重新验证。
3. **数据血缘的方向过滤是前端实现。** 表格层按焦点实体做有向可达性遍历，焦点默认为加载根表、点击节点后切换；该行为需实机确认符合预期。
4. **告警规则只能创建、编辑、启停，不能删除。** 若后续补上后端删除端点，前端需同步加回操作。
5. **全量重新向量化尚未开放**。原占位端点无法满足旧向量保留、计数验证和失败回滚约束，审查修复时已删除；不得把端点存在当作能力存在。
6. **操作日志的统计口径仍不一致**（总数服务端、其余当前页）。已显式标注，但根治需后端聚合接口。
