## 五、能力缺口：无法承载的项（如实记录，未伪造）

以下能力**在前后端两侧都不成立**，因此没有前端归属，也不会出现在页面上：

| 缺口 | 后端事实 | 前端处理 |
| --- | --- | --- |
| 分类体系 CRUD | 未发现独立的分类体系 Controller | 不制作虚假的分类管理页（§12）；字段标签继续使用现有接口 |
| 部门成员摘要 | `DepartmentController` 只有部门树与增删改，无成员接口 | 「部门」Tab 内说明缺失，并引导到「用户」Tab 按部门筛选 |
| 告警执行历史与恢复闭环 | 无告警执行记录、历史、恢复、去重接口 | 运行监控的告警规则 Tab 显式标注「只支持规则配置」，不显示任何执行统计 |
| 向量化任务进度百分比 | `vector_index_task` 无进度列 | 索引状态展示状态与起止时间，并说明无法给出百分比 |
| 术语审核意见 | `glossary_term` 无存放拒绝原因的列 | 审核记录展示状态/审核人/时间，并说明审核意见不可得 |
| 数据源级授权的**优先级** | `DatasourcePermissionVO` 无 `priority`（`AccessPolicyVO` 的 `priority` / `validFrom` / `validUntil` **已暴露**） | 「数据源授权」Tab 如实标注优先级无数据来源；「表列策略」Tab 已渲染「优先级」与「策略有效期」两列。授权本身的有效期（`expiresAt`）也已有数据来源并渲染 |
| 审批的治理状态复查结果 | 后端审批时执行复查，但不回写申请记录 | 审批详情说明复查存在但结果不可得，不伪造「复查通过」标记 |
| 血缘边的编辑 | 后端只有创建与删除血缘的接口，无更新接口 | 移除右键菜单的「编辑」项，而不是保留一个必然失败的动作 |
| 告警规则的删除 | `AlertController` 只有列表/创建/更新/启停，无删除端点 | 不提供删除按钮，页面说明缺口 |
| 普通用户「我的申请」 | 列表范围已由后端收窄，但入口开放需产品确认（§7.14） | API 封装已就绪，暂不开放入口 |

## 六、核验结论

| 核验项 | 结论 |
| --- | --- |
| 旧视图能力是否有遗漏 | **实施时曾遗漏 2 项**：数据源驾驶舱的知识文档列表、血缘页的「查询问题」列。两项已于 2026-09-12 修复轮回补，15 个旧视图现均有新归属。该遗漏由事后审查发现，实施时交付物写的是「无遗漏」 |
| 旧 URL 是否兼容 | **34 个表项全部兼容**（33 个重定向、1 个保持原路由），保留 ID/Tab/查询参数 |
| 旧菜单入口是否仍在 | 否。侧边栏只有七个一级业务域。**但「不再有链接指向」这句曾经不成立**：`views/guide/AdminGuide.vue`（`/guide/admin`，由 `/guide/query` 进入）里有 5 处链接指向旧 URL——`/admin/datasources`、`/admin/metadata/sync`、`/admin/governance/quality`、`/admin/metadata/lifecycle`、`/admin/knowledge`。这些链接可正常重定向，**不是断链**，但它们是旧 URL 的在用入口。已于 2026-09-12 改为新路由（`/admin/data-sources`、`/admin/collections`、`/admin/governance`、`/admin/releases`、`/admin/semantics/knowledge`）。`utils/adminNavigation.ts` 里保留的旧路径是后端 `blockReasons.actionPath` 的转换表，不是页面链接；仍被链接的兼容表项只剩 `/admin`（后台根路径，重定向到 `/admin/workbench`） |
| 是否存在超纲死代码 | 阶段 8 删除后由脚本复核：无不可达的代码文件 |
| 无法承载的能力是否如实记录 | 是，见第五节 10 项；页面内均有说明，未伪造字段 |
| 是否已有运行时验证 | **否**。本表的「能力承载」结论均基于静态阅读与构建验证 |
