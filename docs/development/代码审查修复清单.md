### ✅ C0-1：XSS 漏洞 — CatalogSearch.vue v-html 未净化（已完成）

**问题**：`frontend/src/views/admin/metadata/CatalogSearch.vue:132-138` 使用 `v-html` 渲染搜索高亮结果，但 `highlightMatch()` 函数未对 HTML 进行净化。如果元数据中包含恶意脚本，会被直接执行。

**影响**：安全漏洞，可能导致 XSS 攻击。

**修复方案**：
1. 在 `highlightMatch()` 函数中使用 DOMPurify 净化输入文本
2. DOMPurify 已在 `package.json` 中声明依赖但未使用

**涉及文件**：
- `frontend/src/views/admin/metadata/CatalogSearch.vue`

**修复代码**：
```typescript
import DOMPurify from 'dompurify'

function highlightMatch(text: string | undefined, q: string): string {
  if (!text || !q) return text || ''
  const safe = DOMPurify.sanitize(text)
  const regex = new RegExp(`(${q.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')})`, 'gi')
  return safe.replace(regex, '<mark>$1</mark>')
}
```

**验证方法**：
1. 在元数据中手动注入 `<script>alert('xss')</script>` 测试数据
2. 搜索该数据，确认脚本不被执行
3. 确认正常搜索高亮功能仍正常工作

**测试**：`npm run build`

**修复后提交**：`fix(frontend): 修复 CatalogSearch XSS 漏洞，使用 DOMPurify 净化 v-html 输入`

### C0-3：轮询架构 — 前端应改用 SSE

**问题**：前端 `QueryDatasourceView.vue` 使用 `pollTaskResult()` 每 2 秒轮询一次，最多 60 次。Java 后端已消费 Python SSE 并实时回写进度到数据库，但前端到 Java 之间仍是轮询。

3. 前端用 `EventSource` 接收实时进度

**涉及文件**：

- 修改 `backend/.../query/client/impl/PythonAgentClientImpl.java`
- 修改 `frontend/src/views/query/QueryDatasourceView.vue`
- 新增 `frontend/src/composables/useQuerySse.ts`

**验证方法**：
1. 提交查询后，确认前端实时收到进度更新（无 2 秒延迟）
2. 确认取消功能正常
3. 确认网络断开后能正确降级

**测试**：
- `npm run build`
- `mvn test`
- 手动测试查询链路

**修复后提交**：`feat(query): 前端查询进度改用 SSE 实时推送替代轮询`
