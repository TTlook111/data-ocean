# DataOcean 后台前端整体重构实施任务清单

> 文档状态：可执行开发任务书  
> 上位文档：`DataOcean-后台前端整体重构任务与实施指导.md`  
> 设计基线：`DataOcean-后台前端整体重构开发指导.md`  
> 实施范围：只重构后台前端；不修改 Java、Python、数据库、权限码和后端 API URL  
> 开发身份：真实拥有 `*` 权限的超级管理员；本轮不实施细粒度前端权限组合

## 1. 使用方式

开发人员应按“阶段 0 至阶段 8”依次实施。每一阶段必须完成代码、构建、浏览器流程验证、截图和实施记录，才能进入下一阶段。

本清单中的菜单、工作区、路由和页面归属是本轮默认决策，不是供开发人员再次自由选择的候选方案。发现后端事实与文档冲突时：

1. 以 Controller、DTO、VO、Service 和实际响应为准。
2. 暂停冲突页面的实现，不用前端模拟不存在的能力。
3. 在实施总结中记录证据、影响页面和建议处理。
4. 更新设计基线后继续开发。

不得因为旧页面已经存在，就跳过业务流程重组；也不得先删除旧能力再补新页面。

## 2. 冻结的信息架构

| 一级业务域 | 二级工作区 | 主要用户任务 |
| --- | --- | --- |

固定跨产品操作“进入智能问数”放在侧栏底部或工作台主要行动区，不作为后台一级菜单。

## 4. 路由元数据契约

每个后台路由至少声明：

```ts
interface AdminRouteMeta {
  title: string
  domainKey: string
  workspaceKey: string
  contextMode: 'none' | 'datasource' | 'datasource-snapshot' | 'locked-resource'
  breadcrumbParent?: string
}
```

规则：

- 本轮 `*` 超级管理员显示全部一级业务域、工作区和 Tab，不根据旧权限码裁剪菜单。
- `permission`、`anyPermissions` 等细粒度路由元数据留待新权限系统设计，不在本轮提前固化。
- 前端不得伪造 `*`；真实账号、后端鉴权和业务状态校验仍然生效。
- 路由锁定对象页面先通过详情接口验证对象，再渲染标题和面包屑。
- 旧 URL 重定向必须保留对象 ID 和可转换的查询参数。

readiness 的 `blockReasons.actionPath` 当前返回旧前端路径。阶段 1 必须建立唯一的集中转换函数，不允许各页面分别写判断：

| 后端当前 `actionPath` | 新前端目标 |
| --- | --- |
| `/admin/datasources` | `/admin/data-sources` |
| `/admin/metadata/lifecycle` | `/admin/releases` |
| `/admin/governance/issues` | `/admin/governance/issues` |
| `/admin/knowledge/review` | `/admin/semantics/knowledge?tab=review` |
| `/admin/permission/access` | `/admin/access?tab=grants` |

目标工作区需要数据源时，转换函数同时附加当前 `datasourceId`。未知路径不得猜测，应显示操作文案并提供返回对应业务域首页的安全入口，同时记录日志供后续补充映射。

## 6. Store 与数据加载任务

`auth` 继续负责当前用户和现有权限；新建或重构 `adminScope`，只保存跨列表页面共享的数据源和快照范围。

`adminScope` 必须满足：

- `datasourceId` 改变时，同一事务内清除 `snapshotId`、实体、表字段和旧筛选。
- URL 中合法参数优先于持久化状态。
- 路由锁定的数据源、快照、实体和知识文档不得被全局选择器覆盖。
- 选择的快照必须属于当前数据源；不合法时清除并提示，不静默替换成旧值。
- 资产目录固定读取当前数据源已发布后同步的实体；无已发布版本时显示引导发布的空状态，不降级到草稿。
- 页面卸载或请求切换后，旧请求响应不得覆盖新上下文；使用取消请求或请求序号防止竞态。

通知状态独立管理；分页、筛选、Drawer 和表单草稿保留在页面局部，不塞入全局 Store。

### 7.5 必须补齐的前端 API 封装

以下后端能力已存在，但当前前端 API 层缺少或未完整封装。本轮迁移对应页面时必须补齐，页面不得直接散落拼接 URL：

| 业务域 | 必须补齐的封装 |
| --- | --- |
| 目录资产 | 实体标签查询/确认/取消、脱敏候选查询/确认/拒绝；数据源内搜索暂基于 `getEntitiesByDatasource` 前端过滤 |

## 9. 操作与状态门禁

所有写操作必须以服务端当前状态为准。前端按钮显示规则仅改善体验，接口失败时仍展示后端错误。

| 对象 | 当前状态/条件 | 可以突出显示 | 不得显示为可执行 |
| --- | --- | --- | --- |
| 数据源 | 连接未通过 | 测试或修复连接 | 直接采集、直接问数 |
| 数据源 | 连接通过但无快照 | 启动采集 | 发布快照 |
| 快照 | 存在阻断治理问题 | 进入问题中心 | 发布 |
| 快照 | 待审核 | 审核动作或查看审核 | 直接标记已发布 |
| 快照 | 已批准 | 发布 | 把批准当成发布完成 |
| 知识文档 | 草稿 | 编辑、提交审核 | 直接展示为可检索 |
| 知识文档 | 审核拒绝 | 查看原因、继续编辑 | 发布 |
| 知识文档 | 已批准 | 发布/索引 | 宣称已经可检索 |
| 知识文档 | 索引中 | 查看进度 | 重复提交发布 |
| 权限 | 最终决策为拒绝 | 查看冲突与来源 | 仅因存在 ALLOW 就显示可访问 |

删除、撤回、回滚、连接池重置、重新向量化必须显示目标对象、影响范围和二次确认。

## 10. 接口缺口的固定处理

| 缺口 | 本轮前端决策 |
| --- | --- |
| 工作台统计只允许 `*` | 非超级管理员不请求或不展示该统计区，改用有权列表和 readiness |
| 慢查询不支持数据源过滤 | 性能 Tab 不显示数据源选择器，也不声称按源过滤 |
| 访问审批普通用户范围不安全 | 只做管理员审批队列；“我的申请”延期 |
| 告警无事件和历史接口 | 只展示“告警规则”，不制作告警中心、次数和趋势 |
| 无独立分类 CRUD | 不创建分类管理页，只保留已有字段标签能力 |
| 系统健康只允许 `*` | 本轮使用真实 `*` 账号完整访问；普通角色处理后置 |
| 无统一待办聚合接口 | 工作台组合 readiness、业务列表和通知；失败分区呈现，不整页归零 |

这些限制应进入页面文案和实施总结，不得用静态假数据补齐。

## 14. 验证命令与运行边界

静态验证至少执行：

```powershell
cd frontend
npm run build
```

如果项目脚本将 `vue-tsc` 独立配置，还应执行相应类型检查命令。构建通过只证明编译和打包通过，不证明后端接口、状态机、超级管理员完整流程和浏览器体验已经通过。

浏览器验收需要 Java、Python 和依赖服务真实可用。服务未启动时，只能记录为“运行态未验证”，不能用构建结果替代。不得为完成本前端任务擅自创建或启动新的 Docker 基础设施。

## 16. 最终完成条件

只有同时满足以下条件，后台前端整体重构才可以结束：

1. 七个一级业务域和全部工作区已经落地。
2. 后端已有管理能力均有合理归属，未承载能力有明确原因。
3. 数据源接入到可问数的核心旅程可以连续完成。
4. 页面能够说明当前对象、状态、阻断、合法操作和下一步。
5. 旧页面能力迁移无遗漏，旧 URL 已兼容。
6. 后端现有权限与安全校验仍然有效，并由真实 `*` 超级管理员账号完成全部页面和操作验证。
7. 前端构建通过，真实服务下的关键浏览器场景完成。
8. 所有未验证项和后端缺口如实记录。
9. 旧菜单、重复组件、重复 API 和重复状态映射已经收敛。
10. 新信息架构稳定，能够作为后续权限系统重新设计的业务输入。

完成上述条件后，才开始新的权限体系规划；不得把权限重构夹带进本轮前端实施。
