## 4. 布局规范

### 4.1 宽桌面：真正的并排工作区

参考图的核心关系如下，DOM 层级可按现有组件适配：

```text
问数工作区
├─ 左侧历史栏：品牌、新建对话、历史搜索/列表、账号菜单
└─ 主工作区
   ├─ 顶部：智能问数、数据源选择、真实就绪状态、详细信息
   └─ 工作区主体
      ├─ 对话区域：当前对话、消息滚动区、追问入口
      ├─ 对话区域底部：输入框、发送/停止
      └─ 右侧结果区域：查询结果、收起、图表/数据、明细、操作
```

可用宽度达到 1280px 时，左栏约 240px，结果区约 400～560px，对话区占余量且不小于约 460px。尺寸应随工作区实际宽度变化；Codex 面板里的可用宽度可能小于电脑屏幕宽度。

- 用 Grid/Flex 为结果区分配实际列宽。桌面结果区不能使用固定定位覆盖消息或输入。
- 工作区可用高度使用 `100dvh` 等合适方案，子网格设置 `min-width: 0`、`min-height: 0`。
- 消息列表和结果内容各自滚动；输入保持可达，结果收起后对话区自然扩展。
- 顶部标题统一为“智能问数”，会话题目放入对话区域；版本、SQL、模型执行细节放进详细信息。
- 数据源选择器只保留一个有效入口，移动到头部后仍调用已有切换、刷新和 URL 同步方法。可抽为 `QueryDatasourceSelector.vue`，不复制两套加载逻辑。
- 正常结果沿用右侧“图表 / 数据”主视图；可信依据与 SQL 通过详细入口访问，不能因减少主 Tab 丢失现有功能。

### 4.2 中等宽度：保留输入，切换内容

769～1279px 不强行塞三栏。保留约 200px 的历史栏，主工作区使用“对话 / 结果”可切换的单列内容，底部保留同一个输入区。打开结果是用户明确点击的动作，不自动盖住对话；收起/返回对话入口始终可见。

提交问题或收到后台进度时，保持用户当前输入与阅读位置。新结果可提示“查看结果”，不要由每次 `latestResult` 更新强行切换主视图。

### 4.3 窄屏：先让用户能提问

宽度不超过 768px 时，品牌、数据源和历史入口收敛为紧凑头部；历史列表默认收起，用户主动展开。主内容单列，输入可达，不重复堆放整块桌面侧栏。

结果使用明确可关闭的单列视图，保留继续追问入口。长表格可以在自身容器内横向滚动，整个页面不应横向溢出。检查 390 CSS px、长数据源名、长问题、浏览器放大及手机软键盘影响。

### 4.4 视觉基准

- 主色、背景、边框与文字复用现有 `--do-*` 令牌；布局依靠对齐、间距和分隔线。
- 中文正文 14～16px，次要说明至少 12px，数值列对齐，耗时优先显示容易理解的秒数。
- 主操作是输入区的“发送 / 停止”；新建对话和结果操作是辅助层级。
- 角色展示用已有身份事实，例如“系统管理员 / 当前账号”，不把“S1 权限动态判定”当作业务角色名。
- 选中、hover、focus、loading、disabled 状态清晰；图标来自既有 Lucide；减少非必要入场动画并尊重 reduced motion。

## 5. 结果数据与交互接线

### 5.1 一个当前显示结果

对话、图表、表格、SQL、可信依据、CSV 和反馈必须指向同一任务。现在旧消息的“查看结果”只是打开全局最后一个结果，改版时要明确选中结果。

推荐在页面维护“跟随最新结果 / 用户选中的 taskId”，派生一个 `displayResult`，供结果组件、分页和 `useQueryExport` 使用。点击旧消息时使用该消息的 taskId，经现有 `iamS1GetTask` 读取当前可返回结果；读取失败应显示错误并清除这次选择的数据展示，不保留看似属于新选择的旧表格。

SQL 读取复用现有 `iamS1ViewSql`。如果调整 `refreshSql`，使它接收明确 taskId 或目标结果，确保返回值不会写到另一个任务。切换数据源和新建会话时清理选中结果；请求竞态不得把上一个源的结果放进当前工作区。

### 5.2 保留真实接口与权限语义

- 提问只发送自然语言、datasourceId 和已有 conversationId 等必要字段，不恢复客户端选表/字段。
- 数据、columns、chartConfig 和脱敏信息使用 Java 当前返回的受保护结果；设计图中的 50/120/40、标题、历史和用户名只能用于测试夹具。
- SQL 和导出入口读取现有能力摘要及任务 `canViewSql` / `canExport`。明确 false 必须隐藏或禁用；缺失时按已有服务端能力结论处理，不能用“不是 false 就允许”自行放行。
- “已按当前权限校验”只在真实 `finalProtectionStatus` 足以支持时展示；证据缺失不画绿色通过标记。
- CSV 继续走 `iamS1ExportCsv` 服务端接口；反馈继续关联正确 taskId，图表仅消费已有 chartConfig。

### 5.3 图表与数据视图

“图表”视图以图表为主，可在下方展示**同一份分页数据**的明细，与参考图对应；“数据”视图突出表格。两处表格复用渲染或分页逻辑，避免各自维护不同数据副本。

没有 chartConfig 或渲染失败时，显示同一份受保护表格及明确提示。切换任务应重置图表失败标记和分页。保留已有图表类型控制，但不从列名猜指标、货币或业务口径。

左右区域收放并不一定触发 window resize。复用现有图表容器，必要时增加容器 ResizeObserver 或显式 resize 通知；处理隐藏后重新显示、卸载 dispose 与 observer 清理。不要新建第二套 ECharts 管理代码。

PNG 目前没有完成导出，首轮隐藏该入口或诚实标明不可用，不把提示函数包装为已经成功的导出。

### 5.4 示例与追问

结果后的追问使用该结果返回的 `suggestedQuestions`。初始没有可信问题来源时，显示中性的提问模板或帮助文案，不向所有数据源硬编码客户、库存、部门费用或图片里的两条追问，也不声称已按数据源筛选例题。

点击追问只回填问题并聚焦输入，发送由用户明确触发；保留 Enter 发送、Shift+Enter 换行，中文输入法组合输入期间不能误发。

## 6. 状态必须互斥

优先读取服务端任务状态；提交中和本地网络错误仍需按已有本地消息状态处理，不创建假的服务端终态。

| 情况 | 应呈现 | 可执行操作 |
| --- | --- | --- |
| 未选源、无可用源 | 选择入口或明确原因 | 刷新或现有帮助 |
| 未就绪 / 无问数能力 | 原因和真实的下一步 | 保留选择，输入不可发 |
| 没有查询结果 | 首次提问引导 | 输入问题 |
| 本地提交中 / PROCESSING | 真实进度或“正在查询” | 停止；不显示空结果结论 |
| PROCESSING 且本地等待耗尽 | 任务仍在处理的说明 | 原 taskId 的恢复等待 |
| CLARIFICATION_REQUIRED | 补充条件说明 | 回填原问题并聚焦；不显示“查询完成但无数据” |
| COMPLETED 且有数据 | 正常图表/表格 | 有能力时查看 SQL、CSV；结果评价 |
| COMPLETED 且无数据 | 查询成功、没有匹配记录 | 提示调整筛选；不暗示服务故障 |
| FAILED / 本地请求错误 | 实际错误或安全中文提示 | 重新提问 / 重试 |
| TIMEOUT | 服务端任务已经终止 | 重新提问，不能提供恢复等待 |
| CANCELLED | 已停止本次查询 | 保留原问题并可再次提问 |

用互斥分支或统一视图状态实现，不能叠加多个 `v-if` 让澄清、失败或取消同时变成空数据成功。图表、导出与结果评价只在适用结果状态下出现。若接口回传状态与数据不一致，按状态限制展示，不用残留数据冒充成功。

可信依据不能在 COMPLETED 或 CLARIFICATION_REQUIRED 时把全部节点都标成 done。若接口没有完整节点轨迹，采用保守的“当前阶段 / 最终状态”展示；不要推断每个分支都执行过，成功结果尤其不能把“需要补充说明”标成已执行。

**已知外部限制：**本轮实测模型供应商返回 `Arrearage`，Python 最终给出澄清。前端没有可靠结构化字段能把该响应改成供应商故障。本次只修正澄清的展示，不在 UI 猜测欠费；故障分类与契约修复留给独立后端任务。验收时也不能把供应商拒绝写成“成功查询已通过”。

## 7. 三批实施顺序

### 第一批：布局与视觉

完成真正并排的宽桌面、头部数据源入口、紧凑窄屏、消息/输入/结果的滚动与收放。保留数据接线和任务控制，不混入后端重构。

这一批结束时展示宽屏及约 920px 页面，证明结果不会盖住输入；检查新建对话、切换数据源和历史入口仍可操作。纯 CSS 调整不要求新增镜像式单元测试。

### 第二批：状态与功能接线

落实第 5～6 节：当前显示结果一致性、互斥状态、权限入口、图表/表格回退、保守进度、详情与追问。保持已有恢复和消息分页逻辑。

补充有意义的组件/状态测试：

1. 澄清不出现成功空结果、表格、导出和结果评价；失败/取消等带残留行时也不显示成功结果。
2. 图表缺失或报错时回退到同一份数据及列，分页仍正确。
3. SQL / 导出明确拒绝时入口不可用，读取失败时不残留另一任务的 SQL。
4. 选中旧消息后显示、SQL、CSV、反馈都使用所选 taskId；快速切源不显示旧源结果。
5. 本地等待耗尽和服务端 TIMEOUT 保持区分；已有原问题关联和历史分页测试继续通过。
