# 第五阶段：元数据版本与知识工作区

基线 `0e74e3c5e1880b02fcd5ddf7c3a1041dba4230c8`，分支 `feat/frontend-conversation-v2-20261029`。先提交版本，再迁移知识；沿暖白/墨色/铜橙与既有七域路由。仅前端，不改数据库、后端或IAM，不合并main或部署。

## 版本批次功能映射

| 原能力 | 当前入口 | 不变合同 |
| --- | --- | --- |
| 全状态版本分页/当前正式版 | 准备路径下的当前正式版摘要、版本列表 | 服务端total；当前正式版由published-snapshot身份判断，不从最大版本号猜测 |
| 手选比较/与当前正式版比较 | 选择两版本、行内比较 | 保留先选基准顺序，只允许同源，跳原差异路由 |
| 结构与审核依据 | 版本号打开统一详情，独立详情路由保留 | 结构metadata:view；发布域列表/审计/门禁release:view；两者互不补权 |
| 操作历史/问题与治理 | 同一详情操作记录Tab、精确快照治理链接 | 历史来自真实audit；问题总数来自三种未解决状态，导航单独核权 |
| 质量检查/进入审核/批准 | 按状态与独立能力显示的行内动作 | check不替代review；PARTIAL不报完整；批准与发布分开 |
| 发布门禁/确认发布 | 独立确认与三项门禁 | FAIL阻断，语义WARN不阻断；读取失败交后端最终判定；不触发知识或RAG |
| 撤回 | PUBLISHED版本、原因确认 | 原因非空、发布能力；409保留输入，不自动重发 |
| 差异内容 | 独立差异页 | 精确路径ID、显式源及双源一致；保留新增/删除表与字段、类型及注释变化 |
| 进入知识准备 | 已有正式版的知识文档导航 | 目标源knowledge:view，不代表已经生成或发布 |

账号/IAM/显式源变化同步清除旧读取、详情与本工作面确认。每个操作发起前冻结对象、来源和账号，确认后再次核权；旧成功、错误与finally不改变新范围。HTTP408/5xx/网络中断保留精确未知动作记录，普通列表刷新、换源/账号与组件导航不直接清除。精确审计出现写前基线ID之后的目标事件只说明已观察到目标作用，不证明原请求唯一归属；无事件不能证明未执行。

后端快照写接口没有客户端幂等键或expectedVersion参数。前端单次锁不能代替多客户端原子并发保障，内存未知记录也不能跨整页刷新提供持久执行证明。质量检查没有可据此确认的状态审计时保持未知，不盲目重试。

## 知识批次必须保留

知识列表/全状态统计、来源准备情况、审核队列、快照目录生成与完整来源预览、手工新建、表关联配置、构建历史及明确构建；详情包括人工编辑/提交/审核/驳回/发布、版本/回滚草稿/差异、来源快照与资格、切分预览、旧向量任务和AI独立候选人工采纳。知识能力不附加datasource:view；目录生成仍需metadata:view；来源准备与正式快照摘要分别按其真实辅助权限读取。

文档、快照和索引各自发布/生效；活动旧build仍合法服务与事实来源失效分别呈现。保留精确版本、修订、hash、来源快照和对象，不在前端自动构建、不新增RAG问数硬门禁。本轮已迁移上述工作面，具体运行覆盖见[本轮验收](../acceptance/2026-10-29-版本与知识V2.md)，不据功能存在推定真实服务通过。

## 知识批次落地映射

| 原能力 | 现入口 | 精确保护 |
| --- | --- | --- |
| 全量列表/统计/状态/本页检索 | 全部文档Tab；准备摘要按需展开 | 服务端分页和计数，身份/源失效先清旧统计；无权正式快照摘要不报不存在 |
| 审核队列/正文展开/通过驳回 | 审核队列Tab、逐行审核 | 每个功能与目标源在其自身合法绑定成立；确认前锁、确认后精确重读版本，意见保留 |
| 来源与活动索引/构建记录 | 独立「构建与索引」Tab | knowledge:view读取；knowledge:publish确认；不附加datasource/metadata/release查看权 |
| 明确构建 | 独立构建窗口，文档来源选项或已人工核对的精确ID | 固定源/快照；当前或曾发布来源由服务端校验；旧ACTIVE/同快照旧build不解锁本次未知 |
| 确定性生成完整目录 | 列表生成窗口、详情按快照生成 | 选择器独立metadata:view；生成输入只接受PUBLISHED；整组生成按identity/source/snapshot跨入口共享防重 |
| 手工创建 | 新建页 | 可无metadata/view；冻结源与载荷，重复不重发，等待新增输入保留；manage-only成功留回执，不跳无权详情 |
| 编辑/预览/提交/审核/发布 | 详情内容与顶部当前状态操作 | 标题+正文脏检查；保存doc.version，与内容currentVersion区分；草稿未保存不提交 |
| 来源/审核/版本/切分/索引 | 详情原六Tab全部保留，预览按需展开 | 数据随doc.version失效重读；精确旧版本正文仍有版本标签；旧build不随当前草稿变更直接失效 |
| 回滚/差异/历史正文 | 版本Tab | 已发布文档、已审核目标；回滚只生成新草稿；差异固定版本对及窗口代次 |
| AI释义候选、编辑、选择、采纳 | 内容页AI辅助补写窗口 | 独立候选与精确乐观锁；身份/文档/版本/表范围切换失效，采纳期间锁输入，409保留所属人工候选 |
| 表关联与问数入口 | 原按需表关联区、已发布文档问数入口 | 原lineage:view/manage和queryUse能力，未扩大到其他知识人员 |

保存等待期间有新输入时，只有精确重读确认版本为自己的预期增量且标题/正文与冻结保存载荷一致，才推进该表单基准锁并保留新增输入；第三方版本不同继续提示冲突，不静默覆盖。普通刷新保稿，明确替换已保存稿需确认。

未知写记录只在内存保存，会随完整刷新消失。保存/AI接口带乐观锁，提交/审核/发布/回滚接口不接受客户端expectedVersion；前端确认后预检仍有服务器并发窗口。RAG确认每次都会创建新代际，没有幂等参数；结果未知只允许重读核对，不凭旧build自动恢复重发。
