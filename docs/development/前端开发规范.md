# 前端开发规范

维护现行导航、共享交互和页面组织。业务合同与代码定位见[模块导航](../modules/README.md)，完成度和验证范围见[项目现状](../项目现状.md)。

## 先读的边界

设计从用户任务、信息层级和实际使用体验出发，优先删除冗余说明与重复容器，再优化布局。主题、菜单数量、卡片数量和具体尺寸可以随需求调整；页面改动须保留有效业务能力、精确身份与范围、权限、审核发布、SQL 安全及草稿恢复。

前端只调用 Java。能力摘要控制交互，Java 裁决授权、readiness、发布、RAG 构建和结果保护。加载、空、失败、无权、未知及部分成功分别表达，不用假数据、零值或新权限掩盖缺口。

每个新增或修改的逻辑块按项目约定补充有效中文注释，说明用途、约束或设计原因。通用行为在本页维护，模块细节在主责文档维护，避免重复。

## 视觉与共享组件

当前界面使用纸白数据面、浅灰导航、墨色正文与海蓝主操作。菜单当前项有浅蓝底和窄边标。玉绿、琥珀、莓红分别表示成功、警示、危险。图表类别使用独立的六个分类色，屏幕与导出从同一主题取色。[颜色令牌](../../frontend/src/styles/variables.css) · [基础样式](../../frontend/src/style.css) · [工作区容器与焦点](../../frontend/src/styles/product-workspace.css)

- 两张 Dashboard 使用白色图面、墨色数字和钴蓝趋势线。问数时段均值严格超过目标时用红菱形标点，等于目标时保留普通圆点，缺测留空。反馈覆盖条的分母为反馈权限范围内所有已完成回答，点踩占比的分母为已评价回答。图例、焦点、画布与明细共用[局部颜色令牌](../../frontend/src/styles/dashboard-palette.css)。AI 设置用一行实际配置事实。
- 导航与表格优先用字重、间距和细线分层。普通状态文字使用中性色，颜色集中在对应的状态标记与当前操作。实心按钮与文字动作分别校验 hover、active、focus-visible 前景对比。
- 登录入口沿用锚形标识和四个几何角色。桌面插画与表单并排，手机将角色缩到品牌右侧。角色跟随鼠标转身，点按某个角色会短暂弹起。焦点进入普通控件时角色望向表单，输入或显示密码时闭眼转开。触屏保留滚动，启用减少动态时使用静态表情，装饰元素不占用 Tab 顺序。表单只向插画传递关注和回避两种状态。
- 调整主题时用真实版本表格、知识正文、问数代码区、独立弹层及危险文字按钮复核。最新全站视图、改前截图和已测对比度见[配色验收](../archive/2026-11-07-全站配色与版本发布.md)。

- 复用 Vue、Element Plus、ECharts、GSAP、Lucide 及现有 LoadingState、EmptyState、ErrorState、BusinessStatusBadge；不引入第二套组件库。
- 每页一个主标题，复用 [TaskPageHeader](../../frontend/src/components/admin/TaskPageHeader.vue)。普通用途说明通过 TitleHelp 或原生 details 按需阅读；对象身份、状态、错误、阻断原因和危险影响直接可见。
- 列表、阅读、编辑与分析按任务组织单层工作面。宽表在自身容器滚动；长说明可完整展开，不将必要信息只放在 tooltip 中。数量、统计范围、版本和分类使用真实口径。
- 保留可见焦点、图标按钮名称、对比度与减少动态效果。状态不能只靠颜色；禁用原因与控件关联。应用文字和控件保持原生交互，不用整页截图替代。
- 弹窗/抽屉复用 `useAdminScrollLock` 锁住后台内容容器，内部正文可滚动，标题、错误和主操作可达。传送至 body 的浮层同样使用根级令牌。
- Element Plus 全局使用 `zh-cn`。服务端总数、当前页统计和前端集合数量分别标明，不为统一外观混用口径；前端分页只用于已完整读取的集合。
- 错误状态仅在存在实际处理函数时提供重试。未知写入不能由通用重试自动重发；减少动态效果时保留异步卸载与导航的安全顺序。

### 列表工作区填充能力

需要固定筛选、表头和分页的列表页可复用 `admin-list-fill`、`admin-list-fill__panel`、`admin-list-fill__body` 与表格 `height="100%"`。根类必须挂在页面根节点，由同一个 computed 同步决定 CSS 类和表格高度；当前基线在宽度至少 1200px、高度至少 700px 时启用，窄/矮窗口回退主内容区滚动。

是否填充由当前任务和可用空间决定，不能要求所有页面使用固定高度。对象详情和双表结构按父容器实际空间保留上下文、表头及分页，正文空间不足时回退自然滚动；同一模式只保留一个主要纵向滚动容器。不通过修改全局 body 滚动或固定像素高度掩盖溢出。

- 后台品牌进入 `/admin`。独立问数入口与账号菜单快捷切换均核对 `queryUse`；账号入口折叠后仍可操作。正式兼容跳转只以 router 已声明项为准，未知地址进入 404。

## 权限、请求和恢复

认证 store 保存身份与令牌；交互授权读取 [iamS1 store](../../frontend/src/stores/iamS1.ts) 的 `queryUse/viewSql/exportResult/hasGlobal/canOnDatasource`，不恢复旧角色数组或自行增加权限码。普通问数 SQL/CSV 同时核对顶层能力与当前任务能力，不附加后台负责源门禁。

请求复用 [http.ts](../../frontend/src/api/http.ts) 与已有 API 模块，错误复用 [httpError.ts](../../frontend/src/utils/httpError.ts)。页面状态留在本地，共享上下文才放 Pinia。

- 请求创建时固定身份；响应、错误和 finally 核对账号、范围、对象及请求代次。换账号/范围、关弹窗或卸载使旧请求失效，不能借用后来账号的令牌发送，也不能由旧 401 清除新会话。
- 登录/退出清旧资料、能力和已验证范围缓存；偏好必须经当前账号 API 复核。真实当前会话 401 清理状态并要求重登，异步导航再核对身份及导航归属。
- 写操作在确认与校验前冻结目标、版本和草稿，确认后重核身份、能力与精确对象；重复操作互斥，只关闭本工作面拥有的确认。预读或前端锁不能冒充服务端 CAS。
- 普通刷新、晚 AI、保存等待期间的新输入和失败保留人工草稿。409 不自动换成新版本重发；明确重读覆盖脏输入前确认。未知写按原目标核对回执，批量部分成功保留未完成项与原因。
- 数据源维护按目标源 `datasource:manage`；采集独立核对 `metadata:collect:run`。合法主任务与辅助目录独立判权，不将读取失败显示成空记录、零统计或已完成。
- 筛选从 URL 恢复后保持可见或显示活动条件；错误时间范围不能退成全量。对象切换清旧详情，缺失与失败分开。高影响动作保留精确对象和影响提示。

## 工作台与治理总览

工作台按服务端自然日切换今天、昨天和近七天，展示账号负责范围内的问数体验。等候时间按同一已完成任务的受理至答案就绪时间计算，可计时样本参与均值、P95 和超过 10 秒目标的统计，任务状态总数单独展示。时段没有样本时保留断点，只存在一个可计时时段时直接显示其范围。图表点击和键盘时段选择器进入同一桶的只读明细。

等候和提问情况依赖 `audit:view` 负责源；赞踩依赖 `governance:field:view` 负责源。点踩占比以有效评价为分母，评价覆盖使用反馈范围内的已完成回答。没有独立答案核验集合时展示抽检数据缺失。下钻携带后端截止点、周期及慢回答的具体桶，翻页重验权限。身份切换、撤权、读取拒绝或旧周期晚回不得泄露前一范围。旧 `focusSourceId` 书签只将合法 ID 导向有权的精确数据源详情。[平台模块](../modules/010-platform-operations.md#工作台与告警配置)

治理总览按已核验的来源及快照展示近 7 天或近 30 天的未解决问题。在同一日期轴上用折线展示余量、上下柱展示进入和移出。起算日前留空，今天标明读数截止时刻。点选图形或用键盘选择日期只解释该日变化。当前问题及质量检查分别导航至独立页面。[治理指标与精确跳转](../modules/004-metadata-governance.md#指标与精确跳转合同)

## 治理工作区的视觉取舍

- 总览、质量检查、规则、问题和状态维护各自承载对应任务，沿用公共 ScopeBar，刷新时保留精确的 URL 范围。问题中心默认突出问题域、表、状态，低频条件按需展开。
- 规则区分全局默认/本源配置、配置状态/实际执行、技术规划/业务适用；启用不表示已检查。检查项是系统方法，不开放自由 SQL。列表使用服务端分页，规划与问题总数不能由当前页计算。
- 新建按检查项、对象范围、异常条件、处理建议组织；技术摘要按需展开。列表/详情/表单复用 `qualityRulePresentation.ts`，真实表单校验覆盖动态参数，检查项说明与本规则处理建议分开。
- 规则执行记录按真实 `batchDatasourceId/snapshotId/batchId`打开精确检查依据，另提供“同范围当前问题”；缺范围或目标能力不显示对应入口。未知保存、检查与批量状态变更按各自合同恢复，不自动重发。
- 状态维护和内嵌字段标签只消费公共快照，不重复提供选择器。字段深链不属于可读表/快照时拒绝；显式重选只清旧对象，保留已核验范围。

详细规则、问题处理和字段阶段见[治理模块](../modules/004-metadata-governance.md)，批量标签、归因、参考分和人工核验见[治理任务与业务知识](../modules/governance/治理任务与业务知识.md)及[反馈归因与使用档案](../modules/governance/反馈归因与使用档案.md)。

### 质量检查与问题处理主线

- 实际来源检查统一在 `/admin/governance/checks` 显式发起。规则和版本页面的“前往质量检查”只导航精确源与快照。专页保留批次身份、原操作核对和返回入口。
- 本次维度与表采用紧凑多选，空选表示全部；发送前冻结选择，执行中或结果待核对时互斥。表目录单独按 `metadata:view`读取，失败/无权时不显示假空选项、不能使用未核验表范围；合法全范围主任务不因此自动失权。
- 检查使用原 UUID 的持久回执。[useQualityCheckOperations.ts](../../frontend/src/views/admin/governance/useQualityCheckOperations.ts)仅持久化源/快照/操作/批次/状态等恢复标识，刷新查询原操作，不自动重发 POST。POST计算结果仍须以原UUID读取持久批次；终态消费先完成，再固定批次URL，避免主动导航使成功回执遗留成在途锁。未知与 `RUNNING`保留互斥；未登记只允许继续核对或显式终结未开始请求，不宣称停止已运行检查。
- 检查专页 `batchId` 固定精确历史批次。旧总览的 `batchId` 或来自发布页的链接保留原范围与返回位置。非法或错属批次直接报错。进入问题中心使用 `returnBatchId` 返回原批次，问题仍按当前快照读取。
- [useQualityBusinessScope.ts](../../frontend/src/composables/useQualityBusinessScope.ts)在缺元数据目录权时，用主业务 `quality-context`核验显式源/快照，结果仅留本工作面，不补公共元数据目录缓存或权限。辅助表目录、用户目录分别保留自己的能力检查。接口最小字段与授权条件见[治理主任务范围](../modules/004-metadata-governance.md#治理主任务范围)。
- 问题状态/分派提交所读 `rowVersion`作为 `expectedVersion`，批量提交逐问题 `expectedVersions`映射；缺版本不猜默认值，409保留原问题与人工处理依据，不自动换版本重发。原记录被复查标为 `AUTO_CLOSED`属于自动替代历史，不显示为用户已解决；原ID/责任人/批次继续可追溯。问题写入的未知结果仍按既有边界核对，不能把版本条件说成持久幂等回执。

行为和接口细节集中在[治理模块](../modules/004-metadata-governance.md#检查操作与精确批次)；本轮真实检查、角色、异常及视觉范围见[检查闭环验收](../archive/2026-11-07-质量检查闭环与视觉对齐.md)。未覆盖的其他工作区、RAG中断接管和模型成功问数不能据此宣称完成。

### 质量规则的编辑与可靠写入

[QualityRulesView.vue](../../frontend/src/views/admin/governance/QualityRulesView.vue)组织页面、编辑会话与详情；`rules/useQualityRuleScope.ts`维护配置授权和规划范围，`useQualityRuleReads.ts`负责列表/目录/规划读取，`qualityRuleDrafts.ts`负责人工草稿与原版本，`useQualityRuleOperations.ts`负责提交与回执生命周期。[qualityRuleOperations.ts](../../frontend/src/api/admin/qualityRuleOperations.ts)只适配规则操作接口，业务合同与全部旧端点的严格参数/返回值变化统一见[规则写入合同](../modules/004-metadata-governance.md#规则写入合同)，不建设全站通用写入框架。

- 编辑器先显示主配置，辅助目录独立加载；没有 `metadata:view` 不阻止查看和维护有权规则的既有配置，也不允许选择无权目录。列表、配置修订、快照规划和执行历史分别表达；保存、启用或恢复均不等于执行检查。
- 草稿与服务端原版本分离。关闭重开、切换有权来源和 SPA 返回保留内存输入，冲突不静默换基线；整页刷新只恢复操作关联。新建采用稳定草稿定位键，表单范围变化不改变所属草稿。权限暂时不可核验时隐藏，确认撤权或主规则读取 403 后定向清理关联内容；旧响应不能清除其他有权对象的草稿，退出或换账号清空内存草稿。
- 发请求前固定操作 ID、动作、对象、原版本和正文。服务端原子版本检查及持久回执负责正确性；前端按钮锁只防重复交互。`localStorage`按账号仅保存恢复所需的操作/对象/范围/草稿定位标识、时间及已提交结果 ID/版本，不保存草稿正文或新增令牌副本；恢复记录不可读/不可写时不发新写请求。
- 成功、明确拒绝、版本/业务冲突与未知结果分别展示。网络错误、超时、5xx 和不完整回执保留原操作；刷新后查询原 ID，不自动重发。`NOT_FOUND`不解锁，必须继续核对或由服务端持久终结原 ID 后再开始。配置读取成功也不能代替原操作回执。
- `APPLIED`后仍需处理对应草稿：等待期间的新输入、关闭重开或离开工作面时，保留成功回执并阻止重复创建；显式核对已保存配置，确认替换该操作的脏草稿后才释放。回读失败保留原操作，迟到成功不关闭或改写后来打开的编辑器。每个操作使用独立本地键；另一标签页消费只保存最小已消费终态，不能解锁原发起页面仍存活的创建草稿。已确认撤权后的晚成功不回填操作标识或版本。
- 规则列表严格使用 Java 的 Page（records/total），不再兼容旧测试数组或以缺字段补空成功。保存错误摘要在同一编辑会话内获得焦点并滚入视口；关闭后或旧身份的错误不抢新工作面的焦点。

本轮代码、回归、真实角色与异常证据分列在[质量规则可靠写入验收](../archive/2026-11-07-质量规则可靠写入.md)。该协议只覆盖质量规则配置；问题处理、治理状态和其他工作区的未知写恢复仍按各自主责文档和待办记录，不能据此宣称全站写入闭环完成。

### 业务知识的阅读与修订

字段解释默认阅读当前已审核解释及独立收录依据，主动修订才展示候选/草稿/审核。业务知识采用事实列表与纵向阅读，正文、依赖、原始依据和同一修订历史集中；展开历史才请求。已撤回不因待确认数为零显示完成，AI 候选不等于事实。

返回阅读保留本地草稿与版本锁，切对象/快照/账号清旧工作面；只读审核者看到已保存修订。收录依据核对源、快照、字段、修订及返回的文档版本/build/chunk，无映射不按名称猜测。已收录无需重复发布/构建，未知先核对，新修订仍须审核。关键来源变化理由直接显示，长依据可完整展开。

## 采集、对象与版本

采集发起/查看按目标源能力判断；全局计划仅系统管理员可保存，running 仅表示调度注册。时间预设与 Cron 无损往返，切 Tab 保留草稿，离开停止轮询。目录与快照结构共用独立范围，不能依赖被权限阻挡的子组件同步来源；详情先显示来源与内容，关联读取失败不写成零。见[采集与目录](../modules/003-metadata-collection.md)。

版本工作区使用真实 `version-history`，当前正式版由 `published-snapshot` 的 snapshotId 判断，不由状态、版本号或时间推断。比较只限同源真实快照，详情/操作记录弹窗关闭保留原列表位置；操作记录来自审计接口，不能从状态拼事件。检查、审核、发布、撤回和 RAG 构建分别保留能力与状态门禁；FAIL/WARN/读取失败按后端语义呈现，不为列表逐行请求发布门禁。见[版本模块](../modules/005-metadata-versioning.md)。

## 问数、术语与知识

问数以连续对话为主，数据源与可问范围集中在页头，底部只承担输入、发送/停止和状态；每条结果绑定自己的任务，SQL/来源/CSV/反馈按需展开并独立判权。当前 Java 重读决定正文与受保护结果，失败、取消、澄清或超时不能展示旧成功内容。停止未确认时保留原源和会话继续核对，退出登录不受阻；删除会话确认绑定精确身份与会话。历史搜索、范围目录、结果列名和证据阅读统一见[问数交互](../modules/query/页面交互与结果展示.md)。

术语表单按业务定义、实际字段映射、核对保存组织，允许未关联草稿；定义与映射读取同一修订，目录失败或撤权不自动清空已选字段。列表与详情优先呈现业务信息，技术 ID 按需展开。见[术语与 AI 释义](../modules/knowledge/业务术语与AI释义.md)。

知识工作区按文档、审核、构建任务组织，准备与关联按需核对，当前错误和来源变化直接显示。默认阅读已保存内容，有权且状态允许时显式编辑；返回阅读保留草稿与冲突。正文与预览复用 [MarkdownContent](../../frontend/src/components/common/MarkdownContent.vue)：原始 HTML 转义，解析后用独立 DOMPurify 净化，失败回退文本，链接校验协议，图片只显示 alt，主动资源不得入 DOM。编辑载荷保持原文。

审核、发布、显式 RAG 构建和活动索引分别展示。构建来源独立读取全部已发布文档，不沿用当前分页/筛选；默认仅选真实 ACTIVE，历史须显式选择并标非活动，版本只在精确匹配时显示。无辅助能力不请求该数据；不因名称读取增加维护权，知识权不推导 queryUse。详情及构建流程见[知识模块](../modules/006-knowledge.md)与[RAG 生命周期](../modules/rag/构建与集合生命周期.md)。

## 权限、平台与审计

权限组织保持功能权、同绑定负责源、独立数据授权三权分离。主列表与辅助目录独立，允许/拒绝回执核对精确目标；他人有效权限不能混入操作者职责。访问审批区分原申请、批准子集和实际审批记录，审核时冻结编辑。用户凭据、导入逐项回执、部门树、字段保护与角色数组规则见[IAM 模块](../modules/007-iam-s1.md)和[账号模块](../modules/001-user.md)。

登录保留原生必填、密码显隐、验证码键盘刷新与错误恢复；首次改密不能绕过。本人表单校验前锁重复，普通重读保草稿，身份切换清旧输入；密码重置导致本人的 token 失效须按现有流程恢复。

Prompt 场景、草稿与批准版本独立；角色和任务作为版本包保存，冲突不自动换版本重试。批准即激活、回滚生成草稿；校验预览是合成数据，模型返回不是业务通过。晚列表/保存回执不得覆盖新输入或重选旧场景。AI Chat/Embedding 的 active/pending 分开，密钥不回显，未核对 provider 归属的自动维度检测不开放。配置、通知和运行规则见[平台模块](../modules/010-platform-operations.md#平台工作面)。

血缘分关系图谱与查询使用/输出来源，执行完成与投影完成分开；查询审计和操作日志权限/统计口径各自独立。原 SQL 与参数按需读，不从 HTTP 成功推断业务完成，不承诺不存在的导出或筛选。见[审计与血缘](../modules/011-audit-lineage.md)。

## 修改后的检查

核对正式入口、源/快照、后端状态、能力摘要、加载/空/失败、草稿恢复和键盘行为。按风险运行定向测试与构建，再使用 ego-lite 验证实际挂载页面、主操作与代表桌面窗口；涉及布局时检查原生缩放与焦点。不用地址变化替代组件挂载，不将未建模辅助 API 返回假空成功。

实际截图与机器输出放 `output/playwright/`，注明日期、角色、范围和操作；静态检查、合成浏览器、真实接口与业务正确性分别记录。未做的检查明确未验证，当前不新增手机适配任务。[验收索引](../acceptance/README.md)维护证据，[后续开发](后续开发.md)维护剩余工作。
