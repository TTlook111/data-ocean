# 前端开发规范

> 状态：现行产品与前端规范；整理日期：2026-10-24。承接用户确认的导航与交互决定，不维护提交/迁移/测试流水；实际人工验收范围见项目现状。

## 先读的边界

2026-10-29 后续视觉修正：后台共享壳已迁移暖白/墨色/铜橙，数据源页面采用任务准备路径，采集与对象、治理任务及字段解释/审核页面沿该方向逐页迁移。下文保留的旧海蓝/玻璃条目不要求将新壳恢复为旧样式；业务、导航、权限与状态合同继续有效，其余页面按后续逐页验收迁移。

字段解释工作面采用左侧原始来源/当前有效解释，右侧「候选与草稿 / 人工审核 / 来源与历史」；AI候选按需展开，图示与状态不把候选当正式事实。服务端同修订阶段及下一步原因单独显示，当前解释已审核、批次执行成功、文档发布和索引生效不互相替代。切换字段、快照、修订或账号后旧请求不得覆盖当前阶段。

任务与字段工作面复用 `useGovernanceScope`：源级可达性与快照就绪分开，源级反馈/旧记录不能新加快照门禁。公共快照与字段目录读取继续核对metadata:view，无权时显示合同缺口，不补权。表单基准版本与审核修订/版本分开固定；晚AI、保存后重读、普通失败重试保留人工脏输入，未保存草稿不能提交。409不自动重发且保留审核依据；明确重读覆盖脏输入前需该工作面确认。失效URL立即清旧对象，切换/卸载只关闭自身拥有的确认。批量来源逐项固定版本，部分成功保留未完成项与原因。

字段明细/收录和术语各按真实接口能力读取，不能因某个辅助接口无权而请求或展示其数据；术语查看不额外要求知识查看。只读审核者核对真实已保存的待审修订，不以不可编辑的表单当前值冒充。知识页导航只传同源合法范围，不通过前端新增发布或build动作。

前端只调用 Java。权限、readiness、文档发布、RAG 构建与结果保护由后端裁决；不因视觉需求伪造数据、改变授权、绕过状态或触发构建。加载、空、失败、无权和部分成功必须可区分。

版本页的准备路径解释采集核对→人工审核→快照发布→知识准备，不能把质量检查、批准、发布和RAG合成一个按钮。结构读取metadata:view独立于版本域release:view；缺结构权不隐藏审计和发布门禁。快照动作的确认/请求/finally按账号与范围隔离，未知写保留精确目标并核对真实审计，不因列表成功就自动重试。

知识工作区按文档、审核、构建任务分区。构建入口独立于datasource:view摘要；来源可明确核对当前/曾发布快照，生成输入与RAG的来源状态合同分别校验。详情保留六个证据Tab，辅助数据跟随doc.version失效，正文预览按需展开。脏标题/正文不能提交旧版，保存等待新增输入须保留；只有精确证实是自身保存才推进表单锁。候选、整组生成、创建回执及未知操作均固定对象/源/身份，不用旧build冒认本次成功。窄屏动作换行，固定表格列不遮蔽版本/文档身份。

### 产品与上下文规则

七个业务域为工作台、数据接入、数据资产、数据治理、语义中心、权限与组织、运营与平台。桌面一级域和当前域下的二级工作区均在左侧，不恢复内容区全局工作区栏。

- 信息架构：数据血缘归入「数据资产」（`/admin/assets/lineage`），与数据对象目录、元数据版本共同承担“看对象、看关系、看版本”；「数据治理」承担知识任务、规则、检查、问题、状态维护和字段业务知识/标签/使用可信度/反馈；字段业务解释移入「语义中心 → 字段解释」（`/admin/semantics/field-explanations`）；脱敏候选并入「授权配置 → 字段保护」；「运营与平台」保留查询分析、操作日志、运行监控、AI 服务配置与 Prompt 策略（`/admin/platform/prompts`，旧 `/admin/semantics/prompts` 保留查询参数和锚点跳转）。治理域内原「资产状态」入口更名为「治理状态维护」；血缘页说明关系来源和当前图谱计数，治理检查不生成血缘。
- 二级菜单按工作区的 `viewCapability` 与当前 S1 摘要过滤：全局能力用 `hasGlobal`，源范围能力在任一实际负责源上命中即可，`global-or-datasource` 任一命中即可，`anyOf` 内部为 OR。不能因当前选择资产源 2，就隐藏账号有权维护的知识源 1。未声明查看能力的工作区保持可见；能力摘要未加载或读取失败时沿用既有 fail-open 展示，不替代服务端授权。全部二级项不可见时隐藏一级域，一级入口使用可见列表的首项。数据源、采集、对象目录和查询分析分别声明 `datasource:view`、`metadata:collect:view`、`metadata:view`、`audit:view`，工作台域单独核对 `admin:workbench:view`。
- 全站二级菜单按业务分层使用 `groupKey/groupLabel` 分组：数据接入（接入配置 / 采集与同步）、数据资产（对象与结构 / 关系与影响 / 版本与发布）、数据治理（结果与问题 / 规则与状态 / 字段治理）、语义中心（术语与知识）、权限与组织（授权与审批 / 组织与角色）、运营与平台（分析与审计 / 平台运行与 AI）。组标题使用弱化色和 `role="group"`；折叠侧栏不渲染二级分组。不引入第三级导航。
- 顶部面包屑由路由 meta、工作区元数据和 `buildContextQuery` 白名单生成：有 `breadcrumbParent` 时父级为可点击工作区链接，否则回退当前工作区；当前页保留 `aria-current="page"` 且不可点击。父级只带 `datasourceId/snapshotId`，不复制 tab、分页和筛选；父级不可解析时不渲染坏链接。页面内返回按钮继续保留，用于保留页面级筛选。
- 发布门禁只在单个快照的详情弹窗、发布确认和快照详情页读取，不为版本列表逐行请求。`FAIL` 阻断发布并禁用确认，`WARN` 明确标注“不阻断发布”；门禁读取失败不成为前端写阻断，由后端再次校验并返回 409。
- 血缘工作区 URL 契约为 `datasourceId` + `entityId`（元数据实体 ID，不是 `columnMetaId`）。对象详情的血缘 Tab 只传这两个参数；血缘页以该实体为增强血缘起点，对象不存在时回退首个表并提示。节点点击和搜索命中用 `router.replace` 写回 `entityId`，保留数据源范围；跨数据源节点不写回。
- 知识页的统计、已发布快照、RAG 列表和生成弹窗按范围代次/请求序号/生命周期接纳返回，旧响应、错误和 finally 不覆盖当前状态；换源、关弹窗、卸载及时失效。主图和实体展开的重叠读取统一管理 loading 所有权，增强及回退每次异步返回均校验当前请求，旧失败/finally 不干扰新请求。血缘影响面板明确成功受保护查询的统计覆盖、最早记录、本源待处理数及明细上限，不把零记录解释为零影响；受控测试与真实浏览器验收分开。

- 正式路径与工作区元数据：[adminNavigation.ts](../../frontend/src/router/adminNavigation.ts)、[router/index.ts](../../frontend/src/router/index.ts)。
- 高亮使用 `route.meta.domainKey/workspaceKey`等值匹配，不按路径前缀推断。
- 新后台路由声明 `title/domainKey/workspaceKey/contextMode`，详情页与 Tab 不成为二级菜单。
- 一级域入口由 `findDomainHome`推导；跨工作区使用 `buildContextQuery`白名单传递 datasourceId/snapshotId，不复制整个 route.query。
- 复用 ScopeBar 与现有范围 store；对象在路径参数，Tab/筛选在 query，刷新与前进后退应恢复。
- 字段解释工作面只选择当前公共 ScopeBar 快照下的表/字段，不再增加数据源或快照选择器；对象目录字段入口传 `columnMetaId`、表名和精确快照，问题中心的 SEMANTIC 入口带回同一快照字段。保存、候选、审核、来源与问数收录状态分开呈现。
- 仅保留 router/index.ts 已声明的兼容跳转（当前为规则模板与 Prompt 旧入口）；其余未知后台 URL 进入统一 404，不据历史文档恢复路由。

账号、头像和菜单固定在左侧底部，折叠时仍能操作；顶部只保留位置和通知。全局问数切换放在账号菜单，读取 `queryUse`，不因“管理员”标签自动显示。知识对象的验证入口仍可保留。

通用后台入口、品牌与首页面包屑进入 `/admin`，待当前 S1 摘要加载后选择可查看的工作区及其合法数据源；仍可用的偏好保留，失效偏好仅在该目标工作区的真实范围内重选。一级和二级菜单按每个工作区的实际有权源保持可达：当前源仍有权则保留，否则指向该功能的合法源；跨源链接清除旧快照，不把不同角色的功能和负责源拼接。明确 URL 的范围继续按原上下文合同处理。直接访问无工作台能力或被服务端 403 拒绝的工作台显示原因，不展示业务概览或快捷操作；不通过授予工作台权修正落点。

账号登录或退出后，使已验证的数据源、快照、知识列表及能力缓存失效；选择偏好仅经当前账号 API 重新核验后恢复。登录清除旧账号的资料缓存；用户资料响应及异步退出完成时核对发起请求的 token 归属，旧响应不得覆盖新账号资料或清除新会话。旧初始化、历史详情和能力响应不得回填新会话；旧账号或匿名请求迟到的 401 不清除已建立的新会话，当前会话的真实 401 仍清理登录状态并要求重新登录。这些仅是前端显示与会话归属保护，不替代 S1 后台鉴权、独立数据授权或真实多角色验收。

公共后台范围先读取当前 S1 摘要：非系统管理员使用摘要中的实际负责源及名称，系统管理员沿用管理端数据源列表；保留的源/快照/文档偏好须重新核验。快照与知识选项各自按 `metadata:view`、`knowledge:view` 加载，某一辅助选项无权不阻断另一类合法工作区。源名缺少数据库名时直接显示真实名称，不拼接空数据库名。

## 任务与渐进式呈现

每页一个主体主标题，使用 [TaskPageHeader](../../frontend/src/components/admin/TaskPageHeader.vue)。普通说明收进标题右上角问号，支持悬停与聚焦；这是 2026-10-05 对最初左上角要求的修正。业务状态、错误、阻断原因与对象标识直接显示。

工作台定位为跨域待办收件箱：顶部汇总真实的阻塞数据源、治理问题、访问待审批，以及按能力显示的待审核知识/待发布版本入口；读取失败显示原因而不是 0。数据源 readiness 明细仍保留在下部，不与各域总览重复计算。列表突出“查看详情”，低频动作进“更多”。详情使用一份准备条件清单，不重复流程、百分比和成功卡片。治理结果与问题、知识审核与构建状态优先，低频配置和技术记录按需展开。发布知识与确认 RAG build 始终是两个业务动作。

## 视觉与交互

[variables.css](../../frontend/src/styles/variables.css)是基础令牌入口，[style.css](../../frontend/src/style.css)承接共用样式。用户于 2026-10-29 认可对话主导 V2：问数页使用暖白、墨色与铜橙交互色；第二阶段后台共享外壳沿用该克制配色和原品牌蓝 Logo，由 [product-workspace.css](../../frontend/src/styles/product-workspace.css)限定在问数、后台及相关浮层。后台业务页面逐页迁移，继承外壳不代表页面已重设计验收；登录页继续原有样式。不复制一份色值表到文档维护。

- 沿用 Vue、Element Plus、ECharts、GSAP 和 `lucide-vue-next`；不引入第二套组件库。图标使用 Lucide，既有可互动登录角色保留。
- 桌面登录两侧等高、上下边缘对齐、无缝连接，内缝无间距和圆角；原参考图的右侧较短与中间空隙已被用户否定。窄屏按内容上下排列。
- 验证码直接点击图片刷新，保留键盘操作、可访问名称、加载禁用和失败重试，不恢复重复“换一张”按钮。
- 问数桌面采用左侧历史/新建、中间单列连续问答、底部输入区；结果属于各条回答，图表/数据内嵌，SQL、来源与大视图按需打开，不再常驻并排结果栏。窄屏保留历史展开和同一输入入口。仅自然语言输入，不恢复 SQL 输入。
- 问数结果以当前显示任务为准，保留图表/表格切换、SQL/依据/CSV/反馈的能力控制和回退；历史结果不能冒充新任务成功。
- 问数页只保留“智能问数”一个页面主标题；会话名称用紧凑低权重标题行。历史会话按“今天/昨天/更早”的真实时间分组，标题最多两行，组内时间简化。
- 问数数据源菜单使用 Element Plus teleported popover 挂载到 `body`，不依赖顶栏内部的 `overflow` 或层叠上下文；菜单左对齐选择器并留约 6px 间距，宽度按剩余视口收敛，选项在菜单内部滚动，面板使用近不透明白色底、浅边框和统一阴影。
- 问数消息正文 15–16px、行高约 1.6；用户消息右对齐、助手消息左对齐。澄清消息以“需要补充信息”轻量状态标题开头，以“补充问题”为主要操作。
- 只有真实 `COMPLETED` 回答可内嵌结果；完成正文、追问与数据统一来自当前 Java 重读，不在核验失败后继续显示旧摘要。每条卡片独立绑定 taskId、会话源、分页、SQL 与反馈；历史与新任务在各自消息和时间位置区分。澄清、失败、取消及服务端超时不展示旧成功图表。
- 问数输入区与正文阅读列对齐，默认轻描边、聚焦采用工作区主色，自动增高并设置上限，隐藏原生拖拽角；数据源只在输入区附近显示一处，快捷键提示位于下沿。首屏历史装载期间不可发送或新建，失败要有真正可重试的历史入口。
- 使用真实数量、时间、源名称与状态，不为匹配图稿编造示例记录。
- 保留可见焦点、图标按钮名称、合理对比度与减少动态效果；装饰背景不能降低正文清晰度。

对象详情采用按可用空间切换的滚动规则（实际视觉验收范围见项目现状）：桌面空间足够时固定对象上下文、必要提示和 Tab，表格固定表头、仅表体滚动，非表格 Tab 仅正文滚动；有分页时保持分页可见。窄屏、低窗口或大字号导致正文空间不足时回退后台主内容区自然滚动。高度由父容器实际剩余高度减去稳定区域测量得出，不写死表格高度；同一模式只保留一个主要纵向滚动容器；技术信息展开、长内容和错误提示均须可达。适配仅限对象详情，不修改全局 `body` 或其他后台页面的滚动规则。具体边界见[采集与资产目录](../modules/003-metadata-collection.md)。

数据对象目录的“快照表结构”在范围行并列带有“数据源”“快照”标签的选择器和独立刷新操作；数据源选择器约 400–440px，快照选择器约 160–200px，数据源列表刷新使用有 tooltip 与可访问名称的紧凑图标按钮。下一行展示所选快照真实状态、表/字段数及质量分；版本由快照选择器展示，不在摘要重复。表属性压缩为字段表上方的辅助信息，标签使用次要文字色、值使用正文色，异常治理状态保持语义色。字段表序号从当前表的 1 开始，按真实 `ordinalPosition` 顺序排列，不展示字段对象 ID。字段表在自身区域处理横向滚动。桌面视口宽度足够且实际剩余空间达到可读阈值时，工作区固定上下文、表头，并在表列表和字段正文内滚动；否则回退主内容区自然滚动。表格高度由父容器弹性布局提供，不写固定像素高度。该布局目前代码及构建检查已完成，**页面视觉待用户截图确认**。

“元数据版本”保留 `/admin/releases` 正式路由和 `releases` 导航身份；导航标题、页面标题和详情/差异页来源路径统一使用新文案。工作区按标题/数据源、当前正式版摘要、版本列表工具栏、单一版本表格组织。桌面将标题与数据源范围并列，页面主体使用自然内容高度，并沿用后台公共海蓝画布；白色面板仅用于正式版摘要、版本列表和详情弹窗。数据源标签、选择器与刷新图标作为一个控件组对齐，空间不足时随标题区换行。工具栏在比较入口旁显示轻量原因/方向，避免另占整行。`version-history` 返回数据源范围内所有真实快照状态，表格统一承载候选与历史；不再使用常驻候选/历史/差异标签。

版本号是详情入口，直接打开当前工作区的统一详情弹窗；操作记录入口打开同一弹窗的“操作记录”页签。弹窗版本内容复用独立快照详情的详情读取状态和内容组件，表清单按快照 `tableMetaId` 展开真实字段结构。操作记录只读审计接口的动作、操作人、原因和时间，不从状态拼事件；读取失败、成功无记录和详情空数据分开呈现。弹窗关闭不修改数据源、列表页码、比较选择或滚动位置；独立详情与差异路由仍可直接访问。

列表比较支持手选两个同源版本，以及以 `published-snapshot` 实际返回的 `snapshotId` 为基准与当前正式版比较。当前正式版身份按快照 ID 判断，不能从状态、版本号或时间推断；差异继续跳转现有差异路由/接口。版本行单独显示发布状态与当前正式版身份，审校人继续标记为“审校人”。当前 `published-snapshot` / `version-history` 契约没有发布人字段，当前正式版摘要不显示发布人；质量分接口也没有评分说明，仅显示真实数值且不作为发布许可。

列表操作仅按已有状态与 IAM-SIMPLE-1 能力显示：质量检查、审核批准、发布/撤回、操作记录和问题入口各自保留门禁；撤回仍直接显示为危险色文字。弹窗的治理情况入口需要 `governance:view`；处理问题的强调入口只在已读取到真实 OPEN/CONFIRMED/REOPENED 问题且有 `governance:issue:manage` 时出现。页面沿用后台公共海蓝画布，正式版摘要、版本列表和详情弹窗使用不透明白色表面；宽表在表格区域横向滚动，弹窗正文单独纵向滚动。**代码与定向检查已完成，页面视觉待用户截图确认**。

版本表按内容分配列宽：比较、数量和质量分使用紧凑宽度，版本列吸收剩余空间，时间列保留完整采集/发布时间，审校人列固定约 150px 并通过 tooltip 查看长姓名。操作列依据当前页实际有权限显示的操作计算宽度；宽屏无横向溢出时无固定列阴影，表格确需横向滚动时只在表格区域滚动。**本轮宽度和控件组微调完成代码检查，页面仍待用户截图确认**。

元数据版本列表中可用的“操作记录”入口使用正常次要文字色，悬停与键盘聚焦时使用主色和下划线，保留公共焦点轮廓，与真正禁用态区分。此项视觉调整待用户截图确认。

## 权限、请求和状态

认证 store 只保存身份与令牌，不持有可供授权使用的旧角色/权限数组。读取 [stores/iamS1.ts](../../frontend/src/stores/iamS1.ts)能力摘要，通过 `queryUse/viewSql/exportResult/hasGlobal/canOnDatasource`等现有入口判定显示；能力摘要是交互依据，Java 才是安全边界。

普通问数的 SQL/导出按顶层 `viewSql/exportResult` 与当前任务 `canViewSql/canExport` 同时判断，不能额外要求后台负责源。后台 `canOnDatasource` 的同绑定合同保持原义。卡片卸载、账号或任务变化后，旧读取、SQL、CSV、反馈不得回填；只关闭该卡片拥有的补充反馈框，不全局关闭其他弹窗。

不要自造现行 S1 功能目录之外的权限码；不使用 `auth.user.permissions`或旧 `meta.permission`。摘要失败显示明确错误，不伪装成空能力、零统计或恢复旧权限。后台入口读取 `hasAnyAdminCapability`。

数据源列表和详情的测试连接、编辑、启停与删除按目标源的 `datasource:manage` 控制按钮和事件处理器，不能借用其他源的维护权；新建沿用全局功能判定。采集独立使用 `metadata:collect:run`，不以数据源维护权替代。元数据版本的“开始检查”与“进入审核”分别使用检查、审核能力；部分检查、失败和不适用应如实反馈，不显示空分数或完整完成。

请求复用 [api/http.ts](../../frontend/src/api/http.ts)与已有 API 模块；错误文案复用 [utils/httpError.ts](../../frontend/src/utils/httpError.ts)，不再复制旧 `any`类型异常解析模板。页面状态使用局部 ref/reactive，共享上下文才放 Pinia。

治理总览使用 ScopeBar 的数据源/快照上下文；检查状态来自后端最近批次，须与快照历史评分分开展示。待处理问题总数使用后端完整统计，首屏问题预览不得推算总数；列表或摘要查询失败不能显示零。执行中的、部分失败、失败、无结果和迁移前有限历史结果分别表达，检查不完整不得显示全绿或全通过。

治理总览复用公共 ScopeBar，以知识治理入口和当前检查状态为主；来源质量检查是独立动作。历史记录折叠，历史分数不放在未检查标题旁；不重复规划统计或重复绘制范围/空态。实际执行与配置数分开，不以零问题证明质量通过。

问题中心复用公共范围，默认显示问题域、表和状态筛选，其他条件按需展开。当前问题与历史批次分开；空状态只保留一处。

质量规则管理统一位于 `/admin/governance/rules`；侧栏不再提供“检查类型”并列管理入口，治理状态维护仍在 `/admin/governance/status`。检查项是系统提供的检查方法，质量规则是“检查项 + 对象范围 + 异常条件 + 风险/处理建议”的配置。支持的检查项在规则页内说明弹窗或表单内选择器展示；列表读取由规则页统一负责，子组件只浏览/选择，不自行请求或保存规则。

新建规则依次展示“1. 检查什么问题、2. 适用于哪些对象、3. 什么情况算异常、4. 发现异常如何处理”。检查项说明提供默认条件与参数边界；固定条件直接解释，空值率给出比例与百分数示例。只读用户可浏览支持的检查项，无维护权时不能通过说明入口新建；点击选择也不自动保存、启用或执行检查。编辑已有规则才展示编号/配置版本等摘要，避免新建时让用户先理解技术身份。

旧 `/admin/governance/rule-templates` 路由保留兼容跳转到规则页内说明，保留数据源/快照，使用 `showChecks=1` 一次性标记；处理时等待公共范围同步，消费标记而不反复弹窗。历史 `createTemplate` 链接继续核验范围和能力后预填。检查项编码与后端执行器合同不变；当前未开放新增检查方法或自由 SQL/表达式。全局规则维护仍只允许受保护系统管理员，其他范围按该源能力判定，后端最终授权。

质量规则的列表、详情和表单共用 `utils/qualityRulePresentation.ts` 的字段标签、范围顺序和格式化：检查项、适用范围、严重程度、扣分、处理建议等不得各写一套。表单用 `el-form` 的 `model/rules` 做真实校验，并补齐数据源、目标表/字段和动态参数的非空/范围校验；选择模板后只读展示检查方式、治理维度、检查目标和检查项说明。编辑弹窗顶部显示规则编号、配置版本、检查项、检查方式、治理维度、检查目标和适用范围，必须与列表行和详情一致。检查项说明只作为“检查项说明”，用户填写的 `description` 只作为“处理建议（本规则）”，两者不互相覆盖。模板 `allowedScopes` 由前端按 GLOBAL→DATASOURCE→TABLE→COLUMN 排序，不依赖后端 `Set` 顺序。

规则交互：规则页直接说明“启用 ≠ 已执行”，提供治理总览、问题中心及行内执行记录入口；主列表展示检查条件、对象、覆盖关系与配置状态，严重程度不重复显示。表单配置预览只解释条件、范围和风险，不伪造执行对象数量或试运行结果。创建模板意图须等待公共范围与 URL 一致后消费，不得在旧数据源打开表单。执行历史必须使用 `batchDatasourceId/snapshotId` 跳转对应范围的问题中心，明确标为“同范围当前问题”；缺少范围或没有该源问题查看权时不提供跳转。

质量规则列表使用后端分页（`GET /api/admin/quality-rules` 返回分页对象），默认每页 10 条，表格下方始终显示总数和页码；筛选、切换管理范围或新建规则后回到第一页，删除后当前页越界时退回最后一页。不得在前端对全量结果做假分页。详情使用单一摘要及轻分隔分区，摘要展示检查项、适用范围、严重程度和配置版本；列表行、详情和编辑弹窗的同一字段必须显示同一值。

弹窗或抽屉打开时使用 `useAdminScrollLock` 锁住 `.admin-shell__content`，只允许弹窗/抽屉自身滚动；不能出现外层页面与内层表单同时滚动。Element Plus 的 `lock-scroll` 只处理 body，不足以覆盖后台自定义滚动容器。

规则及治理页面的真实业务、视觉和键盘/窄屏验收范围见项目现状；构建和旧截图不能替代新页面人工验收。

复用 LoadingState、EmptyState、ErrorState、BusinessStatusBadge 和统一标题组件。首次加载不闪空数据，接口失败不显示成正常零值；批量部分成功显示跳过数量和原因。

对象详情的异步读取按对象和来源上下文隔离，旧请求的成功、失败和结束回调都不得覆盖新对象。写操作确认期间对象切换时停止原动作，不能在确认后改取新路由的资源 ID。

从目录进入字段治理时，传递并核验真实数据源、实际来源快照、表和字段标识；跨工作区仍使用上下文白名单。显式指定的历史快照未出现在首批列表时精确读取或明确报错，不静默选最新版本。审核状态与当前有效性分别显示，核验原因来自后端，不将缺少历史审核证据统一写成来源已变化。

字段解释复用公共范围；原始注释、当前有效解释、草稿、AI 候选及问数资格分开。新审核通过必须明确原始资料引用和人工确认，不能把模型自述当依据；无 knowledge:view 时不读取候选/草稿/审核详情。

治理工作区：治理五个工作区（总览、质量规则、问题中心、治理状态维护、字段治理）使用 `styles/governance.css` 限定的视觉节奏，统一页头、表格和弹窗/抽屉，不改变全站 ScopeBar 或海蓝基调。规则页明确区分“当前数据源 · 规则与生效”和“全局默认规则库”，每行标注继承/本源配置及当前快照的规划原因。规划数量使用后端全量启用配置口径，列表包含停用配置且保留服务端分页；不能用当前页推算规划或问题总数。业务适用前提与技术规划必须分别显示。

治理总览新增检查前适用性核对，解释候选、可参与、跳过与配置异常的差异；历史评分、最近批次、当前规划与问题记录分别显示，未完成可核验检查时不能用“0 问题”暗示通过。新建/编辑分区卡片与右侧保存前核对在窄屏下单列；执行/配置记录采用独立卡片和自然语言条件。规划依旧只读，不把静态草稿预览写成已扫描结果。

治理状态维护不再提供第二个快照选择器，只消费公共上下文，不能在已选历史快照不在列表时退回其他版本。高影响确认与异步响应必须绑定原范围/对象，范围变化后不得改用新快照发送原操作。表选择使用可键盘操作的按钮，表/字段读取错误与空结果区分。页面视觉、窄屏、焦点和真实写操作仍由用户手动确认。

## 术语与知识维护

业务术语的容器显示为“术语分组”，不让用户误解为数据库表。统一表单按“业务定义 → 关联实际字段 → 核对与保存”组织；源/表/字段逐级选择，已选路径、中文说明、类型可见。可先保存未关联草稿，提交前核对定义及映射。候选服务端分页搜索，失败与空结果分开。

列表显示定义、同义词、可见源名称与字段数量；详情先展示映射，再展示审核意见和对应快照，技术 ID 折叠。异步读取避免旧术语响应覆盖当前选择，读取失败时禁止用空集合覆盖原映射。待审核及通过后的修改遵循后端状态门禁。

知识生成前展示真实快照、覆盖、已审核术语和排除原因；AI 补写是独立动作，候选可修改/选择，必须明确确认后才能追加新草稿。来源失效直接显示，不能隐藏在说明中。欠费/超时/无效输出说明原内容保留与重试方式；加载失败不显示成零条来源。长表单弹窗保留可滚动正文及可见标题、保存按钮。

保存、采纳或审核后同步刷新当前版本、来源和当前 Tab，避免正文已更新而来源表仍显示旧版本。知识页的标题与操作区按可用宽度换行，表格在容器内处理宽度，不能把整页撑出横向溢出。

知识文档按“编辑 → 审核 → 发布 → 在知识列表显式确认 RAG 构建”说明各次人工动作。手工无来源快照文档不因发布而自动具备构建资格；回滚仅创建待重新审核的草稿，不直接进入索引或切换活动 build。

知识维护与元数据、数据源查看是不同能力。知识列表与详情不为加载名称而强制调用数据源管理接口；准备情况、发布快照摘要、按快照生成分别核对各自依赖能力，缺少时停止对应请求并说明或隐藏该辅助区，不能推断为零记录、无正式快照或自动授予权限。文档标题和正文只有在当前文档所属源上具备维护能力时可编辑，审核者看到只读内容。

已发布知识的“去问数/进入智能问数”入口只在 `queryUse` 为真时显示，事件处理器也重核该能力；知识查看、维护或审核权不自动带来问数权。

## 治理工作区的视觉取舍

治理工作区使用“清晰列表”方向：保留既有海蓝外壳与公共 ScopeBar，业务内容收为单层白色工作表面，不再给每段说明、每组统计和每个空状态另加卡片。治理总览只强调当前检查状态与执行入口，规则准备与待处理问题并列，历史记录折叠；不显示步骤条、重复规划统计或把历史评分放在未检查标题旁。

规则列表固定为规则、来源、适用对象、状态、操作五列。每条仅展示一行简短条件；业务前提、风险扣分和具体覆盖原因进入详情或“检查覆盖”抽屉，异常仍用“需核对”入口提示，读取失败/无权/未选范围直接显示。来源使用全局默认/本源专用，状态不再同时出现开关、标签和解释；启停、执行记录与复制/删除归入“更多”，只读用户仍可查看执行记录，写操作仍按原 IAM 能力控制。检查项筛选移入更多筛选，服务器分页和全量规划口径不变。

问题中心默认仅展示问题域、表、状态三个筛选；维度、级别、责任人按需展开，原有筛选参数与清除逻辑不变。零值域统计不重复占行，空状态只保留一处。状态维护不重复显示当前范围或长说明条，使用平面分栏选择对象。字段治理移除说明条与嵌套卡片，标签在内嵌模式只消费公共快照，不再显示/请求第二套快照列表；未选表时只显示引导，不同时绘制空表和插图。可信度/反馈由表格自身呈现一个空状态。

新增规则先选择检查项；适用说明和编号/版本等技术摘要默认折叠。配置区保持分区与单一保存前核对区域，执行/配置记录采用轻分隔行，长帮助继续按需展开。生成稿中的示例规则文字不作为实现合同，主键缺失仍检查表结构、注释缺失不增加任意长度阈值。功能测试、构建和 HTTP 不作为视觉验收；继续按用户约定保留页面视觉/键盘/窄屏的手动确认。

## 知识治理闭环工作面

字段治理默认显示“治理任务”，主要操作是发现缺口并启动 AI 首轮；列表显示对象、当前阶段和下一步，保留逐项失败/人工接管。数据源和快照只消费公共范围，显式来源不匹配时停止请求，切换范围后旧读取、保存和 finally 不得解锁或覆盖新范围。

业务知识复用同一工作台，语义中心的 `/admin/semantics/business-knowledge` 提供完整编辑入口；字段解释仍使用原编辑工作面并可返回当前任务。来源对比、未确定项及审核证据按需查看，审核者可只读检查，保存包含基准版本和来源确认。知识复查通过与 RAG 生效分别表达；资料引用/原始摘录和人工确认明确区分于 AI 参考说明；新草稿、当前有效版和撤销操作明确区分；被替代的历史修订默认收起、可展开追溯，不适用必须填写原因。

使用可信度展示当前语义版本和独立证据账本；旧可信度与反馈面板仅展开时加载，避免新旧分数混淆。反馈队列先确认实际字段归因并固定负向反馈的复现情景及预期结果，再计入试行参考分；知识复查之后显示待验证，人工按原标准验收并记录证据后显示人工核验通过。用户端可读取自己评价的处理进度；完成且零行结果也可反馈。所有列表使用服务端总数，不用当前页条数冒充全量。页面测试和构建不替代用户视觉验收。

## Prompt 策略工作区

Prompt 策略归运营与平台，按后端真实场景目录组织问数、知识治理和会话，独立展示配置记录。场景已接入而目标库未初始化时说明使用内置策略，禁止用虚构记录开放保存；历史意图模板只供追溯。角色与任务分栏编辑并作为一个版本包保存，角色不接受动态业务变量，变量含义、输出合同和固定约束折叠查看；只读用户不能编辑。

编辑版本和已批准生效版本分别显示；后台策略开关不表示关闭 AI 功能。提交、批准和驳回携带操作开始时看到的版本号；服务端冲突须刷新并重读，不能自动替换为最新版本重试。审核通过即激活，按钮明确说明；保存草稿不替换线上。校验预览使用合成数据，不声称执行了模型测试。调用记录展示实际来源、版本、回退原因、合同、摘要指纹及模型返回/失败；空记录不证明没有调用，失败不伪装成空结果。旧效果统计标注为历史任务审计，不能替代场景业务验收或人工采纳率。

异步读取按场景与请求隔离；列表刷新还须核验开始时的选择版本及同步递增的编辑修订，旧列表响应不能重选原场景或覆盖新输入；角色、任务和变更摘要均受保护。成功或失败的刷新若遇到新编辑，保留草稿并提示未应用刷新结果。保存请求期间的新输入也不得被完成回调清空。确认期间切换场景取消原写操作，已发写请求返回后不得覆盖新场景。旧链接继续保留 code/tab/days 和锚点。页面视觉、窄屏与键盘验收仍独立记录。

## 修改后的检查

确认业务域、正式路由、上下文、后端状态、能力摘要、加载/空/失败状态、键盘与窄屏行为。按行为运行现有定向测试；构建通过不能替代浏览器验证。实际截图和机器输出放在 `output/playwright/`，按运行日期记录覆盖与限制。

[验收索引](../acceptance/README.md)记录实际范围；[项目现状](../项目现状.md)维护完成度；后续工作只进入[后续开发](后续开发.md)。

## 采集与对象 V2 交互

采集页按任务职责呈现，发起与查看各按目标源能力控制；全局计划只给系统管理员保存入口，running仅称调度注册。时间预设必须能无损往返Cron；自定义原串保留，空时间不能提交。计划切Tab保留草稿，任务离开停止轮询。

正式目录和快照结构共用一个独立挂载的数据源范围区；范围同步不能依赖受门禁的结构组件先挂载。显式URL无权/不合法不回退偏好源，有权时同步到指定源再读。结构快照由URL和本页选择器驱动，公共store偏好仅作无显式版本时默认，不反向覆盖历史URL。对象详情先读来源与内容，再操作维护；权限、来源和部分失败直接表达，关联区不由零值代替未知。
