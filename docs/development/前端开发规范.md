# 前端开发规范

> 文档类型：现行产品与开发规范；核对日期：2026-10-18。原整理基线 `619bca6`；本次术语改造工作树基于 `cbb7e9a`。承接已记录的用户决定；原始图稿或旧 Prompt 与本页冲突的部分不再作为目标。

## 先读的边界

前端只调用 Java。权限、readiness、文档发布、RAG 构建与结果保护由后端裁决；不因视觉需求伪造数据、改变授权、绕过状态或触发构建。加载、空、失败、无权和部分成功必须可区分。

## 导航与上下文

七个业务域为工作台、数据接入、数据资产、数据治理、语义中心、权限与组织、运营与平台。桌面一级域和当前域下的二级工作区均在左侧，不恢复内容区全局工作区栏。

- 正式路径与工作区元数据：[adminNavigation.ts](../../frontend/src/router/adminNavigation.ts)、[router/index.ts](../../frontend/src/router/index.ts)。
- 高亮使用 `route.meta.domainKey/workspaceKey`等值匹配，不按路径前缀推断。
- 新后台路由声明 `title/domainKey/workspaceKey/contextMode`，详情页与 Tab 不成为二级菜单。
- 一级域入口由 `findDomainHome`推导；跨工作区使用 `buildContextQuery`白名单传递 datasourceId/snapshotId，不复制整个 route.query。
- 复用 ScopeBar 与现有范围 store；对象在路径参数，Tab/筛选在 query，刷新与前进后退应恢复。
- 旧后台 URL 按统一 NotFound/404 处理，不重新加入兼容跳转。

账号、头像和菜单固定在左侧底部，折叠时仍能操作；顶部只保留位置和通知。全局问数切换放在账号菜单，读取 `queryUse`，不因“管理员”标签自动显示。知识对象的验证入口仍可保留。

## 任务与渐进式呈现

每页一个主体主标题，使用 [TaskPageHeader](../../frontend/src/components/admin/TaskPageHeader.vue)。普通说明收进标题右上角问号，支持悬停与聚焦；这是 2026-10-05 对最初左上角要求的修正。业务状态、错误、阻断原因与对象标识直接显示。

工作台突出待处理事项和数据源摘要；列表突出“查看详情”，低频动作进“更多”。详情使用一份准备条件清单，不重复流程、百分比和成功卡片。治理结果与问题、知识审核与构建状态优先，低频配置和技术记录按需展开。发布知识与确认 RAG build 始终是两个业务动作。

## 视觉与交互

[variables.css](../../frontend/src/styles/variables.css)是令牌定义入口，[style.css](../../frontend/src/style.css)承接共用样式。采用现有海蓝画布与玻璃材质；旧指南的浅绿背景、旧色值、旧扁平图稿不能覆盖当前实现要求。不复制一份色值表到文档维护。

- 沿用 Vue、Element Plus、ECharts、GSAP 和 `lucide-vue-next`；不引入第二套组件库。图标使用 Lucide，既有可互动登录角色保留。
- 桌面登录两侧等高、上下边缘对齐、无缝连接，内缝无间距和圆角；原参考图的右侧较短与中间空隙已被用户否定。窄屏按内容上下排列。
- 验证码直接点击图片刷新，保留键盘操作、可访问名称、加载禁用和失败重试，不恢复重复“换一张”按钮。
- 问数宽屏保留对话与结果并排；窄屏保留切换和历史入口。仅自然语言输入，不恢复 SQL 输入。
- 问数结果以当前显示任务为准，保留图表/表格切换、SQL/依据/CSV/反馈的能力控制和回退；历史结果不能冒充新任务成功。
- 使用真实数量、时间、源名称与状态，不为匹配图稿编造示例记录。
- 保留可见焦点、图标按钮名称、合理对比度与减少动态效果；装饰背景不能降低正文清晰度。

## 权限、请求和状态

认证 store 只保存身份与令牌，不持有可供授权使用的旧角色/权限数组。读取 [stores/iamS1.ts](../../frontend/src/stores/iamS1.ts)能力摘要，通过 `queryUse/viewSql/exportResult/hasGlobal/canOnDatasource`等现有入口判定显示；能力摘要是交互依据，Java 才是安全边界。

不要自造 54 项固定目录之外的权限码；不使用 `auth.user.permissions`或旧 `meta.permission`。摘要失败显示明确错误，不伪装成空能力、零统计或恢复旧权限。后台入口读取 `hasAnyAdminCapability`。

请求复用 [api/http.ts](../../frontend/src/api/http.ts)与已有 API 模块；错误文案复用 [utils/httpError.ts](../../frontend/src/utils/httpError.ts)，不再复制旧 `any`类型异常解析模板。页面状态使用局部 ref/reactive，共享上下文才放 Pinia。

复用 LoadingState、EmptyState、ErrorState、BusinessStatusBadge 和统一标题组件。首次加载不闪空数据，接口失败不显示成正常零值；批量部分成功显示跳过数量和原因。

## 术语与知识维护

业务术语的容器显示为“术语分组”，不让用户误解为数据库表。统一表单按“业务定义 → 关联实际字段 → 核对与保存”组织；源/表/字段逐级选择，已选路径、中文说明、类型可见。可先保存未关联草稿，提交前核对定义及映射。候选服务端分页搜索，失败与空结果分开。

列表显示定义、同义词、可见源名称与字段数量；详情先展示映射，再展示审核意见和对应快照，技术 ID 折叠。异步读取避免旧术语响应覆盖当前选择，读取失败时禁止用空集合覆盖原映射。待审核及通过后的修改遵循后端状态门禁。

知识生成前展示真实快照、覆盖、已审核术语和排除原因；AI 补写是独立动作，候选可修改/选择，必须明确确认后才能追加新草稿。来源失效直接显示，不能隐藏在说明中。欠费/超时/无效输出说明原内容保留与重试方式；加载失败不显示成零条来源。长表单弹窗保留可滚动正文及可见标题、保存按钮。

保存、采纳或审核后同步刷新当前版本、来源和当前 Tab，避免正文已更新而来源表仍显示旧版本。知识页的标题与操作区按可用宽度换行，表格在容器内处理宽度，不能把整页撑出横向溢出。

## 修改后的检查

确认业务域、正式路由、上下文、后端状态、能力摘要、加载/空/失败状态、键盘与窄屏行为。按行为运行现有定向测试；构建通过不能替代浏览器验证。实际截图和机器输出放在 `output/playwright/`，按运行日期记录覆盖与限制。
