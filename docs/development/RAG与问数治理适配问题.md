## 本轮结论与阶段边界

治理、RAG、问数及血缘分别承担事实维护、受控知识交付、受保护执行和来源追溯。修复的目标是保持事实身份、完整依赖与当前授权贯穿这些阶段；自动化不能证明人工填入的业务口径为真，也不能替代真实发布、索引激活和业务题验收。

V73 增加血缘来源摘要、任务固定引用及查询追溯待处理状态；V72 仍是 Prompt 策略迁移。当前没有对本机应用库执行这两项迁移，没有自动批准知识、创建 build、调用真实模型或改变业务授权。历史知识缺少新血缘身份凭据时安全排除；应重新生成、审核并显式构建，不能原地补造批准或删除旧活动集合。

## 从问数要解决的问题出发

用户需要的是业务含义正确、在当前权限内且可以解释来源的答案。为此，链路必须分别回答以下问题；一个阶段的状态不能代替另一阶段的证据。

| 必须回答的问题 | 最小证据 | 不能据此推断 |
| --- | --- | --- |
| 来源质量状况是什么 | 指定源/快照的检查批次、覆盖、失败/不适用及现行发布门禁结论 | 历史满分、没有问题记录或语义审核通过不证明本次来源检查通过 |
| 口径是否真实且足够 | 人工确认的原始依据、粒度、公式、单位、条件及完整依赖 | AI 候选、检查通过或参考分高不证明业务为真 |
| 本次用的是哪个有效版本 | 精确知识来源/修订、文档版本、快照、build membership，及使用时的当前资格 | 已发布不等于已构建，曾审核通过不等于现在仍有效 |
| 是否允许本次使用 | 当前用户/数据源/资源与 usage、授权/执行/保护/完成阶段复核 | 可检索不等于允许 JOIN、投影、导出或读取所有结果 |
| SQL 和结果是否符合口径 | 业务预期、最终 SQL 的粒度/关联/聚合核对及同一受保护尝试结果 | SQL 能执行、模型返回或字段被引用不证明答案正确 |
| 能否追溯和判断影响 | 结果列来源、完整 SQL 使用字段、任务/尝试/hash，以及记录覆盖范围 | 输出来源不证明某条知识被模型采用，零条记录不证明零影响 |

“六类对象”是数据源、表、字段、业务关系、指标和血缘的能力覆盖范围，不要求每个问题同时具备六类事实。单表计数可以不需要业务关系或字段派生；多表指标必须有与其口径有关的粒度、关系和公式依据。缺少真实口径时澄清或补治理，权限/来源失效时拒绝；已有合规知识却未进入上下文是检索/适配问题，应查缺陷或使用已有安全兜底，不能让用户补资料来掩盖。供应商、网络及格式故障继续归系统失败。

## 血缘的存储、消费与展示边界

血缘有两个适配方向：已确认血缘经知识文档和 RAG 供问数使用；本次 SQL 的真实使用与输出来源形成查询记录，供追溯和影响分析。

| 环节 | 权威事实与当前行为 | 边界 |
| --- | --- | --- |
| 实体关系图 | `metadata_entity/metadata_relationship` 保存手工/ETL 表级关系及字段映射；原维护、可见性和复采绑定继续使用 | ETL 类型录入不证明已自动接入外部 ETL 引擎；跨源图可按权限追溯，不授权单次问数跨库 JOIN |
| 血缘知识 | 已确认、当前绑定的同源关系固定类型、两端实体/FQN、快照及完整依赖，生成来源摘要 | 表级 `LINEAGE` 与字段级 `DERIVED_FROM` 分别校验；外源端点不能截为本源同名表 |
| 查询追溯 | `query_task.iam_source_trace` 保存同一受保护尝试的来源；`query_lineage_table/column` 是提交后生成的使用/输出来源索引 | SELECT 的派生目标是本次结果列，不是另一张参与 JOIN 的物理表；不生成 FROM→JOIN 物理数据流边 |
| 页面与影响 | 实体图与查询明细各用其真实来源；影响面板显示成功受保护查询的去重数量、明细限制、最早记录及本源待处理数 | 统计覆盖历史快照，没有精确快照/时间筛选；未补证旧记录不计入，零记录不等于没有影响 |

接口、图谱维护和源码入口统一见[审计与血缘模块](../modules/011-audit-lineage.md)。质量问题、审核后的业务 Join 和使用参考分均不自动改写数据流。

## 修正后的最终方案与红队审查

方案以单一权威来源和最小持久状态实现：知识来源摘要由 Java 计算；构建和任务冻结摘要；Python 只能在已授权事实内规划；结果来源以同一 PROTECTED 尝试为准。完成事务同时保存来源和 `PENDING` 标记，提交后独立事务投影，后台有限批次重试；不新增外部消息服务或第二套对话存储。

| 对抗场景 | 修正后的规则 | 验证或限制 |
| --- | --- | --- |
| 两个 helper 都把数据库名误当表，彼此校验仍通过 | 按三段表/四段字段身份解析，并与实体类型、真实资源及同源边界核对 | Java/Python 正反例；异常和不能无歧义解析的 FQN 拒绝使用 |
| 为让探针变绿放行空列字段派生 | 先确定事实类型的最小完整依赖，再修正错误测试期望 | 空列 `DERIVED_FROM` 拒绝，真正完整的表级事实保留 |
| 列表读取后同 ID 内容变化，旧正文误配新摘要 | 正文与摘要都由 currentSnapshot 的同一份关系记录生成，候选列表只提供身份；后续资格再验 | 两次读取不同版本的确定性反例，生成正文/摘要一致且后续改动使旧摘要失效 |
| 同一关系 ID 改端点、转换内容、确认或绑定 | 冻结包含来源/双端/快照/内容/依赖的摘要，构建、派发及各执行门禁重验 | 来源变化、撤回、重绑定和执行阶段拒绝有回归 |
| 同表对的未采用候选缺 JOIN 权限，或补一半才发现所选关系无权 | 规划输出 selectedRelationIds，仅校验所选审核关系并原子补键，SQL 上下文只保留所选业务关系 | 买方/卖方候选对照、未知/未审核 ID 拒绝及缺 JOIN 权限不修改规划 |
| 重复完成、取消与并发投影 | 先锁任务再锁尝试；仅成功状态转换发提交后通知；同任务投影行锁和同事务完成标记 | CAS=0、重复/并发、回滚与提交顺序有测试 |
| 提交后通知丢失、进程中断或索引写一半 | 权威来源和待处理标记与结果一起提交；投影失败全回滚并保留待处理，扫描恢复且坏任务不阻塞后续任务 | 恢复入口和部分失败有 H2 证据；未做真实进程崩溃演练，不承诺物理上的恰一次投递 |
| JSON 整数表现型不同导致合法身份误拒绝 | 按精确整数值核对权限/快照身份，拒绝小数截断 | 受保护身份与真实事务投影回归 |
| 明细截断、同任务多来源或旧记录混入总数 | 独立 SQL 按成功受保护任务去重，近期任务去重，展示覆盖与待处理限制 | 超过 100 个任务、源隔离、重复和失败/取消有对照 |
| A→B→A、主图与实体展开重叠、旧失败晚到或卸载 | 主图与 loadEntityLineage 展开入口接管同一 loading 所有权，按当前请求接纳响应/错误并清理；增强及回退每次异步返回均校验 | 重叠后可刷新、旧增强成功/失败不覆盖新展开；知识页和影响面板仍有范围测试，浏览器视觉另验 |

## G0：治理有效知识与文档交接

字段及四类业务知识已有候选、人工依据、人审、精确修订复查和撤回机制。系统校验证明形式、来源及完整依赖符合合同；真实用途、粒度、关系基数和指标口径仍须由人工业务依据确认。主题文档逐篇及整组覆盖校验、发布与显式 build 分离继续保留，不重新开发已完成治理主体。

## G1：表级血缘 FQN 的依赖解析错误

已用[LineageDependencies](../../backend/DataOcean/src/main/java/com/dataocean/module/knowledge/support/LineageDependencies.java)统一 Java 生成/校验的解析，Python `_lineage_dependencies` 同样区分三段表、四段字段并核对显式依赖。`ds.db.orders → ds.db.rollups` 解析为两张真实表；异常、混合端点、外源/外库及伪造依赖不能作为单源知识。实体图中的关系本身不因此删除。

[LineageFactService](../../backend/DataOcean/src/main/java/com/dataocean/module/knowledge/service/impl/LineageFactService.java)另核验当前发布快照、实体归属、端点类型与治理状态，避免只比较两个字符串 helper。`currentSnapshot` 从同一份关系记录生成正文输入及其摘要；列表读取只用于确定候选 ID，不再从旧列表行组装正文后附上新摘要。来源摘要经 marker、Python chunk、MySQL chunk 与 build membership 传递，后续来源变化仍由审核/构建和查询各阶段重验。

## R1：纯表级事实在查询准入处丢失

Java 与 Python 已按下表判断完整依赖，保留合法表级事实，不通过伪造字段或放宽 IAM 完成适配。

| 事实 | 最小依赖边界 | 空列处理 |
| --- | --- | --- |
| 结构说明、用途、表粒度、纯表计数指标 | 该事实实际涉及的完整表依赖；引用字段时仍须带齐字段 | 确实无字段依赖且当前合规时允许 |
| 表级 `LINEAGE` | 真实 TABLE 端点、关系来源及两端完整表依赖 | 可无字段，不伪造列 |
| 字段级 `DERIVED_FROM`、字段解释及依赖字段的关系/指标 | 真实字段端点或公式/连接字段，及所属表完整依赖 | 拒绝空列或缺少任一必要字段 |

原始空列 `DERIVED_FROM` 探针的正向期望已勘误；失败计数保留在原诊断，不能用它要求扩大白名单。Java 在构造模型输入前核对当前事实来源与可见依赖，Python 防火墙再次核对类型、完整依赖、build/快照和资源范围。

## R2：血缘当前来源资格尚缺同等级查询复核证据

该原始缺口已补当前资格检查。来源摘要绑定关系类型/方向、两端实体/FQN、快照和关系内容；同 ID 原地修改、撤销确认、解绑、复采失效、禁止对象和快照变化都会使原引用失效。文档审核/构建、查询派发以及尝试授权、执行开始、结果保护和完成均保持相应核验。

任务使用 `lineage_refs_json` 固定本次合规候选的来源摘要和完整依赖，与字段/业务引用一样采取保守失效策略。失效后拒绝并要求重新提问，不切换 build。旧在途任务缺少冻结凭据时不猜测补齐；已完成历史结果仍按原当前 IAM 读取合同展示。真实撤权/复采及有在途引用的 build 替换仍待运行验收。

## Q1：新业务关系没有进入关联字段补齐分支

规划器的固定 `schema_linking` 输出合同增加 `selectedRelationIds`，只填写本题采用的已审核 `BUSINESS_RELATION.factSourceIds[0]`，无需关系时填空数组。`_add_confirmed_join_columns` 仅校验这些身份的完整依赖、已选择表范围和当前 JOIN usage，全部通过后原子补键；不再把同表对的其他候选变成必需条件。未知、未审核、格式不符或越出本题表范围的选择按规划合同失败处理；所选关系缺 JOIN 权限仍拒绝，旧 `JOIN_PATH` 不直通。

SQL 上下文的 `_linked_rag` 同样只保留所选业务关系，避免未采用候选再次混入生成阶段。该身份列表是规划选择声明，不证明 SQL 实际采用；Java 已冻结的候选来源及原保守失效合同保持不变，最终口径仍需核对 SQL 和业务结果。

## 相关问题：构建页面的范围显示可能过期

知识页统计、已发布快照、RAG 列表、生成弹窗快照和生成结果已绑定范围、请求序号和生命周期。切源、关弹窗及卸载会使旧请求失效；旧响应、异常和 finally 不覆盖新范围或解除其加载状态。血缘影响面板同样隔离旧结果与旧失败。主图与实体展开共享请求/加载状态的所有权，当前请求统一清理 loading；旧增强响应或失败不覆盖新展开、不触发过期回退，重叠结束后可再次刷新。现有布局保留，桌面/窄屏与真实快速切换仍需浏览器验收。

## Q2：当前问数到查询血缘的写入未接通

该原始断点已接通：完成回调仅接受同任务、同 attemptId/hash 的 PROTECTED 尝试，以其字段、数据和来源替换回调自报内容。完成事务保存来源凭据及待处理状态；[QueryTraceProjectionService](../../backend/DataOcean/src/main/java/com/dataocean/module/audit/service/impl/QueryTraceProjectionService.java)提交后重读并核对尝试、权限/快照、使用表字段和输出来源，写入查询使用及输出列来源索引。

筛选、连接、分组、排序等实际使用字段与输出来源分别记录或可关联核对。COUNT(*) 的表依赖和无列来源标记、常量输出保留在权威来源中，不伪造字段。旧 `saveLineage/columnDerivations` 物理桥接已移除；本轮不向参与 JOIN 的实体表之间制造数据流边。

## Q3：完成审计的提交顺序与幂等

完成、尝试及投影统一采用任务→尝试的加锁顺序。只有成功的 PROCESSING→COMPLETED 转换才通知；CAS=0、重复完成和主事务回滚均不产生成功投影。完成转换后的持久化异常向外传播使事务回滚，不伪报权限变化。

投影在独立事务中持有任务行锁，审计、使用索引和 `trace_projection_status=COMPLETED` 一起提交；任何一步失败均回滚，保留 `PENDING`。提交后异步处理加有限批次扫描，基于已持久化来源重试，不重新执行 SQL；每轮固定扫描上界，坏任务不阻塞其他待处理任务。幂等约束重复消费，持久待处理状态支持恢复；尚未证明真实数据库故障/进程崩溃下的全部运维恢复行为。

## Q4：图谱展示与影响分析的统计边界

总数已独立聚合为当前可见数据源范围内、成功受保护且完成追溯记录的去重任务数。表/列明细最多 100 行，近期任务去重，不以明细长度代替总数；未处理完的任务显示本数据源待处理数量。

当前接口按数据源与表/列名汇总历史快照，没有精确版本或时间过滤。最早记录只说明已有记录的起点，不证明此后无遗漏；旧任务没有本轮受保护身份凭据和完成标记时不自动补成有效历史。实体上下游图、查询使用、输出派生仍分别展示，零记录不解释为没有影响。

## R3：动态使用档案与既有置信度口径

动态 profiles 在资源选定后进入 SQL 上下文；同任务固定、下一任务读取最新证据。使用参考分不证明业务正确，不放行权限；仅分数变化不改知识正文、不触发 embedding。前置重排尚未接入此分数，是独立优化；旧 `field_confidence` 与新版本化事件不能混为同一权威口径。

## R4：显式构建与向量复用不能混称

文档审核发布、显式 build、manifest 校验、活动指针和旧引用保护继续保留；本轮没有实现跨 build 的向量复用，也没有自动重建旧活动集合。内容 hash 冻结不等于增量 embedding，成本优化不作为本次必要修复的前置条件。

## 如何证明问题已解决

证据按含义区分：冻结候选只证明本次可提供的知识集合；召回并进入上下文只证明提供过；AST/授权字段与受保护来源证明 SQL 使用及输出依赖。精确口径是否落实仍需核对最终 SQL 和结果，不能由字段重合、模型自报或候选引用列表推定某条知识已被采用。没有自动采用映射时保留人工核对或“未证明”。

最小贯通题可选“按客户统计指定时间窗口的已支付订单实付金额”：先确认条件、时区、币种、粒度及基数。隔离样例为同一客户两笔合格订单 30、70，各有 2、1 条明细；预期 2 笔、合计 100，错误连明细后重复求和会得 130。逐段保存必要知识修订、文档/build、上下文、SQL/尝试/hash、结果及来源，再核对明细与统计；补撤回必要关系、去掉 JOIN usage、重复完成和仅改参考分的对照。

该业务题仍待真实资料与运行验收，不替代表级/字段级血缘、无权来源和源隔离测试。自动化及构建证据、失败后修复过程和未执行项集中在[本轮修复记录](../acceptance/2026-10-27-治理下游适配修复.md)，后续动作只在待办维护。
