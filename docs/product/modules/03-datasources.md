# 数据源接入与元数据采集

本页帮助理解方案第 3 章的职责和衔接，详细规则以[方案原件](../产品方案.docx)为准；不表示模块已经实现。

## 职责与使用者

具备相应管理能力的人员维护连接、采集覆盖和结构变化。

## 主流程

配置只读连接 → 分项测试 → 用户确认采集当前数据源 → 采集成功后更新目录并分析结构变化（首次建立基线）→ 系统明确识别的差异直接确认，疑点才交人工核实 → 同一对象的待核实变化全部确认或排除后，主动进入对应表字段治理 → 同页核对影响、AI 辅助编辑及人工审核，按需更新知识。

## 衔接与边界

- 采集记录独立成页，元数据目录与结构变化同页；失败直接显示原因，成功后才展示采集结果。菜单顺序及状态交互见[前端页面](../../frontend/pages/datasources.md)。

- 连接健康、采集状态、治理及知识可用性分别展示，连接成功不代表采集成功或业务可用。
- 采集任务只使用排队中、采集中、采集成功、采集失败、已取消；读取不全统一为采集失败，具体原因及已读内容留在任务内。只有采集成功才更新目录并分析结构变化；首次成功建立初始基线，后续成功与可比的成功快照对照。失败或取消不推进结构分析及治理；重新采集覆盖当前数据源的全部配置范围，原任务保留。系统能明确判定的差异直接确认，事实不明才交人工核实。
- 采集、目录查看和业务数据访问分别授权；新表新列不因被发现而自动开放。
- 企业业务说明归属明确的数据源，按源供治理人员和获准治理任务共享，不设置逐人使用名单；原始附件的后台查看与下载单独受控，发布后的通用知识按当前源问数授权取用。
- 资料所有修订均未被任何治理任务取用或治理成果引用时可删除，确认时重新核验权限及引用；历史任务、历史成果与在途取用同样阻止删除。已使用资料可撤下并恢复，保留修订、原因及操作记录；撤下停止后续取用，已有治理成果按依赖复核，不自动改写或停用已发布知识。删除只保留必要操作记录。
- 每次采集均有任务和候选快照，只有实际差异才新增变化记录；无变化对象沿用原结构修订，失败或取消的已读内容只保留在任务，不替换最近成功结果或分析结构变化。快照编号不代表结构修改次数。
- 配置修订、采集快照、对象结构修订、对象世代、资料修订、治理修订及知识草稿／候选／发布版本分别记录，触发条件见方案第 3 章“版本与知识更新的关系”。变化保留来源任务与前后快照，历史来源不随新采集改写。
- 目录状态与任务结果分开，结构变化和属性缺失可并存。对象、字段和变化项分别展示；普通视图不套用表的物理约束，读取缺项不写成属性不存在。
- 采集成功后对照同范围、成功且可比较的新旧结构快照，可靠差异直接进入待治理，证据不足才进入待核实。结构变化列表按对象、类型、发现时间、处理阶段和下一步操作组织；阶段为待核实、待治理、治理中、知识处理中、已完成。事实结论、来源依据、禁用范围和具体完成结果在详情回看。访问丢失由维护人员核实对象是否仍存在：确认删除后禁用对象并进入治理，对象仍存在则排除结构变化，访问异常继续保留到成功读取。无法判断时取消或返回。事实核实不替代业务治理，阶段完成不代表来源访问恢复。
- 每条变化保留来源任务、前后内容、检测证据和核实记录；已知变更原因作为来源说明及依据回看，不另设原因填写任务。原因未知不阻挡可靠差异进入治理。技术疑点在核实页面表达，业务问题随受影响的治理条目核对。
- 变化事实只在数据源侧核实一次；同一张表及字段的待核实项全部确认或排除后，主动进入表治理的受影响条目，其他已核实对象可独立办理。治理沿用来源结论和证据，直接维护业务内容，不另办变化待办或无需修改结案；审核自动回写来源进度。未受影响条目维持原确认，单纯目录可见性改变不重置业务定义；不自动发布或解除禁止。
- 已引用业务说明的正文或附件更新、撤下形成关联实际修订及前后内容的治理待办；标题修改不触发。历史引用不改绑最新版，恢复资料不自动结束已有事项。
