# 数据源接入与元数据采集

本页帮助理解方案第 3 章的职责和衔接，详细规则以[方案原件](../产品方案.docx)为准；不表示模块已经实现。

## 职责与使用者

具备相应管理能力的人员维护连接、采集覆盖和结构变化。

## 主流程

配置只读连接 → 分项测试 → 采集可见结构并形成目录 → 可靠差异自动确认、疑点按需核实 → 治理影响评估 → 无影响结束，有影响交治理并按需更新知识。

## 衔接与边界

- 连接健康、采集完整性、治理及知识可用性分别展示，连接成功不代表业务可用。
- 采集、目录查看和业务数据访问分别授权；新表新列不因被发现而自动开放。
- 企业业务说明归属明确的数据源，按源供治理人员和获准治理任务共享，不设置逐人使用名单；原始附件的后台查看与下载单独受控，发布后的通用知识按当前源问数授权取用。
- 资料所有修订均未被任何治理任务取用或治理成果引用时可删除，确认时重新核验权限及引用；历史任务、历史成果与在途取用同样阻止删除。已使用资料可撤下并恢复，保留修订、原因及操作记录；撤下停止后续取用，已有治理成果按依赖复核，不自动改写或停用已发布知识。删除只保留必要操作记录。
- 每次采集均有任务和候选快照，只有实际差异才新增变化记录；无变化对象沿用原结构修订，失败或取消不替换最近已验证结果。快照编号不代表结构修改次数。
- 配置修订、采集快照、对象结构修订、对象世代、资料修订、治理修订及知识草稿／候选／发布版本分别记录，触发条件见方案第 3 章“版本与知识更新的关系”。变化保留来源任务与前后快照，历史来源不随新采集改写。
- 目录状态与任务结果分开，结构变化和属性缺失可并存。对象、字段和变化项分别展示；普通视图不套用表的物理约束，读取缺项不写成属性不存在。
- 变化事实与处理进度分开。可靠差异直接已确认，访问丢失或证据不足保留待核实；继续核实不冒充事实已确认，排除结构变化不解除来源访问异常。事实核实不替代业务治理。
- 已确认变化在治理审核与复核中评估；无影响记录依据后结束，不强制负责人；需要治理时关联对象、关系或指标并交接有治理编辑权限者。来源记录可回看负责人、结论和办理结果，治理确认不自动发布或解除禁止。
- 已引用业务说明的正文或附件更新、撤下形成关联实际修订及前后内容的影响评估；标题修改不触发。历史引用不改绑最新版，恢复资料不自动结束已有评估。
