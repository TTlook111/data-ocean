# 智能问数与查询流程

本页帮助理解方案第 6 章的职责和衔接，详细规则以[方案原件](../产品方案.docx)为准；不表示模块已经实现。

## 职责与使用者

有权用户在独立问数工作台提出、补充或修正问题。

## 主流程

选单一数据源 → 用户提出问题 → AI 理解需求并取得适用口径 → 判断是否需要用户补充 → 条件明确后生成 SQL → 核对原意、安全、权限与输出限制 → 只读执行 → 结果与反馈。

需要补充时在原对话中追问，用户答复后回到需求理解，合并补充和纠正，再判断条件是否充分；已有适用的企业默认口径时可直接继续并注明依据。所属部门范围及所选输出限制规则随本次问数共同核验，不能代替提问、需求理解和追问步骤。

答复更新意图后，复用仍适用且获准的检索候选及同版治理依据，不无条件重做外部检索。尚无 SQL 才进入首次生成；已有 SQL 则先重新核对意图，由生成后的检查决定是否修复。仅补明输出含义且原意检查所依赖条件未变时，可继续输出校验；正式知识缺失不能靠追问普通用户补造定义。

## 衔接与边界

- 同一输入框承载追问、改条件和换题；切源隔离上下文，不跨源拼接结果。
- 业务歧义、无权限、知识不足和技术失败分别处理，不凭猜测执行。
- 角色控制功能，所属部门及组织层级决定系统自动识别的部门范围；数据源授权选择可复用的中文输出限制规则，不设置授权期限。
- 规则限制输出，不禁止受限字段用于 WHERE 等合法条件。检查每个输出的真实含义和来源，不清楚时补取同发布修订的字段或指标治理标签。
- 命中输出限制时带原因回生成，重新核对原问题并完整校验；只有无法在权限内满足原问题才说明无权，标签不足不能误报无权。
- 文字、表格、图表、历史回看和导出遵守同一输出限制；治理禁止使用与输出限制分别核验。
- 历史展示当次事实，重新查询产生新记录；问数结果能查看即可导出，不提供回答分享。
