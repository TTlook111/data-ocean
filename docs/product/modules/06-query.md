# 智能问数与查询流程

本页帮助理解方案第 6 章的职责和衔接，详细规则以[方案原件](../产品方案.docx)为准；不表示模块已经实现。

## 职责与使用者

有权用户在独立问数工作台提出、补充或修正问题。

## 主流程

选单一数据源 → 用户提出问题 → AI 理解需求并取得适用口径 → 判断是否需要用户补充 → 条件明确后生成 SQL → 核对原意、安全、权限与输出限制 → 只读执行 → 结果与反馈。

需要补充时在原对话中追问，保存缺项和暂停节点。答复仅填入原来未确定的必要条件，且未改动已确认条件、未新增影响查询含义的要求时，合并补充后回原节点继续；答复改变已确认的指标、时间、范围、粒度或新增影响查询含义的要求时，才回到需求理解。判断必须覆盖完整答复，例如“扣掉退货，顺便按天列”包含新增分组要求，不能只消费前半句。已有适用的企业默认口径时可直接继续并注明依据。数据源授权及所选输出限制规则随本次问数共同核验，不能代替提问、需求理解和追问步骤。

补齐缺项不等于重新理解，也不等于已有检查自动通过。暂停时保存原节点、处理阶段、当前候选、尚未完成的生成任务及返回位置；有旧 SQL 留存时，也按正在处理的任务恢复，不以“有没有 SQL”决定去向。生成中补知识后续生成，校验中补知识后续相应校验；恢复生成仍须满足原生成或修复许可且不重复计数。SQL、参数或检查所依赖条件变化时，重新执行受影响的检查。改变原意后，复用仍适用且获准的依据，已有候选由意图校验判断是否需要修复。

相对日期在对应条件首次明确时按业务时区与营业日规则展开，记录锚点和实际区间；等待、恢复或重试不重算已经确定的区间。用户明确改时间时更新对应条件，新问题重新确定时间。同比、环比明确比较完整周期还是相同进度，缺少适用口径且会影响答案时追问。固定查询区间不代表冻结业务库数据。

用户可明确要求对获准的已发布基础指标做临时组合计算，记录本次公式、单位、粒度及分母为零或缺失时的处理，按实际 SQL 校验；不会自动成为企业正式指标。基础指标、必要关系或企业定义缺失仍交治理，不让普通用户现场补造企业定义。“为什么”类问题先确定可核验的时期、指标和维度对比；只有销量等事实时报告变化和贡献，明确不能据此证明客流、价格或促销造成变化。

意图校验依据原话、已确认条件、治理依据与 SQL 解析结果，逐项核对实际过滤、聚合、关联、去重、单位和比较区间；生成模型的计划和解释只作为待核对材料。

实际结果核对并通过交付权限检查后，可先交付表格及范围、口径和完整性。模型解释另记未开始、生成中、完成、失败或已停止；解释失败保留结果，只重试解释，不重新执行 SQL。解释重试仍核对当前权限、结果有效性及预算，不重置原问数计数。

## 衔接与边界

- 同一输入框承载追问、改条件和换题；切源隔离上下文，不跨源拼接结果。
- 业务歧义、无权限、知识不足和技术失败分别处理，不凭猜测执行。
- 角色控制功能，部门可分配数据源和可复用的中文输出限制规则，不设置授权期限。获得某源访问后，平台不再依据所属部门限制该源中的业务记录。
- 用户指定的门店、部门等是业务查询条件，理解与 SQL 校验仍须准确保留；没有指定时不从登录部门补入过滤。多来源规则合并与共享规则修改的生效方式仍待确定。
- 规则限制输出，不禁止受限字段用于 WHERE 等合法条件。检查每个输出的真实含义和来源，不清楚时补取同发布修订的字段或指标治理标签。
- 命中输出限制时带原因回生成，重新核对原问题并完整校验；只有无法在权限内满足原问题才说明无权，标签不足不能误报无权。
- 文字、表格、图表、历史回看和导出遵守同一输出限制；治理禁止使用与输出限制分别核验。
- 历史展示当次事实，重新查询产生新记录；问数结果能查看即可导出，不提供回答分享。
- 请求终态统一为已交付结果、权限不允许、超出问数范围、知识不足、资源或预算超限、技术失败、用户取消、等待到期未继续。终态、具体原因、数据库任务状态和解释状态分别记录；解释失败不把已成功交付的结果改报查询失败。
