# 人员角色与权限

本页帮助理解方案第 2 章的职责和衔接，详细规则以[方案原件](../产品方案.docx)为准；不表示模块已经实现。

## 职责与使用者

人员管理者维护身份与组织，授权管理者维护能力及范围，业务负责人核定用途。

## 主流程

创建账号与首次改密 → 分配个人功能角色、关联部门初始数据访问 → 额外数据申请与审批 → 执行生效 → 撤权、复核与恢复。

## 衔接与边界

- 登录账号是登录名，配合密码；管理员设置初始密码，首次登录和重置后修改密码再登录。
- 页面查看、按钮操作、数据范围、记录归属及对象状态分别约束访问；审批和执行授权分别控制。
- 个人角色只控制页面、按钮和功能。部门用于人员归属和初始数据访问分配；问数按数据源授权与输出限制规则核验，不依据所属部门或组织层级过滤业务记录。
- 人员角色分配只选择角色，可多选或清空，不设置有效时长；人员详情只展示角色名称。角色的页面和按钮功能在角色管理中维护，不在人员分配时展开。
- 数据源访问由部门初始配置和已生效申请提供。配置只选择数据源与输出限制规则，不逐项勾选表字段，也不设置授权期限。
- 部门不分配角色，初始配置关联直属及直属兼任成员；下级成员不继承上级配置。所属部门变化更新初始数据访问来源，申请不改写组织归属。
- 有权限人员统一维护规则名称和中文限制内容，例如“用户信息限制：不返回身份证、电话”“产品成本限制：不返回产品成本”。授权时可多选并查看全文，无需知道表字段。
- 输出限制只约束交付信息，受限字段仍可用于 WHERE 等合法条件。SQL 校验按输出实际含义、来源字段和治理标签匹配规则；标签不足先补取，仍无法判断则知识阻塞；命中后原意内重生成，无法按原问题回答才说明无权。
- 共享规则修改如何影响已有来源、多来源输出限制如何合并仍待确定；保留各笔来源及实际采用规则，不默认跨来源解除限制。
- 超出初始范围的数据访问必须申请，不提供岗位直接授予的旁路。批准只是执行依据，执行成功才产生实际数据授权。
- 部门初始访问、每笔申请分别保留来源、数据源与所选输出限制规则，不设置授权期限。结束一项只移除该来源，其他合法数据来源和个人角色保留；详情将功能角色与数据访问来源分开，详见[页面规则](../../frontend/pages/people-access.md#功能权限与数据访问)。
- 使用功能时共同核对功能许可、数据源授权及输出限制；用户主动指定的门店、部门等作为本题业务条件解析，不能从登录部门自动追加条件或扩大数据源授权。
- 重置密码不改变业务权限；授予上限与权限恢复属于受保护操作。
