# 人员角色与权限

本页帮助理解方案第 2 章的职责和衔接，详细规则以[方案原件](../产品方案.docx)为准；不表示模块已经实现。

## 职责与使用者

人员管理者维护身份与组织，授权管理者维护能力及范围，业务负责人核定用途。

## 主流程

创建账号与首次改密 → 分配个人功能角色、关联部门初始数据访问 → 额外数据申请与审批 → 执行生效 → 撤权、复核与恢复。

## 衔接与边界

- 登录账号是登录名，配合密码；管理员设置初始密码，首次登录和重置后修改密码再登录。
- 页面查看、按钮操作、数据范围、记录归属及对象状态分别约束访问；审批和执行授权分别控制。
- 个人角色只控制页面、按钮和功能；数据源及业务数据范围由部门初始访问和已生效申请提供，角色调整不自动扩大数据访问。
- 复用已确认治理结果，由 AI 提出业务范围及对象映射候选；有权人员核对范围、映射和开放边界后，供部门配置或申请授权使用。范围确认本身不授予数据访问，详细规则见方案第 2 章“额外数据访问申请与执行”。
- 部门不分配角色，只配置初始数据源、获准表、行条件、字段及期限；直属兼任成员也关联该来源，上下级部门不隐式继承。
- 超出初始范围的数据访问必须申请，不提供岗位直接授予的旁路。批准只是执行依据，执行成功才产生实际数据授权。
- 部门初始访问、每笔申请分别保留来源与期限。结束一项只移除该来源，其他合法数据来源和个人角色保留；详情将功能角色与数据访问来源分开，详见[页面规则](../../frontend/pages/people-access.md#功能权限与数据访问)。
- 使用功能时同时核对功能权限和对应数据访问；不同数据来源的表、行条件和字段范围不能交叉拼接。
- 重置密码不改变业务权限；授予上限与权限恢复属于受保护操作。
