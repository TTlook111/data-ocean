# 模型配置与安全调用

本页解说[产品方案](../产品方案.docx)第9章，页面交互见[模型配置与调用记录](../../frontend/pages/models.md)，不能据此推断真实服务已经实现。

管理员先在模型列表分别选择模型类型和实际接口格式，填写URL、模型名称、凭据和连接参数；再在节点列表查看每个AI节点做什么，为该节点选择已配置模型。生成、Embedding与Rerank是能力分类，不作为统一协议名称。节点分别分配，可共用同一模型，也可分别选不同模型。启停状态与最近连接测试独立表达，配置页面不要求登记用途验收、业务验收或另办审批。

系统配置保留模型配置、调用记录与故障两个页面；模型配置包含模型列表、节点列表两个页签。RAG是问数自动检索知识的流程，其向量和可选重排模型归入对应节点，不另设知识检索配置页面，不逐题选择文档。

AI节点覆盖治理解释与候选、知识文档规划及正文生成更新、标准题建议、问题理解与追问、历史摘要、SQL生成修正、SQL意图语义核对、输出含义识别、结果解释、RAG向量化和重排、反馈问题向量化。意图核对和输出含义对应方案第6章已有职责，模型提供语义判断依据，系统保留最终核对和授权决定；反馈向量化只供相似候选召回。当前原型将这些职责展开为18个配置节点：15个生成、2个Embedding、1个可选Rerank。业务核实、权限、只读执行、预算、禁止状态和发布决定仍由人工或系统规则控制。

模型接口格式决定请求和响应适配，凭据不回显且不进入提示词或日志。节点分配和模型维护分别核权；必需节点清空前确认不可用影响。配置修改和实际调用修订可追溯，停用恢复属于状态变化，历史调用保留当次配置和来源任务摘要；有权时可定位业务对象并返回原调用记录。停用显示受影响节点，结果未知不重复提交，解释失败不重发SQL。索引必须与Embedding模型匹配：已选择配置和当前生效配置分别展示，知识和反馈问题库各自提供索引更新任务及失败重试；更新期间及失败时保留仍可用的原匹配路径，没有匹配路径时明确不可用，校验通过后切换。索引更新不改变知识正文或替代发布，生成模型切换不自动改知识或重建索引。
