# 知识库与发布管理

本页帮助理解方案第 5 章的职责和衔接，详细规则以[方案原件](../产品方案.docx)为准；不表示模块已经实现。

## 职责与使用者

知识整理、测试及发布人员各自处理获准范围的文档和候选版本。

## 主流程

已确认治理内容 → 知识草稿 → 候选构建与相关测试 → 发布检查 → 范围整体切换 → 影响复核或回退。

## 衔接与边界

- 草稿、候选与当前有效版本隔离；构建或测试失败不切换有效版本。
- 知识含义改变需回到治理记录确认，不能产生两套口径。
- 变更先检查业务事实、依赖、正式文档及检索结构的实际影响，再决定是否更新受影响知识；原始资料或注释更新先复核，不直接改写已确认知识。
- 配置或采集编号变化、技术核实及治理确认均不直接切换发布版本。仅需要修改的知识进入草稿与固定候选，构建、相关测试及发布检查通过并完成范围切换后生效；无影响内容复用。
- 输出限制、数据源授权、本题条件及禁止状态本身变化不触发知识文档重新生成；问数按实际生效规则校验，必要时补取同版治理定义。业务事实缺项或错误经确认需要修正时，才进入治理与知识更新。
- 业务适用条件指口径成立的条件，不是输出限制规则。已引用资料的正文或附件变化、撤下形成可追踪的治理待办，在工作台详情核对影响；标题修改、未使用资料不自动触发知识更新，历史引用仍绑定实际使用修订。
- 治理条目人工审核后，涉及定义变动、新增、删除或仍禁止时原事项保持待知识更新，直接关联该次审核与修订；必要更新、验证及发布完成后才结束，不再另走治理结果确认。条目审核不冒充发布，亦不解除已有禁止；无需修改时记录依据并复用原知识。
- 已发布通用知识按当前源问数授权、发布有效性与禁止状态取用，不继承原始资料的逐人名单；原始附件及证据仍按后台资料权限单独核验。
- 回退仅到直接上一版，并重新检查当前依赖和禁止状态；回退不恢复已撤销权限。
