# 知识库与发布管理

[产品方案第 5 章](../产品方案.docx)维护知识文档、标准题、发布与恢复的业务规则。本页提供阅读顺序、职责和重构输入，不另维护一套详细规则。页面表达见[知识页面说明](../../frontend/pages/knowledge-release.md)，实现与验证边界见[原型状态](../../frontend/原型状态.md)。

## 职责与主流程

治理维护唯一的表说明、字段、关联和指标定义。知识模块组织这些已确认成果，不另创业务口径，不管理主题或场景分类；每份文档属于一个源，单次问数不跨源。

发起规划 → AI 提出文档建议 → 人工调整职责并核对完整范围 → 生成或合并草稿 → 确认实际修订 → 固定候选、构建和相关验证 → 发布预检 → 本批完整切换。

规划在有权限者发起时产生，不是进入列表就自动在后台运行。建议包含名称、用途、适用条件、问题、用表作用、依据、已有文档匹配和缺项。规划建议尚不算真实文档，生成草稿不等于发布；同一有权限者可以兼任，各步仍分别核权和留记录。

## 重构时必须保留的边界

- 按业务职责决定篇数，不按表、指标或问法数量计算；引用表不带入全部字段。商品中心库的两篇是当前受控样例，销量可独立发布，不是全系统固定篇数。
- 主动条目和必要依赖分别保存，冻结对象身份、世代及确切修订。删除关键依赖须先收窄用途；外键、同名字段和单段关联不能证明新算法成立。
- 操作意图、依据情况和当前使用控制独立。缺项允许保留规划及输入；部分失败保留成功结果，重试和重复提交不重复建稿。
- 已有文档的职责调整先保留为可核对的输入，不静默覆盖或丢弃。正文相同但采用依据换版仍形成新修订；采集批次或资料展示标题变化不强行改绑。
- 段落或章节对应实际治理依据。维护待办不作为正式事实；不扣退货、未知状态等已确认限制必须随相关知识进入检索上下文，原始资料及附件另行核权。
- 来源变化找全草稿、正式版本和在途候选。事项全部必要范围完成更新发布、退出、无影响判断及必要显式恢复后才回写完成，不等待无关对象。
- 合并拆分保留原稿与目标，处理来源期间新增人工修改和显式引用去向；新内容生效与旧内容退出同批完成。结果不明确时核实完整组合，部分切换不能重发；回退和恢复不能只恢复新旧内容的一边。
- 标准题覆盖关键能力和边界。审核、裁定绑定实际看到的题目、文档依据和运行记录；变化后重查，不删题绕过失败，不沿用失效成绩。
- 正式版本、下一草稿、更新提醒、暂停及禁止分别表达。发布或验证不自动恢复生产；显式恢复仍核对本次正式修订、结构、权限及风险。

## 重构记录核对

| 逻辑记录 | 必须能够追溯的内容 |
| --- | --- |
| 生成规划 | 所属源、输入依据、建议与人工调整、操作和依据情况、核对快照、逐项结果及幂等关联 |
| 文档及修订 | 稳定身份、职责、条件、问题、排除项、核心范围和完整依赖、章节与确切治理修订、生成基稿及人工正文、确认与历史 |
| 来源事项 | 全部实际受影响文档及版本、章节和问题、处理结论、待办与完成条件，不以首篇结果替代整体结果 |
| 合并拆分 | 原稿、目标、人工修改基准、待替代状态、取消、引用去向、一并切换及回退的完整组合 |
| 固定候选与运行 | 正文和范围快照、治理及文档引用、题目修订、预期与实际、裁定、基础版本、旧文档退出与实际切换结果 |
| 正式入口与控制 | 各篇实际修订和来源批次、当前依赖与权限、禁止及暂停、恢复验证、显式解除和直接上一版组合 |

这些是业务逻辑要求，不预定真实数据库表、API 或正式技术栈。原型中的样例规则、页面内存、同步动作和固定数据执行器不得直接当作真实 AI、授权、索引或事务服务。真实重构仍须按项目阶段另行确定实现任务与技术设计。
