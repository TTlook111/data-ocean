## 文档维护规则

- 行为变更更新主责模块；页面决定更新前端规范；未完成项只进后续开发；状态页只概括结论并链接证据。不要把同一批测试数字、迁移流水或问题清单复制多处。
- 一轮工作结束时，将有独立价值的执行记录和验收报告移入 `archive/`。同一轮尚未解决的事项写入后续开发，附完成条件。已被替代的操作约定直接更新到主责文档，临时草稿可从 Git 历史追溯。
- 已执行数据库迁移保持字节不变，不为文档整理修改其中的历史注释。
- 验收只保留独立证据，同一范围更新已有报告。记录环境、版本、失败与覆盖限制，区分 H2/Mock、真实数据库、模型和页面验证；不把历史证据当作当前计划或操作授权。

默认搜索排除验收材料和归档。回溯证据时可运行 `rg --no-ignore <关键词> docs/acceptance docs/archive`。
