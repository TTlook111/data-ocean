## 先概览，再按需深入

项目入口只给定位与链接；模块首页先说明职责、主流程和关键边界，再提供实现、排障和验证入口。优先使用同页章节，只有独立主题足够复杂时才拆文件。安全约束、明确禁止事项和验收限制应直接可见，不藏进折叠区。

## 方案冲突怎么判断

1. 用户后续明确指正或批准的要求优先于已被否定的旧方案、旧图稿和旧 Prompt；日期较新本身不代表已批准。
2. 现行规范承接已经确认的要求。代码用来核对落实程度，不能用尚未落实的代码反向覆盖用户要求。
3. 用户要求与实现不一致时，记录具体差距和证据；没有明确结论的争议标为待确认，不从历史方案里擅自补成决定。
4. 历史正文中的“唯一入口”“立即执行”“尚未开始”和临时授权只属于原记录时点。归档不表示重新批准，也不会触发其中的操作。
5. [前端规范](development/前端开发规范.md)、[IAM](modules/007-iam-s1.md)、[问数](modules/008-query-memory.md)、[RAG](modules/009-schema-rag.md)分别维护对应的现行要求。
