## 文档状态与使用规则

| 状态 | 用途 | 不得用于 |
| --- | --- | --- |
| 现行说明 | 已确认目标、当前实现及规范，各自在上表指定位置维护 | 用实现缺口删减已确认需求 |
| 历史证据 | 查询原日期的环境、结果、截图与覆盖限制 | 冒充当前测试基线、供应商状态或完整验收 |
| 历史参考 | 经明确需要回溯的设计和规格 | 默认作为新开发合同或待办 |
| 废弃方案 | 只解释已被替代的旧决策 | 恢复旧权限、旧 Agent、发布即索引或旧页面布局 |

现行阅读与检索先限定到本页列出的入口及其现行模块；`docs/archive/`、`specs/` 和验收历史不应作为默认当前资料。需要历史证据时才从[历史索引](archive/README.md)或[规格适用性](../specs/README.md)进入，并保留状态、日期和适用范围。此规则约束仓库文档使用，不表示已改变应用数据库中的知识文档或活动 RAG 索引。

根目录 [.rgignore](../.rgignore)已对默认 ripgrep 搜索排除历史目录、规格、验收记录和历史 SQL 夹具；Git 仍保留这些文件。明确回溯时可直接打开已知文件，或使用 `rg --no-ignore <关键词> docs/archive specs docs/acceptance`，不能将回溯结果直接升级为现行事实。

## 方案冲突怎么判断

1. 用户后续明确指正或批准的要求优先；较新日期或文件名含“最终”本身不代表批准。
2. 产品目标、当前实现、验证证据和剩余动作分开维护。代码用于核对落实程度，不能反向抹去需求。
3. 发生缺口时写入后续开发并标明证据，不把历史任务勾选状态搬回来。
4. 历史正文中的“唯一执行文档”“立即执行”和临时迁移/删除授权均不在当前生效。

## 维护方式

行为变化更新对应模块，状态变化更新项目现状，未完成动作只进后续开发；测试和运行结果只进带日期的验收记录。编辑日期不等于验证日期。

旧方案实施后移到历史参考；被明确替代的方案标为废弃。保留仍有追溯价值的原始证据，不在现行页累积迁移流水、重复测试数字、旧阻断和完整实施时间线。历史文件内的相对链接随移动更新，不能用失效链接充当删除记录。

本机运行日志、备份和 PID 位于本机环境记录指定的仓库外目录；页面证据位于 `output/playwright/`。共享文档不写本机密钥，且不承诺历史本机输出在其他机器存在。
