## 2. 高/阻断级问题详解

### A1（阻断）`/admin/metadata/tables` 是活页面，交付物却称它已重定向

**代码事实**（`frontend/src/router/index.ts:256-261`）：

```ts
{
  path: 'metadata/tables',
  name: 'admin-metadata-tables',
  component: TableExplorer,
  meta: { title: '表浏览器', domainKey: 'data-assets', workspaceKey: 'assets', contextMode: 'datasource-snapshot' },
},
```

是 `component` 不是 `redirect`，且带完整 route meta——这是**一等公民活页面**，不是遗留残渣。

**规范要求**：

- 开发指导 §9 重定向表：`| /admin/metadata/tables | /admin/assets |`
- 实施任务清单 §7.2：`资产目录 | getEntitiesByDatasource… | 合并 CatalogSearch.vue、TableExplorer.vue`

**交付物却写着**：`原能力迁移对照表.md:56` 记录 `/admin/metadata/tables → /admin/assets`；同文档 §六 写「旧菜单入口是否仍在：否……旧 URL 仅作兼容重定向」。

**加重情节**：F4 缺陷修复**正是以这条路由为案例**完成的（修复它二级导航高亮为 0）。也就是说实施者手里有「这条路由是活的」的直接证据，却在强制交付物里写成了重定向。同时 `ADMIN_WORKSPACES` 无此项，该页**没有任何导航入口**，只能手输旧 URL 到达。

**结论**：阶段 8 的这一项**未完成**，且交付物作了相反陈述。

### A2（高）授权「有效期」静默失效 → 临时授权变永久授权

三个独立审查通道同时命中。

**前端**（`api/admin/permission.ts:74-75`，注释为实施者所写）：

```ts
/** 授权有效期；留空表示长期有效。后端 DTO 已有该字段，此前前端类型未定义导致无法设置 */
expiresAt?: string
```

`AccessControl.vue:685-693` 提供 `el-date-picker`，`:287` 提交 `grantDatasourcePermission(grantForm)`。

**后端**：`DatasourcePermissionController:40` 收 `@Valid @RequestBody DatasourcePermissionGrantDTO`，该 DTO **7 个字段里没有 `expiresAt`**（末字段为 `accessEffect`）。`DatasourcePermissionServiceImpl.grant()` 也从不调用 `setExpiresAt()`。`PUT /{id}` 虽走 `Map` 体，但 `permissionService.update(...)` 的签名同样没有该参数。

**没有任何写入路径。** Spring Boot 默认关闭 `FAIL_ON_UNKNOWN_PROPERTIES`，字段被静默丢弃。

**为什么这条严重**——症状不是「控件没反应」：

1. `DatasourcePermissionVO:27` **有** `expiresAt`，`AccessControl.vue:523` 真的渲染它。
2. `DatasourceAccessMapper:58` 的 `AND (a.expires_at IS NULL OR a.expires_at > NOW())` 证明该字段**真会被权限判定使用**。
3. 于是：管理员选好到期时间 → 提交成功 → 提示「授权成功」→ 该行显示「长期有效」。**临时授权实际成为永久授权，且事后无从自证**。

**修复方向**：给 `DatasourcePermissionGrantDTO` 加 `expiresAt` 并在 `grant()` 中落库；或前端移除该控件并如实标注缺口。**不能保留现状。**

### A3（高，本轮回归）权限预览把「无任何授权」显示成「允许」

`AccessControl.vue:170`：

```ts
const effectLabel = (effect?: string) => (effect === 'DENY' ? '禁止' : '允许')
```

**只有 `DENY` 被识别，其余一律「允许」。**

- 后端 `DatasourcePermissionDecisionVO:24`：`private String accessEffect = "NONE";` —— **默认值就是 `NONE`**。
- `DatasourceAccessServiceImpl.mergeDecision()` 在无任何部门/角色/用户授权时直接返回默认值，`accessEffect` 保持 `NONE`。
- 前端自己的类型也声明了 `accessEffect: 'ALLOW' | 'DENY' | 'NONE'`（`api/admin/permission.ts:89`）。

**这是回归**：旧代码 `git show main:frontend/src/views/admin/permission/AccessControl.vue:236` 打印原始枚举 `{{ decision.accessEffect }}`，`NONE` 至少显示为 `NONE`。

**用户可见后果**：对一个完全没有授权的用户，「最终权限预览」显示「最终效果：允许」，而**同一面板下方**写着「查询：禁止 / 导出：禁止 / 查看 SQL：隐藏」，且 §637 的 DENY 说明块（只在 `DENY` 时显示）不触发。管理员据此得出「存在允许授权」的结论。

**这正是开发指导 §9 门禁表明令禁止的行为**：「仅因存在 ALLOW 就显示可访问」。

### A5（高）`/re-vectorize` 是占位实现，页面还展示恒为 0/0 的假进度

**Python 侧自陈**（`python-service/dataocean/rag/router.py:167-181`）：

```python
@router.post("/re-vectorize")
async def re_vectorize(request: ReVectorizeRequest) -> dict:
    """全量重新向量化入口占位。

    当前按文档先完成 pending 向量化协议；实际全量任务编排由 Java 侧读取 chunks 后
    调用 /vectorize 分批完成。这里提供统一入口，便于前端触发和后续扩展进度管理。
    """
    return {
        "status": "ACCEPTED",
        "isPending": request.is_pending,
        ...
    }
```

函数体只回显请求，不做任何事。Java `AiConfigServiceImpl:345-353` 据此返回。

**前端却宣称**（`AiConfig.vue:429-457`）：确认文案写「该操作会遍历并重新向量化全部知识切片，属于高风险操作」，成功后提示「已触发重新向量化，可稍后刷新查看进度」。

**假进度**：`AiConfigVO.VectorizeStatus` 的 `totalChunks/completedChunks/failedChunks` 全仓只在 `defaultVectorizeStatus()` 里被写成 `0`，`errorMessage` **从无写入者**。前端 `v-if="typeof vectorizeStatus?.totalChunks === 'number'"` 恒为真 → 页面**永远**显示「切片进度：已完成 0 / 共 0」，「失败原因」永不出现。

**后果**：用户以为索引正在重建，实际什么都没发生（Java 侧 `REINDEX_REQUIRED` / `pendingEmbedding` 状态也不会被这次调用改写），同时页面持续展示一个无论知识库多大都恒为 `0/0` 的**误导性统计**。

**阶段 7 总结第 97 行「已展示…切片进度、失败原因」与第 110 行的风险描述均未指出端点本身是占位实现。**

### A13（高）脱敏摘要在说谎——脱敏有效，标签错误

## 4. 方法论问题：「构建通过」覆盖不到什么

实施过程中一直把「`npm run build` 通过」作为主要验证证据。本次审查确认它有一个**实质性盲区**：

- `frontend/tsconfig*.json` **没有配置 `vueCompilerOptions.strictTemplates`**，默认关闭。
- 因此 `vue-tsc` **不检查模板中的组件解析**——未导入的组件不会导致类型错误。
- 实证：A6/B19 的三个未导入组件（`LoadingState`、`ErrorState`、`ChevronDown`）**全部穿过了 `npm run build`**，退出码 0。

**结论**：对「模板引用了不存在的东西」这一类缺陷，**构建通过不构成任何证据**。阶段总结里「构建通过 = 结构断言成立」的表述需要相应降级。

**可复用的补充检查**（本次审查所用，脚本思路）：以 `main.ts` 为根解析真实 import 路径做传递可达性；交叉核对全部 `.vue` 模板中 PascalCase 标签与 script 导入（排除 `El*` 前缀与已全局注册项）；对模板里每个字段访问与导入类型做并集比对。这三项抓出了本次全部「静默失效」类问题的另一半。
