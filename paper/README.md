# DataOcean 论文写作

本目录保存围绕 DataOcean 的论文要求、素材、正文、参考文献与图件。当前只建立写作入口，尚未确定题目、起草正文或开展论文实验。

## 写作要求与进度

| 项目 | 当前约定 |
| --- | --- |
| 研究对象 | DataOcean 项目；论文选题与具体贡献待明确 |
| 语言 | 按用户要求；中文任务保持中文 |
| 类型与格式 | 学位论文、课程论文或投稿稿件待明确；学校或目标期刊模板优先 |
| 已有材料 | 仓库现行文档、相关实现与注明范围的验证证据 |
| 当前进度 | 写作空间已建立，尚无正文、论文实验数据或投稿结论 |

## 写作工具入口

已配置的本机 Codex 用户可通过 `$academic-writing` 使用统一入口，也可直接描述“写论文”“修改开题报告”“正式整理这份报告”等任务。入口先读取全局的“写作工具说明”，再选择具体技能；项目不重复存放第三方技能。

全局工具按当前用户安装，不随本仓库自动分发；其他机器使用前需检查是否存在该入口。完整来源、版本和工具分工由全局入口维护，项目内只维护本项目要求、材料与进度。

首次开展具体写作时，更新上表的已确认信息，再按实际需要组织正文、引用与图件；保留引用来源、图件可编辑源文件和最终使用版本。已有明确输出路径时按用户要求保存。

## 项目事实与材料来源

- 从[文档导航](../docs/README.md)进入当前资料；架构与模块职责见[技术栈与模块职责](../docs/技术栈与模块职责.md)，具体行为从[模块导航](../docs/modules/README.md)核对相关实现。
- 当前状态与限制以[项目现状](../docs/项目现状.md)为入口；每项测试、真实接口和人工验收结论须回到注明日期与覆盖范围的原始证据。
- 产品目标、当前实现、已完成验证和待办分别表述。历史规格需先查[规格适用性](../specs/README.md)，不能直接写成现行实现或已完成实验。
- 论文中的数字、性能对比、创新性和结论边界必须有相应数据或来源。缺失处标注“待补证据”，不能把设计目标或自动化测试通过改写为已证明的科研结论。
- 设计文档可作为理解项目的材料；论文对外使用前检查是否包含私有地址、凭据或不宜公开的数据。

项目开发文档继续在原位置维护；论文写作进度在本页更新。
